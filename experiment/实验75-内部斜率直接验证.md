# 实验75：内部斜率直接验证

日期：2026-09-26。目标是直接检验“查询目标最大值必在四角”的未证假设。公开1M不参与候选选择。

## 预注册

- 基线：当前 mult2 residue 表的四角，`S=120`，斜率 `(a,b)` 为
  `[(1500,1270),(1500,-1250),(-1500,1270),(-1500,-1250)]`。
- 候选固定为三组，不看标签后增删：
  - `x-half`：`[(750,1270),(750,-1250),(-750,1270),(-750,-1250)]`；
  - `y-half`：`[(1500,635),(1500,-625),(-1500,635),(-1500,-625)]`；
  - `xy-half`：`[(750,635),(750,-625),(-750,635),(-750,-625)]`。
- 评估路径固定为 `-residue-mult 2 -endpoint-mode off -residual off -bias-ps 0`，只比较 residue 核心，避免端点枚举和残差模型掩盖斜率效果。候选均从同一架构、同一表构建流程生成。
- 新窗口由 `scripts/make_scale_requests.py --mode unique --rows 2048 --block-rows 2048` 生成；标签用 exact Router 产生。该窗口不使用公开1M、exp24/exp43/exp62/exp64 已看标签。
- 主指标是可达行的 MAPE 和 accuracy，逐行配对；候选只有在新窗口上优于基线且输出行数、端点和不可达语义一致时，才允许进入更大独立窗口。没有把这次小窗口结果直接用于正式接入。

## 执行证据

候选二进制和输出写入 `build/exp75/`，窗口与 exact 标签身份写入 `validation/results/exp75-slope-screen.json`。本轮只做精度筛选，性能仍按 3 对交错协议另行测量。

## 结果

新窗口共 32 行，exact 输出 SHA 为 `0e9511a5293cd0d0739ecfb13b0b1caf38104ca9f75a0d8652d8ade1937771c0`。四个输出均为 32 行且端点逐行一致；可达行 MAPE 如下：

| 配置 | MAPE | accuracy | MAE |
| --- | ---: | ---: | ---: |
| corner | 1.960429% | 98.039571% | 49.68 ps |
| x-half | 8.886380% | 91.113619% | 283.23 ps |
| y-half | 27.530351% | 72.469649% | 1003.29 ps |
| xy-half | 34.190909% | 65.809091% | 1225.58 ps |

三种内部斜率均明显退化，按预注册停止条件不扩大窗口，也不接入正式路径。证据 `validation/results/exp75-slope-screen.json`；内部斜率仍没有一般性数学排除，但本轮固定候选已经被新 exact 窗口否定。候选宏源码保留在提交 `9d010c9`，可分别用 `-DEXP75_X_HALF`、`-DEXP75_Y_HALF`、`-DEXP75_XY_HALF` 编译；正式源码由 `f85bc3c` 恢复。
