# 实验195 C1 端点可达性资格审计结果

2026-10-10。实验在 exp194 的不可达资格缺口后执行。C++ guard 只读取架构和
`exp174-raw-sample-requests.csv`，未读取 exact；Python 仅在运行后用 exp174 标签核对。

## 结果

6176 条固定请求全部完成：

| 项目 | 数量 |
| --- | ---: |
| exact 可达 | 6076 |
| exact 不可达 | 100 |
| 源侧 `E_s` 失败 | 61 |
| 目标侧 `E_t` 失败 | 40 |
| `local_direct` | 1 |
| guard 通过 | 6076 |
| 可达行被过滤 | 0 |
| 不可达行未被过滤 | 0 |

源侧和目标侧各自是 `Architecture::resolveNet` /
`resolveNetPredecessor` 的必要端点检查，和生产 `collectExits` /
`collectEntrances` 使用同一解析语义。当前样本中，`E_s/E_t` 过滤掉全部 100 条不可达
行，同时没有过滤任何可达行。该结果是固定样本的必要条件证据，不是全域完备性证明。

## 采纳

- 在任何 h_safe 或其他 finite 下界使用前，先保持原预测 `P<0` 的不可达语义。
- 对需要 Net 的请求执行 `E_s/E_t`；失败时跳过 finite 下界，不把它转换为输出。
- `local_direct` 保留同针脚和同单元直接 Arc 语义。
- 下一轮可在 guard 后重算 h_safe 的可达行 oracle；仍需搜索
  `E_s∧E_t` 全通过但中间 port-state 不可达的反例，不能把本轮样本结果提升为定理。
