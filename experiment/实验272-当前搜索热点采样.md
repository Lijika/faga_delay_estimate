# 实验272 当前搜索热点采样

2026-10-15。exp270完整1M为370.26与366.50秒，
第一阶段目标仍为100秒。以当前冻结代码采样，选择下一项
具有足够成本占比的优化方向。

## 预注册

使用exp270全部相同源码与编译选项，仅保留符号并增加调试信息；
运行前比较`.text`、`.rodata`、`.data`内容及已加载段布局。
若机器码或静态数据改变，先说明差异，采样仅作诊断。
冻结原ELF、采样ELF、命令、输入、源码和采样工具身份。

远程r9r4900工作目录内core3串行，对两种原序20k各做
一次cycles用户态采样，频率999Hz，实际CSV写出；完整输出
SHA与exp270配对结果一致。采样期CPU仅作诊断，不加入
性能配对。记录采样命令、函数占比、query内主要指令位置、
丢失事件和输出身份。

先检查排序准备/求值、堆push/pop、距离及parent访存、
几何解析、失败后P回退的实际占比，再决定下一项实验。
采样证据不直接给出优化速度或跨机器结论。
远程完成exp270完整1M后才开始；本地开工可用419GiB。
所有新文件位于`build/exp272/`及`validation/results/exp272/`。

## 采样结果

`.text`、`.rodata`、`.data`的完整SHA及ELF加载段布局均与exp270一致。
远程两组输出SHA与exp270相同，U-output有10,136个样本，
U-role有10,379个样本，两组丢失事件均为0。

| 函数 | U-output占比 | U-role占比 |
| --- | ---: | ---: |
| relax lambda | 47.43% | 46.05% |
| query主函数 | 24.51% | 23.98% |
| ZSTD_decompressSequences | 7.23% | 6.99% |
| LegalPathSearch::init | 5.99% | 5.84% |
| ResidueEstimator::tableValue | 4.81% | 4.69% |
| UpperTree::evaluate | 0.95% | 3.77% |

行级报告中，`legal_path_search.cpp:251`的距离比较占15.74%与15.05%，
后继循环的312行占3.93%与3.78%。四角最大值、堆比较及移动分散在
rankZ、tuple与vector对应行。采样点可定位开销，cache miss和分支
失误的份额仍需专门事件核验。

本地按mangled symbol调用annotate两次返回无样本。远程改用报告中的
demangled全名后能得到反汇编及样本总数，各指令占比仍全部为0，
因此指令级占比仅保留原始文件，选择下一项以函数与源码行报告为据。
证据见`profile.json`、`analysis.json`、两组`*-lines.txt`与
`evidence-check.json`。
四份原始functions/lines报告保留perf的行尾列对齐空格，
`git diff --check`在这些行报告空白；其余新增文件检查通过。
原始报告保持完整字节及已冻结SHA。

## 下一项与边界

优先试固定Z后继邻接及源编号复用，保留Arc原序，减少每次后继的
`isNetSource`、端口到状态编号及端口到rank源编号查找。距离表访问
与堆操作随后分别检查。窄表缺席时leader/margin仍计算的成本先保留，
当前两组热点对应窄表可用路径，收益需要另有触发数据。

本轮只提供当前Xeon、两套开发20k的热点定位，性能结论继续使用
无插桩配对计时。正式入口及交付包保持原状。本地收尾可用419GiB，
本轮未删除文件，释放0GiB。
