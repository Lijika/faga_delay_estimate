# 实验20C：区域接口骨架（CCH / TNR / HL 局部原型）

## 目标
把20A的8x8窗口（L1=2x2、L2=4x4 tiles）压成区域接口骨架，并在骨架上实现CCH、TNR（access+table+
保守locality filter）与HL（superlabel cover+查询）。全部测试代码，不读golden、不改生产默认。

## 方法
- **骨架**（`tests/interface_graph.h`）：节点=L1 entry/exit 去重（8192）；边=完整L1矩阵的每个有限
  entry→exit 项（253952，从 `TwoLevelCrp` 只读 getter 导出，不重算CRP）+ 原图跨L1的Net hop（4096，
  窗口里跨cell边恰好都是Net）。另有一个 `complete` 变体：补非entry接口节点的cell内source行、
  非exit接口节点的sink列，用于完整性讨论。
- **CCH**：复用 `tests/cch.h`；顺序用 `validation/exp20b_order.py --prefix exp20c` 的真实METIS
  NodeND（pymetis 2025.2.2，seed 20260919），order header带骨架FNV与perm sha256，探针拒绝不符。
- **TNR**（`tests/tnr.h`）：T=有跨L2边的接口节点（=L2 exits，2048）；每个T做正向与反向Dijkstra且
  不穿过其他T，得每个非T节点的Aout(s)=d(s→τ)、Ain(t)=d(τ→t)；T×T用完整骨架exact（每T一次
  Dijkstra）；locality filter=s∈T 或 t∈T 或两者非T且 remove-T 后弱连通分量不同才global，否则local
  （骨架plain）；global式若INF直接-1（无plain fallback，避免掩盖cover错误与污染global计时）。
- **HL**（`tests/hl.h`）：复用CCH的完整forward-upward与reverse-upward可达label（不裁剪、不用relay、
  不声称strict），(hub,up_distance)与(hub,down_distance)按hub排序，查询双指针最小和；winning hub
  再用骨架plain核对两侧距离=cover证据。
- **预算**：2e9B。只有transit table在分配前用精确 |T|²×4 检查；access与labels在构建中按**实测累计
  容量+实时RSS+本步增量**检查（不做"按首个样本外推"），scratch字段名标 `estimated_*`；`budget_ok`
  与 `passed` 都含 `ru_maxrss` 与实际RSS。
- **请求**：固定seed生成160条**接口**请求（8 zero/40 local/40 global/72 random），全部与窗口plain
  reference比对；人工8x4图（2x2/4x4 cell）另做接口全对（900对），并要求无补全变体出现差异作为负例。
- **独立验证**：`validation/exp20c_verify.py` 从CSV与order文件重算102项（含负控制：改距离/改label
  计数/改order/改表计数都被对应检查抓到）。

## 结果（数字以 `validation/results/exp20c.json` 与 `exp20c-queries.csv` 为准）
- 骨架：8192接口节点、253952矩阵弧+4096跨cell Net=258048无向边，构建0.003s；CRP L1矩阵
  1081344项中253952有限（0.12s定制），L2 1048576项全有限（0.90s）。
- **完整性（只对已核对的图成立）**：最小骨架在**全部 67,108,864 个有序接口对**上与窗口plain一致
  （0不一致）→ 本窗口不需要 entry/exit 之外的同cell连接；补全变体在本窗口同样全对（4096+4096条额外
  边没有改变任何一对的距离）。人工接口骨架相反：无补全变体900对里60对偏大，反例 source=0→target=5
  图16 vs 骨架17，说明**该图**上最小骨架会高估、确实需要额外同cell连接。该反例没有记录两端角色
  （entry/exit），所以不声称它具体是"exit-only→entry-only"这一种形态，也不对一般图声明补全的完备性。
- **CCH（骨架）**：258048无向边→4587491弧（fill 4329443，16.78x）、max up 1535 / down 3154、
  拓扑200.5s、定制81.9s（init 0.06 + triangle 81.8）、三角形2.138e9、权payload 36.7MB、结构225.0MB。
- **TNR**：T=2048、remove-T后4个分量、access 3.15M(out)+2.10M(in)=42.0MB（每节点≤512）、
  table 2048²全有限（4194304/4194304，16.8MB）、plan 0.009s / access 1.79s / table 3.99s。
- **HL**：11,962,830 forward + 12,043,094 backward 项（24.0M项，payload 192.0MB，最大label 1954），
  构建287.1s；winning hub 160/160 与骨架plain两侧距离一致。
- **160条接口请求**：plain/CCH/TNR/HL **160/160** 都与窗口reference一致；不可达0条（接口层实测：
  T×T表全有限，生成时的48个抽样源×全目标扫描无INF目标——"不可达0"是实测结论，不是遗漏）。
  延迟均值 plain 1017µs / CCH 15650µs / TNR 620µs / HL 19.7µs，p95 2154/35698/2004/65；
  TNR local 47条(1134µs，走骨架plain) vs global 113条(406µs，平均59k access对/查询)；零对8条。
- **内存**：accounted 484.7MB（CRP 8.5 + CCH 225.0 + TNR表16.8 + access 42.0 + label 192.0）、
  resident 444.5MB、峰值RSS 433516KiB、表前投影299.0MB，全部<2e9；`budget_ok=true` 且 passed 含预算。
- **结论**：HL 查询是 O(|Lf|+|Lr|) 的双指针扫描（本实例平均1914个label项/查询），实测19.7µs，
  比骨架plain快51.7x、比骨架CCH快794x；TNR global 快于 local（406 vs 1134µs）但 local 仍退化为
  骨架plain；CCH 在 fill 16.8x 的稠密接口图上查询最慢。度量与"接口图是稠密的入口×出口矩阵图"一致，
  不是实现失败。
- **不可达/INF专测**（`validation/results/exp20c-tiny-unreachable.json`，机械并入主JSON的
  `tiny_unreachable` 字段）：接口实例里没有不可达接口对，所以直接用原 `TinyDirectedGraph`(32节点，
  含trap/source)跑同一套CCH/TNR/HL全对，顺序复用 `exp20b-order-artificial.txt`；**T取全部节点**，
  1024对全部走global分支：plain/CCH/TNR/HL 四者都恰好61对不可达（=trap无出边31 + source无入边31 −
  重合1，与预期一致）、TNR表963/1024有限、963个可达对cover全对、0不一致。

## 失败记录
- `runMethods` 首版把原WindowGraph节点id传给建在骨架上的CCH/HL→越界崩溃：改为骨架local id
  （winning hub 经 `nodeOfRank` 也是骨架id，导出到CSV时再用 `originalNode` 映回窗口坐标）；人工图先过。
- HL backward方向（与20B同类错误）：必须遍历 `upArcs`、取 `downWeight`、松弛 `arcHi`；已修。
- HL预算首版把"首个label字节×剩余节点"外推，且把全体外层vector头每一个label都算一遍，393KB头被
  放大成~3.2GB误abort；改为只按实测累计容量/实时RSS/本步增量判定（headers只计一次）。
- TNR `plan` 曾先分配table，导致后续 `RSS+tableBytes` 重复计：table改到 `buildTable` 内先做精确
  尺寸检查再分配。
- TNR global INF 曾 fallback 到plain：会掩盖cover错误且污染global计时；已删除，正确性交给独立plain
  对照判定。
- 负控制脚本自身先mutate后设目录，曾在20B改坏真实4x4产物；本次先设目录，clean/tamper/restore三态
  全部验证过（真实产物未被触碰）。
- 补全变体的 `source_row_non_self`/`sink_row_non_self` 计数是最后才加的落盘字段，故已存的JSON没有
  该字段（不为字段重跑12分钟）；完整性结论由"最小骨架67108864对全对"与人工反例直接给出。

## 未验证边界
- 未做TNR多层/局部TNR、未做HL pruning（partial/complete）与label压缩、未做路径解包；只窗口内exact。
- 补全变体的完备性只在人工接口骨架与8x8窗口两个已核对图上成立，未对一般图证明。
- 骨架仍是单窗口；跨窗口衔接、AIR map、巨型图与规模验收另发；未读golden、未计分。
- 接口骨架的CCH是稠密图（fill 16.8x），HL项数随fill增长，16x16及以上规模的可行性未验证。

## 复跑
```
g++ -std=c++17 -O2 -o build/exp20c_probe tests/exp20c_probe.cpp src/architecture.cpp
./build/exp20c_probe --dump-graph /tmp/exp20c
build/venv-ml/bin/python validation/exp20b_order.py --skip-dump --tmp /tmp/exp20c --prefix exp20c \
    --names artificial-interface,interface8x8
./build/exp20c_probe --json validation/results/exp20c.json --csv validation/results/exp20c-queries.csv
python3 validation/exp20c_verify.py
# 不可达/INF专项（秒级，独立小文件 + 机械并入主JSON）：
./build/exp20c_probe --tiny-check validation/results/exp20c-tiny-unreachable.json
python3 - <<'PY'
import json
main = json.load(open('validation/results/exp20c.json'))
tiny = json.load(open('validation/results/exp20c-tiny-unreachable.json'))['tiny_unreachable']
main['tiny_unreachable'] = tiny                      # verbatim copy, nothing else touched
json.dump(main, open('validation/results/exp20c.json', 'w'), indent=1, sort_keys=True)
PY
python3 validation/exp20c_verify.py                  # 校验 merged 同位复制
```
真实段约12分钟（其中67M对×2变体的全对核验约8分钟）；`--skip-real` 可只跑人工小图（秒级）。
20C起 `CustomizableCh` 增加 `order_`（rank→node）并计入 index capacity/element 账；20B 已发布的
`structure_bytes` 是当时的修订口径（只有 rank_、无 order_），按审查要求不重测，日志内存段已注明。
