# 实验6 真实端点修正

日期 2026-09-18。起点基线 ff9940d，实验5 完成后基线 cff6aa3，本轮在其上。本轮只新增
tests/endpoint_probe.cpp 与 validation/score_endpoint.py，不改生产 src、不改根 estimate、
不新增生产选项、不接默认路径（测量时的 src 工作区为 cff6aa3，未含同期的 router7 改动，
本轮也不提交它）。预测阶段只用请求 From/To；golden 只在评分阶段读取，32 条留出的

## 研究问题

在保留当前 residue 中间估计的前提下，显式使用真实第一条 Net 与最后一条 Net，能否改善
端点/边界/Block skip 误差，实际收益是否抵得过开销。

## 方法与工具

同一个 ResidueEstimator（cacheBytes=0）一次构建，输出四列：

| 列 | 含义 |
|---|---|
| baseline | 现状 estimate(source,target) |
| source | Z 源 resolveNet 到 I，prefix=gap；非 Z 源枚举 outgoing Arc 到 Z 再 resolveNet，prefix=arc+gap；S=min(prefix+residue(exitI,target), 短合法候选) |
| target | I 目标取真实 Net 前驱 Z+gap；Z* 与 logic-out 目标枚举 incomingArcs 的源 I（同格），经逆表取真实前驱 Z+gap+terminalArc；T=min(residue(source,entryZ)+suffix, 短合法候选) |
| both | exitI 与 entryZ 之间一个 residue 查询拼中间段：prefix+residue(exitI,entryZ)+suffix，再并入短合法候选 |

短合法候选=同 pin 0、同格直接 Arc、第一条 Net 内已命中目标（I 或 I→target Arc）。每段自带
Line，原请求 Line 不再加。任一 min 集合为空输出 -1（图语义，不以 base 替换）。输出 0 可以来自
同 pin，也可以来自真实零费路径（例如同一行内没有 Line/Block 费用的一跳 Net 落在 I 目标）。
Z 目标不再以自身为 entrance（首轮实现曾如此，10K 前已修）。

逆表按 (landingCell,netIndex) 建立：60,200 个 SRB × 160 Net 共 9,632,000 次 resolveNet，
有效 hop 9,417,280、无效 214,720、唯一键 9,417,280、冲突 0；冲突会保留短列表并报告。构建后
对全表 re-resolve 复核，10K/1M/留出三次运行 verify_mismatch 均为 0。表内存约 85MB。

命令（构建只编译本测试工具，不跑 scripts/build.sh）：

## 32 条架构派生留出

生成（--gen-holdout --seed 20260918）：mt19937 固定种子，每次从组内起点池抽起点，
走 k∈{3,5,8} 次合法 Net 转移（Arc 决定 Z 端口，resolveNet 决定落点），始端按样本序号
轮换 Z/logic-in/I，末端按 (序号/3) 轮换 Z/logic-out/I；组内前 8 条按序生成，起点池：
translation-internal=x[8,72],y[104,545] 且全程无 skip；boundary=距边界 3 格内；
block-positive=可水平穿越 Block 西侧 14 列内且至少一次正方向 skip；
block-negative=东侧 14 列内且至少一次负方向 skip。实际长度分布 nets=3:11、nets=5:11、
nets=8:10；含 Block skip 的样本 16/32（block 两组全部，其余组无 skip）；From 类别
Z/logic-in/I = 11/11/10，To 类别 Z/logic-out/I = 12/11/9。排除集=公开 1M 全部
1,000,000 对 From/To + 8 对自检 pin（仅读 From/To 两列，不读 delay），生成时逐条剔除重复。
exact 用 plain Router（useSpanHeuristic=false、landmarks=0、cache=false），32 行全部可达、witness 违规 0、

## 交叉核验

1. 同一次 10K 请求用根目录 ./estimate（cache=0）与探针 baseline 列逐行比较：10,000 行 0 差异。
2. 32 条留出请求用 ./estimate -exact -no-heuristic -landmarks 0 与探针 --exact 逐行比较：
   32 行 0 差异，且都被游走 witness 上界夹住（exact≤witness，witness 违规 0）。
3. 评分脚本 --self-test：pred=[90,100,110]/golden=[100,100,100] 得到 over=under=exact=1；
   全 0 golden 时 quantile 为 null 而不是报错；-1 只计 unreachable 不落 over/under。

评分口径与 validation/verify.py 对齐：exact 计数含 golden=0 且 pred=0 的行；golden=0 且
pred>0 记 over；-1 记 unreachable 并从误差统计剔除、在 golden>0 上按 0 分计入 accuracy。

## 未通过项与限制

1. Block 邻域短查询仍大幅低估：留出 #17（exact 1000 / B 410 / ST 910）、#19（1008 / 416 /
   923）。真实最后一条 Net 把 410 拉到 910，但中间 residue 仍按名义位移，剩余约 90ps 低估。
   本轮没有发现这四个候选的高估反例（over=0），高估类别只在自检里覆盖（292 反例 B=327/337；
   Z 目标 405/407 vs 402/400），所以留出不是高估方向的盲测；32 条是结构性小集且路径短，
   只能定位缺陷类型，不能量化全图分布或作为规模结论。
2. 公开 10K/1M 的 From 只有 Z/logic-in、To 只有 Z/logic-out，没有 I 端点，所以 I 目标的
   entrance（真实最后 Net 最直接的用法）在公开样本上完全未覆盖；该路径只由自检和留出的
   9 条 I 目标样本覆盖。留出的 exact 来自同一套 Router 家族的 plain Dijkstra，是独立样本
   而非独立求解器；上面的生产二进制交叉比对降低但不能排除共享实现风险。
3. target 单独收益有限（1M +0.385pp），但成本是 17.6M 次 estimate（B 的 6.2s vs 0.3s）；
   ST 的收益最大（+2.05pp）但每行 155 次 estimate、1M 57.8s，是 B 的约 193 倍。是否值得
   接入进入后续规模/缓存验证设计决定，本轮不接默认、不跑 10M 以上。cache 关闭是本轮口径，
   1G 打榜复制场景的 cache 收益未测。
4. 边界无效跳语义：S/ST 会按图意义给 -1，而 T 仍保留名义第一跳（自检 boundary-invalid-hop
   B=1075、T=1078、exact=-1）；公开样本没有触发（10K/1M -1 计数全为 0），因此该语义在真实
   样本上的代价未量化。
5. 6 个采样点（-1 语义、同格 Arc、short 路径）只在自检覆盖；公开样本 over=0 也意味着
   “残差修正”都是单侧（低估）修正，不能据此声称端点修正对高估同样有效。
6. 首轮 10K 输出因 Z 目标 entrance 退化而被主代理复核发现并作废，本日志所有 10K/1M 数字
   均为修正后重跑；旧文件保留在 /tmp/endpoint6/*-prefix-invalid.json。
