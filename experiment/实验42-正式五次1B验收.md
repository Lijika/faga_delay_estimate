# 实验42 正式五次 1B 验收

日期 2026-09-23。目的：按赛题正式约束做五次一组的 1B 验收，比较冻结的 exp41 候选和实验29 正式估计器。正式 `./estimate` 与 `build/submission/estimate` 保持实验29（`db2cca1e…`），候选仍是 `-residual xgb-base` 默认关闭。

## 设计

十轮交错 `baseline,candidate` 各五次，`taskset -c 3`，每轮 3600 秒硬超时，输出同一路径 `build/exp42/out-1b.csv`，每轮结束后用 `verify_scale_output.py` 核对 1000/1000 个 1M 块、精确 EOF 和完整 SHA。驱动 `validation/exp42_1b_formal.py`；启动身份是提交 `0bf26f7` 的文件（SHA `293c3412…`），审查修订后的文件 SHA `a756581e…`，修订只在门槛与重审逻辑，不动估计器。

| 侧 | 二进制 | SHA |
|---|---|---|
| baseline | `./estimate`（实验29） | `db2cca1eb976df543b2b7281326402fd77fc7b58bf1492d530535903df88ba35` |
| candidate | `build/exp41/frozen-1b-v1/estimate-base` | `d66c067658a7e7ad92edc5cc0351119661543648c61adaa3682779df390c45c5` |

参考输出：baseline 对 `build/exp29/estimate-full-1m.csv`，candidate 对 `build/exp41/frozen-1b-v1/1m-xgb-base.csv`。线程证据有两层：`run_scale.py` 修正后的采样器记录真实估计器子树的 `observed_max_threads`，另有 30 秒一次的真实 PID `/proc` 采样写入 `validation/results/exp42-1b-formal/monitor-threads.txt`。

## 门槛

输出契约：每轮 exit 0、测量有效、真实估计器线程 == 1、RSS 字节 <= 2,000,000,000、1000/1000 块、核对通过、完整 64 位 SHA。正式验收（修订逻辑）要求两侧各五次、每侧完整 SHA 唯一且一致，并把缺 SHA、截短输出、失败轮都算不通过；不足五轮、不一致 SHA 都不算正式验收。

CPU 判读：公开集 accuracy 差 0.068026 个百分点，综合分每 1 s CPU 扣 1/120，允许新增 CPU = `96 × 0.068026 = 6.530496 s/1B`。主判读是五对 candidate−baseline 差的 95% 配对区间（t=2.776，df=4）是否整体低于 6.530496 s；同时报告完整五次均值，第一轮保留。交错固定顺序控制了邻近时间，但仍可能受顺序和机器漂移影响；未显著的 CPU 差不等于“无惩罚”。实验41 的四轮只作探索，不计入这五次。

## 执行层修正

启动监控的 shell 用 `pgrep -f exp42_1b_formal.py` 找驱动，这个模式会匹配到监控 shell 自己的命令行，所以驱动结束后循环不会退出。当前 ps 显示监控 shell 309083、其子 shell 309084、真实驱动 309088 的 PGID 都是 309083，`nohup` 不改变进程组。主代理只对正 PID 309083 发 SIGTERM 结束多余的外层监控，没有发负 PGID 信号，驱动 309088 与真实估计器继续运行；我这一侧看到的 rc143 只是观察 shell 结束。之后观察改为每次不超过 60 秒的只读采样，按 `/proc/309088` 的子进程树找真实估计器，不再用会自匹配的循环；驱动和轮次记录未受影响。

五对 candidate−baseline 差：−150.59、−12.76、+25.85、−11.11、−22.84 s；均值 −34.290 s，样本标准差 67.592 s，95% 配对区间（t=2.776，df=4）**[−118.20, +49.62] s**。第一轮基线 618.60 s 是明显的冷启动离群值（后四轮均值 460.515 s），候选第六轮 486.69 s 也是反向离群；去掉第一对后四对均值 −5.22 s，但预声明规则保留第一轮，不以剔除后数字作主判读。

## 门槛判读

输出契约（修订逻辑重审 `summary-reaudit.json`）：full_sequence_complete、five_rounds_per_side、all_round_gates_ok、unique_complete_sha_per_side 四项全真，**正式五次验收通过**；两侧 SHA 与记录值一致。

CPU 预算：公开集 accuracy 差 0.068026 个百分点允许新增 `96 × 0.068026 = 6.530496 s/1B`；五对配对区间的上界 +49.62 s 远高于允许值（下界 −118.20 s），`paired_ci95_upper_below_budget = false`。点估计和四对稳态值都是负的（候选更快），但区间包含 0 且上界远超预算，**不能判定候选稳定落在精度增益允许的 CPU 预算内**；同样也不能把这次测量说成“无惩罚”。

## 结论

按预声明规则，候选保持默认 off，不做接入前的最小 overhead 检查和正式入口讨论。理由不是输出或精度失败，而是计时证据不足：五次输出契约全过、精度增益有独立与公开证据，但 1B 的 CPU 配对区间没有整体落在 6.530496 s 预算内，均值差被冷启动离群值和反向离群值同时放大。若要重测，需要先把冷启动控制住（例如每侧先跑一轮丢弃、或延长预热）并用同一预声明区间规则复现。

证据：`validation/results/exp42-1b-formal/summary.json`（启动版本原始输出）、`summary-reaudit.json`（修订逻辑重审，含 formal_acceptance、cpu_budget、paired_analysis、warmup_analysis）、十轮 `round01..10-*.json`、`*.time.txt`、`*.stderr.txt`、`*.verify.log`，真实 PID 采样 `monitor-threads.txt`。未验证：全独特 1B、赛方机器、官方隐藏分数；repeated 1B 只含 1M 个不同 key。
