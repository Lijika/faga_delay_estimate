# 实验328 端口名称索引成本原型

## 预注册

2026-10-16，正式入口exp323。先做独立成本原型，生产源码保持。
当前Architecture::parsePin每次构造短std::string，再查端口名称map。
每个合法请求执行两次，缓存命中时也需要执行。
exp264与exp326表明共同费用需要纳入独特1B的100至300秒预算。

主假设是以端口编号为槽值的开放寻址索引能够降低名称查找成本。
索引由加载架构的全部端口名称生成，容量取至少两倍端口数的2次幂。
以std::hash<string_view>定位，线性探测，比较完整名称后返回原编号。
索引保存编号，名称继续由Architecture拥有；复制架构后可以重建索引。
本轮仅评价这一固定表示，独特请求缓存、坐标解析和算法保持。

复用原Architecture加载器，按原序读取冻结U-output独特1M。
计时前抽取全部2M端口名称视图。先验证所有已加载名称以及空名称、
前后缀、含NUL和长名称的结果等于原portId。再核对每个实际端点，
要求原编号与索引结果逐项相同。索引容量与装载率逐项断言。

本机AMD串行测量，先原版和索引各预热一次，再正序、反序、正序
三对，各扫描完整2M名称。保留原输入顺序和读取依赖，消费编号校验和，
以steady_clock记录查找循环时间。普通与ASan/UBSan分别运行，
性能只引用普通构建。重复测量属于同一开发输入。

这项结果只描述名称查找循环。视图抽取、坐标解析、CSV、缓存、
初始化与估算均在该计时范围外。AMD速度用于原型描述，完整候选
资格保留到Xeon完整程序判断。若正确性失败，修正并保留失败证据；
正确性通过后记录局部效应，再冻结完整源码候选的协议。

构建与运行入口如下。精度评分和新增exact成本均为0。

```sh
g++ -std=c++17 -O2 -Wall -Wextra -Isrc \
  tests/exp328_port_lookup.cpp src/architecture.cpp \
  -o build/exp328/port-lookup
build/exp328/port-lookup doc/eda比赛文件/arch build/exp262/output-1m.csv
```

正式parsePin尚待实现与验收。公开1M、完整程序CPU、其他架构、
完整算法100M/1B和比赛平台仍待验证。
