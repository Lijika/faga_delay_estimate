# 实验286：当前工程基线的树模式与端点模式复评

## 预注册

2026-10-16，基线提交 `932ea6f`，完整程序采用 exp281 combined。
本轮复评历史 tree-mode0、endpoint-source、endpoint-both，并复用 exp283
no-tree 作为同批对照。历史输出与精度证据来自 exp282，原始结论保持。

主假设是减少父树映射或改变端点枚举可以形成当前工程基线上的 CPU–acc
折中。模型、搜索预算、q、队列、缓存、真实图和最终 bias 保持。
tree-mode0 仅把 UpperTree 查询中的八映射改为 mode0；端点候选在生产配置
完成后改 ResidueEstimator 的 endpointMode，与历史消融干预位置一致。
这些候选改变预测，精度结论采用配对评分。

影响范围为私有 `build/exp286/{tree-mode0,endpoint-source,endpoint-both}/src/`
中的 `upper_tree.h` 或 `main.cpp`，以及新实验 runner 和记录。既有评分类、
计时器、契约检查与 bootstrap 直接复用。没有正式接口和交付包更新。
通用静态构建参数与模型对象复用 exp281。

### 样本与测量

- 五臂顺序为 baseline、no-tree、tree-mode0、endpoint-source、endpoint-both。
  七行边界先各一次。四套已查看开发样本依次为 U-output 9,472、
  U-role 14,080、exp255 12,320、exp258 12,320 行，保持原序、标签和分层权重。
- 每个样本先按五臂顺序预热，再正序、逆序、正序三轮。r9r4900 Xeon
  core 3，同机串行完整进程 user+sys；AMD 只承担构建与自检。
  acc 使用计时进程的输出；相同输出、输入、标签及权重时复用评分。
- 每次检查端点原序、三字段、整数 delay、精确 EOF、完整 SHA、多次一致、
  单线程、RSS <=2,000,000,000 B、wall/CPU <=3600 s。
  U-output/U-role 的各臂输出须匹配历史完整 SHA；四样本基线和 no-tree
  复用 exp283 的输出身份。boundary 保持已验证输出。
- CPU 采用三轮配对差与 Student-t 95% 区间，两端各扩 0.02 s
  表示计时舍入。acc 复用 exp283 分层配对 bootstrap，10,000 次，
  seed=20261016283。比较逐项报告，未作多重比较校正，三对计时的正态性
  尚未确认。开发样本用于选型，区间跨零保留待定。
- 总体 acc 严格 >99% 且处于同批 CPU–acc 前沿为候选规则。
  最小实际 CPU 收益预设 0.5%，用于效应描述；阶段指标保持独特
  1M <100 s、100M <100 s、1B 100–300 s。样本 CPU 含初始化，
  分层 acc 与未加权进程 CPU 分别说明。
- 报告总体及分距离组精度、变化/改善/恶化行数、特殊零值与不可达行、
  CPU/acc 区间和候选间支配关系。历史候选的旧证据继续保留。

### 后续与停止条件

实现或输出契约不满足预注册身份时，停止该次执行并保留失败证据。
四套总体 acc 均 >99%，且至少一个分布的性能/精度区间仍可能位于前沿的
新候选，进入冻结后的新请求与完整 1M 验证。完整阶段另外冻结输入、候选、
次序与预算后执行；样本收益只支持该规模。精度不足的固定构造保留结果。
