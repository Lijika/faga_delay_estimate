# 实验198 C1 映射前驱链真实重放精度探针

2026-10-10。承接实验190的车道映射覆盖审计。本轮只回答一个问题：
完整 finite 的 cycle1--cycle7 与 xor4 映射，把40棵 nominal parent tree
按端口置换重用后，经过真实 `resolveNet` 重放，能否产生可用的合法上界。
不修改正式源码、`estimate`、交付包、既有精度候选或统计门。

## 假设

实验190显示8个完整映射保持2,752条finite边，但2,553--2,602条边的
费用发生变化。若把每棵树的状态 `p -> phi(p)`、源端口和父链同时置换，
再用真实几何逐hop重放，则得到的费用是合法路径上界；它可以作为
`min(existing_all, mapped_U)` 的离线精度候选。

本轮不把映射后的费用当作等价 residue，也不使用 exact 选择路径。exact
只用于离线检查 `U >= G` 和评分，在线算法尚未实现。

## 固定对象

- exp190 完整映射：`cycle1`--`cycle7`、`xor4`。
- exp171 的40棵 parent tree 原始 `uint8` 文件，按映射懒惰重解释，不复制
  320份树。
- exp174 的6176条加权请求、`all` 预测和exact标签。
- 当前公开五个架构JSON，真实路径逐hop调用 `Architecture::resolveNet`。

## 预注册输出

每个映射和8映射并集分别输出：

- 有效重放得到的最小 `U`；
- `min(all,U)` 后的逐行预测；
- 有效路径数、改变行数、加权 accuracy、false finite/unreachable；
- 所有可达 exact 行满足 `U >= exact`。

这是一项开发精度探针，不测CPU，不接生产，不扩大已有统计门。若并集
候选未达到新增 `+0.10 pp` 且配对区间下界为正，停止为它生成在线大表；
若达到，再另行预注册在线选择、容量和完整1M验收。

## 证据边界

映射父链共享原始树容量，当前结果只证明固定开发集上的真实重放效果。
它没有证明新请求泛化、端点候选完整、启动成本、缓存行为或最终交付
ELF成本。所有父链、Arc费用、边界和终端重放失败都保留在逐行CSV中。
