# 实验114 C2 跨场差分与100MB容量压缩

2026-10-08（UTC）。本协议先于跨场差分结果提交。分支 `research/exp114-port-fields`，基线提交 `2de3d29`。已读理论索引、`距离场端口重排与模差分的无损性` 与 `有限真实图距离场的Line归一化平移边界`。

## 问题与固定假设

- 实验113的单场最坏压缩为4,706,677 B，20场保守估算102,123,444 B，超100,000,000 B。假设多个源场的同位置、同端口槽存在可压缩的跨场相关性。
- H1 对固定空间源，按一个完整基准场与其余源场的uint16模差分再做纵向差分和字节分平面，能把20场估算压回100MB。
- H2 对平移源，基准场同样可作为跨场预测器；Line修正只用于独立查询诊断，不作为无损编码的一部分。
- 复用实验113七个已验证场：`old0`、`old1`、`phase0`、`phase1`、`lane1`、`longE`、`longN`。只读其原始uint16场，保留全部160个Z/lane状态。
- 评估包括固定基准选择、按源逐场差分、全组联合压缩以及每场恢复SHA。新增场或生产接入不在本轮改变。

## 编码候选

每个场仍为 `uint16[550,120,160]`，INF位模式65535。对基准场直接采用实验113最优布局；对其他场按固定空间槽计算

```text
R_i = (F_i - P_i) mod 2^16
```

再对 `R_i` 应用 `dy` 模差分、低高字节平面和zlib level 9。恢复顺序为逆字节平面、纵向累加、加回 `P_i`，每步都按 `uint16` 模运算。另测无跨场预测的七场独立最优布局，作为压缩对照。

基准只允许从已测七场中选择；先按总大小枚举七种基准，报告最小值和每个基准的构成，避免用结果外的最佳基准。编码顺序固定为输入列表顺序，压缩流逐场独立，禁止依赖压缩器跨文件状态。

## 验收与容量门槛

- 每个布局候选记录压缩字节数与CPU；每个最终选中布局完成逐字节恢复，并由小数组自检覆盖所有编码布局。记录原始SHA、恢复SHA、压缩SHA、压缩/解压CPU和峰值RSS。
- 七场试验同时检查跨场编码与独立编码的总字节数；按实际最大单场扩展到20场只作估算，正式文件大小另验。
- 容量估算固定为 `7,989,904 B + 20 × (基准场摊销 + 其余场平均字节数) ≤ 100,000,000 B`。基准与其余场的比例必须写入结果；不使用“只取最好场”推断所有端口。
- 任何反演、INF、shape、字节序、A*场检查失败，或RSS超过2GB时停止。

## 判定与后续

若固定七场的跨场编码总量降低至少10%，且20场估算≤100MB，则继续按真实Z端口频数选择完整源集合，仍先离线验证。低于10%或容量仍超预算时，保留跨场差分作为压缩工具，转向减少场数、选择性源类覆盖和查询回退，C1/C2/C4方向保持开放。

压缩结果只证明存储可行性，不证明源模板查询正确。任何平移复用仍需独立请求分布、端口身份和边界路径验证。正式接入前仍需完整1M输出契约、单线程、RSS≤2GB和3600秒验收。

证据写入 `validation/results/exp114-*`，压缩产物写入 `build/exp114/`。本轮开工空间为473GB；收尾再次记录空间，七个实验113场和按名输入保留，副本清理按仓库约定逐项核对。

初版实现曾在基准枚举中对每个布局都立即解码，运行约11分钟仍未完成且无结果文件；已中断该自有进程，改为每个候选只压缩、每个选中布局再解码验证。该失败运行只留下空的临时计时文件并单独改名保留，不作为实验结果。

系统Python首次导入xgboost的旧实验helper时缺少该包，本轮编码器只依赖NumPy与标准库，因此使用系统Python完成；独立编码器自检通过。

## 结果

实现提交 `1db70f9`。七场均使用完整`uint16[550,120,160]`，七种基准全部枚举。最小组合基准为 `longN`，选中流总大小36,271,046 B，基准场3,463,270 B，其余六场平均5,467,962.67 B；按19个残差场估算的20场交付文件为115,344,464.67 B，仍超100,000,000 B。

独立场最优布局的七场总大小为29,587,194 B，跨场残差最优布局比它大6,683,852 B（+22.59%）。各基准的20场估算如下：

| 基准 | 七场流 | 20场估算含8MB代码 |
| --- | ---: | ---: |
| `source0` | 38,811,150 B | 121,444,304.5 B |
| `source1` | 40,211,169 B | 125,889,603.8 B |
| `phase0` | 43,000,626 B | 134,467,445.2 B |
| `phase1` | 43,541,320 B | 136,390,275.3 B |
| `lane1` | 42,689,770 B | 132,976,375.5 B |
| `longE` | 38,012,057 B | 120,012,209.0 B |
| `longN` | **36,271,046 B** | **115,344,464.7 B** |

选中基准的残差流分别为 `source0=4,859,023`、`source1=5,518,160`、`phase0=6,454,355`、`phase1=6,629,836`、`lane1=5,884,260`、`longE=3,462,142` B。7个最终流逐个解压并逆变换后与输入SHA一致；各非选中布局保留压缩尺寸，编码自检覆盖模溢出、INF和小数组逆变换。

资源为CPU 1,390.97秒、wall 1,390.56秒、峰值RSS 366,256,128 B；初版重复解码的11分钟运行中断，不计入结果。跨场枚举本身成本高于当前查询预算，不能直接放入生产启动路径。

本结果否定“用一个完整场预测其他场能在当前七场范围压回100MB”的固定候选，未否定跨场差分在更窄的同端口/同相位族或选择性场集合中的使用。C1/C2/C4方向保持开放。下一步转向LZMA/XZ与按端口类别的选择性场容量探针，先固定新协议再运行。
