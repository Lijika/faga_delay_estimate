# 实验27 不确定度代理与精确回退

本轮测试模型修正幅度能否选择值得 exact 回退的请求。离线精度筛选后，分别测量 span Router 与 Router+PDB 的实际 CPU，再核对公开 1M 的目标覆盖及最高可能得分。现有证据支持保持默认 xgb，生产源码和 binary 保持不变。

## 冻结规则与样本

规则使用关闭残差的 `off` 与冻结模型的 `xgb`，两者均为正时计算

```text
proxy = abs(xgb-off) / max(abs(xgb),abs(off),1)
trigger = proxy > threshold
threshold ∈ {0.01, 0.025, 0.05, 0.10}
```

该差异只表示模型修正幅度，尚未校准为错误概率。四个阈值均在读取本次公开评分前冻结。第一步使用实验24的 3,107 条独立架构样本，把触发行替换成保存的 exact，测量成功回退的反事实精度。44 条负 exact 沿用修后的 -1，收益计算只覆盖其余 3,063 条可达请求。

每条使用实验24的 `N_band/n_band` 权重。可达权重占全语料的 0.983025544921875；把可达条件的 accuracy 增益和触发率同时乘此比例，得到全语料值。

| 阈值 | 触发行 | 可达条件的加权触发率 | 可达条件的 accuracy 增益 | 初筛加权查询 elapsed |
|---|---|---|---|---|
| 0.01 | 2,092 | 38.9008% | 2.787296 点 | 5,385.990 µs |
| 0.025 | 1,216 | 9.0505% | 1.131436 点 | 1,177.197 µs |
| 0.05 | 500 | 2.1086% | 0.354308 点 | 1,884.100 µs |
| 0.10 | 55 | 0.2462% | 0.061760 点 | 732.772 µs |

初筛时间来自保存的 `us_pdb`，属于 elapsed，且未含目标准备。0.025、0.10 在 1M 独特 key 重复到 1B 的条件下有进一步测量价值。其余两个阈值未通过该成本筛选。评分时间项为正时，accuracy 每增加 1 个百分点最多允许增加 96 秒 CPU。

## 实际搜索 CPU

`tests/fallback_cpu_probe.cpp` 复用生产 Architecture、Router 和 PatternDatabase。每个模式独立进程、串行运行，关闭 landmark 和内部答案缓存，采用 binary heap。逐行核对坐标、端口、距离带和 exact 标签，查询与目标准备分别用进程 CPU 时钟测量。生产已有的架构加载作为共享成本单独说明。

| 模式与样本 | 查询次数 | 标签差异 | Router 初始化 | PDB 初始化 | 目标准备 CPU | 全部查询 CPU | 峰值 RSS |
|---|---|---|---|---|---|---|---|
| span，0.025 | 1,216 | 0 | 0.0275 s | 0 | 0 | 86.2199 s | 117,432 KiB |
| PDB，0.025 | 1,216 | 0 | 0.0390 s | 0.2419 s | 24.2727 s，416 目标 | 0.9077 s | 438,708 KiB |
| PDB，0.10，五轮 | 275 | 0 | 0.0256 s | 0.2643 s | 2.7875 s，47 目标 | 0.0962 s | 93,648 KiB |

0.025 的加权平均查询 CPU 为 span 499,760.5 µs、PDB 1,540.2 µs。在独立架构分布、1M 独特 key 的条件下，PDB 查询加初始化与已测目标准备约需 161.6 秒，精度收益只允许 106.8 秒。0.10 的 PDB 五轮加权查询均值约为 607 µs，单轮范围为 591至634 µs。47 目标的小样本条件下，总额外 CPU 约 4.55 秒，低于 5.83 秒预算；更广目标集合需要另行验证。

1B 全独特条件下，两个阈值的查询成本均超过对应精度预算。以上为样本 CPU 的条件外推。模型触发判断、最终缓存和生产组合路径的成本尚未实测，单独探针 RSS 也只描述各自进程。

## 公开目标覆盖与得分上限

用最终 binary 重建公开 1M 的 residual off 输出，与已有 xgb 参考逐行配对。规则只读取两份预测和请求，公开目标覆盖结果如下。

| 阈值 | 触发行 | 触发率 | 目标 port 种数 |
|---|---|---|---|
| 0.025 | 84,072 | 8.4072% | 256 |
| 0.10 | 2,234 | 0.2234% | 255 |

0.10 的 255 种目标明显多于独立小样本的 47 种。探针按公开请求中的真实目标集合执行一次 prepare-only，目标准备 CPU 为 14.628018 秒，PDB 初始化为 0.245263 秒，Router 初始化为 0.022735 秒。逐目标列表与覆盖集合一致，表为 242,841,600 bytes，进程峰值 RSS 为 287,136 KiB。

随后只在最终离线评分中读取 golden，将每条触发行的得分允许提高到最高 1 分，其余行保留原 xgb 得分。这给出冻结规则在公开数据上的最大可能收益，规则、特征、模型和标签生成继续使用原配置。

| 阈值 | 最大 accuracy 增益 | 允许增加的总 CPU |
|---|---|---|
| 0.025 | 0.976003 点 | 93.696288 s |
| 0.10 | 0.048219 点 | 4.629059 s |

基础 accuracy 复现 96.116008。公开 0.10 的目标准备 CPU 已超过最高收益对应预算，查询和触发判断还会增加成本，因此这个 PDB 回退方案在该输入上无法提高综合分。1M 独特 key 重复到 1B 时，每个触发 key 可由最终缓存复用，准备成本仍需支付一次。

## 审查与取舍

初版 CPU 分析误把 416 目标的准备成本计给 0.10 子集；中间版本又混合了独立样本收益与公开触发率。正式分析分别报告两种分布，按每轮完整 index 集合聚合 CPU，所有成本统一成秒后与预算比较。均值乘目标数量属于情景外推，实际 255 目标准备结果另行记录。

正式 CPU 分析的 11 项自检通过，覆盖加权均值、重复轮次、遗漏与重复行、距离带错配和单位换算；公开评分的 4 项自检通过。协调代理复跑分析得到相同数值，目标列表的 255 个端口及逐目标 CPU 和核对通过。审查修订与证据提交为 `99c80e9`。

保持 mult2、source-short 150、冻结 xgb 和 64 MiB 缓存。0.025 在独立分布的成本筛选失败，0.10 在公开目标集合上有确定的得分上限与成本证据。PDB 继续用于 exact 标签生成，样本小目标集合的条件收益保留在记录中。

主要证据为 `validation/results/exp27-fallback-screen.json`、`exp27-cpu-analysis.json`、各模式逐行 CPU CSV、`exp27-coverage-1m.json`、`exp27-prepare-only-t010.json` 和 `exp27-oracle-ceiling.json`。原始计时结果继续保留，修正后的分析替代早期判定。最终生产 binary 仍为实验25的 `92a76319…`，五次 1B 证据继续适用。
