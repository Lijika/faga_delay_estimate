# 实验102：交错depth10与depth8直接对照

日期：2026-09-27。开工 `/dev/sdd` 可用约479G。

实验101在相同depth10模型上四树交错平均节省 `1.206667 s/1M unique`，95%区间不跨零。现在直接对照正式depth8包，以免跨轮计时差值代替配对证据。

精度固定复用实验93独立 `[38M,40M)` exact窗口：depth10相对depth8加权accuracy增益 `+0.040127154 pp`，95%区间 `[+0.000556993,+0.080474344] pp`，两类可达性误判均为零；报告SHA `0baa25fbf5fd95f37a99650c1b53c65eca30a4b5d58a192831634740f3149a7d`。模型、特征和输出未改变，实验101的等价检查支持复用这份精度证据。

基线为实验92静态包，SHA `607b52e80cb6dad8905e4c46ff3ed45fa7670730b165e3ca995e34c97c837c63`；候选为实验101交错depth10，SHA `62b502d0fb497711a18e8d2d62ce5429889338be956e19b44e6d85b01c316afe`。两侧预热、核3、三对交错完整1M unique；每轮检查完整输出SHA、端点原文、行数、三字段、整数delay、精确EOF、负值位置、单线程、RSS≤2GB及wall≤3600秒。CPU差采用三对t区间。正式接入条件为 `0.8×精度增益−CPU差/120` 点估计≥`+0.01` 且精度下界和CPU上界形成的保守下界>0。失败则关闭该depth10部署候选，保持正式模型。

```sh
build/venv-ml/bin/python validation/exp102_interleaved_vs_depth8.py
```

原始报告写入 `validation/results/exp102-depth10-vs-depth8.json`。本轮不运行1B；隐藏集与平台成绩以实际评测为准。

## 结果与判断

三对候选减基线CPU差为 `+2.59/+1.69/+1.35 s`，均值 `+1.876667 s`，95% t区间 `[+0.285008,+3.468325] s`。复用实验93的独立精度增益后，综合收益点值 `+0.016463`，精度区间下界与CPU区间上界合成的保守下界 `-0.028457`，预设正式接入门槛未通过。与实验99删末层depth10的直接比较相比，交错遍历降低了CPU成本，但这两轮各自有配对计时误差，不能用均值差替代配对结论。

双方预热及六次计时运行各自重现冻结的完整1M输出SHA。端点原文、行数、三字段、整数delay、精确EOF和17,585个负值位置均通过；最大RSS `571,142,144 B`，最大wall `29.39 s`，进程树采样全部单线程。当前候选保持私有，正式模型和交付包不变。平台1B、隐藏集与其他输入分布的综合收益尚未验证。

当前47维特征与这组训练池上的扩容、标签增量和遍历优化已逐项筛选：实验95/96的depth12与256树未过开发门槛，实验97/100的新增12,162条标签未过开发门槛，实验102的depth10部署未过综合收益门槛。这个结论只关闭已测候选。实验87的标签扩池、实验92的gamma调整曾在新窗口取得正收益，且新路径级在线信号尚未形成并检验具体候选，因此无法据此判定XGBoost或机器学习整体收益耗尽。下一轮如继续机器学习研究，应先提出可在线计算且不重复现有47维的路径级信号，用已有标签做覆盖与增量信息预检；只有预检显示足够覆盖和独立信息，才进入训练与新exact窗口。
