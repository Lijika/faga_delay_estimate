## 冻结协议

- 正式基线为 `exp85-radix-reuse-5f5e016`，包内二进制 SHA-256 `e79648162f765f146e6f3989dfcda02e54622a3a96e4906f70697591673be3eb`，模型为 `build/exp77/model-128.json`，SHA-256 `28445cb3bcd08dfc6838984f2e5a1a4491656919208215ffbabfa655757e3774`。该正式模型已经使用 47 维 `base`、depth 8、128 树及输出 `-3 ps`，所以实验58窗口已经进入其训练池，只作实现检查。
- 训练 control 完整复现实验85模型。单变量候选 A：原34,352行训练池、47维/六个屏蔽槽、128树、目标 `exact-fast`、加权L1、seed `20260919`、eta 0.1 与原权重不变，只把 depth 8 改为 depth 6。候选 B：depth 8/128树和所有训练参数不变，只加入实验77 `[28M,30M)` 与实验78 `[30M,32M)` 的可达 exact 行；完整端点去重，冲突即停止。fast/base 分别由冻结的实验61与41二进制重新计算，绝不读 golden、公开1M标签或预测值作为训练标签。
- 实验64 `[22M,24M)` 与实验76 `[26M,28M)` 为开发筛选窗口，均不在上述训练池内。两窗的正式 exp85 输出与 Python control 必须逐行相同。按各窗原始距离带份额计算 pooled accuracy、MAPE 和两类可达性误判。候选须在两窗均有正增益、两窗平均增益至少 `+0.01 pp`，可达性误判不增加；若两候选通过，按两窗平均增益选一个。开发结果只用于选型。
- 胜出模型冻结 SHA 后，独立窗口固定为 affine unique `[32M,34M)`，按七带各最多1024条 exact 抽样；排除公开输入、训练池与历史样本，命中即停止且不替换。主指标为语料带权 pooled accuracy，paired bootstrap 10000次、seed `20260925`。精度门槛为点增益至少 `+0.02 pp`、95%下界正、false finite 与 reachable false unreachable 不增加，并报告每带和 MAPE。CPU 可先变慢；候选符合精度门槛后再做部署和性能优化，正式综合收益仍须按精度与CPU联合评估。
- 性能用同一1M unique输入预热后3对交错，计 CPU/RSS/线程、完整输出 SHA 与逐行契约。先 profile 当前正式路径并列 ROI，再一次只改一个变量。正式打包遵守完整1M验收与不可变版本目录规则；本轮不运行1B。

脚本 `build/venv-ml/bin/python validation/exp87_model_screen.py`。原始开发证据写入 `validation/results/exp87-screen.json`；胜出后另记独立窗口身份和结果。本轮正式入口、交付包和已有实验文件保持不变。
