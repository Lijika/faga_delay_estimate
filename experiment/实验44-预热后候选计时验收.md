## 每次运行（含预热）的完整契约

`taskset -c 3`，`scripts/run_scale.py` 的 3600 秒硬超时，随后 `scripts/verify_scale_output.py --mode repeated`：exit 0、测量有效、真实估计器子树线程 == 1、RSS 字节 <= 2,000,000,000、1000/1000 个 1M 块、精确 EOF、完整 64 位 SHA、核对通过。每侧所有轮次的完整 SHA 集合必须唯一且一致。

## 设计

先各跑一轮不记入的完整 1B 预热（baseline、candidate），每轮用各自冻结的期望 SHA 核对。预热只记录，不进入均值、配对统计和条件综合分。

然后 12 轮测量，六对相邻配对，顺序交替使每侧各在 3 对里排第一：

```
对1: baseline,candidate    对4: candidate,baseline
对2: candidate,baseline    对5: baseline,candidate
对3: baseline,candidate    对6: candidate,baseline
```

相邻两轮构成一对，配对时与顺序无关：每对的差固定为 `candidate_cpu − baseline_cpu`。

## 统计与判定

主统计量是六对差的配对 t 95% 区间：均值、样本标准差、SE、`t(0.975, df=5) = 2.570582`，区间为 `mean ± 2.570582·SE`。允许的新增 CPU 是 `96 × (96.184034 − 96.116008) = 6.530496 s/1B`。

- 区间上界 < 6.530496 s：计时预算证据成立，可以继续接入讨论；
- 否则（含区间跨 0、上界超预算）：**结论不成立（inconclusive）**，候选保持默认 off，不进入正式入口。

同时报告测量轮的两侧均值、wall、RSS、条件综合分（用公开 1M accuracy 与固定一致性分，属条件估算），并单列预热轮。

## 边界

repeated 1B 只有 1M 个不同 key，不等于全独特 1B、赛方机器或官方隐藏分数；不宣称 SOTA，不改正式入口。生成本轮新文件前记录 `df -h /dev/sdd`，收尾再记录一次，并按 AGENTS.md 的三条删除检查处理可重建副本。
