# 实验282 历史候选联合指标与帕累托复评

2026-10-16。按用户新规则回查历史数据，主目标继续优化独特请求 CPU。
本轮为已查看证据的回顾分析，原实验协议、原始结果和旧判定完整保留。

## 规则与范围

总体 acc 严格大于 99%，并进入可比较条件下的 CPU–acc 前沿作为候选标准。
精度允许相对 exp258 下降，报告配对差、总体和分组误差、变化/改善/变差行数。
AMD 计时只供参考；远端 Xeon 用作主要性能比较，官方平台和跨架构仍分别验证。
阶段目标保持 1M <100 s、100M <100 s、1B 100–300 s。旧最小节省比例用于描述收益。

复用 exp258 消融的两套带 exact 标签开发样本，各 43 臂，共 86 个点。逐点核对
同次估计运行的输出 SHA、完整契约、原始 time、输入与标签身份；重新评分并核对
七组精度。CPU 为样本完整进程 user+sys，acc 使用原 1B 分层人口权重。两者使用
同一组请求，但 CPU 反映实际样本组成，acc 反映重加权分布；单次样本计时只支持
开发点估计前沿。统计上尚无法区分的支配关系继续保留待定。无新增估计程序运行。

脚本 `validation/exp282_history_pareto.py` 的自检覆盖严格 >99、相同点、多目标
折中、被支配点、空集和零标签评分。全部 86 点复核通过，原始结果为
`validation/results/exp282/history.json`，完整候选表为同目录 `history.md`。
评分 CPU 单列，旧 exact 生成及模型运行成本保留在原记录。

## 下一项与限制

固定以 exp281 为工程基线，优先联合复测 baseline、search512、no-tree 及必要组合。
输出和 CPU 同次采集，复用既有 exact 标签作开发选择；候选冻结后使用新请求验收。
新预测臂沿用输出契约与资源门，等价 checker 仅用于等价实现。

本轮 86 点均为回顾开发数据，单次计时没有 CPU 置信区间；相互比较支持候选排序，
统计支配和新请求泛化仍待验证。保留所有臂可降低只报告优胜项的选择偏差；按原分层
权重和分组结果解释总体，且独特与重复负载分别记录。第一阶段尚未完成。

开工与收尾 `/dev/sdd` 均约 412 GiB 可用，新增结果小于 1 MiB；删除 0 文件、释放 0 B。
