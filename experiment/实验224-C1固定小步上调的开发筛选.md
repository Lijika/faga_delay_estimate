# 实验224 C1 固定小步上调的开发筛选

2026-10-12。正式入口exp131、私有对照exp220不变。
exp223已查看窗口区间oracle相对两端点多+0.785884/+0.753919 pp；
本轮检验只用在线P和合法U的固定小步规则能否取回一部分空间。
开工`/dev/sdd`可用约434 GiB，私有目录`build/exp224/`。

## 预注册

对exp214开发6176条、exp215已查看6180条分别固定截断后的P与
C4800合法U。候选步长`k ∈ {0,1,2,3,5,8,13,21,34}` ps，
若P>0且U>P，则输出`min(U,P+k)`；其余保留P。
所有输出仍是整数，零值与负值保持。只使用exp214开发集按总体权重
选择加权accuracy增益最大的k；相同时选较小k。随后用已查看的
exp215窗口复核所选k，报告每个k在两窗的增益、改写/改善/恶化行、
七带贡献与exp215分带配对bootstrap 10000次、固定seed 20261012的
95%区间。两窗都已查看，这些结果只用于低成本原型筛选。

主假设是合法U高于P时，固定的小整数步比直接跳到U更不易造成高估损失。
进入全新请求验证的门为开发集选出的k>0，在exp215已查看窗口
增益至少+0.03 pp且该配对bootstrap的95%下界>0。
若未过，仅停止无条件固定小步规则；特征条件化插值另立假设。
新请求的实际增益、运行CPU、跨架构及完整1M均属于后续验收。
在查看各k表现前冻结脚本、输入、候选及判据并提交。

```bash
PYTHONDONTWRITEBYTECODE=1 build/venv-ml/bin/python validation/exp224_fixed_step.py freeze
# 提交冻结清单后
PYTHONDONTWRITEBYTECODE=1 build/venv-ml/bin/python validation/exp224_fixed_step.py analyze
```
