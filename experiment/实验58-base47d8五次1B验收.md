# 实验58 私有 base-d8（walk）五次 1B 正式验收

日期：2026-09-26。本轮执行第五次 1B（repeated 1,000,000,000 行）资源与输出契约验收，
五对交错、固定顺序，候选为实验58 优化后的私有 `xgb-base47-d8-walk`。
正式入口、交付包、`RESULTS.md`、`DESIGN.md` 本轮未改动。

## 假设与判据（固定于运行前）

- 精度（实验58 冻结窗口 [16M,18M)，6178 行）base-d8 相对实验29 的 pooled 加权 accuracy
  增益 `+0.12059737022848083 pp`，bootstrap 95% 区间 `[+0.0705052, +0.1703978]` pp，
  false finite `0`、reachable false unreachable `0`、负 exact `99` 行保持 `-1`。
- 新增 CPU 预算 `96 × 0.1205973702 = 11.5773475 s`（1M unique distinct 摊销到 1B）。
- 主判据：五对配对 CPU 差（candidate − baseline）均值 ≤ 预算，且 95% 区间上端 < 预算；
  每轮必须单线程、`RSS×1024 ≤ 2,000,000,000 B`、`wall ≤ 3600 s`、1000 个 1M block 全等、
  精确 EOF、完整 SHA。综合收益 95% 下界（`0.8×Δacc_lo − ΔCPU_hi/120`）单独报告。

## 命令与顺序

- 身份阶段：校验上述二进制/输入、`requests-1m.csv` 是 `requests-1b.csv` 的前 1,000,001 行
  （逐行比较通过）。
- 参考阶段（固定命令，一次）：
  `taskset -c 3 build/exp58/estimate-base47d8-opt -arch doc/eda比赛文件/arch -residue-mult 2
  -endpoint-mode source-short -endpoint-short-distance 150 -quiet -residual xgb-base47-d8-walk
  -in build/exp57/requests-1m.csv -out build/exp58/formal-1b/candidate-1m-reference.csv`，
  再逐行核对 1,000,000 行的 3 字段、端点顺序、整数 delay、精确 EOF（全部通过，0 负值行）。
- baseline 1M 参考另用
  `taskset -c 3 ./estimate -arch doc/eda比赛文件/arch -in build/exp57/requests-1m.csv -out
  build/exp58/formal-1b/baseline-1m-recheck.csv` 独立复现，与 `estimate-full-1m.csv`
  **逐字节相同**（`c5ba12ae…`）。
- 1B 五对（固定顺序 baseline,candidate ×5），每轮独立 JSON/time/stderr/verify：
  `taskset -c 3 python3 scripts/run_scale.py --binary <bin> --arch doc/eda比赛文件/arch
  --input build/final-scale/requests-1b.csv --output build/exp58/formal-1b/output-1b.csv
  --input-meta build/exp38/requests-1b-meta.json --estimator-timeout-seconds 3600 [--extra ...]`
  然后
  `taskset -c 3 python3 scripts/verify_scale_output.py --output … --mode repeated
  --reference-result <1M 参考> --block-rows 1000000 --expect-rows 1000000000`。
  两个官方脚本未修改；编排、门禁与统计在 `validation/exp58_base47d8_formal.py`。
- 运行期间加“无竞争”门禁：开跑前与运行中每 5 s 用 `/proc/*/comm` 检测非本进程会话的
  `estimate*` 进程和 `eda-exp58-timing-b3` systemd 单元；一旦出现即中止该轮并记录证据。

### 配对统计（n=5，t₀.₉₇₅,df=4 = 2.776）

| 对 | baseline CPU | candidate CPU | Δ = cand − base |

- 均值 `−9.606 s`，样本 sd `15.918 s`，95% 区间 `[−29.368, +10.156] s`。
- 两侧均值：baseline `576.100 s`，candidate `566.494 s`（−1.67%）。
- 预算 `11.5773 s`：配对均值在预算内 ✓；区间上端 `10.156 s < 11.5773 s` ✓。
- 综合收益：点估计 `0.8×0.1205974 − (−9.606)/120 = +0.17653`；
  95% 下界 `0.8×0.0705052 − 10.156/120 = −0.02823`，**不为正**。
  即：本机 1B 噪声（sd 15.9 s）相对精度区间下限（0.0705 pp）过大，
  **本轮不能宣称综合收益显著为正**；能成立的是“资源与输出契约全部通过、
  CPU 点估计优于基线、且配对区间上端仍在 11.5773 s 预算内”。

## 正式结论

1B 十轮契约全部通过；配对 CPU 差均值 `-9.606 s`、95% 区间 `[-29.368, +10.156] s`，
两者都在 `11.5773 s` 预算内；综合收益 95% 下界 `-0.028225` 不为正。
**正式版继续冻结**（实验29 `./estimate`、`build/submission/estimate`、
`RESULTS.md`、`DESIGN.md` 均未改动，SHA 仍为 `db2cca1e…88ba35`），
本轮候选保持私有，等待负责人确认后再讨论接入。

## 失败与中止说明（保留证据）

- 04:03:19 第一轮 baseline 被外部 SIGTERM 终止（`rc=-15`，写至 4,920,008,704 B）：
  逐条记录了该部分输出的 size 与头/尾 64 MiB 指纹
  （`validation/results/exp58-1b-formal/aborted-round01-partial.json`，头部
  `a2ce0694…`、尾部 `0d805238…`），随后由重跑覆盖。
- 04:06–04:09 监控侧以 `systemd-run --user --unit=eda-exp58-timing-b3` 启动了并发的
  `timing-clean`（1M）进程，与正式验收要求的“无其他负载”冲突；同时本轮 harness 的首版
  竞争检测误判自身子链，导致第 1 轮两次自中止。修正为按 `/proc/*/comm` 判定可执行名并排除
  本会话与测量子会话后，04:10:26 起 10 轮全部在“machine quiet”下完成。
- 操作说明：由于 Herdr 面板在收到新指令时会向前台进程组发 SIGTERM，长时测量改为
  `setsid` 独立会话执行，逐轮轮询；每轮仍按其固定命令、固定顺序串行、`taskset -c 3`、
  3600 s 硬超时，并在下一轮前完成完整校验。
- 未复用污染数据：b1/b2/b3 的任何结果都没有进入本轮统计。
