# 实验382 排序8位逐槽异常的无损容量先导

2026-10-17，在新结果前登记。对应exp258文档中的INT8与异常表建议。
exp372至373的整块回退没有8位窄块，本轮改成逐槽异常，完整保留int16原值。
主假设是少量离群值导致整块跨度过大，逐槽处理可减少总容量。
竞争解释是有限值普遍分散，异常表与随机访问索引会抵消8位节省。

固定使用exp372导出的[288,480,160,4]搜索rank表，共88,473,600槽，
原176,947,200字节，SHA为
`e157a8326027d512c9ee3c459e1a406eb7069f07946eaff6c4bc189708e386f9`。
本轮全部数据属于架构静态表，未读取新的请求或标签。
正式入口、源码和交付保持exp354；exp323发布版继续作为CPU基准。

预先固定源块8、16、32、80、160，每个象限独立使用有限值最小值或
有限值下中位数减127作为基值，共10布局。基值限于int16；
有限差值0至254直接保存，码255表示异常，INF也进入异常表。
每64槽保存uint64异常位图和uint32异常前缀计数，异常值按原槽序保存int16。
随机读取异常用前缀计数加字内popcount定位。逐目标列独立编码，
报告真实尾部对齐、基值、码流、位图、前缀和异常值字节。
与整块回退相比，新增的是逐槽资格和精确随机访问索引。

先运行合成边界自检，包含全INF、有限负数、最大最小值、255边界、
位图第0/63/64位和尾部。随后10布局逐槽编码、按实际位图定位解码，
完整核对88,473,600槽，基值和异常指针范围均用assert检查。
主指标为总字节及逐槽异常比例，最小容量收益固定为5%。
容量达到该值的布局保留为在线候选，CPU另行登记；其余固定布局
本轮止于容量结果，后续新基值或重排须单独说明信息增量。
容量改善仅支持在线试验，实际CPU需计入基值读取、分支与popcount。

范围仅涉及`validation/exp382_rank_escape.py`及本轮记录；
复用exp372原表与exp208身份/排他写入工具。新增exact、评分和估计程序运行成本为0。
命令为`OPENBLAS_NUM_THREADS=1 python3 validation/exp382_rank_escape.py prepare`，
随后使用同一脚本的`measure`阶段。原始证据放`validation/results/exp382/`，
完整码流只在内存往返，不新增静态blob或生产binary。
开工`df -h /dev/sdd`可用约386GiB，结束记录空间和清理情况。

## 结果

十布局全部逐槽恢复88,473,600个值，11个合成边界自检通过。
最小布局为block8-min，总204,672,906字节，相对原表增加15.668915%。
其中异常38,745,477槽，占43.793264%；码流88,473,600字节，
基值22,118,400字节，位图11,059,200字节，前缀5,530,752字节，
异常原值77,490,954字节。冻结原表INF数量为0。

| 源块 | min布局总字节 | median布局总字节 |
| --- | ---: | ---: |
| 8 | 204,672,906 | 219,192,190 |
| 16 | 218,810,284 | 231,022,738 |
| 32 | 244,244,230 | 249,863,576 |
| 80 | 262,160,208 | 255,775,250 |
| 160 | 272,928,246 | 257,442,978 |

异常占比较大，新增的逐槽表示与随机定位元数据共同超过int16原表。
十个固定布局均结束本轮在线接入；其他基值、重排与有损量化维持独立研究资格。
该结果支持容量判断，当前各布局的在线C++与CPU尚未测量。
