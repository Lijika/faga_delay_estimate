# 实验455 面向1B的完整程序热点分解

2026-10-18预登记。固定exp444/gw作为工程基线，八源非重复100M
完整程序CPU均值48.44秒，40k同次输出抽样acc99.176604%。
同分布1B线性外推约482秒，属于成本估计。正式入口仍为exp354，
发布CPU比较基准仍为exp323。本轮沿用exp443非重复10M开发输入。

主假设是当前逐请求开销由解析、随机距离表读取和边界修正共同构成。
先在远端Xeon core 3串行执行一次cycles用户态采样和一次硬件计数。
二进制、架构、八源资产和输入保持冻结身份，所有输出SHA必须等于
exp448完整输出。perf附加开销单列，本轮计时只用于热点诊断。

主指标为函数样本比例、每请求cycles/instructions、分支失误和缓存
失误。先记录结果再选择后续候选。优先处理样本占比超过10%且有
可保持输出等价的实现路径；预期完整CPU改善至少5%才进入下一轮
非重复1M消融，随后10M和100M。采样不提供全源容量和1B达标证据。

复现命令为`python3 validation/exp455_profile.py`，远端工作目录固定
为`/home/lhj/lhjwork/eda2026`。首次执行要求新的exp455目录。

## 结果

两次10M输出SHA均保持，cache_hits均为0。每请求约1828.65 cycles、
2370.52 instructions、6.20次branch miss、3.71次cache miss、
2.43次dTLB load miss。硬件事件复用的运行比例为57%至71%，
这些计数用于量级判断，细微差异需独立测量。

用户态样本中main含内联估计路径占54.15%，parsePin占12.88%，
名称哈希链占8.90%，字符串哈希占2.65%，memchr占6.63%。
函数样本无法进一步把main内部访存等待与算术精确分开。
exp456因此固定解析索引与大页存储两项消融。

记录脚本两次恢复分别处理远端缺少本地分析报告、独占写入进度文件。
两次perf命令都已完成并核对SHA，恢复直接复用输出。
原失败目录、实际运行脚本身份和修正后复现脚本身份见recovery.json。
