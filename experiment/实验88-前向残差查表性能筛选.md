# 实验88：前向残差查表性能筛选

## 假设

在 `runResidueDijkstra` 中预计算 `(Z 端口, residue)` 的前向残差，能够减少每次松弛的两次模运算，保持逐字节输出一致并降低 1M unique CPU 时间。

## 方法与固定身份

- 基线：`subm/versions/exp87-more-labels-54e0202/bin-estimate`，SHA-256 `2813881c1a22fca79c47752d71784a120e5000fec282d86be94bfa47332bf043`。
- 候选：`build/exp88/estimate-next-residue`，SHA-256 `8fc81f1c4d891528490613349a878eacf0c9045a12463659dc08f54b79543ebe`。
- 输入：`build/exp57/timing-1m-unique.csv`，SHA-256 `2cf587f1b27ccc5699040e64ea3efc6eb68c100cfd72a36cad383383a018d7bd`。
- 命令：`taskset -c 3 <binary> -arch doc/eda比赛文件/arch -quiet -residual xgb-base47-d8 -bias-ps -3 -in build/exp57/timing-1m-unique.csv -out <output>`；基线省略显式模型参数，使用同一生产默认配置。
- 预热 1 次，之后按基线、候选、候选、基线、基线、候选交错运行 3 对。

## 结果

- 基线与候选每轮均为 1,000,000 行，输出 SHA-256 均为 `2fabc5f89059bcd15d16735e5579ec7e472a92706ef1e749c01b5209e999ee0d`。
- 负值均为 17,585 行，负值位置 SHA-256 均为 `6c9e67fb737c58a52edc1db23a805285bc26118600da3aca8cc1db85c7d242a6`；输出字段、端点顺序和 EOF 检查通过。
- 候选减基线 CPU 差为 `[-0.59, +0.08, -0.50] s`，均值 `-0.337 s`，95% 区间 `[-1.240, +0.567] s`。
- 最大 RSS `572,116,992 B`，每轮单线程，最大 wall `27.12 s`。
- 原始计时和契约记录：`validation/results/exp88-timing-1m-unique.json`。

## 结论与局限

输出等价成立，CPU 区间跨过 0，未达到可确认的性能收益门槛，因此不接入正式源码，也不重新打包。候选二进制和计时证据保留，可由上述命令重建；本轮未运行 1B。

## 清理

三份重复输出在删除前逐一比对 SHA-256，均为 `2fabc5f89059bcd15d16735e5579ec7e472a92706ef1e749c01b5209e999ee0d`；可由计时命令重建，且不被正式复现命令按名引用。删除路径：`build/exp88/timing-baseline.csv`、`build/exp88/timing-candidate.csv`、`validation/results/exp88-timing/candidate.csv`。`df -h /dev/sdd` 收尾可用空间仍为约 `484G`。
