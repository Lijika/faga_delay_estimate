# 实验225 C1 上界间隙阈值上调的开发筛选

2026-10-12。正式入口exp131与私有对照exp220不变。exp224无条件固定小步
在开发/已查看窗口最多分别增益+0.003856/+0.009492 pp；按距离带选型
的事后诊断在已查看窗口仅+0.019799 pp。本轮只检验上界间隙
`D=U-P`能否作为廉价上调资格信号。`/dev/sdd`开工可用434 GiB。

## 预注册

固定exp214开发6176行、exp215已查看6180行的截断预测P和C4800合法
上界U。仅当`P>0`、`U>P`且`U-P>=t`时返回`min(U,P+k)`，其余返回P。
候选为保持原值的`(k,t)=(0,0)`，以及`k ∈ {1,2,3,5,8}` ps与
`t ∈ {1,4,16,64}` ps的20个组合。阈值64在开发窗口有703条有资格
请求；不纳入仅71条有资格请求的256阈值。整数输出、零值和负值约束
沿用exp224。

先在exp214按加权accuracy增益选择最大值；同分时依次选更小k、
更小t。用exp215已查看窗口报告固定选型的总体和七带增益、
改写/改善/恶化行，并以seed 20261013做10000次七带配对bootstrap。
报告全部候选在两窗的增益。主假设是较大的合法上界间隙可筛掉
部分过估请求，使条件步长比统一步长取得更高净增益。进入全新
exact请求验证的门为选中非零k、exp215增益至少+0.03 pp且其
95%配对区间下界大于0。未通过则停止只按间隙设阈值的规则。

两窗标签均已查看，exp215的区间只作筛选描述；新请求精度、
CPU和完整1M另验。查看本轮候选结果前冻结本协议、脚本、输入和门槛。

```bash
PYTHONDONTWRITEBYTECODE=1 build/venv-ml/bin/python validation/exp225_margin_step.py freeze
# 单独提交冻结清单
PYTHONDONTWRITEBYTECODE=1 build/venv-ml/bin/python validation/exp225_margin_step.py analyze
```
