# 实验201 C1 端点提升与安全下界单项消融

2026-10-10。承接实验199的逐行等价结果和实验200的组合计时。本轮只在
固定的7个cycle映射上分离两个工程改动，比较端点集合提升和Arc-only下界
剪枝各自能否降低完整探针进程CPU。

## 假设与四个臂

- `control7`：7个cycle映射，端点集合在`mode × tree × query`内层生成，
  不使用下界剪枝。
- `endpoint`：同一映射和路径，端点集合每个query只生成一次，不剪枝。
- `lb`：端点集合保持内层生成，使用
  `seed + mapped Arc和 + terminal Arc` 的非负费用下界。
- `full`：同时使用端点提升和Arc-only下界。

四个消融臂由同一 `tests/exp201_ablation.cpp` 以编译期宏生成：
`EXP201_ENDPOINT_HOIST` 和 `EXP201_LB`。每臂分别构建计数审计版和无计数
计时版；后者不执行调用计数，避免把插桩指令差计入节省。这样热循环没有
运行时模式分支。
所有臂使用相同架构、40棵exp171 parent tree、exp174的6176条加权请求和
相同的7个映射。输出契约审计使用CSV，CPU计时输出写入`/dev/null`并计入
加载、恢复、端点准备、parent追链、真实重放、统计和输出调用。

## 预注册验收

1. 四臂逐行`prediction`必须保持一致，并分别与exp198的cycle1--7及
   exp199的full结果核对；`U < exact`、false finite、false unreachable
   和评分恶化均为零。
2. 记录每臂的端点准备、chain、完整链、LB拒绝、replay resolver和
   terminal resolver计数。
3. 采用同机、单线程、CPU core 3、每臂一次预热、10个交错配对块。
   每块运行四臂各一次，顺序按块轮转。预注册主比较为`endpoint-control7`
   与`lb-control7`，各给df=9的双侧95% Bonferroni同时t区间；`full`的
   比较给普通双侧95%配对t区间，作组合描述。RSS须≤2,000,000,000字节，
   wall须≤1800秒。
4. 单项CPU区间跨零时只保留工作量和等价证据，不宣称CPU收益。完整候选
   只有在等价、资源和CPU证据同时充分时才考虑完整1M；本轮不改正式源码、
   `estimate`、交付包或既有accuracy统计门。
