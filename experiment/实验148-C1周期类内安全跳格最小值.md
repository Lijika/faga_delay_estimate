# 实验148：C1 周期类内安全跳格最小值

## 目标与假设

exp147 的 safe bound 对每个 Router 状态逐个枚举 `c∈[-128,128]`，每个候选计算四象限 residue
最大值。理论笔记 `周期类内安全跳格最小值的凸性与精确查找` 推导：对固定符号及
`m mod P`，其中 `P=mx/gcd(mx,14)`，候选值是凸函数的向下取整，因而在该离散子序列上弱单谷。
本轮假设邻点二分能保持逐状态完全相同的 `h_safe`，同时减少 query CPU。

候选只替换 `|c|` 最小化方法。safe bound 公式、dense cache、Router、输入和状态语义全部固定。

## 固定基线与数据

- 基线提交：`41275e0`（exp147 dense cache）。
- 基线实现：`tests/exp147_router_safe_residue.cpp` 的逐项 `safe()`。
- 数据：冻结的 `validation/results/exp146-router-safe-residue.csv`，92行，其中8行保留 plain Dijkstra 对照。
- exact 对照：exp146标签及逐行输出；exp147 CSV 作为答案、扩张和松弛基准。
- 正式版本身份：exp131 SHA `aed8b929957a14cd5a2ae73bf94fedfd0cfaa86732ff79a7ee08a9e7afca064c`。
- 搜索域：保持 `|c|<=128`；周期从运行时 `mx` 与14计算；`c=0`、非有限 residue 类和尾部完成判断保持原语义。

## 执行与测量

1. 运行前校验基线、输入、架构和正式二进制 SHA；同一 test-only 实现编译枚举版与二分版。
2. 第一次审计运行中，对每个枚举版实际访问的 Router 状态比较两版 `supported/known/complete/value`；
   记录每次 bound 计算的 residue 候选求值次数。固定样本的每行答案、扩张数、松弛数须与 exp147 一致。
3. 两版各运行一轮不计时预热，随后五个配对批次，顺序为
   `enum-fast, fast-enum, enum-fast, fast-enum, enum-fast`。固定 CPU 3、单线程、禁用 Router 查询缓存与 landmark。
4. 记录每批 query CPU/wall、扩张/松弛数、候选求值总数，以及完整进程 CPU/wall、RSS、线程数。
5. 报告配对差 `fast-enum` 的均值、样本标准差及双侧95% t区间（df=4）。

## 判决门槛

- 任一实际状态上的 bound 值、known/complete 状态或 Router 输出不同：停止，保留枚举版。
- 对应 residue 子序列的单谷断言或邻点二分对照失败：停止，修正推导或实现。
- CPU候选晋级需同时满足：`fast-enum` 的95%区间上界小于0，且平均 CPU 节省至少为枚举版均值的5%。
- 候选求值次数减少但 query CPU 未达门槛：不进入更大请求集。
- 本轮通过仅允许进入更大筛选样本；不构成完整1M精度、资源或正式接入验收。
