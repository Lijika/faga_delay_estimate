# EDA2026 最终研究对比报告

日期：2026-09-24。正式入口为实验29冻结二进制 `./estimate`，交付入口为
`build/submission/estimate`；两者 SHA-256 均为
`db2cca1eb976df543b2b7281326402fd77fc7b58bf1492d530535903df88ba35`。

## 结论

正式版本继续采用 mult2 residue、`source-short 150`、64 棵树的 xgb 残差和 64 MiB 完整请求缓存。
公开 1M accuracy 为 96.116008，1B repeated 五次平均 CPU 为 464.056 s，峰值 RSS 为
925,442,048 bytes，五次输出逐字节一致。平台回执为 total 93.81、accuracy 96.12、time 79.45、
consistency 100。

相对启动时原始 mult1/端点关闭实现，公开 1M accuracy 从 91.6213558624 提升到 96.116008，
增加 4.494652 个百分点。相同公开 1M 请求重复到 1B 的计时协议中，实验25到实验29的平均 CPU
从 679.322 s 降到 464.056 s，减少 31.69%；两版完整输出一致。该比较属于本机公开 repeated
分布，平台输入字节和赛方机器仍按下文边界报告。

没有新的候选满足“精度收益、95% 置信下界、CPU 预算、单线程、2 GB、3,600 s、五次完整输出一致”
的联合条件。实验47完成了候选的五次 1B 资源和输出验收，但 CPU 配对区间跨过零，精度复用了旧标签；
实验31、41、48分别受稳定计时、样本选择或新族泛化限制，均不接入正式入口。

## 实验50边界

10M 输入 SHA 为 `4aadb6c2d352cd7eabc3bc022ef74fa248c6a692b5eb555d93515c25ce4ce316`，
100M 输入 SHA 为 `7038c2629a70ea1b5379791a15801ca2199bb1e5138b71bed44e25092961b6de`。
10M 的四轮顺序为 cache=0,64,64,0，wall 为 256.45、235.40、231.00、233.44 s；
100M 的两轮顺序为 cache=64,0，wall 为 2183.44、2182.34 s。每轮退出码为 0、线程数为 1、
峰值 RSS 小于 2,000,000,000 bytes，`verify_scale_output.py --mode unique` 均检查了行数、端点原文、
整数 delay 和精确 EOF。10M 输出 SHA 为 `650f2962aa717f0285c73040c08d339ff4e3049e9f7089a0b0aca5ce9b2b91b5`，
100M 输出 SHA 为 `befd804c79d6051e77c73e97fe9f4f0a68f269c94234ac3aa051684ca537db61`，缓存开关不改变结果。

预注册规则用 10M 最大 wall 得到 `est_100M = 2318.8 s`，因此执行 100M。用 100M 最大 wall
得到 `est_1B = 21,574.3 s ≈ 5.99 h`，超过 3,600 s 上限，本轮不启动全独特 1B。该判断只描述
全独特上界负载；公开 1M 请求扩展到 1B 时只有约 1M 个 distinct key，正式 repeated 验收仍以实验29为准。

| ALT、PDB、CRP/MLD、CCH、HL、TNR | 仅用于 exact 标签、诊断或局部原型；没有整图端到端收益证据 | 实验7/9–11/14/18/20A–C/27 |
| AIR/VPR 与布局类论文 | 作为方法参照；任务和指标不等价，不改生产 | 实验22；`doc/paper/01/03/04/07` |

仍未验证。

## 重启条件与复现

候选重新进入正式验收需要：未参与选型的新架构或新请求标签、配对 accuracy 改善的 95% 置信下界为正、
固定最小实际收益、同机交错 CPU 预算通过、单线程、峰值 RSS 不超过 2,000,000,000 bytes、每次运行不超过
3,600 s、五次完整输出一致。实验50的输入可按 `validation/exp50_unique_scale.py` 和日志中的生成命令重建；
