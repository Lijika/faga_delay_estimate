# 实验151 C1 消元精确搜索大样本成本

2026-10-10，Asia/Shanghai。分支`research/exp151-folded-exact-cost`，起点`1387a81`。
开工`/dev/sdd`可用454G。

## 假设与固定候选

exp150通过92行组件门。唯一搜索配置为原exp147枚举安全界、dense缓存、I*真实唯一终端消元、
binary heap、无landmark、无Router查询缓存。假设它在更大的同架构真实请求上保持exact，
并使部分精确回退具有正的条件性综合收益。

本轮只量化组件与两个已知触发族，不训练模型或改变预测规则。
全量exact和两档触发阈值0.025/0.10均预先固定；阈值沿用实验27，
按当前冻结exp131预测与已保存无残差fast值形成如下诊断定义。

```text
off = fast < 0 ? -1 : max(0, fast - 3)
trigger = off > 0 and baseline > 0
          and abs(baseline-off) / max(baseline,off) > threshold
```

该定义是本轮固定诊断，部署中的特征/CPU节省仍需另验。完整exact仅作成本上限与正确性对象；
各触发族只作开发筛选，不直接宣布独立精度收益。

## 数据、身份与测量

固定exp138的同架构`[48M,50M)`七带分层6176行，全部已查看，复用核验exact，
不读golden、不补标签。输入为`exp138-predictions.csv`，exact与fast来自
`exp138-raw-exact-labels.csv`，权重与总体来自`exp138-score.json`。
按完整端点映射，核对6176个唯一键、exact、七带/权重与2M总体。
先提交协议/实现并生成冻结输入身份，再运行新查询。

每进程共享一个residue、Router、provider；前64行预热一次，随后全6176行按冻结顺序运行3次。
CPU3、单线程、同机串行，逐行计CPU、expanded/relaxed和provider调用/计算/命中。
输出每次逐行答案与已核验exact一致；再次运行必须保持答案和搜索轨迹。
逐行保存完整前缀；标签、轨迹、provider unknown/incomplete或线程错误立即停止。
原92行控制结果可复用，不再次重跑大成本控制。

资源记录共同residue初始化、增量Router/provider初始化及query CPU/wall、RSS、线程数。
运行上限1800秒，任一标签/重复轨迹错误立即停止，保留前缀日志。

## 指标、门槛与停止

主正确性门为6176行全部exact一致、3次答案/轨迹一致、无unknown/incomplete、单线程、
RSS<=2,000,000,000 B、wall<=1800秒。通过后仅允许后续组件/回退验证。

按七带权重报告全量与两档触发族的覆盖、accuracy上限增益、weighted query CPU及长尾。
query CPU按3次每行均值外推1M distinct；共同residue初始化复用生产已嵌入表，
新增Router/provider初始化实测单列。保守地将全部触发query CPU计作新增成本，
暂时忽略替代原模型计算可能节省的成本。

```text
诊断综合点收益 = 0.8 * accuracy_gain_pp - (query_cpu_for_1m + incremental_init_cpu)/120
```

上式对应1B运行只有1M distinct计算、精确结果随生产答案缓存复用的条件模型；
缓存容量、miss数和新增初始化最终需在实际接入中验证。
同时列出1B全distinct的查询CPU外推及线性预算诊断；时间分归零后的实际分数不作线性外推。

成对分带bootstrap固定10000次、seed20261010，对每行精度收益与CPU联合重采样；
每个draw先从3轮中有放回抽3轮，所有带共用该轮组合，再在各带成对抽行，
全量普查带保持行集合。报告95%百分位区间及三轮CPU范围。
至少一个固定触发族在1M distinct条件模型中点收益>=0.01且区间下界>0，
才登记新的独立请求/实际接入验证；若均未过，先保持exact并优化CPU。
全量exact、阈值0.025和0.10分别报告，停止条件与门槛保持固定。
