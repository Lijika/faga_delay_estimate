报告中的“证明”都列出成立前提；“预算”是设计上限或验收目标；“历史实测”明确指向原材料；“预期方向”不冒充已达成的 Acc 或 CPU 成绩。这里没有承诺任何尚未实现的模型会获得 99%/100 秒。

## 0.3 本报告给出的核心判断

现有证据更接近“表示可以继续改进，但实现成本与缺失条件共同限制近期收益”，而不是已经证明当前架构有不可逾越上限。固定名义键的多位置差异证明仅依赖该键的函数不充分；它没有证明包含真实位置特征的整个 S8/V8 系统不充分。

近期主线应为：在冻结函数上削减准备工作和依赖访存，同时用在线可计算的支持状态做严格配对、匹配残差实验。更高上限主线应为：离线编译有条件的路径片段和距离表达式，在线限制候选数，必要时用可证上下界约束预测。纯 CCH/Hub Labeling 全图索引不作为第一选择；纯加秩也不作为第一选择。理由分别是原始状态规模、查询预算和已有配对收益，而非这些方法在理论上无效。

# 1 目标可行性与需要跨越的差距

## 1.1 以 6242R 的 98.52% / 220 秒重新计算

达到严格 >99% 需要增加超过 0.48 个百分点；达到 >99.1% 需要超过 0.58 个百分点。当前评分损失为 1.48 个百分点，因此需要消除现有总评分损失的超过 32.43% 和 39.19%。这是最终官方损失的比例，不是要求降低同等比例的 MAE。[P1；本轮算术]

220→100 秒意味着 2.20 倍速度、54.55% CPU 降幅；220→90 秒意味着约 2.444 倍速度、59.09% 降幅，严格 <90 还需要更多。100 秒和 90 秒分别只给每条请求 100 ns 与 90 ns，包含启动、输入、输出和内核 CPU 的摊销。3.1 GHz 下为 310 与 279 cycles，4.1 GHz 下为 410 与 369 cycles；不能把最大睿频当作实测持续频率。[P0，§3.2][L1]

这不是“小修几处热点即可稳妥达标”的任务。假设一个真正互斥计时的部分占比为 f，且仅该部分加速 r 倍，则 T_new = 220 × [(1-f)+f/r]。f=0.8、r=2 时仍为 132 秒；f=0.8、r=3 时约 102.67 秒；f=0.9、r=3 时为 88 秒。这些是条件情景，不是预测。它们说明必须影响绝大部分在线工作，或直接移除某些阶段。

## 1.2 哪些支持目标，哪些反对目标

支持因素有三个：架构固定且规模有限，适合提前求值；查询的离散结构具有复用，不依赖完整请求重复；历史上结构改变比局部指令优化更有收益。exp705 又给出真实位置改变路径支持的见证，说明存在当前分解未充分表达的信息。[P0，§5]

反对因素同样明确：现有历史精度增量大多明显小于本轮 0.48 pp 缺口；双 64 背景的名义改善没有充分转化为真实 OOF 收益；大资产存在多个随机读取和依赖链；完整输入输出约 75.33 GB，CSV 与系统调用并非免费。精度新机制若只是追加在旧查询后面，很可能使速度目标更远。[P0，§3–5]

因此，本报告的判断是“有值得验证的结构机会，但成功概率不能由现有材料可靠量化”。最能改变判断的新增测量不是再跑一个点积微基准，而是目标机上三种完整处理骨架：只读写保留契约、解析并生成准备状态、完整预测。它们决定不可省工作是否已经接近 90–100 秒；第二个决定性实验是支持状态在独立请求上的最终评分可恢复损失，而不是 oracle 覆盖率。

## 1.3 为什么不把 oracle 干预量直接相加

背景、地图和 Line 干预分别改变一个有相互补偿的系统。它们的收益不具备可加性，且 exact 替换不代表在线可计算。ordinary_word 的全局地图干预贡献约 0.246 pp，提示值得研究，但不能宣称该群必然提供这部分可部署收益，也不足以单独证明可以填满 0.48 pp。[P0，§5.3]

需要登记一张“损失覆盖账”：每个不重叠请求群的人口权重、原损失贡献、支持状态可预测部分、oracle 上限、实际 OOF 改善、上线成本。只有最后两项进入工程决策。只报某个群内部很高的命中率，会遗漏它的总体权重。

# 2 源码审查：先解决语义和函数身份

## 2.1 角色域与同 pin 空路径不是同一问题

实际 worker 的生产入口在构造请求后，先检查源/目标是否属于 208×288 角色域，满足后才调用 prepare596。prepare596 自身虽然把完全相同 pin 返回 0，但域外同 pin 根本到不了这一分支。默认状态仍会输出 -1。[R8，worker.cpp:100–110、247–260]

这个结论是调用链层面的源码发现，不是说所有同 pin 都错误。必须区分：角色域内同 pin；合法存在但角色域外同 pin；不存在 SRB 上的伪 pin。修正顺序应为完整解析→存在性与端口合法性→官方允许空路径时的同 pin 分支→受支持角色检查。不能简单把“同 pin 返回零”移到所有合法性检查之前。

新增协议明确不能从公开样本推导官方只允许当前角色域，且提供了域外可达查询的 exact 验证入口。对该问题，合理选择只有两种：取得明确输入承诺并固化为契约，或扩展模型/确定性回退覆盖。不能把合法域外可达请求统一标作不可达。离线 exact 工具可用于检验，但在线不应无界启动最短路搜索。[R4][R3]

## 2.2 nominal geometry domain 的 assert 也属于覆盖审查

prepare596 对对齐后的 bx≤119、by≤549 使用 require，而它们来自 t-a+v，不是原始两端坐标差。真实首 Net 跳格可能使两者不同。当前 1B 未触发断言不等于所有官方合法请求都满足该界。[R8，worker.cpp:111–124]

应离线枚举“有效源位置×160 种首 Net×目标坐标域”的可达边界，先通过坐标极值求出可能的 bx/by 上界，再对超域组合做可达性检查。若存在合法超域请求，选择扩展表域或确定性回退，不能在正式 1B 中途退出。这个检查是语义枚举，不是用户禁止的旧规模性能测试。

## 2.3 数值函数必须按实际表达式冻结

可读点积代码的关键表达式为：

```cpp
total += double(dot64(a_group, b_group))
       * double(left_scale[group])
       * double(right_scale[group]);
```

因此，尺度虽然以 float32 存储，却分别转换成 double，随后按源表达式执行两次 double 乘法。预先计算 float32 的 scale 乘积、把两个 scale 合成一次乘法，或引入 FMA，都不能自动视为逐位等价。近域八组也要保持原累加顺序。[R9，exp608_geometry.h:48–60]

随后还有背景反归一化、第一次舍入、cycle 覆盖、首段和曲线修正、树值合成、第二次舍入以及 Line 加回。只验证 dot64 一致不等于完整输出一致。所有“等价加速”必须保留这条函数链；改变任何一项则重新归类为算法候选。[P0，§4][R8]

## 2.4 当前残差不是统一匹配当前背景训练的

新增训练材料说明：S8 的监督背景是 base_q4，V8 是 base_curve；当前生产路径又使用 D64 加曲线。这个历史来源不等于代码错误，但会使“背景变好，最终 Acc 却不动”有一个具体的竞争解释：旧残差在补偿另一种背景。[R5]

同时，codebook 构建源端口留出，不等于 code assignment 完全留出。当前曲线材料明确区分了这两者。新的跨源端口泛化实验必须分别标记共享 codebook、每行目录分配以及残差树看过哪些标签；不能统称为“端口留出”。[R5]

## 2.5 不把已经完成或已被编译器删除的工作再算一遍

exp704/706 的直接端口目录已有完整 100M 配对证据，下一步应复用，不应再把它列作新发现。用户的 220 秒若已经包含它，也不能再从该数值扣除历史节省。[R7][P1]

resolveNet 已有冻结查表路线，因此“把 Net 求解改成表”不是新的核心机制。真正待查的是表项布局、随后重复取得的元数据、依赖链，以及能够取消的组合工作。worker 中仍写着完整 feature[53]，但无 trace 的生产分支可能已删除未使用表达式；没有反汇编和有效宏证据，不应给“删掉 53 个特征”估算收益。[P0，§4.3、§6.1][R8][R10]

# 3 数学基础：真实距离、路径支持与安全修正

## 3.1 正确的数学对象

定义真实有向图 G：状态是 v=(x,y,p)，其中 (x,y) 为存在的 SRB，p 为完整端口。Arc 保持坐标并改变端口；Net 经过真实 resolver，可能跳格、收费或非法。D(s,t) 是完整图最短路，D0(s,t) 在同一可行路径集合上把 Line 费用置零。不是把缺格填满，也不是改用无向曼哈顿距离。[P0，§1]

完整端口状态展开有 60,200×496=29,859,200 个槽位；仅保留 160 个 Net 源端口也有 9,632,000 个槽位。这些是直接表示规模，不是任何算法的空间下界。消除内部端口时必须保留相应有向连接与最小 Arc 费用，不能仅按坐标合并。

对一个具体端口词 w，定义部分函数 F_w(x,y,p)=(valid,end_port,end_x,end_y,c0,cLine)。组合必须依次执行真实 Net 和 Arc。只有 valid 为真、最终完整 pin 等于请求目标时，c0+cLine 才是该请求的一条合法路径费用。

## 3.2 D0 加必过 Line 是下界，而非一般意义上的真实答案

设 M(s,t) 是对每条合法路径都成立的 Line 费用下界。在首 Net 确实强制、且不是空路径的条件下，可以把已执行首段的 Line 实际费用，加上首落点到目标所必须跨越的坐标割费用。还须核实当前 lineDelayCrossing 的边界、重复跨线及收费规则，不能只凭函数名字授予下界资格。

对任一可行路径 P，有 c0(P)≥D0、cLine(P)≥M，因此：

```text
D(s,t) >= D0(s,t) + M(s,t).
```

证明只依赖同一可行路径集合与逐路径不等式。等号要求存在同一条路径同时达到 D0 最优和 Line 下界。分别存在一个 D0 最优词、一个最低 Line 词，不足以推出等号。

这意味着从 exp705 取一条 D0 最优词后，把它的 D0 费用加上 M，不一定得到合法路径的完整费用，更不能自动当作上界。要得到 U≥D，必须按真实位置重放该词，并累计它实际跨过的所有 Line；回绕引起的额外跨线不能忽略。

## 3.3 一个可以保留的严格性质：区间投影不恶化评分

若对同一个可达请求，已严格证明 L≤D≤U，且 p 是原整数预测，定义：

```text
p_new = min(U, max(L, p))       # L、U 为有效的整数界
```

则 |p_new-D|≤|p-D|。因为 tanh 在非负实数上单调，该请求的官方评分不会下降。只有合法上界时使用 min(p,U)，只有有效下界时使用 max(p,L)，同样成立。这是逐点保证，不依赖样本分布。

这里的保证不适用于未经证明的“名义背景下界”、把失败重放费用当作 U、把 D0+M 当作 U、或者把 -1 不可达输出当作普通预测。若还加入一个学习残差，投影只保证相对“投影前的那个预测”不恶化，不能保证相对最初 exp688 不恶化。

当 L=U 时可直接输出 exact，不再读取背景或执行树；这同时提供精度和速度机会。当区间非零，仅凭“很窄”不能保证胜过当前预测；但可形成可审计的误差证书。若 L>0，取区间中点并整数化，其最坏相对误差不超过 (U-L+1)/(2L)。这种保守界是否有用要看真实区间宽度，不能先假定大量请求会闭合。

### 相对评分下的最优保守输出

若只知道 0<L≤D≤U，希望不读背景就选择一个具有最好最坏相对误差的输出，则连续最优点不是算术中点，而是 p*=2LU/(L+U)。因为区间内最坏相对误差出现在两个端点，分别为 (p-L)/L 与 (U-p)/U；令两者相等得到 ρ*=(U-L)/(U+L)。整数情形只需比较 p* 的向下、向上取整两者的端点风险，再限制在区间内。

因此可以用 100[1-tanh(4ρ)] 给出该请求的保守评分证书，并将证书足够高的请求送入无需背景的快路径。它不是“相对原预测不下降”的保证；那是前述投影的另一种性质，两者不能混淆。L=0 时此证书不适用，应先处理 exact 零值或回到普通路径。整数除法和证书判定也要计入成本；可用离线生成的保守有理阈值做交叉乘法比较，避免线上 tanh。

短延迟使证书很苛刻：g=128 ps 时仅错 1 ps，评分约为 96.88%。所以“少量 ps 已经很准”并非正确的资源分配依据。小区间快路径最适合能够闭合为 exact 的短距离，或容许窄相对区间的较大延迟，而不是无差别跳过近域模型。

## 3.4 廉价下界：在真实边上认证的端口势函数

可尝试 K_L 个势函数 φ_k(x,y,p)=α_k x+β_k y+η_k,p。要求对每一条真实合法边 u→v：φ_k(v)-φ_k(u)≤c0(u,v)。沿路径求和可得 L0=max(0,max_k[φ_k(t)-φ_k(s)])≤D0；随后加经过认证的 M 得到完整距离下界。它不是把现有低秩预测硬改称下界。

固定 α、β 后，对 Arc 检查 η_q-η_p≤c_arc；对 Net 检查 η_q-η_p≤min_location[c0_net-αΔx_real-βΔy_real]。因此可先枚举真实 Net 的有限几何类型，再在完整端口上解差分约束；若有负环，该 α、β 不可行。允许以缩放方向、线性规划或保守整数构造寻找可行系数。真实跳格位移必须进入约束。

部署用整数系数 A、B、H 和公共 Q>0：AΔx+BΔy+H_q-H_p≤Q c0(e)。所有乘加使用足够宽的整数并检查范围，构造后重新枚举 Arc 模板和全部有效 Net 位置验证。因为 D0 是整数，可对势差/Q 向上取整得到整数下界；负数除法必须实现数学意义的 ceil，而非直接依赖 C++ 截零。

16 个势、每个 496 个端口系数及两轴系数，按 int32 存储共 31,872 B。这个容量很小，但查询执行 16 组比较并不免费。先比较 4、8、16 个势的“下界收紧/CPU”收益；可能最终只在廉价条件筛出的困难域使用。紧致性尚无数据证据，不能指望它单独补齐 0.48 pp。

## 3.5 固定名义键的差异到底证明了什么

exp705 的多位置设计有效地消去了同键共同的名义背景项，显示真实位置会改变最优费用与具体词的可迁移性。但它同时消去了同键共享的地图偏置，不能说明这部分偏置不存在；也不能直接判定改变来源是唯一一条保存的最优词。[P0，§5.3][R2]

可以构造一个受限表示的经验下限。设表示仅输出键 z 的数值 p_z，而每条记录有已知整数偏移 a_i，定义 R_z(p)=Σ_i w_i tanh(4|p+a_i-g_i|/g_i)。g_i>0 时，每两个折点 g_i-a_i 之间，此函数是凹函数之和，最小值可在端点寻找；因此检查观测折点即可得到该经验问题的最优常数损失。这量化“合并这些状态至少付出多少损失”，但只对该表示与该样本成立，不是当前全模型或隐藏总体的不可达证明。

特别地，同一无偏移键有等权 g1<g2 两种真值时，任意共同预测的最小平均损失为 0.5×tanh(4(g2-g1)/g2)，由选择 g1 获得。它说明不同真值被合并必然付出代价，却不说明哪种在线小状态足以消除全部代价。

# 4 主方向一：把路径支持变成可部署的小状态

## 4.1 先区分三层信息

第一层是请求直接可计算的信息：完整 pair、首 Net 类型、真实首落点、方向与余类、边界距离、局部有效动作、Line 前缀、中央走廊及 y 带号。第二层是对一个已存候选模板计算的信息：其支持谓词、真实落点偏移、目标端口是否接续、实际费用。第三层是只能看 exact 才知道的信息：最优词的 S、最优词用了哪些障碍、真实最优路线属于哪个候选。第三层不能混进部署特征。

建议先构造第一层加最多 3 个候选支持位，形成至多 8 类 support code，交给现有残差或共享修正模块使用；不要直接建“位置×pair×context”的大表。8 类是首轮复杂度上限，不是已发现的真实充分状态数。

| 字段 | 取值/宽度建议 | 在线来源及保留的信息 |
| --- | --- | --- |
| 完整 pair | 0…59,903；uint16 | 原始角色和 lane 不合并 |
| direction、rx、ry、qx、qy | 4×10×12；当前 qx≤11、qy≤45 | 保持冻结对齐名义位移定义 |
| 首段 motion 与落点 | 16 类轴向动作候选，坐标 uint16 | 从当前真实 resolver 生成；不丢目的端口 |
| 两端区域/带号 | x 三侧，y 带 0…5，y%100 | 描述边界与缺格的相对位置，不宣称充分 |
| 局部合法动作掩码 | 每位置 16 bit 候选 | 仅压缩经验证等价的几何动作，不替代端口邻接 |
| 支持位 | 最多 3 bit 起步 | 三个指定候选在当前请求上的合法且到达判定 |
| 候选跳格类别 | 0、+14、-14、OTHER | 由候选真实转换计算，绝不是 oracle 最优词标签 |

如果首 Net 的几何结果不仅依赖位移，还依赖模板自身属性，16 类压缩就不成立，必须增加类别。应对 60,200 个合法源位置、160 个 Net 模板逐一比较“合并前后有效性、落点、全部费用”。几何合并不意味着端口/lane 合并。

反向局部支持也不能简单把 Net 位移取负。跳格与缺格可能使逆映射不是单值，应离线建立真实逆关系或只使用可以证明的目标侧必要条件。

## 4.2 离线从 exp705 提取什么，而不是背下什么

按完整端口序列对词去重，保存起止端口、Arc 费用、名义净位移、前缀位移、实际重放结果与失败位置。把重放原因 1/2/3/4 分开：出界、缺格、终点改变、合法但费用改变是不同机制。reason=3 的费用不是原请求的合法上界；reason=0 也不保证目标位置最优。[R2]

然后从失败前缀提取候选条件，例如某一段进入中央 Block 的 y 带、横向跨越顺序、最后几跳与目标端口的接续、离边界的最小余量。训练阶段可以用完整路径解释原因，但部署条件必须还原成请求坐标、端口元数据和少量模板检查。

小状态的价值必须按增量测量：在同一 fold 上比较原特征、原特征加局部支持、原特征加候选支持、以及替换掉一组旧几何特征。最后一种最重要，因为它可能同时减少树对复杂交互的拟合负担和特征计算量。只把支持位追加到模型尾部，不能自动产生 CPU 收益。

## 4.3 支持集合如何表示

对固定词 w，精确定义 S_w={起始状态：逐步合法且目标端口转换可完成}，以及其终点映射 E_w。S_w 只表示可执行还不够；查询还必须验证 E_w(s)=t。一个词在新位置不收费，并不表示它与旧位置具有相同落点。

直接为 239,616 个词各存 60,200 位有效位置位图，约需 1,803,110,400 B，还没有终点映射、费用和索引。此计算已经排除“不加选择地把全部见证编译成位图”，但不排除共享后缀、同构词、决策 DAG 或稀疏例外。

建议支持编译器按顺序尝试：区间/矩形的布尔组合；共享子表达式 DAG；小的异常位置表。每个候选规定最多 8 个在线原子条件；超过预算就标记为不可编译，不允许截断条件后仍宣称合法。对固定有限词，可以枚举所有起点校验守卫与真实重放一致。对参数化重复片段，则必须对参数域一并枚举或给出符号证明。

这些状态遗漏的内容包括：远处绕行是否更便宜、未列入候选的接续方式、多次反向穿越、复杂近轴端口限制，以及多个局部合法片段连接后的全局终点约束。因此只能称它们为候选支持状态，不能称“最短路充分状态”。

## 4.4 lane 和门户怎样才允许合并

精确合并需要一个保持权重、方向、Net 几何和查询端点解释的图同构，或针对保留目标集合的加权双模拟关系。例如同时对源、目标及全部内部端口施加同一 lane 置换，若它保持所有 Arc 和 Net 模板及费用，则对应距离相等。只因为同族端口名字相似，或 lane 统计误差接近，不足以合并。

门户同理：把同一坐标上的不同入端口当成一个门户，可能引入原图不存在的转弯。需要保留有向入口/出口状态及内部连接矩阵。近似合并可作为学习表示，但要记录各合并类在留出数据上的条件损失与反例；若用于上下界，必须另外证明是图的松弛或真实可行路径，不能沿用经验等价。

## 4.5 如何处理最短路平局

新增材料说明 tracer 使用严格降低才更新父指针，队列和后继顺序共同决定保存的词，未优化最少跳数或跨位置稳定性。因此“保存词重放失败”不等于“所有最优词均不能重放”。[R2]

首轮应比较至少三种确定性选词：原策略、原费用优先再最少跳数、保持原费用的另一种后继优先级。再允许少量 ε-次优词，费用仍按原边权核验。若构造最短路子图，含零费用环时不能直接把它当 DAG；应先处理零费用强连通分量，或用有界代表词策略。

四位置中另三个 oracle 词覆盖约 80.16%、恢复 D0 exact 约 75.01%，这是诊断的有力信号，但既不是线上可得候选覆盖率，也不是未知位置上的保证。应报告加入多个平局代表后：支持模式是否稳定、候选数增长多少、在线规则是否仍能压缩。如果只有保存词的标签变得复杂而费用预测不改善，就停止扩大词库。

## 4.6 跳格校正的精确分解与坐标变换

还可以把支持问题写成一个更具体的数学对象。设 J_after(P) 为路径在首 Net 之后，各 Net 的“真实位移减名义位移”向量之和。由 d=t-a+v 可得，整个词的名义净位移为 d-J_after(P)。这解释了为何真实路径不是简单的“名义距离(d)+障碍收费”。

若 N(pair,z) 是无位置限制的名义图精确 Arc 费用、名义 Net 不另收非 Line 费，并且真实非 Line 额外费均非负，则可按 j 分组写成：

```text
D0(q) = first_non_Line_fee(q)
        + min over feasible j { N(pair, d-j) + R_j(q) }
R_j(q) = min over real feasible words with J_after=j
         { ArcCost(word) + BlockCost_after(word) }
         - N(pair, d-j) >= 0.
```

该式是带前提的精确分解，不是可直接部署的算法：可行 j 的集合及 R_j 仍未知。但它把两种问题分开：位移校正选择了哪个名义函数；真实位置与端口支持给该函数增加了多少代价。线上候选模板可以提供少量可实现 j，不能把 oracle 最优 j 当作特征。若只枚举 j∈{-14,0,+14}，这是受限候选集，不能作为包含所有路径的松弛来声称下界。

对中央 Block，考虑 W(x,y)=x-14·1[y 位于阻塞半带且 x≥90]。水平合法跨越时，它可能抵消 14 格跳跃；但对 x≥90 的垂直移动，W 的变化包含 -14·(B(y_to)-B(y_from))。因此障碍的影响被转移到跨带的垂直转移，未被消灭。完整端口与跨带状态仍然必要，变换后的图也不是均匀矩形网格。

更重要的是，worker 的现有 feature[51] 已经包含这一类首落点与目标的压缩横坐标差。再提出相同坐标变换不是新机制。值得研究的是将它与具体词/端口的跨带支持连接起来，而不是再增加一个高度重复的几何特征。[R8，worker.cpp:141]

# 5 主方向二：离线编译有守卫的结构距离函数

## 5.1 推荐的高上限架构

本报告选择“有守卫的参数化路径模板 + 可证势函数 + 预算受控残差”为主架构候选。它直接近似真实距离，而不是把整个原始图搬到线上。基本函数为：

```text
U(q) = min { C_r(q) : r in Recipes[pair, context], Guard_r(q)=true }
L(q) = certified lower bound
p(q) = integer prediction from a compact residual/structural model
answer = clamp(p(q), L(q), U(q))     # 无候选时 U=+infinity
```

每个 C_r 必须是一条完整合法路径的全部费用，包含 Line；否则 U 只是普通模型值。若 L=U，直接返回并省掉背景与残差。保守版本中的 p 是 exp688，因而可以隔离支持/界的实际新增价值；最终高速度版本的 p 必须换成更小模型，否则无法同时保留旧 93.4 MB 制品和大型新目录。

这不是声称已经找到了这样的紧凑模板族。它的关键可证伪前提是：大量评分损失和常见查询能够由少数、短守卫、可共享的模板覆盖；否则应保留保守接入，放弃大规模重构。

## 5.2 模板的数学结构与重复片段

一个模板可由“前缀→重复水平片段→重复垂直片段→后缀”组成，也可交换两轴次序或插入有限绕行片段。重复片段必须返回同一个完整端口，并具有可验证的净位移和费用。不能从水平最大步长 10、垂直最大步长 12，直接断言每个 lane 都有相应最优周期。

在不触发跳格、所有中间 SRB 都存在的平移区域，重复片段可给出仿射费用 c0+n_x c_x+n_y c_y，位移方程决定非负整数 n_x、n_y；余类由前后缀承担。跨 Block 时，这个平移性质可能失效，必须用显式异常片段分段，或拒绝该候选。

Line 的完整费用也可以离线化，但不能只看模板的起终点。对平移重复片段中的每条 Net 边，其第 k 次起终点为线性函数；与某条 Line 相交的 k 满足整数区间条件，可以计数后乘费用。含回绕的片段会多次跨线，必须计入。只有经过单调性证明的段，才能把该段 Line 费化为两个前缀之差。

min-plus/max-plus 矩阵幂的周期理论支持研究“重复片段和周期”，但其对象通常是固定矩阵随步数的幂。这里同时约束二维位移、完整端口和真实位置合法性，不能由一个一维最终周期性结论推出 480 个 context 上的小型全局精确公式。本报告不把该类文献当作模板可压缩性的现成证明。[L13]

## 5.3 可复现的离线构造流程

第一步从已有词中提取起止端口相同的循环、常用首尾片段、共享后缀和失败前缀；同时从固定架构名义图发现补充片段，避免候选库只覆盖四个位置的最优词。候选费用和位移先由原图验证，之后才进行合并。

第二步按完整 pair 和 context 建立候选模板组，解位移参数，编译真实支持谓词与 Line 计数公式。一个组初始最多 4 个候选，每个候选最多 4 个宏片段、8 个守卫原子；这些上限是实验设计，不是性能实测。超过上限的复杂词进入离线失败清单，不能在线展开任意长词。

第三步对每个固定词枚举起点，对参数化词覆盖全部允许参数域或用经过检查的符号规则认证。只保留合法候选，上界资格和“是否最优”分开：合法性可以认证，最优覆盖质量仍需 exact 评估。

第四步做字典共享与成本敏感选择。选择目标不是最小重构 SSE，而是留出数据的最终评分改善减去 CPU/容量成本。模板选择、守卫压缩、路由阈值和残差训练全部在相应外层训练折内完成。

建表成本必须列为：原始求解 CPU、候选挖掘 CPU、枚举/证明认证次数、字典优化 CPU、峰值内存和最终资产 SHA。仅固定词的朴素全位置认证就可能达到“词数×60,200×词长”，不能把它描述为免费预处理。优先利用共享前缀、全位置批量状态推进和拒绝高复杂候选降低构造成本。

## 5.4 固定成本查询伪代码

```text
parse two pins, preserve original input slice
validate legal endpoints and handle allowed empty path
obtain compiled source/target records and aligned geometry
choose recipe group by full pair and context
L = certified_bound(q)                 # 固定上限的势函数数
U = infinity
for r in group's at-most-4 recipes:
    if at-most-8 guard atoms pass:
        solve bounded integer macro counts
        verify exact terminal pin
        U = min(U, full_cost_of_at-most-4_macros)
if L == U:
    answer = L
else:
    answer = clamp(compact_model(q, group), L, U)
write original endpoints and integer answer in original order
```

不匹配的 lane、近边界、复杂跳格和目录缺省都使用同一个有界后备模型；不启动无界 A*、CCH 查询或完整词重放。候选数有界只证明成本有界，尚不证明成本低于 90 ns。必须另外测试“全部进入最坏候选分支”的非重复请求集，报告每请求计数、总 CPU 和预测质量。

在已验证的范围内，完整端口对都是固定架构资产的索引；“未知请求”不妨碍结构表覆盖这些 pair。对训练未见的 pair，结构合法性仍可成立，预测质量却没有自动保证。对角色域之外的合法 pair，则需要另外的目录或回退，不能把未知 pair 与非法 pair 混为一谈。

## 5.5 为什么不首选全图 CCH、Hub Labeling、ALT 或门户表

CCH 可以处理有向权重，并非因为本题有方向就不能使用。其原始方法将拓扑处理与权重定制分开；相关扩展也讨论了转向限制导致的状态展开。问题在于本题的端口状态、容量和每请求预算，不能套用道路网络的查询数字。[L5][L6，§4.3]

仅为 29,859,200 个原始状态保存一个 uint32 偏移就需 119,436,800 B，已经超过 ELF 容量；这只是直接表示的反证，不是压缩 CCH 的不可能性证明。压缩到 160 个 Net 源端口后仍有 9,632,000 状态，偏移约 38.53 MB，之后还有有向 shortcut、权重与查询结构。先量实际 separator、shortcut 和标签规模，再谈上线。

Hub Labeling 依赖可覆盖最短路的标签集合；低 highway dimension 等结构假设不能由“图画在二维网格上”自动推出。ALT 的有向下界也需要两个方向的距离。原始展开图若用 16 个 landmark、双向 uint32 距离，需要 3,821,977,600 B，既超过 ELF，也超过 2 GB RSS。[L7][L8；本轮计数]

这些方法仍有三个合理位置：离线标签与认证、已证明松弛的小图上的下界、严格缩减后的困难域子图。门户分解必须保留有向端口接续；若门户边费用来自真实可实现片段，可形成上界，若来自明确图松弛则可形成下界。混用两者会破坏剪枝正确性。

## 5.6 从 99%/100 秒延伸到 99.1%/90 秒

可扩展维度包括：更多共享模板但不增加每请求候选上限；更好的路由在同样 4 个候选中选得更准；更紧的低成本势函数提高 L=U 比例；更紧凑的近域模型；用支持位替换昂贵特征。它们比“每个请求多算一倍候选”更适合同时追求速度与精度。

最可能先遇到的限制是目录与守卫的条件复杂度，而不是整数点积吞吐。若需要为每个真实位置、pair 和距离建立独立例外，结构假设就失败了；若 exact 闭合率不高但候选费用仍改善残差，可退回条件学习表示，不必强行保留上界查询的开销。

# 6 评分、训练和泛化：优化真正交付的函数

## 6.1 官方评分的含义与可用推导

对 g>0，损失 ℓ(p,g)=tanh(4|p-g|/g)。小误差时约为 4|p-g|/g，因此相对误差而非绝对误差最接近评分。但饱和区不可忽略：其梯度绝对值为 (4/g)sech²(4|p-g|/g)，大错误的梯度反而变小，直接用它训练可能忽略灾难样本。

一个充分而非必要的条件是 MARE<0.0025，则由 tanh(x)≤x 可得 Acc>99%；对于 99.1% 相应为 MARE<0.00225。不能反过来从 Acc=99% 推出 MARE≈0.25%，因为少量大误差可能已经饱和。

建议用相对 MAE 或平滑相对 L1 训练、以整数化后的真实评分选模，并对大错/不可达/零延迟另设约束。当前 1000/max(d0+mandatory,128) 权重是一个历史代理，不等价于 1/g，也不等价于最终评分。应比较 g 分母、历史分母以及有界重要性权重，而不是先认定全部短延迟应无限加权。[P0，§2.2][R5]

## 6.2 必须执行的背景—残差对照

| 试验 | 背景 | 残差的实际训练目标 | 它回答的问题 |
| --- | --- | --- | --- |
| A | B0：冻结背景 | R0：原 S8/V8 | 当前制品基线，保留历史不匹配 |
| B | B1：候选背景 | 原 R0 不变 | 单独替换背景是否被旧补偿抵消 |
| C | B0 | 重新训练 R(B0) | 仅修复背景匹配有多少收益 |
| D | B1 | 重新训练 R(B1) | 新背景与匹配残差的真正联合价值 |

B1 包含其曲线与整数化顺序，不能只在训练时使用未量化浮点背景。每个残差都应明确是在 D0 空间还是完整距离空间训练。若继续输出 D0 残差，最终筛选仍必须用完整 g 和实际 mandatory 合成后的整数预测；否则 Line 不足以解释的交互仍被遗漏。

交互量可写为 (Acc_D-Acc_C)-(Acc_B-Acc_A)。它不是新背景独立收益，但能揭示旧残差补偿的影响。必要时再把曲线是否匹配作为第三个因子；先完成这四格，不同时增加秩、换路由和改特征。

## 6.3 如何保持 outer-fold 隔离

对外层测试折 H，所有从标签学习的背景选择、codebook、code assignment、守卫筛选、路由阈值、特征选择和残差均不得使用 H 的评分或标签。若某些名义场由固定架构精确生成且规则允许，可以作为结构预计算使用，但一旦依据 H 的真实表现选超参数，它就参与了选择过程。

需要区分三种泛化：同架构新请求；未见完整源 pin/端口族；新架构。第一种允许利用整个固定架构的合法结构，第二种要求说明什么阶段见过该源族，第三种要重新构造资产，当前证据不支持直接外推。CatBoost 的 ordered boosting 理论不能替代项目级数据隔离；当前记录使用 Plain，外部 fold 仍必须独立组织。[R4][R5][L11]

479,232 条发布数据已标为 historical_1b_reviewed，source_pin_seen_in_training=0 只是一个隔离属性，不会自动让数据变成未观察的盲测集。应把它用于诊断和开发，把最终模型锁定后另生成的请求用于确认。[R3]

## 6.4 分层配对统计与 exact 预算

设端口对为 h，人口权重 W_h=N_h/N，每层随机无放回取 n_h 条，逐条评分为 y。估计量为 Acc_hat=Σ_h W_h mean(y_h)，设计方差为 Σ_h W_h²(1-n_h/N_h)s_h²/n_h。比较两个候选时，将 y 换成同一行的评分差，而不是把两个独立区间相减。

源 pin/family 的重采样回答的是组成敏感性或相关结构问题，与固定人口分层抽样误差不同，应分别报告。每层只有 8 条的发布子集适合复核和初步诊断，但不能因为总行数大，就宣称充分覆盖每个稀有条件或能稳定识别很小的分层收益。

扩充 exact 可用成本修正的 Neyman 分配：n_h 与 N_h σ_h/√cost_h 成正比，保留每个端口对的最低覆盖。σ_h 应来自冻结的开发诊断；最终抽样概率必须记录。主动选取边界反例服务训练，不能直接当作无偏总体评分样本。

严格 >99% 的结论应要求预先指定置信水平的一侧下界越过 99%，并说明目标总体和抽样假设；仅点估计 99.001% 不够稳妥。多个候选、连续查看和提前停止要用预登记阶段或多重比较控制。综合收益 ΔTotal=0.8ΔAcc-ΔCPU/120 的区间同时考虑精度和计时不确定性，不能拼接最优一次时间与另一次精度。

## 6.5 损失应怎样分组

至少交叉记录：近/远域、短 exact 延迟、近轴、方向、源/目标族与 lane、空间区域、边界距离、V/H/ordinary、支持掩码、首 Net 真实跳格和训练重合标识。每群同时给人口占比、群内 Acc、对总体损失的贡献和配对改善。

训练数据中 V 事件比例约 0.2613%，只能作为该训练分布的事实。即便假设新分布恰好相同，且该群原先全部得零、改后全部满分，理论最大总体改善也只有 0.2613 pp，仍小于 0.48 pp。这个极端上限说明不能只盯着 V8；实际可恢复量会更小。它不是对隐藏集事件比例的断言。[R5；本轮条件推导]

# 7 固定架构查询准备编译与完整资源账

## 7.1 依赖关系决定什么能提前计算

| 量 | 依赖 | 建议处理 |
| --- | --- | --- |
| 角色、族、lane、Net 模板、cycle 值 | 仅完整端口 | 融合为紧凑端口描述，避免同一索引反复查元数据 |
| SRB 存在性、Line 前缀、带号、局部几何 | 仅坐标 | 小型 CellMeta，启动时生成或复用已有表 |
| 首 Net 真实落点和费用 | 源坐标与首 Net 几何类 | 在已查表基础上融合所需字段，保留完整目标端口 |
| 背景左因子、中心项、部分 lane 关系 | pair/方向 | 保留共享资产，避免无收益地再建 pair 大表 |
| 名义对齐位移、context、商坐标 | 首落点、目标、名义首位移 | 一次计算并复用，区别于真实 x=t-a |
| mandatory、forced、V 事件 | 真实坐标组合 | 可分解一元部分，二元逻辑仍需在线或证明后编译 |
| cycle 覆盖、两次舍入 | 完整查询及预测链 | 精确保留，不能并入普通距离近似 |

“依赖有限域”不等于“查表一定更快”。只有当一个表项替代足够多的分支、对象访问或依赖步骤，且热工作集可控，才有价值。特别是 pair×真实位置表不能因为可枚举就被默认物化。

## 7.2 一套可检验的记录布局

```cpp
struct PortDesc {                 // 设计为 16 B，构建时 static_assert
    int16_t source_role, target_role;
    uint16_t net_code, after_net_port;
    int8_t dx, dy;
    uint8_t sf, sl, tf, tl;
    uint8_t motion_id, flags;
};
struct MotionRec {                // 8 B；字段范围须全枚举断言
    uint16_t ax, ay;              // ax=65535 表示无效
    uint16_t non_line_fee, first_line_fee;
};
struct CellMeta {                 // 16 B
    uint32_t line_x_prefix, line_y_prefix;
    uint16_t legal_motion_mask;
    uint8_t band, phase, side, exists;
    uint16_t reserved;
};
struct Prepared32 {               // 32 B，不改变 raw 的 double 类型
    uint16_t pair, context;
    uint8_t qx, qy, flags, direction;
    int32_t fee, mandatory;
    double raw;
    int32_t cycle_or_answer;
    uint32_t local_index;
};
```

坐标按 120×550 的稠密格号索引，存在性另由字段表示。16×66,000×8 B 的 MotionRec 为 8,448,000 B；CellMeta 为 1,056,000 B；496 个 PortDesc 为 7,936 B，合计 9,511,936 B。若首段费用不能放入 uint16，必须扩大字段并重新核算，不能饱和截断。

这些表可以从嵌入架构在启动时生成，因此占运行内存而不必占同等 ELF 空间。更好的实现可能复用当前 resolver 已有数据而非另复制一份；必须对照实际头文件和恢复代码确认。本报告尚未取得全部这些头文件，9.51 MB 是候选完整布局的上限计数，不是已确认的净增量。

原 Prepared596 在常见 x86-64 ABI 下按字段可推算约 56 B；实际需 sizeof 验证。新布局把 batch8 的准备区从约 448 B 降至 256 B，同时保留局部索引，可能减少重复索引计算与栈复制。变窄字段仅在全域范围验证后使用。

## 7.3 每查询依赖访存与特例

建议第一阶段并行发出两次 PortDesc 和两次 CellMeta 读取；源端口描述决定 motion 后，才读取一次 MotionRec。首落点确定后构造 d、pair/context 和 mandatory；然后发出背景左/右因子、尺度、中心和曲线目录预取。曲线正文读取依赖 code，不能把两次访问当成同一层。

这一方案的新增逻辑记录访问为：2 个端口记录、2 个坐标记录、至多 1 个 motion 记录；由于不同记录可能共享缓存行，不能把记录数等同于 cache miss 数。它也不是在原方案上额外增加这些访问，而是要替代原来分散的访问，只有替代成功才计收益。

forced 必须继续使用首落点 a 和目标 t，且对应真实 Block 的横跨与纵区间条件；V 判断与 forced 不同。背景 context 使用 d=t-a+v，树中特征 x=t-a 不能误用 d。cycle 特例仅在冻结条件满足时触发；同 pin 空路径先按合法域处理。将这些语义都变成逐字段差分测试，而不是只比最终平均 Acc。

| 项目 | 字节 | 性质 |
| --- | --- | --- |
| 冻结 exp688 ELF | 93,402,392 | 已有记录，含原资产、索引、尺度、解码器与静态库 |
| 新支持状态/修正资产上限 | 3,000,000 | 待构建的硬上限 |

这是“在旧制品上验证机制”的预算，不是新模型质量保证。新增几何表 9.51 MB、VNNI 右侧和 0.597 MB、资产恢复缓冲及 I/O 缓冲另计 RSS。以冻结 RSS 约 206 MB 为起点，可先设候选 RSS 工程门为 300 MB，逐项记录 mmap/file-backed/private/恢复峰值；它远低于 2 GB，但不能代替实测。

进一步给恢复峰值设定可执行的上限：保留原峰值 206,372,864 B；新增 ELF 页最多 3,851,968 B；上述记录表 9,511,936 B；VNNI 和表 597,120 B；新资产解压后限制为 33,554,432 B；恢复工作缓冲 8,388,608 B；新增输入输出缓冲合计 8,388,608 B；额外栈与临时状态 2,097,152 B。即使全部同时驻留、且不扣除可复用的旧空间，账面合计为 272,762,688 B，距 300,000,000 B 工程门留 27,237,312 B。这些分配限制必须在实现中落实，不能把该预算当作已经测得的 RSS。

启动恢复使用单个有界缓冲顺序解码，不在内存中同时保留多个不必要副本；共享资产只链接一次，各 ISA worker 只保存指针。所有上限都以最终静态 ELF 的实际文件大小验收，ZIP 压缩率不能抵扣 ELF 大小。[P0，§2、§4.4]

公共部分的 7,589,408 B 来自 93,402,392−56,503,992−29,308,992，是账面预留而非本轮链接节实测；不能据此原样保留会引用旧大资产的 worker。重构后仍须检查真实 ELF。该表说明一个候选表示可以被约束在容量内，不说明配方池一定装得下，也不说明 8 MB 后备模型足够准确。目录本身已占 57.5 MB；若组数远少于 256，可用 uint8 降到 28.75 MB，但若需要双层目录，必须把第二级读取成本加回。任何压缩都必须同时看读取依赖，而不只是压缩比。

## 7.6 容量分配原则

先按最终损失和访问成本比较 N512、D64、曲线目录、曲线正文与地图模型。近域 30.67 MB 左因子不应因“近域难”自动保留全部；远域目录 28.75 MB 也不应因“一字节很小”免于审查。重要的是全体请求的权重、短延迟评分敏感性，以及每个缓存行减少多少最终损失。

可在固定总容量下做少量预登记配置，计算边际 ΔAcc/Δbyte 和 ΔAcc/ΔCPU，并观察交互。不把这些比值当作全局可加的贪心最优准则。优先把释放的容量用于可部署支持条件和匹配残差，而不是未经对照地继续增加 rank。

# 8 批处理、CSV、树和完整成本预算

## 8.1 batch8 的改造顺序

保留批 8 作为第一基线。先减少 Prepared 大小和公共路径工作，再测两阶段或三阶段流水：解析/首段→发出因子与 code 预取→取得 code 并预取曲线→完成点积/树/格式化。树计算不必永远在最早阶段完成，应比较把部分独立树比较放到访存等待窗口的布局。

小批按方向或事件重排只在路由分歧/局部性收益超过开销时采用。每条保存原始位置索引，结果写回固定槽，最后按原序输出。8 条中做排序、复制大状态和多次 gather 很可能不划算；先尝试四方向的稳定小桶或只把极少数 V 请求送独立函数。

旧 Ring-8、batch16/32 的失败不能被否认。重开的充分理由是状态变小、依赖链改变、树结构和函数边界变化；若这些前提没有变化，就没有必要再重复旧实验。只比较 8 与一个有明确机制的候选，不做任意大范围批次扫描。[P0，§5.1]

## 8.2 缓存布局：减少依赖，别机械地增加对齐

远域 rank64 的 INT8 行是 64 B，适合单缓存行；把 4 B scale 填进每行再补齐到 128 B，可能让两个大因子工作集接近翻倍，得不偿失。可以试 68 B 紧凑行、分块 AoSoA 或保留独立尺度数组；每种方案都要数实际跨行、TLB 页和预取距离。

当前曲线读取是目录 code→正文，单条请求存在串行依赖。可在准备之后尽早完成 code 读取，为正文访问争取距离。不要因为采样落在 prefetch 语句就认为 prefetch 自身耗掉该比例 CPU；它也可能承接前面的停顿。

6242R 单 socket 标称 cache 为 35.75 MB，不应把双路总量视为一条线程的统一 71.5 MB 局部缓存。恢复资产大于该量，真实热点仍取决于近/远比例、端口和行序；必须通过 LLC/DTLB 指标和访问采样判断，不凭总大小推断每次都到 DRAM。[L1][P0，§8.1]

## 8.3 对称树：优先固定比较，谨慎 gather

S8 每请求选择一路的八棵深度 4 对称树，每棵每层只有一个判定，得到 4 bit 叶索引。因此它与任意非对称树遍历不同，不宜直接移植通用树加速论文的倍数。[P0，§4.3][L9][L10]

两种布局值得对比：一条查询内以树为 SIMD lane，同时计算八棵树的同层判定；或同 route 的多条查询并行计算同一阈值。前者需不同特征收集，后者需批内分组。两者均要把叶值按冻结顺序相加，不能为方便水平归约而改变浮点加法次序。

只有当前实际树所用的一元阈值值得提前编译成掩码。若把每 route 的 32 个判定全部按坐标物化，单端 66,000×16×4 B 就是 4,224,000 B；双端翻倍，且许多判定本来是二元关系。应先做依赖分析，拒绝把所有特征盲目表化。

V8 保持低频独立函数边界，避免放大的寄存器需求和指令路径污染普通请求。SIMD 宽度不是越大越好；标量比较、普通加载和小查表可能比 gather 更合适。

## 8.4 CSV 和格式化的安全优化边界

exp704 的端口直接目录已有结果；后续新机制应集中于减少重复扫描、固定格式坐标解析、输入行切片复用和整数输出。先测静态 libc 的 memchr/memcpy 实际调用和成本，再决定是否新增 SIMD 扫描。[R7]

扫描时只对完整可访问块做向量加载，跨缓冲和尾部使用显式剩余长度或复制到有界临时区。不能以“文件后面通常还有映射页”为理由越界读取。坐标解析检查数字数目、范围和溢出，端口目录仍做完整 key/长度确认。CRLF、无结尾换行、空行和空白的处理以官方契约为准，不静默扩大或缩小语言。

输出保留原端点文本、原序和精确行数。可以一次拷贝原行再追加逗号与十进制 delay，但必须明确 reader 返回的切片是否含换行/回车。尾批不足 8 条、跨缓冲的长端口名、输出短写和 fclose 失败都在验收范围内。符号与字符串处理优化不能以错误返回 -1 来换速度。

## 8.5 100 秒的互斥预算，而非叠加热点百分比

下面是用于指导设计的预算，不是对当前程序的分项实测，也不是已预测可达到的时间。

| 互斥记账项 | 100 秒方案目标 | 90 秒结构方案目标 |
| --- | --- | --- |
| 启动、恢复、建表 | 1 秒 | 1 秒 |
| 输入扫描、分隔与解析（用户态） | 24 秒 | 20 秒 |
| 首段、索引、条件准备 | 18 秒 | 12 秒 |
| 背景或结构距离求值 | 16 秒 | 18 秒 |
| 独立曲线修正 | 5 秒 | 0 秒（已并入结构表示） |
| 地图/残差计算 | 12 秒 | 10 秒 |
| 格式化、复制、输出缓冲（用户态） | 12 秒 | 12 秒 |
| read/write 等内核 CPU | 8 秒 | 8 秒 |
| 剩余工作与预算余量 | 4 秒 | 9 秒 |
| 合计 | 100 秒 | 90 秒 |

严格 <90 仍需小于最后一列总额。每项都要实测验证，尤其 1 秒启动与 8 秒系统态只是预算目标。用户态分项用互斥区域或受控消融定位，内核 CPU 单独记录；由于执行和访存重叠，单项消融节省不能直接相加。

通用路径与 6242R 路径目前无法诚实给出窄时间置信区间。可以给条件范围：若真实可优化部分占 80%–90%，该部分达到 2–3 倍，则由 220 秒得到约 88–132 秒；这个范围来自假设，不是硬件预测。通用配置是否位于高端、6242R 是否位于低端，必须由同输入实测决定，不能以 ISA 名称代替证据。

## 8.6 最少的性能测量组合

保留完整文件契约，依次构造：读写原端点并输出固定合法整数的骨架；加端点解析与所有有效性检查；加准备状态但不读预测资产；完整程序。固定输出只用于 CPU 归因，绝不作为算法成绩。另做去掉树/曲线/点积的局部消融，输出变化仅用于研究且明确标识。

在目标机同时记录 user、sys、wall、cycles、instructions、分支错误、LLC 与 DTLB 相关事件，以及实际频率/CPU 迁移。优先按 Intel Top-down 方法区分前端、错误推测、后端和有效退休；具体事件必须依据实际 PMU 支持，不能跨微架构照抄事件编码。[L12]

历史 r9 指令数约 1,488 条/请求只是参考。在 100 ns、3.1 GHz、假设 IPC=2.5 的情景下只容纳约 775 条指令；这提示工作量削减的重要性，但不是严格硬件下界。IPC、uop、频率和内存停顿会随代码变化。

历史输入输出共约 75.33 GB，100 秒相当于约 0.753 GB/CPU 秒的字节处理需求。它不是磁盘 wall 吞吐要求；I/O 等待不计同样的 CPU。必须固定页缓存与存储条件并报告 wall，不用高缓存命中时的 CPU 替代全流程可用性。

# 9 通用 CPU 分派、VNNI 与数值一致性

## 9.1 选择整条 worker，而不是每条查询检测

建议 main 在通用代码中检测一次能力，完成共享资产初始化，再选择整条 worker。worker 内部让 dot、特征和批处理按该配置内联。批次级函数指针适合共享大部分流程且内核足够重的情况，但这里每条请求很短，分派和跨函数优化损失需要计量。逐请求检测与逐 dot 函数指针不作为默认方案。

```cpp
Capabilities caps = detect_in_generic_code();
CpuIdentity id = read_vendor_family_model_brand();
Worker fn = worker_sse2;
if (validated_6242r_profile(id) && caps.meets(profile.required_isa))
    fn = profile.worker;            // 可能混合 scalar/AVX2/EVEX256
else if (validated_portable_avx2 && caps.avx2_usable)
    fn = worker_avx2;
initialize_shared_assets_once();
return fn(input_path, output_path, shared_assets);
```

其它 Intel/AMD 上并非禁用加速，而是使用已经验收的通用 ISA 配置；新型号可运行不等于已经验证它最快。未知型号、被虚拟化屏蔽的能力或识别不完整时回落到安全配置。功能等价的 worker 可采用不同布局，但恢复后的公共大资产不应重复。

## 9.2 CPU 身份与指令安全分开

vendor、family/model/stepping、brand string 用于选择调优档；CPUID 能力与 OS 状态用于保证指令可执行。Family 6、Model 85、Stepping 7 不能独自唯一确定 6242R SKU。brand string 应通过扩展叶 0x80000002–0x80000004 取得并规范化匹配，先检查最大扩展叶；不通过普通子串误匹配其他型号。

下表为本报告建议内核所需的关键检查，不是整个 -march=cascadelake 的完整能力集合。[L2–L4]

| 检查 | 位置/掩码 | 用途 |
| --- | --- | --- |
| SSE2 | CPUID.1:EDX bit26 | x86-64 基础路径 |
| XSAVE、OSXSAVE、AVX | CPUID.1:ECX bit26、27、28 | 调用 XGETBV 与 AVX 状态前提 |
| XMM/YMM 状态 | XGETBV(0) & 0x06 == 0x06 | AVX/AVX2 可用 |
| AVX2 | CPUID.7.0:EBX bit5 | AVX2 worker |
| AVX512F/BW/VL | CPUID.7.0:EBX bit16/30/31 | 512 基础、字节处理和 EVEX 短向量 |
| AVX512VNNI | CPUID.7.0:ECX bit11 | EVEX VPDPBUSD |
| opmask 和全部 ZMM 状态 | XGETBV(0) & 0xE6 == 0xE6 | 包括 256 位 EVEX VNNI 的状态要求 |
| AVX512DQ | CPUID.7.0:EBX bit17 | 仅在实际生成的内核需要时加入 |
| AVX-VNNI | CPUID.7.1:EAX bit4 | VEX VNNI，必须与 EVEX 能力分开 |

执行 CPUID 子叶前检查叶范围：先确认最大基本叶≥7，再用 CPUID.7.0:EAX 确认是否存在子叶 1；扩展 brand 叶也先检查最大扩展叶。执行 XGETBV 前检查 OSXSAVE 等前提。GCC 11.4 的 cpuinfo.h 实现已经用 XGETBV 的 0x06/0xE6 掩码筛选 AVX 和 AVX-512 特征，然后才设置相应 __builtin_cpu_supports 标志，因此“GCC 内建只看硬件、不管 OS”在这里不成立。可在 main 显式调用 __builtin_cpu_init，并以同一实现的源代码与屏蔽测试作为证据。[L3，get_available_features]

手工检测适合审计和特征屏蔽测试，不应维护一份与内建实现长期分叉的宽泛 CPU 数据库。若使用 IFUNC 在构造器之前运行，初始化顺序另有要求；本项目使用 main 内分派更简单。[L2]

## 9.3 编译、链接和启动隔离

新架构应先把共享初始化、Architecture 对象、嵌入资产与动态构造移至通用单元，再构建多个 worker。不能直接多次编译现有 worker 就假定资产不会重复；头文件定义的数组需要改为 extern 声明，由一个资产单元提供定义。

以下是建议的新模块构建骨架，不是可原样替换当前 build.py 的完整命令：

```sh
COMMON='-std=c++17 -O3 -fno-rtti -fno-fast-math -ffp-contract=off -fno-lto'
g++ $COMMON -march=x86-64 -mtune=generic -c entry_generic.cpp
g++ $COMMON -march=x86-64 -mtune=generic -c shared_assets.cpp
g++ $COMMON -march=x86-64 -mtune=generic -c worker_sse2.cpp
g++ $COMMON -march=x86-64 -mavx2 -mtune=generic -c worker_avx2.cpp
g++ $COMMON -march=x86-64 -mavx2 -mavx512f -mavx512bw \
    -mavx512vl -mavx512vnni -mtune=cascadelake -c worker_vnni.cpp
# architecture/JSON 所需异常支持保留；仅适合的 worker 使用 -fno-exceptions。
# 链接时复用冻结静态运行库与单份资产，并再次检查文件大小。
```

-mtune 调整调度偏好，不等于 -march 扩大指令集。若改用 -march=cascadelake，就同时允许许多额外 ISA，如 BMI/BMI2、FMA、AES 等，单独检测 AVX512VNNI 不够。优先使用最小特征开关；确需完整架构目标时，维护并验证其完整 required_isa 集合。[L4]

扩展单元禁止动态全局构造；共享对象的构造、析构与静态库启动路径均须审计。先关闭跨单元 LTO，禁止高 ISA 代码被带入分派前路径。函数 target 属性可用于内核实验，但不替代整体启动审计。[L14]

```sh
readelf -lW estimate                 # 不得有动态 INTERP
readelf -dW estimate                 # 不得依赖外部 NEEDED 库
readelf -SW worker_vnni.o            # 检查 .init_array 等段
nm -C worker_vnni.o                  # 检查 _GLOBAL__sub_I 与动态初始化
objdump -drwC -Mintel estimate       # 检查入口、构造路径及目标内核
stat -c '%s' estimate               # 必须严格 < 100000000
```

仅 grep 某个符号不存在不是完整证明；还需检查启动调用图、静态库配置和特征屏蔽环境。历史 exp608 的构造器事故应成为固定回归用例，而不是一次性修补。[P0，§8.2]

## 9.4 signed INT8×signed INT8 的等价 VNNI 变换

设 a_i、b_i∈[-128,127]，令 u_i=a_i+128，其字节实现为 a XOR 0x80。则：

```text
sum(a_i*b_i) = sum(u_i*b_i) - 128*sum(b_i).
```

这恰好把 signed×signed 转成 VPDPBUSD 所需的 unsigned×signed，再补偿。使用不带 dword 饱和的 dpbusd；当前长度的中间值本来不会溢出。对于每组 64 维：

| 量 | 最小值 | 最大值 |
| --- | --- | --- |
| Σ b_i | -8,192 | 8,128 |
| Σ u_i b_i | -2,088,960 | 2,072,640 |
| 128Σ b_i | -1,048,576 | 1,040,384 |
| Σ a_i b_i | -1,040,384 | 1,048,576 |

单个 dword 的四乘积也仅在 [-130,560,129,540]，横向归约及补偿都在 int32 范围。采用 int16 存右因子每个 64 维块的 Σb，近域 4,800×8 块、远域 260,160 块，共 597,120 B。启动生成即可，不必压缩后再嵌入。近域八组仍分别点积、分别 scale、按冻结顺序累加。

512 位内核一次加载 64 字节；256 位 EVEX 内核两次加载 32 字节、合并 dword 和，再做同一补偿。intrinsic 分别是 _mm512_dpbusd_epi32 和 _mm256_dpbusd_epi32，后者需要 AVX512VL。它与 VEX AVX-VNNI 的识别和编译选项不同；6242R 专用路径应使用其已知的 AVX512_VNNI/EVEX 能力，不把 -mavxvnni 当作同义词。GCC 11.4 文档列出两种独立开关；本轮没有取得该版本 VEX intrinsic 头文件，因此不把 VEX 支路写入已验证实现。[P0，§8.3 Q3.4][L4]

## 9.5 为什么直接使用 VPMADDUBSW 不安全

u=255、b=127 时两个乘积相加为 64,770，超过 signed16 上界；b=-128 时为 -65,280，低于下界。VPMADDUBSW 会在 16 位中间结果饱和，之后转为 int32 也不能恢复。

安全 AVX2 基线仍是符号扩展到 int16 后 PMADDWD 再用 int32 累加，与已读代码一致。另一种可证明的方案把 u 拆成低 7 位与高位 0/128，各自做成对乘加：低部分在 [-32,512,32,258]，高部分在 [-32,768,32,512]，都可放入 int16；必须分别提升到 int32 后再相加，不能先在 int16 相加。它有额外工作，不默认优于原 AVX2。[R9；本轮范围推导]

## 9.6 本轮真正执行的正确性测试

配套 int8_equivalence.cpp 在本地运行了 SSE2、AVX2、EVEX VNNI256、VNNI512 四个内核。每个内核通过 165,600 组点积案例：全部 65,536 种常量字节配对、100,000 组固定种子随机向量以及 64 组交替极值；覆盖不同非对齐起点。观察到的点积极值与上表一致。

另有每个内核 4,096 组八块 scale 合成测试，按原 double 乘法与累加次序比较位模式，全部通过。89,018 个小范围合成区间投影案例验证了数学性质的实现。这些是本轮实测，不包含真实模型因子、半整数邻域、完整两次舍入、cycle 或完整 CSV，所以没有将其升级为生产等价声明。

## 9.7 完整数值验收与 6242R 持续性能

应记录每条调试查询的首落点、费用、pair/context/local、各组整数 dot、各组尺度、response、第一次舍入、cycle、curve、tree raw、第二次舍入及 final。差异先定位到最早不同中间量，而非只看最后 SHA。

测试覆盖 INT8 极值、正负抵消、scale 极端、接近 k+0.5 的两次舍入、零延迟、合法与非法同 pin、不可达、尾批、跨缓冲及最大坐标。保持 -fno-fast-math、-ffp-contract=off，核对 MXCSR 的舍入/FTZ/DAZ；不能为了基准而改变浮点环境后声称等价。

目标机分别测标量/AVX2、EVEX256 和 512 的完整 100M，记录持续频率和热态稳定性。宽向量可能改变频率、寄存器压力和前端供给；短向量 EVEX 也不能仅因使用 YMM 就假设没有相关频率影响。最终用完整 worker 的结果选配置，不使用孤立 dot 的倍数推算全程序速度。[L1][P0，§8.3]

## 9.8 NUMA、SMT 与无特权环境

初始化与查询均由同一线程完成，可利用首次触碰提高局部性，但线程迁移、cpuset 和其他负载不受程序完全控制。程序可以读取允许 CPU 集合并尝试在其中绑定一个 CPU；若系统不允许，应继续安全运行并记录，不依赖固定编号或外部 numactl。不要在算法内写死历史 taskset -c 8。

实验时明确 CPU、NUMA 节点、SMT 同胞是否空闲、内存放置、页缓存与存储。单线程并不免疫同胞争用。若要启动校准，使用固定内置工作负载、固定次数和成本上限，所有候选必须数值等价；但短校准的冷热偏差可能误导。第一版建议用离线验证的调优档，不把自动校准引入关键路径。

# 10 验收矩阵与只做三个高价值假设的研究顺序

## 10.1 先建立一个统一制品账本

每个候选保存：完整 Git SHA、dirty diff、编译器与静态库身份、编译宏、每个模型/资产 SHA、ELF 大小与 SHA、实际分派路径、输入 SHA/唯一性、完整输出 SHA/契约、CPU user/sys/wall、RSS、线程数、评分样本身份与权重。历史 6242R 的 220 秒摘要补入账本，但在身份未对齐前不与 r9 配对统计混算。

构建、资产生成、exact、抽样与输出审计成本单列；在线程序所有初始化、恢复、读写成本计入。评分从该次完整运行的输出提取，不能重新调用另一个预测入口代替它。完整 1B 只跑一次时只能报告单次结果；最终五次输出一致性和平均 CPU 需要真正的五次记录。

## 10.2 ISA 与功能验收矩阵

| 环境 | 必须验证 | 不能据此宣称 |
| --- | --- | --- |
| 仅 SSE2 的真实或特征屏蔽环境 | 启动、构造器、恢复、尾批、输出；无非法指令 | 仿真下的目标机速度 |
| Intel AVX2 实机 | 通用 AVX2 worker 与 SSE2 输出逐字节一致 | 所有 Intel 型号都更快 |
| AMD AVX2 实机 | 同上，附真实完整处理计时 | Intel/AMD 缓存与频率行为相同 |
| AVX-512 无 VNNI 环境 | 不能误入 VNNI worker，安全回退 | 看到 AVX512F 即支持全部 AVX-512 |
| VNNI 与 OS 状态齐备环境 | 256/512 整数与完整数值链、初始化隔离 | 微内核加速等于完整程序加速 |

调试版本允许强制指定一个已验证可执行的 worker，不能跳过能力安全门。发布版保持 -in/-out 契约，不要求评测方提供额外参数或环境变量。强制测试、性能采样和输出审计程序不进入比赛在线依赖。

## 10.3 假设一：主要时间来自可删除的准备工作与访问依赖

决定作用：如果解析/准备/输出已经接近总预算，就不能指望单靠数学模型替换达标。最小机制原型是第 8.6 节三个骨架与完整程序，以及 PortDesc/Prepared32 的等价版本，先不改任何预测函数。

数据与测量：使用新登记的非重复完整 100M，在真实 6242R 上同机串行、固定预热、交错原版/候选，报告配对平均和区间。字段级等价、完整输出 SHA、单线程与内存先过门，才接受时间收益。随后把获胜等价版本接入阶段制品，执行完整 1B。

建议的立项门是：关键分项能被明确归因，且候选完整 100M 的收益下界为正；工程性小改可用至少 0.5 秒/100M 的点估计作为初始实际收益门。该门是本报告建议，可按项目成本预登记调整，不是已有实测。收益不到此量级不代表毫无价值，但不应让连续微调挤占结构研究。

停止/转向：若重排表后依赖 miss 或前端压力抵消节省，回退布局；若大部分剩余成本仍在公共准备，应扩大工作量削减而非继续优化 dot。骨架时间只是当前实现框架的经验底线，不是所有可能实现的物理下界。

## 10.4 假设二：低成本支持状态能解释足够多的最终损失

决定作用：检验“真实路径支持”是否能从 oracle 机制变成可泛化预测。最小原型保留 exp688 背景，生成局部支持状态和最多三个候选支持位，执行第 6.2 节的四格对照。另做合法上界/认证下界投影，以区分安全纠正与纯学习增益。

先在历史 exp705 和发布样本诊断、发现反例，再锁定特征与候选，在新 source-pin/空间留出数据及非重复 100M 上测最终 Acc。主动采样的边界数据只用于训练；总体评分采用记录概率的独立样本。精度标签预算由期望检测的 pp 和分层方差决定，不预设“几十条足够”。

建议机制门：最终 OOF 改善达到至少 0.05 pp，或证明了一个更便宜表示能够达到相同精度；计时与精度联合收益的下界为正。以综合分换算，0.05 pp 只允许约 4.8 秒/1B 的额外 CPU，且不能破坏最终 100 秒硬目标。这里的 0.05 是探索门，不是交付门，更不是声称能填满 0.48 pp。

停止/转向：若加入支持状态只有训练收益、离开四位置就消失，或收益完全由更大的模型容量解释，停止扩大该状态。若合法候选只能纠正过估计而主要损失来自低估计，则转向更紧下界或匹配残差；不能把上界候选覆盖率当作全部误差的可恢复比例。

## 10.5 假设三：结构模板能省掉整个背景/残差阶段

决定作用：验证 2.2–2.44 倍整体速度是否需要且能够通过架构替换取得。最小原型只实现一个有代表性的中远域、两个方向组合和完整端口保持的模板编译器；禁止先写一个覆盖全部功能但无法认证的大系统。

该局部原型必须输出：可编译模板比例、真实合法覆盖、完整 Line 费用误差、L=U 率、评分损失捕获比例、最坏守卫数、候选数、目录和配方字节。先证明正确与可压缩，再扩大所有角色域和方向；原型小域的结果不能替代最终全端口 100M/1B。

决定是否扩大的关键是同时满足两条：结构主路径比被替换路径真正便宜；剩余后备模型可以在总容量内达到目标精度。若仍需要原 N512/D64/曲线全部资产作为后备，7.5 节预算不成立，不能把新旧两套预算分别报小于 100 MB 后认为可以共存。

速度的正确核算是：原成本 B+C_old，新成本 B+C_gate+αC_fast+(1-α)C_old，节省 α(C_old-C_fast)-C_gate。α 是真正绕过旧路径的比例，不是 oracle 覆盖率。精度则看被捕获的加权损失，而不只看 α。两者往往不是同一群请求。

停止条件：守卫/配方池超上限且无法共享；最坏困难分支使完整程序时间失控；独立数据的紧凑后备模型无法恢复精度。即使高上限架构失败，仍可保留通过验收的支持特征、认证上界以及准备编译成果。

## 10.6 最终交付门

在未参与选择的新非重复 100M 上通过合同、资源、精度和完整计时门后，及时形成唯一阶段制品，完成全角色域、完整请求对非重复 1B。报告最终 CPU 与 Acc 必须来自同一制品、同一次输出；若 Acc 来自抽样，写明样本框、权重、区间与检验总体。

最终五次测试检查所有输出 SHA 相同，平均 CPU 满足目标，任一次不超过官方时长与内存限制。普通、近轴、边界、事件集中和不利行序都应作为附加压力分布；其中任何一个不是官方隐藏分布的替身。通过同架构新请求测试，也不自动获得新架构泛化结论。[P0，§2.3]

# 11 可能忽略的问题与历史结论的正确使用

## 11.1 通道之间的抵消需要实验，不宜叙事归因

除四格对照外，可在固定请求上比较背景、地图、Line 的单独与联合 oracle 替换，计算交互项，并保留原符号误差。一个通道的 MAE 降低，可能恰好移除它对另一通道的补偿。固定名义键位置差分则看不到同键共同偏差，需再加入跨名义键、同真实局部支持状态的对照。两类实验互补，不能互相替代。

## 11.2 “费用低”与“路径存在”是不同变量

同一保存词在新位置可以没有费用变化，却落到错误终点；同一最优费用也可能对应多个支持集合不同的词。Block 收费、V/H 事件、边界距离分别描述特定现象，不是路径支持的充分统计量。应比较平局代表、多位置分层、局部守卫与完整词重放，分离“选词偶然性”和“可重复的几何限制”。

exp705 终点偏移均为 ±14 是这组见证的结果，不是全图所有路径偏移的定理。OTHER 类和真实重放验证不可省略。对于未来构造的新模板，必须重新认证净位移。

## 11.3 换矩阵展开轴可以研究，但不是免费的突破

把 pair、方向、位移、位置条件重新展开，或采用条件秩/低秩专家，可能使条件函数更简单；也可能把少量样本分散到更多参数。应先比较条件状态下的经验奇异值/残差风险与最终评分，而非只看全局名义 SSE。

增加 4 个条件后若直接复制 59,904×480 的目录，就从 28.75 MB 变为 115.02 MB，单这一项已越界。因此条件表示必须共享主体，或用小的门控、修正字典、少量索引覆盖稀疏例外。以更复杂目录换来同样多的串行读取，也可能在 CPU 上倒退。

## 11.4 困难域路由必须能在线判断

可用候选支持掩码、认证区间宽度、近轴/边界条件、模型分歧等作为部署信号；不能用 exact 误差、最优词 S 或真实最优路径事件触发纠正。路由自身的查询、分支与误判成本计入总预算。

若平均触发率为 h、纠正额外成本为 c ns，则平均代价约为 hc ns，加上所有请求的门控成本。隐藏分布可能改变 h，因此需要全困难域压力测试和固定工作上限。对于超预算请求，使用确定性后备预测而非扩大搜索；精度损失按人口分组报告。

## 11.5 只重开两个历史失败方向

第一项是小批流水/Ring 类方案，仅当 Prepared 缩小、准备工作削减和 code→curve 依赖安排发生改变时重测。原失败结论继续适用于原实现，不据此宣称新配置一定有效。

第二项是离散响应目录，前提从“低码数直接表示完整响应”改变为“共享连续主体或路径模板，加支持条件和受控残差”。exp687/689 排除的是原表示与训练配置；新方案若只是增加 code 数或换种聚类，没有改变主要前提，就不值得重新打开。[P0，§5.1]

不把纯 D96/双 64 加宽列入优先重开项：它们已有名义改善转化有限的证据，先做匹配残差和最终评分目标更有信息价值。这里不是永久否定更高秩，而是研究顺序判断。

## 11.6 哪些结论能迁移，哪些不能

可迁移：真实图语义、完整端口约束、路径合法上界、势函数下界、整数范围、输出协议、数据隔离原则。需按制品重新验证：量化、舍入、编译器、静态库、代码生成与数值一致性。必须在目标实机测量：频率、缓存/TLB、prefetch、批次、AVX256/512 与 NUMA 的速度收益。

对事先未知请求，经验 Acc 是关于某个测试总体的统计结论，不是任意分布的逐点保证。若隐藏输入集中在模型的低分群，总体可能下降。只有逐请求误差证书或全域误差界，才能提供相应的分布无关保证；当前模型和本报告尚无覆盖全部合法请求的此类证书。

# 12 最终建议与当前不能下的结论

第一优先级是把 6242R 的 220 秒拆成可复核的互斥成本，并建立不改变函数的准备编译基线。第二优先级是支持状态与背景匹配残差的独立收益，特别关注 ordinary、短延迟和近轴，而不是只增加 V8。第三优先级才是有守卫模板的结构主模型，并用可证界实现安全纠正或 exact 快路径。

对 99%/100 秒，现有架构不能被判死，但继续只做点积优化、提高 rank 和旧分布重训，不足以形成可信达标计划。对 99.1%/90 秒，我更看好能够省掉整个旧表示阶段的结构编译方案，而不是在原系统后追加更多模型。

本报告没有算出真实新增方案的 Acc，没有取得目标机上的新计时，也没有证明少量模板足以覆盖整个架构。这三个未知量应由第 10 章实验直接回答。与此同时，区间投影性质、势函数可行性条件、VNNI 整数变换与容量计数已经足以约束实验，避免再把不可部署 oracle、过大的全表或孤立内核倍数当作研究结论。
