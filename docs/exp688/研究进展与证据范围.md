## 已改变正式实现的几项结果

exp640 至 exp644 将原 R8 修正改为对称 S8，每个请求按固定树层计算。
同轮六对 100M 平均节省 2.641978 秒，配对 Acc 下降 0.015695545 pp，
完整 1B 为 225.515516 秒。它提供了较大的 CPU 收益，同时留下精度恢复需求。

exp650 至 exp655 加入端口对、方向和余类条件下的二维共享距离曲线。
字节表示保持 int16 曲线的预测函数，同轮 100M 节省 0.433186667 秒。
新 100M 的配对精度提高 0.191319140 pp，完整 1B 为 243.434110 秒。
早期 1B 使用 239,616 条 exact；后来的扩大样本评分保存在 exp683。
跨版本比较应读取同一批样本的配对统计。

exp677 至 exp688 把 H/V 地图事件分开，最终只启用 V8。
exp686 将低频专家放入独立函数，较原 V8 省 0.441876500 秒/100M。
exp688 的扩大评分确认 V 域收益，其他事件域的输出保持。
这些收益同时依赖事件划分、树前缀和公共查询代码的布局。

## exp705 带来的条件见证

该实验覆盖 59,904 个完整端口对。每个 pair 固定首 Net 对齐的名义位移，
选择四个不同真实位置，共 239,616 条请求。59,904 条旧锚点逐项核验，
新增 179,712 条无 Line 图的 exact 标签，求解 CPU 629.036221 秒。
每条最优端口词均独立重放，并核对落点、费用守恒和移植上界。

四位置中，32,781 个 pair 的扣首 Net 费用发生变化；
11,255 个 pair 的范围至少为 20 ps。把较便宜位置的词移向较贵位置，
共有 127,013 次见证，其中 24,000 次出界，37,087 次落入缺格，
65,601 次终点改变，325 次完整合法且到达同终点但费用改变。

这说明固定端口词能否在真实位置到达指定目标，是值得研究的条件。
即使两处各自最优路径的后续 Block 费用都为零，词的移植仍可能改变落点。
路径本身来自离线 exact，相关见证只支持研究可部署条件状态这一假设。
它们还没有建立未知请求上的精度或 CPU 收益。

详见 `../../validation/results/exp705/report.json`、`groups.json`、
`trace.run.json` 和 `witness-groups.json`。
实验原文保留事先登记；本节补充已经产生的结果。

## 本轮希望外部分析解决的问题

精度方面，需要找到对真实路径合法性、落点和端口支持有解释力的小状态，
并核对它与当前背景误差、地图修正之间的补偿关系。
CPU 方面，需要从查询准备、解析和依赖访存中削减足够工作量。
本轮咨询目标为总体 Acc 严格大于 99%、非重复 1B CPU 约 100 秒，
后续目标为 Acc >99.1%、CPU <90 秒。约 100 秒要求相对当前 243.3 秒
下降约 58.9%，单个小优化的收益有明确上限。详细提问见同目录
`exp688-外部AI提问书.md`，其中加入了通用 x86-64 与 Xeon Gold 6242R
自动选择实现的设计问题。2026-10-25 的配置采集将 r9 识别为 Xeon Gold 6226R；
截图目标为 6242R，目标硬件上的成绩仍待实测，见 [机器证据](../../benchmark/README.md)。

实验只用非重复 100M、1B。100M 通过预登记收益及资源门后，
及时接入阶段版并跑完整全端口非重复 1B。最终精度与 CPU 在同一制品、
同次完整运行输出上联合记录，未知平台表现保留实测边界。
