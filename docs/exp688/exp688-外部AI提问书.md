## 问题和硬约束

任务是在固定 FPGA SRB 有向互连图上，输入完整 From/To pin，
估计真实最短路径延时。状态包括坐标和端口，内部 Arc、跨格 Net、
缺失格点、Block 跳格及 Line 收费共同决定路径。
首 Net 由源端口决定，真实落点会影响后续位移。
图语义请结合 `source/src/architecture.cpp`、五份 `source/arch/` JSON
与 `docs/task/` 的题目原文核对。

| 条件 | 本轮采用的要求 |
| --- | --- |
| 调用接口 | `estimate -in <request.csv> -out <result.csv>` |
| 交付 | 单个静态、自包含 ELF，架构、模型和全部必要数据嵌入程序 |
| 文件大小 | ELF 严格小于 100,000,000 B；此条来自赛题后续补充 |
| 在线资源 | 单线程，峰值 RSS 不超过 2,000,000,000 B |
| 时间 | 完整 1B 每次不超过 3,600 秒；平均 CPU 超过 1,800 秒时，时间项得零分 |
| 确定性 | 五次运行结果完全一致 |
| 输出 | `From,To,delay`，保留端点原文和顺序，整数 delay、恰好三字段、精确行数与 EOF |
| 请求 | 事先未知且完整请求对非重复；端口和几何结构可以共享 |
| 硬件 | 正式通用路径为 x86-64/SSE2，平台 CPU 型号和其他扩展指令仍未知 |
| 离线工作 | 预计算、训练与 exact 标签生成成本单列，最终资产和在线计算满足交付约束 |

V0.3 PDF 没有写后续追加的 ELF 容量限制。当前评测镜像无架构或模型文件，
旁置资产的保留方式也未验证，本轮请按上述单文件要求设计。

对正 exact 延迟 `g`，单点分为 `1 - tanh(4 * abs(pred - g) / g)`，
总体 Acc 为其平均值乘 100。零延迟按现有评分器的特殊值规则单独检查。
这里使用连续得分，精确命中率、MAE 和平方误差各自另报。
时间项为正且一致性相同时，项目使用以下代价换算，其中精度差以百分点计，
CPU 差为一次完整 1B 的秒数。

```text
delta_score = 0.8 * delta_accuracy - delta_CPU / 120
extra_CPU_budget = 96 * delta_accuracy
```

请用同次完整输出联合评价精度和 CPU。小规模外推只能用于预算，
阶段结论分别依赖完整 100M 和 1B。

## 当前实现中需要先理解的关系

查询先解析端口与坐标，按真实首 Net 落点对齐名义位移。
近域使用 N512，远域使用按方向分组的 INT8 D64 背景。
远域还按完整端口对、方向和余类读取字节曲线补偿。
随后组合首段费用、必过 Line 项及 S8 或 V8 地图修正，按冻结顺序舍入为整数。

因此背景、曲线和树修正之间可能存在误差补偿。
已有双 64 背景在名义域改善后，真实 OOF 只提高约 0.01035 pp，
同时增加约 16.3 MB 左侧工作集。新表示需要在最终评分、真实位置条件
和完整查询成本中重新检验。

当前 CPU 画像中，查询准备和解析占比较高，树和 `dot64` 分别约占
用户态样本的 9.85% 与 3.58%。内联项目有包含关系，采样归属也受访存停顿影响。
请从实际代码和指令证据估计可消除的工作量。

exp705 固定完整端口对及对齐名义位移，换真实位置后仍观察到 exact 差异。
跨位置移植最优端口词时，出界、缺格和终点改变都提供了见证。
这支持继续研究路径可实现条件，但路径 oracle 尚无在线使用条件。
