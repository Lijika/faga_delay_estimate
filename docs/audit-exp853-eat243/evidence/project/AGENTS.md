# EDA2026 工作约定

FPGA SRB 布局布线延时估算（赛题一）。生产入口为 `./estimate`，源码用
`sh scripts/build.sh` 构建，交付包用 `sh scripts/build_submission.sh` 构建。
正式版本身份与成绩见 `RESULTS.md` 和冻结记录，设计见 `DESIGN.md`；当前源码构建产物需重新核验。

## 当前研究目标与请求范围（2026-10-27 用户更新）

研究目标以用户 goal 为准：未知、非重复、有效端口全覆盖的 **1B 完整程序 CPU 约100 s，越快越好**，
同时总体 Acc 严格大于99%且留有余量，满足全部赛题约束。阶段进展与最终目标分别记录。
路线B为研究主线；候选须能在官方未知请求上复现收益，增益明确后及时进行100M、1B实测。

生成输入、解释端口覆盖或接入候选前，阅读
`/mnt/d/obsidian_work/竞赛/EDA2026/赛题测试集/`中的`补充信息.md`、`qa.md`和生成规则。
主请求端点排除I*，保证有向可达、From与To不同并打乱顺序。按真实图角色使用
U-role的208个非I源与288个目标，覆盖59,904种角色端口对；U-output作为其子域单列。
I*、不可达和自查询作为接口诊断单列。exp757/758的全496×496命名域结果仅支持扩展域诊断，
其新增覆盖收益不计入比赛主分布的接入收益。当前目标和范围优先于历史实验中的旧目标表述。

## 当前测试阶梯（2026-10-31 用户更新）

### 1B CPU 前置筛选（2026-11-03 用户更新，优先执行）

候选进入完整1B前，先依据完整1M、100M的完整程序CPU估计1B成本。
预计CPU严格大于200秒时，记录`screened_out_cpu`并跳过1B；预计不超过200秒且
满足原有收益条件的候选继续1B验证。本规则优先于本文及历史记录中
“正收益立即1B”“直接两次1B”的要求，适用于EAT、SkyDiscover与手工队列。

筛选记录保留ELF、输入、评估器及硬件身份、user/sys CPU、初始化成本、外推方法
和适用边界。优先采用r9 CPU8同一候选的完整1M/100M结果，分开固定初始化与
随请求数增长的成本；AMD短测试及完整1M直接乘1000只作初步诊断。
缺少匹配证据时先补小规模测量，最少仍为完整1M；身份变化后重新筛选。
外推值用于准入，综合成绩仍来自实测。保留超限候选的源码和机制证据，允许后续
工程优化后重新筛选。历史实测结果保持原身份。

完整程序测试默认使用非重复 **100M → 1B**。出现预登记的正算法收益候选时，立即冻结该源码并安排完整非重复1B，
包括只在 split 或子域上观察到的正收益；不等待100M阶梯完成或总体Acc达到99%。1B须与当前阶段正式版按同一输入、
评估器和硬件比较，并同时检查同次Acc/CPU、输出契约、SHA、单线程、RSS、总时长和一致性。
1B确认预登记的正综合收益且候选通过已测赛题约束后，立即接入阶段正式源码与版本包；其余未完成的官方平台、
五次运行等验收单独标注并继续安排。收益未确认的候选保留为研究证据，明确其适用范围，不作为完整程序增益。
已有1M、10M证据按身份复用；最终Acc严格大于99%及其他赛题约束继续有效。

### 算法原型与小实验的最小测试规模（2026-11-01 用户更新）

后续算法原型和任何小规模算法实验，测试数据至少包含 **1,000,000 条实际参与测试的请求**，
可以直接使用赛题方提供的完整1M数据。不得使用小于1M的数据进行算法实验，
也不得以加载1M文件后只测试少量行、重复小样本或子集成绩代替完整1M测试。
分组与消融分析附属于完整测试，同时报告总体结果和各组样本数。已观察数据按开发数据记录。
该下限优先于历史小样本原型方案；PySR至少10M唯一训练请求、正收益候选立即安排完整1B、
阶段正式接入及交付验收的既有要求继续有效。

赛题内容可先读 `doc/EDA2026赛题一-MinerU-flash.md`。关键规则与解析疑点回查
`doc/赛题一：面向超大规模FPGA的布局布线延时估算算法（紫光同创） (1).pdf`。

## 平台提交硬约束

交付物必须同时满足以下全部条件；违反任一条即无效、得0分或构建失败，不得以「后续再验」绕过。
来源标注：**赛题**=官方规则明文（含 PDF 之后的补充）；**平台**=官方参考包与评测镜像实测确认；
**用户**=用户设定的交付约束。

- **单个可执行文件**〔赛题 5.5〕：调用方式固定为 `estimate -in <request.csv> -out <result.csv>`，
  不得要求位置参数、环境变量或额外输入路径。
- **完全自包含**〔平台〕：评测镜像 `subm/fpga-ziguang-latest.tar` 的全部层只创建
  `/app/{program,ingested_program,input,intermediate,output,ans,work}/`，镜像内没有任何 SRB JSON，
  也没有任何数据文件；官方参考包 `subm/reference_submission/submission.zip` 只含 `bin/` 与
  `bin/estimate`。五个架构 JSON 与全部预计算表必须嵌入 ELF。
- **静态链接**〔平台〕：评测镜像为 Ubuntu 22.04 / glibc 2.35 / GLIBCXX_3.4.30，本机为 glibc 2.39 /
  GLIBCXX_3.4.32，必须 `-static`，`ldd` 输出不得出现 `=>`。
- **静态 ELF 严格小于 100,000,000 B**〔赛题，后续补充〕：十进制 100 MB，是赛题后续追加的硬约束。
  仓库内的赛题 PDF 为 V0.3（2026-08-31），**不含**这一条，回查 PDF 时不要据此认为它不存在。
  由 `scripts/build_submission.sh` 在编译后立即检查，超限即 `exit 1`。
  exp112 记录把它写成「用户明确要求利用100MB交付容量」，那是当时经用户转达的表述，不是自定约束。
- **单线程**〔赛题 5.2〕。
- **峰值内存 ≤ 2 GB**〔赛题 5.2〕：超出即无效并被强制终止。
- **完整测试集总时长 ≤ 1 小时**〔赛题 5.2〕：超时即无效；超过 30 分钟 `time_score` 得 0 分。
  测试集为 10 亿对请求〔赛题 5.4〕。
- **五次运行结果完全一致**〔赛题 5.3〕：不一致则 `consistency_score` = 0。
- **输出契约**〔平台〕：官方答案文件表头为 `From,To,delay`（小写 d，见
  `doc/eda比赛文件/data/delay_estimate_ans.csv`）；输出须精确行数、端点原文与顺序、恰好 3 字段、
  整数 delay、精确 EOF。
- **最终交付总体 acc 严格大于 99%**〔用户〕。

**一条开放项（未验）**：理论上可把预计算表放进 zip 与 `bin/estimate` 并列，平台会把它解到
`/app/ingested_program/`。但官方参考明确只放 `bin/`，没有任何文字说明额外文件会被保留，提交程序的
工作目录也未知，项目内从未测过。若日后平台实测证明额外文件能存活，容量约束会显著放宽；在此之前
一律按单文件静态执行，不得据此放宽设计。

打包前的本地工程门槛（完整 1M 输出契约、单线程、峰值 RSS ≤ 2,000,000,000 B、每次运行 ≤ 3,600 s、
完整 SHA、多次运行一致）是工程门槛，与上述平台限制分别记录，见下节。

## 研究与实验

以下约定用于算法实验、候选选型和正式版本更新。

- 开始研究时确认正式入口、平台交付版与源码候选，冻结比较基线，记录提交、构建参数、二进制、模型、架构与输入身份。检查源码和原始结果中的最新证据；代码、输入和环境未变时复用已通过的验证。
- 查看新验证结果前，固定主假设、候选、数据划分、主指标、最小实际收益、统计方法和停止条件。高成本方向先做局部原型与资源测量，有收益再扩大规模或组合方法。
- 标签来自经核验的exact求解器，公开golden用于评分。反复查看的样本归入开发集；模型、特征或阈值选型发生变化后，用未参与选择的新请求验证，纯部署等价改动可复用标签。
- 按假设选择端点、端口对、空间、距离或变体族切分；成组变体按族重采样。同架构新请求支持同架构泛化，跨架构结论需另有数据。
- 每轮算法修改比较基线、单项和必要组合，解释增益来源。纯等价优化核对逐行输出与性能；零延迟、不可达、边界端点和输出契约单独检查。
- 采用论文方法前核对有向图、端口状态、真实几何和资源条件。将近似值用于精确界或剪枝前，验证数学前提与真实路径语义。外部SOTA仅在任务、数据、标签预算、硬件和指标可比时作优劣结论。

## 评分与正式验收

- 当前 CPU 优化研究按 2026-10-17 用户更新执行。方法探索允许 acc 下降，保留速度、误差与恢复精度的机制证据；最终交付总体 acc 必须严格大于 99%。CPU 固定以 exp323 发布版为基准，在同输入分布、硬件、规模和计时方式下验证收益并防止退化；原发布默认配置与匹配配置对照分别标明。最终候选同时检查 CPU–acc 帕累托前沿。允许相对 exp258 精度下降，仍须报告配对差、分组误差和变化行数；宣称等价的实现继续核对逐行输出与路径。
- 本机 AMD 的计时仅作参考，波动、变慢点估计和本机区间均不作为放弃候选的依据。远端 Xeon 用于主要性能比较，官方平台结果决定平台表现；通用构建及可移植性要求保持。
- acc 与 CPU 使用同一次完整程序运行的输出联合记录；评分和 exact 标签生成的成本单列。输出、输入和标签身份相同时复用评分，避免为 acc 重跑估计程序。
- 帕累托支配指 CPU 不更高、acc 不更低且至少一项严格改善。按分布分别列前沿及不确定性；区间不足以区分的候选保留待定。历史候选按新规则复评，保留旧协议与原始结论，并记录新判定；旧最小节省比例仅作效应描述。
- 最终1B请求全部非重复且事先未知，完整程序CPU目标按2026-10-27用户goal执行，为约100 s，越快越好。有效阶段成绩须来自对应规模的完整实测，固定输出诊断和外推用于筛选与成本分析；已有1M、10M证据按身份复用。阶段指标用于进度记录，有明确CPU收益的方法继续保留。
- 2026-10-17 后续用户调整迭代顺序为完整非重复 **1M → 10M → 100M**。先用 1M 筛选，再以 10M 优化和比较；10M 的 CPU 与精度表现取得明确收益后再扩大到 100M。每次扩大前解释时间瓶颈、初始化成本及预期收益，按本轮预登记规则选择候选；100M 和 1B 的有效阶段目标保持。
- 2026-10-31 用户追加验证要求：出现预登记的正算法收益候选后立即安排完整非重复 1B，不等待默认100M阶梯或最终99%目标。完整程序CPU、wall、RSS、线程数、输入唯一性、输出契约、SHA和精度证据一同记录；抽样exact精度标明样本范围，外推仅作成本分析。1B收益及约束检查通过后立即接入阶段正式版，并把平台、五次运行等未完成验收列为后续状态。
- 保存完整请求对结果带来的重复命中收益仅保留为历史诊断；后续优化围绕未知非重复请求的计算、解析和访存成本。全 miss 缓存探测费用的消除属于有效研究方向。
- 在相同输入分布、硬件和计时方式下比较accuracy、分组误差、CPU、峰值RSS、线程数与输出一致性。核实请求对唯一性，记录cache miss数、行序和初始化成本；输入内唯一性与未参与选型分别说明，外推写明假设。
- 精度采用配对比较；计时预先固定预热、交错顺序和次数，同机串行运行并避开其他重负载。报告效应和区间，将精度与CPU的不确定性共同计入综合收益。
- 2026-10-30 用户追加 CPU 稳定性研究。下一轮关注 exp825 与候选的多次运行波动，
  同时记录均值、中位数、离散程度、user/sys CPU、wall 与机器负载；原因判断以配对实测和机制证据为依据。
- 时间分未归零且一致性相同时，使用下式。accuracy差以百分点计，CPU差为目标1B输入一次完整运行的秒数，小规模测量用于筛选和成本分析。

```text
Δ综合分 = 0.8 × Δaccuracy - ΔCPU / 120
新增CPU预算 = 96 × Δaccuracy
```

- 宣称显著且有实际价值，须满足综合收益的95%置信下界为正，点估计达到预先固定的最小实际收益。分别说明算法收益和工程性能收益。
- 优化候选正式接入的本地门槛是**完整 1M 测试**：在 1M 全量输入上核实输出契约（行数、端点顺序、恰好 3 字段、整数 delay、精确 EOF、完整 SHA、多次运行一致）与资源（单线程、峰值内存≤2,000,000,000字节、每次运行≤3,600秒）通过即可进入打包流程。出现预登记的正算法收益候选（包括 split 或子域正收益）即安排完整非重复 1B；1B以完整程序配对Acc/CPU和预登记综合收益门验证，结合输出契约、单线程、RSS、时限及一致性证据判断约束。收益与约束通过后立即接入阶段正式版，不等待其他规模阶梯或99%目标；未通过时保留候选和结果，记录未通过的指标与适用边界。平台结果、官方五次运行及全量exact精度仍分别记录，平台结果决定正式比赛表现。以赛题原文为准，报告已测分布及未验证范围，隐藏集成绩以实际评测为准。

## 每轮实验收尾：顺手清理过时大文件

### 存储边界与宿主盘余量（2026-11-03 用户更新）

研究源码、数据、模型、checkpoint、日志、报告与临时文件仅写入现有 WSL 项目工作目录
（本仓、`../EDA2026_EAT/`、`../EDA2026_EAT_eval_data/`）或远程机器的项目工作目录。
禁止迁往 Windows 其他盘、项目外目录，或通过指向这些位置的符号链接存放研究产物。
用户已提供的外部资料与归档可以原位只读访问；历史外部笔记保持只读，新理论笔记按本文件规定的项目内位置保存。

Windows F 盘日常剩余空间尽量保持 **大于 23,000,000,000 B**。安排本地写入时，
在该余量之外另计本轮并发任务的新增产物峰值。空间不足时先清理已核验的可重建产物，
或使用已检查容量的远程项目目录。需要停止 WSL 的磁盘压缩操作须先征得用户同意。

单轮 1B/100M 实验动辄产生 35–40 GB 输出。WSL 工作区的宿主盘为 Windows F 盘。
每轮开工、安排大文件写入前及收尾时，通过 PowerShell 查询 F 盘 `FreeSpace`，同时记录
`df -h /dev/sdd`。容量预算以两者较小值为准，预留本轮并发任务的临时峰值与系统余量。
宿主盘空间不足时先清理已核验的可重建产物，或把大规模输出放在已检查容量的远端。
清理记录分别报告 WSL 文件释放量与 F 盘实际增加量；只有 F 盘复测才能确认宿主空间回收。

清理前逐条核对，三条都满足才删：

1. **副本先比哈希**：同族副本先比 SHA-256（或 size + 头尾 64 MB 指纹），逐字节一致后只留一份。
2. **能重建**：文件可由脚本或重跑二进制重新生成，重建命令一并记下。
3. **不被按名引用**：`build/exp29/requests-100m.csv`、`build/exp31/unique-4m.csv`、
   `build/final-scale/requests-1b.csv` 等被复现命令直接引用，属于长期保留。

常删对象：上一轮实验的输出 CSV 与中间产物、已验证过的重复副本、`__pycache__`、临时 tar/zip。

长期保留：`doc/` 下的官方题目与 golden、五个 arch JSON、正式二进制（`./estimate`、`build/submission/`）、
上面按名引用的输入文件。

超过 10 GB 的文件：确认它不是唯一副本且能重建后，在当轮实验记录里写一行
「路径 + 大小 + SHA-256 + 重建命令」，保证可回滚。

删除动作逐条列名执行，先看清单再动手。

## 阅读 `doc/paper/` 的论文 md

`doc/paper/` 存论文正文的 Markdown 解析结果，编号、标题与解析来源见 `doc/paper/INDEX.md`（01–25 本地 `basic`，26–50 远程 `standard`/VLM）。按用途区分阅读方式：

- **正文、方法、结论、表格、图表引用**：直接引用 md，可靠。
- **公式**：以 md 的 LaTeX 源为准阅读；命中以下任一情况时**回查原 PDF 再下结论**：
  - `&lt;` / `&gt;` / `&amp;` 出现在 `$...$` 内（渲染失败，`<` 被 HTML 转义）；
  - 字母被空格拆散（`\operatorname* { l i m }`、`F i x`、`m a x`）；
  - `\left` 没有配对的 `\right`，或 `\begin{array}` 没有 `\end{array}`；
  - 关系符缺失（如 `\lim_{n \infty}` 丢了 `\to`）或自定义宏未定义（如 `\detour`）。
- 引用复杂度界、极限方向、映射关系等精确公式时，**一律回查 PDF**。

依据：全库 15,853 个公式经 KaTeX 渲染验证 98.36% 通过，真问题 0.25%（HTML 实体 11 处、Mathpix 宏与拼写 13 处、语法错误 15 处）；符号级对照 PDF 的保留率为 93.6–99.7%。

原 PDF 在 Zotero `eda2026` 分类（附件即原文件名），按 `INDEX.md` 里的标题对应查找。
