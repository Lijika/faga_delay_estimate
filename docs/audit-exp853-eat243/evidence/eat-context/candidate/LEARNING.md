### Scoring, weighting and validation errata

- Task sampled Acc is `1-tanh(4*abs(prediction-exact)/exact)`, aggregated with
  the evaluator's role-pair population weighting. Integer exact-hit fraction is
  a separate diagnostic.
- The time term is `15-CPU_seconds/120`; one CPU second is `0.008333333`
  composite points. When only one run of a two-run evaluation changes, that
  run's contribution to the mean score is half the per-run difference.
- The installed LossFunctions.jl custom callback aggregates
  `sum_i loss(x_i,y_i,w_i)/sum_i w_i`; the actual tanh callback already contains
  the weight, so there is no additional outer multiplication.
- A 100M positive result is screening evidence. It does not establish 1B sign,
  unknown-request Acc, official-platform performance or five-run consistency.
- No theoretical page-layout or scheduling equivalence is a performance bound;
  only same-machine complete-program runs test CPU.
