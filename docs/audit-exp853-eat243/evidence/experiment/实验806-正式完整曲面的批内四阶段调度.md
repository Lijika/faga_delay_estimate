# 实验806 正式完整曲面的批内四阶段调度

2026-10-29，预登记。最终目标为未知非重复全角色1B完整CPU约100秒，
Acc严格大于99.1%并留余量。正式版本仍为exp780。

## Altitude与唯一候选

exp805在exp781大码本上保持全部输出，与最近原版历史均值相比约省
0.82秒/100M，较正式exp780仍慢0.857654秒，联合收益门失败。
本轮把同一四阶段调度应用于exp780较小码本，测量保持精度的完整成本。
不同码本的缓存条件不同，本轮独立配对，复用既有算法精度证据。

唯一候选保持原批8、目录预取、2048+256码本、模型及数值链。
执行prepare整批、stage整批目录word、finish整批答案、按序writer。
逐请求predict、组件eval、批入口三处在finish前执行stage；
early-return保持answer，末批只处理count条，行视图在本批输出前有效。
Prepared596的word利用原padding，组件须保持56B。
私有生成worker和头文件，其余资产、入口、编译参数全部复用。

## 冻结数据和门

100M沿用exp781完整主角色请求，输入SHA256为
`b26b7e7942dadcc21f58251758fd60da3d0222f8a80bcefd9d86703ddbad7bea`，
输出两臂均须为
`d69146449c13321f6acc1ae665e169b54be75aa41214f3783fd31a95771dbe75`。
身份相同复用唯一性、59904角色覆盖、输出契约及1916928条exact。
该输入已观察，用于纯部署等价验证。

1. 复用239616见证×4折与99200边界的组件测试，全部整数与double位模式相同。
2. 静态ELF严格小于100000000B，继承资产SHA全部符合。
3. r9 CPU8串行，各预热一次，再六对AC、CA、AC、CA、AC、CA。
   记录完整CPU、wall、RSS、线程及每次完整输出SHA。
4. A−C均值至少0.25秒/100M，df5双侧95%系数2.570581835636314，
   区间下界严格大于0，且资源与等价全部通过才进入完整1B。
5. 通过立即运行同输入配对完整1B。顺序AC，各一次，保持磁盘输入及
   memfd普通输出，逐臂前后核验输入SHA、完整输出SHA与资源。
   两次完整1B不足以提供计时区间，阶段接入要求实测节省至少2.4秒，
   对应等精度综合分至少0.02；100M区间提供重复计时证据。
6. 通过后执行清洁目录完整100M验收及不可变阶段打包。
   每次单线程、RSS≤2000000000B、wall及CPU≤3600秒；
   五次一致性复用相同完整输出的六次候选计时。

官方平台结果待测。任何阶段失败停止本固定配置扩大。

## Tactical与Depth

先检查调用覆盖、稳定view和状态大小，再衡量完整CPU。
独立请求提供调度自由，但多个循环和栈读写也有成本；
高精度函数上的改善不能推出正式函数同样受益。
本轮只验证已选调度的适用边界；精度主线另行研究固定码本的选码损失。
本地开工可用267GiB。结果保存于validation/results/exp806/。
