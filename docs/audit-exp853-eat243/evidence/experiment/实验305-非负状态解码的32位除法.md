# 实验305 非负状态解码的32位除法

## 预注册

2026-10-16。完整w1.01/512候选为102.36 s、公开acc99.028029%。
当前localId和decode将非负int状态编号与size_t端口数相除，形成
64位操作数。本轮只将两处商、两处余数的操作数转为uint32，
候选保持全部编号、队列全序、局部地址和路径，复用固定通用O2构建。
主假设为窄除法减少解码成本；独立于exp302的LTO条件收益测量。

理论见vault的《非负状态编号的窄除法等价》。前提为非负合法id
与非零N均在uint32域内，局部结果在int域内，-1父哨兵仅参与
条件判断。标准及ASan/UBSan夹具核对官方全域状态、端口数边界、
INT_MAX附近及随机商余数重建。八臂97,200条搜索字段和895,251
条路径边应复现exp296，四套exact样本及四组CLI输出SHA保持。
任一变化先保存证据并停止性能测试。

Xeon core3同机串行，输入为exp297原序20k/100k，两臂各预热后
AB/BA/AB三对，共16次完整运行。主指标为100k完整user+sys，
包含初始化与I/O；df2 Student-t 95%配对区间两端加0.02 s舍入。
差区间下端<=0保留完整1M资格，明确变慢则结束本次固定实现扩大，
0.5%只记效应，AMD时间只作参考。acc与CPU关联同次输出，精度按
输入、标签、输出身份复用，配对差与变化行应为0。

逐次检查三字段、原端点、整数delay、精确EOF、完整SHA、
多次一致、单线程、RSS<=2GB、CPU/wall<=3600 s。编译、算术
夹具、搜索审计和估计成本分别记录，新增exact与评分为0。
只改私有候选的两个文件和实验工具；正式入口及用户改动保留。
20k/100k全量exact、完整1M、100M/1B、跨架构和官方平台另验。
开工磁盘约407GiB，收尾复查。
