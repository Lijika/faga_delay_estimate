# EAT059 精度模型CPU成本恢复

2026-11-01。保留EAT055的1000树预测函数，使用8行交错遍历和1024行批次降低执行成本。
完整100M测量完成，独立诊断消费者检查继续进行。

## 假设与预登记

同一模型的各行遍历互相独立，可以交错安排，树间浮点累加顺序保持原样。
当前实现同时改变批次与遍历安排；本轮测量两者的组合效果。
预登记采用r9 CPU8同机串行A/B，A为冻结EAT055，B为EAT059。
机制门要求完整CPU至少降低10%，完整输出SHA保持一致。
正式接入仍比较EAT045基线，按原精度、综合收益和资源门判断。

## 决策与边界

相对EAT045既有100M基线，B增加14.136177秒CPU、增加0.000992019pp Acc。
预登记筛选的综合收益下界为−1.201171，正式接入门未通过。
本轮保留改进后的精度候选和完整测量证据，暂不扩大到1B。
正式no-trace版本保持原样。

生产路径100M输出等价已经验证。`predict()`和`eval806_C`的模型接线也已修改，
其独立诊断检查仍在进行，`Trace.raw`与最终预测的语义需要明确记录。
开发数据中少量学生模型的失败只约束所测表示及配置；
模型不可压缩、唯一树结构排除全部子树共享、1B同比例加速等结论均缺少充分证据。
报告中的这些推断已反馈给独立复核角色。
