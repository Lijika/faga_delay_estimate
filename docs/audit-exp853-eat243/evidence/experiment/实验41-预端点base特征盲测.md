# 实验41 预端点 base 特征验证（端点独立）

日期 2026-09-23。起点提交 `d7a7754`。实验40 否决了纯 bounds 特征候选（独立门槛通过但 1B 无综合收益），本轮检查另一个内部信号：生产 `estimate()` 先算出纯 residue 答案 `base`，再用端点修正答案 `fast` 覆盖它，`base` 被丢弃。`base - fast` 衡量真实端点几何把估计移动了多少，这是冻结 44 维特征里没有的信息。

**证据边界**：下面的“独立样本/盲测”只指相对训练端点（10,024 条）独立，不表示选择独立。这 3,107 条在实验28、32、34、40 和本轮反复用于选型比较，已经是被反复查看过的复核集；正式接入前需要一份未参与任何选型的新架构样本，协议见 `experiment/实验43-冻结候选新架构验证.md`。

## 特征与数据

`base` 用 `./estimate -residual off -endpoint-mode off` 生成，只依赖架构和请求，不读 golden，特征里不含 exact。训练标签的 base 输出是 `build/exp41/labels-base-off.csv`（10,024 行，sha256 `2a6168f1…`），独立样本的是 `build/exp41/holdout-base-off.csv`（3,107 行，`22869148…`），stress 的是 `build/exp41/stress-base-off.csv`（99 行，`0d281139…`）。

候选组 base 是 `base`、`base - fast`、`base / max(fast, 1)`；实验40 的 L 组继续保留对照。四个预声明变体各评估一次独立 3,107 条：`base44`（冻结 44 维）、`base_b0`（44+base 组）、`base_l`（44+L 组）、`base_b0l`（44+两组，50 维）。协议沿用实验19A 六折与内部 80/20 网格、语料份额权重、seed 20260919、`reg:absoluteerror`；L 按完整端点键查找，自检覆盖子集、乱序和错配键。

## 独立端点结果

| 变体 | 独立语料加权 | 独立等带加权 | 独立 MAPE | 加权配对均值 | 加权 95% 下界 | 门槛 |
|---|---:|---:|---:|---:|---:|---|
| base44 | 95.3763 | 81.7597 | 1.1836% | — | — | — |
| base_b0 | 95.3800 | 81.9905 | 1.1820% | +0.0038 | −0.0192 | 否 |
| base_l | 95.4532 | 83.2491 | 1.1595% | +0.0769 | +0.0216 | 是 |
| base_b0l | **95.4705** | **83.5678** | **1.1549%** | **+0.0942** | **+0.0401** | 是 |

base 组单独用太弱（加权下界为负），与 L 组合后比只用 L 再高 0.0173 个语料加权百分点、0.3187 个等带百分点，加权配对下界从 +0.0216 升到 +0.0401。分带增益集中在短距，band 0 加 7.202、1-12 加 2.899、13-24 加 1.743、25-50 加 0.633，长距基本不变。六折里 base_b0l 的 endpoint 折 96.260、短距折 80.209。负 exact 四个变体都是 44/44。综合看，**base_b0l 是本轮候选**。

## C++ 候选与一致性

50 维模型导出到 `src/xgb_residual_base_model.h`（kXgbB0 前缀），特征组装与树遍历在 `src/xgb_residual_base.h`。`ResidueEstimator` 新增 `ResidualMode::XgbBase`，CLI 为 `-residual xgb-base`，默认关闭；`applyResidual` 增加 `baseValue` 参数，由 `estimate()` 把已经算出的 `base.value` 传入，不重复查表；启用时在 init 建端口商图表。

一致性：候选在 10,024 条标签、99 条 stress、3,107 条独立请求上的输出与 Python 预测逐行相同（0 不一致）；`-residual off -endpoint-mode off` 的输出与 base 参考逐字节相同；`-residual off` 与 `-residual xgb` 的输出与实验29 参考逐字节相同，默认路径没有回归。

## 1B 交错验收

按 baseline、candidate、baseline、candidate 四轮交错，`taskset -c 3`，每轮 3600 秒硬超时，输出同一路径 `build/exp41/out-1b.csv`，逐轮用 `verify_scale_output.py` 核对 1000 个 1M 块、精确 EOF 和完整 SHA。驱动是 `validation/exp41_1b_interleaved.py`（实验40 驱动的配置副本，未改正式脚本）；第 02 轮首次核对时驱动里的候选参考路径被 sed 写错，输出本身正常，修正路径后对已有输出补跑核对通过，再 `--resume` 完成 03/04 轮。

| 轮次 | 侧 | CPU | wall | RSS KiB | 块核对 | 完整 SHA |
|---|---|---:|---:|---:|---|---|
| round01 | baseline | 485.54 | 487.51 | 903,584 | 1000/1000 | cb64ba26… |
| round02 | candidate | 457.28 | 469.36 | 903,692 | 1000/1000 | ec895f99… |

两轮平均，基线 472.74 s CPU、481.39 s wall，候选 457.58 s、469.42 s，候选少 **15.16 s（−3.21%）**；按公开 accuracy 96.116008 对 96.184034，综合分基线 92.9533、候选 **93.1341，高 0.1808**。

计时读数要加一条限定。基线的两轮相差 25.6 s（485.54 与 459.94），候选两轮只差 0.6 s，均值差主要来自第一轮基线（会话冷启动/机器状态）；拿稳态看，基线第二轮 459.94 对候选均值 457.58，候选快 2.36 s（−0.51%），落在轮间波动内。与实验40 不同，本轮**没有测到候选的 CPU 惩罚**。四轮只是探索，不是赛题五次验收；综合分是条件估算。线程证据来自修正后的采样器（记录的是真实估计器子树），原始 30 秒采样在 `validation/results/exp41-1b-interleaved/monitor-threads.txt`，全程 Threads=1、核 3、RSS 最高 903,884 KiB。

## 决定与证据边界

候选通过端点独立门槛（加权配对下界 +0.0401 个百分点）、Python/C++ 逐行一致性、公开 1M +0.0680 和 100M 输出契约；1B 交错四轮是探索性测量（正式五次验收见实验42），四轮均值综合分高 0.1808，但基线两轮相差 25.6 s 而候选只差 0.6 s，均值差主要来自第一轮基线的冷启动。按公共集预算 `96 × 0.068026 = 6.530496 s/1B`，不能把未显著的 CPU 差说成没有惩罚，正式结论以实验42 的五对配对区间为准。它是目前唯一在端点独立、公开和 1B 三个口径上都为正的候选，建议主代理在实验42 和实验43 都通过后再讨论接入。正式 `./estimate` 与 `build/submission/estimate` 保持实验29，`-residual xgb-base` 默认关闭。

候选 v1 冻结在 `build/exp41/frozen-1b-v1/`（二进制 `d66c0676…`、模型 `2e283391…`、头文件与 1M 参考）。未验证：正式五次 1B 一致性、全独特 1B、赛方机器、官方隐藏分数。
