# 实验414 位移距离曲线的共享斜率程序

2026-10-18，预登记。复用exp413两个源的名义exact场；这些值归入结构开发数据。

exp413的固定外推误差来自有限尺度斜率变化。本轮保留每个变化点，
再对完全相同的一阶差分曲线建立共享字典，检查有限距离函数的精确表示容量。
共享对象由架构和位移域决定，完整请求对答案缓存收益为零。

## 固定方法

每条曲线固定源端口、目标Z、x位移、y方向及`abs(y)%12`。
取`q=0..45`的46个费用，存起点及一阶差分向量的字典编号。
相同差分向量共享一个程序；程序将相同斜率的连续区间编码为
`(起始q, 截距, 斜率)`，分别使用uint8、int16、int16，共5字节。
字典使用uint32偏移，曲线使用uint16起点及uint32字典编号。
任何溢出直接失败；保留全部变化点，查询按q选择正确段。

两个源共1,835,520条曲线，范围`x=-119..119`、`y=-551..551`。
复用exp413窗口证书，另核对增加的550/551行。全部曲线逐值恢复；
自检覆盖常量、仿射、多个变化点、负斜率、相同形状不同起点。

主指标为实际字典数量、段数分布、两源总字节及按160源的容量模型。
分别给出曲线索引固定量和字典在跨源共享未知时的线性上界估算，
保留全部Z端口时总RAM预算2GB、静态资产100MB限制。
若RAM模型超2GB，记录原因并停止该固定格式扩大；若通过，测编译成本和
1M不同名义组件键的查询成本，再考虑真实几何与端点接入。
组件计时与完整请求CPU分列，exp410同期完整1M继续独立执行。

本轮只增加实验脚本及探针。生产调用、模型、CLI与交付包保持。
任何组件证据均不代表真实Block/Line图acc或100M/1B成绩。

## 结果

全部84,433,920个有限域费用逐值恢复，新增550/551行的名义窗口认证通过。
两源1,835,520条曲线得到684,124种差分形状，共4,208,375段。
单曲线形状最多16段，最多的组为5段和6段。
两个源分别346,427/364,735种形状，字典大小11,594,332/12,860,864 B。
合并资产34,792,175 B，构建CPU69.735秒，峰值RSS1,091,948,544 B。

全160源的曲线索引固定881,049,600 B；
按较大实测单源字典线性估算为2,938,787,840 B，未过2GB筛选。
这是以两个已测源为依据的容量模型；全部源的实际字典可能不同。
固定完整曲线字典格式停止扩大，保留精确编码与形状统计。
exp415继续检查不同完整曲线可共享的斜率后缀。

命令为`build/venv-ml/bin/python validation/exp414_curve_program.py`。
输入场、脚本、计划及输出资产身份见`validation/results/exp414/`。
原始场和资产保留在build目录；无完整估计器或新真实exact标签。
