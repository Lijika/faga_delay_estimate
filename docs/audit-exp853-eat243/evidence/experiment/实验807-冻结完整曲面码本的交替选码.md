# 实验807 冻结完整曲面码本的交替选码

2026-10-29，预登记。最终目标仍为未知非重复全角色1B完整CPU约100秒，
Acc严格大于99.1%并留余量。

## Altitude

exp804减少热正文容量后解码反而增加CPU；exp805收回部分大码本开销，
当前组合的精度与CPU联合门仍失败。返回报告要求把表示能力、选择损失、
最终评分和部署成本分别验证。当前exp777/780先独立选A，再选残量B，
已有B之后未重新选择A。这使固定资产内的选择损失成为可直接验证的问题。

唯一候选保持四方向A2048、B256、552格曲面、原整数权重和偏置。
由原贪心码开始，固定两轮，依次固定B重选A、固定A重选B；
仅严格降低本曲面的加权L1才换码，平局保留原码。
本轮不改码本中心、模型、权重、在线指令或目录位宽。
历史exp694与724改变了46点或远域曲线及中心训练；
本轮对象为冻结552格完整曲面上的码号。

## 数据与机制门

先固定方向0，每源40条，共8320曲面。选择种子20261029807，
从exp777已有982671个曲面中排除106496条原码本构造曲面。
选择只读键和构造成员身份；这些曲面对应已观察开发请求，
属于机制检查，不能称独立确认或完整程序性能。

1. 完整核对原数据、码本及原码号身份；重新贪心选码须复现原码号。
2. 小型随机与重复中心、零权重用NumPy枚举检查原生assign及严格改进规则。
3. 每次更新的全部8320个曲面目标逐项不增，全部中间差值符合int16范围。
4. 两轮后总体加权L1相对下降至少1%才扩大到其他方向与开发请求。
   固定门失败则停止当前两轮选码配置；保留其具体排除范围。
5. 报告qx<2、qx≥2及每源损失、改码比例、CPU、wall、RSS。
   离线资源限制CPU600秒、wall900秒、RSS地址空间2GiB。
6. 通过后另行冻结完整方向、匹配残差评分、静态目录压缩与新100M协议。
   只有真实Acc与完整CPU联合通过才进入1B和阶段接入。

## Depth

对每个曲面，固定另一项后，旧码属于新候选集合，所以最小加权L1
不高于旧值。严格下降与平局保持可确定地终止于有限状态；
固定两轮只保证目标不增，局部最优和全局最优均尚未证明。
最终tanh评分、真实位置修正和压缩目录熵分别测量。
数组尺寸与读取次数保持，但访问频率改变仍可能影响CPU。
选择损失改善只增加候选证据，不改变exp780当前成绩。

数据准备在本地，离线计算在l7；r9同期独立运行exp806。
结果保存validation/results/exp807/。本地开工可用267GiB。
