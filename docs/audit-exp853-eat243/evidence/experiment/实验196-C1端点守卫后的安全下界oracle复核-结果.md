# 实验196 C1 端点守卫后的安全下界 oracle 复核结果

2026-10-10。承接 exp194 的 `h_safe` 资格缺口和 exp195 的端点必要条件审计。
本轮只重用已冻结的逐行 oracle、端点 guard 与 exp174 评分数据；没有重新运行
exact Router、没有修改正式源码、`estimate`、交付包或既有统计门。

## 结果

6176 条固定加权请求全部完成，exp195 的端点 guard 没有过滤任何 exact 可达行，
并且所有被使用的 `h_safe` 都满足 `h_safe <= exact`：

| 项目 | 数量 |
| --- | ---: |
| exact 可达 | 6076 |
| exact 不可达 | 100 |
| 可达行被 guard 过滤 | 0 |
| 使用下界且违反安全性 | 0 |
| 触发 `max(P,h_safe)` | 78 |
| 低估行 | 3195 |
| 低估行被捕获 | 78 |
| 恶化行 | 0 |

离线候选保持原预测的不可达语义。基线 accuracy 为
`96.463503166%`，guard 后 oracle 为 `96.469401951%`，点增益
`+0.005898785 pp`。七带配对 bootstrap 的 95% 区间为
`[+0.003846282,+0.008440640] pp`，因此正向效应在此固定样本上可见，
但没有达到预注册的 `+0.20 pp` 扩大门。

101–300 带贡献约 `+0.003159243 pp`。触发行总体权重为 `1.125185%`，
只覆盖低估行的 `78/3195 = 2.4413%`；安全下界与 exact 的差距中位数
为 28 ps、95 分位为 209 ps、最大为 893 ps。只有 1 行选择了非零跳格。

## 结论与采纳

- exp195 的端点 guard 是必要资格过滤器，当前固定样本上安全，可继续作为离线
  下界候选的前置条件。
- `h_safe` 方向的可达行 oracle 上限只有 `+0.005898785 pp`，不值得生成大表、
  接入生产或为其做完整 CPU 测量；该精度候选停止扩大。
- C1 方向保持开放。后续应把研究重点放到能够改变低估预测的结构性候选，并先测
  可部署键覆盖、类内真实费用差异和加权 oracle 上限。
- 仍需保留一个未解决问题：`E_s && E_t` 通过但中间 port-state 不可达的反例
  尚未在更广样本上搜索；本轮结果不能把端点 guard 提升为完备可达性定理。
