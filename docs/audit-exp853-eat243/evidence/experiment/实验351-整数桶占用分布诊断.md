# 实验351 整数桶占用分布诊断

2026-10-17。exp350完整1M比较运行期间，单独检查正式exp335整数桶的
存储工作量。正式入口和exp350计时二进制保持冻结。本诊断在本机AMD执行，
研究成本与Xeon完整程序配对计时分别记录。

主假设为小key入队中存在较多空桶首项写入，出队中存在较多单元素桶。
首项内置可能省去对应vector访存；实际CPU收益需要后续独立候选验证。
本轮只记录操作前桶长度，分组固定为0、1、2--3、4--7、8--15、16及以上，
分别统计push、pop、clear涉及的桶；另记vector扩容次数、大key操作、
clear丢弃的条目和出队清空桶次数。计数使用进程累计uint64_t，
两个持久对象重复报告时核对累计值相同。

源码复制冻结exp334到私有`build/exp351/src`，只增加计数与析构报告。
原vector、三元组全序、位图、堆、clear、cap480、weight1010、cache0、
目标分组、模型和输出语义保持。受影响消费者为SearchQueue夹具、
LegalPathSearch和生产CLI，使用既有构建参数及工具链。

先用既有priority_queue夹具核对395400次push、242496次pop、75次clear；
统计总数及清空关系须相符。随后完整运行冻结非重复U-output 20k开发输入
一次，输出契约及SHA须等于exp335。小key操作计数须复现exp337独立计数的
53972160次push及4152580次pop。任一检查失败则保留原始证据并停止解释分布。
本轮精度、exact和评分均复用同输出身份，阶段成绩继续等待完整非重复
100M及1B实测。插桩CPU只计诊断成本，分布结果用于下一轮表示设计。

```sh
python3 validation/exp351_bucket_sizes.py
```

冻结身份、源码补丁、构建与运行日志、计数及结果写入
`validation/results/exp351/`。收尾记录磁盘变化、删除清单与未验证范围。
