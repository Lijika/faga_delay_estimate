# 实验72：端口ID类别切分

日期2026-09-26。开工 `/dev/sdd` 可用490G。

## 预注册

- 正式基线为exp71包bin SHA `bb8511a60172d0a457a5056ea2ea6dae16faf79718f5d647fef623ce3afac066`，模型仍为exp63 JSON SHA `79e705e78d3680e9528f479dd2b6722ef6dc06ba0272c0ff0e8823385a256fe0`。exp60冻结包仍为整个P1阶段起点；每轮与最新已验收模型比较。
- 假设为端口ID的数值阈值切分限制了共享残差结构的表达。固定矩阵为numeric control、source categorical、target categorical、both categorical；只把对应ID列标为XGBoost `feature_types=c`，数值和其他45列不变。候选使用当前XGBoost3.4.1的hist分区类别切分，`max_cat_to_onehot=4`、`max_cat_threshold=64`（安装文档已核对）。
- 固定exp63的34,352条可达exact训练数据、47维及6屏蔽槽、64棵depth8树、eta0.1、min_child_weight1、256分箱、加权L1和seed20260919；输出仍-3。类别由架构JSON的同一端口ID编码，不按开发标签重新编码。control完整重现模型SHA。
- 开发集为已查看的exp62与exp64；核对身份、完整端点隔离、源标签及control与已验证exp66包预测相同。exp71只改变页映射，复用同一模型和数值基准。每个候选两窗口增益均≥+0.03 pp、两类可达性误判不增加才入选；取较小窗口增益最高者，同分选更少节点，保留单项及组合消融。开发结果只作选择。
- 胜出模型冻结SHA后，用未使用的 `[26M,28M)` 七带每带至多1024条exact，排除公开1M、训练池及全部历史窗口端点，命中即停。固定配对bootstrap10,000次/seed20260925，新窗口增益≥+0.03 pp且95%下界>0，可达性误判不增加，才接入私有C++。
- 类别树需以集合成员判定实现；现数值阈值导出器不能直接使用。仅在精度通过后开发导出，逐行/类别边界与XGBoost核对，预热后3对交错1M CPU，综合点收益≥0.01、保守下界>0，再完整1M契约和资源验收。若开发筛选失败，本轮停止，不消耗新exact，不改正式模型。
- 公开golden只用于最后评分；新窗口支持同架构新请求结论，平台1B和隐藏集另待实测。

`build/venv-ml/bin/python validation/exp72_categorical_ports.py` 完成，原始结果 `validation/results/exp72-screen.json`。control完整复现exp63 SHA，两个开发窗口逐行匹配已验收参考；身份、端点隔离和类别ID的整数/范围检查通过。
