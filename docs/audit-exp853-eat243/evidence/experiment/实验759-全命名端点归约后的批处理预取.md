# 实验759 全命名端点归约后的批处理预取

2026-10-27在构建前停止，原因见实验760的赛题端点范围修正。
四个本地草稿保留；构建、上传和完整运行次数均为0。
以下为停止前的原计划，后续研究从exp728有效角色域基线继续。

2026-10-27预登记。正式基线为exp758阶段包，静态ELF的SHA-256为
8ce4701e50d776be599ec60b23b724d58c66e61bb6e3ef5ee0e6fba33c013a0a。
上一轮完整全命名域1B CPU216.913563秒，正延迟抽样Acc98.599015045%。
本轮为等输出工程优化，最终Acc>99%和接近100秒目标继续保持。

当前旧角色请求使用8条批次分离prepare596与finish596。新增端点
适配在同一行内调用两者，后续请求的预取无法覆盖这一支的geometry
读取。本轮假设是将单项Net归约后的请求并入原批次，可以增加访存
重叠并减少完整CPU。性能幅度尚未测量。

固定一个候选。每条准备状态旁保存head和tail各一个整数，普通
Net归约仍调用同一prepare596，在写出阶段调用finish596后按原次序
处理负数哨兵、前缀减法、零下截断和尾费用。源边界及空路径碰撞
保留exp757有界Arc枚举。原角色准备、批大小、模型、整数与浮点
运算、输入输出契约保持原实现。

先在exp757的498337条全pair、同SRB、随机位置及6305个特例上
比较新旧函数逐值输出，再核对exp758的100M和1B分层请求各984064条。
覆盖全部适配分支、零与不可达，查询内分配必须为0。组件结果通过
即运行完整非重复100M。纯部署等价允许复用输入与exact标签；
新候选的完整输出SHA必须与冻结基线一致，变化行数必须为0。

全部算法实验在r9 Xeon进行，固定CPU8、同机串行并检查其他负载。
100M输入使用exp758保留的完整普通磁盘文件，输出采用memfd普通文件，
原因是远端磁盘仅剩约3GB。两臂存储条件相同，原CLI逐行读写。
先预热AC，再固定四对AC、CA、AC、CA，各版本共五次完整运行。
完整SHA逐次核验，CPU包含初始化与全部I/O；SHA计算单列。
配对CPU节省用Student t的95%区间，Acc差精确为0时只统计CPU不确定性。
最小实际综合收益为0.005分，即100M平均节省至少0.06秒，同时
CPU节省95%下界严格为正。100M乘10仅用于收益筛选。

工程门为静态自包含、单ELF小于100000000B、单线程、RSS不超过
2000000000B、100M CPU小于100秒、wall不超过3600秒、完整契约和
五次一致性。候选达到收益及工程门后，用完整100M做清洁目录空环境
验收并立即接入阶段版，随后完成完整非重复1B。

1B复用exp758的冻结输入压缩档，完整解压并核对输入SHA后运行。
输入tmpfs、输出memfd，与exp758的1B存储条件相同。只运行候选一次，
报告与exp758历史同输入时间差，配对计时证据仍来自本轮100M。
输出完整SHA相同时复用十亿行契约和同次984064条exact样本评分，
并记录当前CPU与原抽样Acc的联合身份。文件内存与程序RSS分别记录，
官方平台及磁盘文件1B继续待验。

输出通过完整SHA核验后，复用exp758的已验证持久归档再释放RAM。
冻结输入、架构、标签、正式二进制与历史版本全部保留。候选失败
时停止扩大，只结束当前批处理配置；运行模型和其他调度方案继续
保留其已有证据。开工本地/dev/sdd为272GiB可用，远端约3GB可用。
