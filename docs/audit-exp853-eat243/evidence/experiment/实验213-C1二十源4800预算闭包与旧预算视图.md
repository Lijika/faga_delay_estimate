# 实验213 C1 二十源4800预算闭包与旧预算视图

2026-10-12。沿用 exp211 的直接 `(z,y,x)` 闭包表示，
把 exp171 的二十个 lane0 源从 C1200 升至 C4800，保留 lane4 的原树。
私有目录为 `build/exp213`，开工 `/dev/sdd` 可用约442 GiB。

## 假设与固定比较

更多源可补足单源中长距离覆盖，并降低合法 U 的 slack。
以现有 C/U7 加 exp210 单源八映射为比较起点，
主指标为二十源八映射的新增开发 oracle。
数据为反复查看的 exp174 6176条请求、原七带总体权重与核验exact。
模型训练和阈值选择留待后续；本轮精度空间作确定性开发集描述。
最低实际收益预定 oracle≥0.05 pp，301+ 新增合法请求≥100行。
候选空间通过而实现成本超门时保留算法候选并继续研究成本。

原二十个 lane0 压缩流在 exp175 blob 中独立串联，exp205逐字节复用。
冻结时核验完整 blob 与原40个流拼接相同。lane0旧流合计6,192,375 B，
相应raw为149,511,040 B。新表在固定最小parent下嵌套旧树，
同时检查原名义费用≤1200和映射费用≤1200可以恢复旧 U/count。
据此容量门采用替换账本
`80,784,016 + 1,000,000 - 6,192,375 + 新二十源frame <= 100,000,000 B`。
旧表逻辑视图和容量抵扣的前提写在 Obsidian
`嵌套前驱表的旧预算逻辑视图.md`。

内存采用保守追加估算
`1,066,463,232 + 64,000,000 + 新二十源raw <= 2,000,000,000 B`，
每源独立恢复CPU≤0.25s。
完整ELF、运行峰值与新的组合查询CPU后续实测。
本轮按源查询的计时仅描述原型成本。

## 实现及独立检查

复用 exp210 源码，生成器增加源端口参数；query同样参数化root，
追链同时累计原Arc和映射Arc。100跳缓冲覆盖C4800的原Arc正费前提。
旧视图的U/count须等于原C1200表，诊断分类与追链成本另列。
二十个源各做小预算八lane同pin自检，共1280条模式输出。
ZSEA[0]完整树与闭包复用exp210/211证据，新query该源完整CSV须同SHA。

其余19个源各按已认证的逐源预算盒生成完整C4800树，
保留原始parent与distance，再用exp211相同二进制构造物理域闭包。
独立Python检查完整parent等式、最小索引tie、预算Bellman边、
唯一根、旧C1200有限域嵌套、Q全部字节、祖先闭包及最小外接矩形。
每源闭包压缩并完整恢复到文件，核验SHA。
三臂为原1200表、新表1200逻辑视图、新表4800查询；
各对全部6176请求做八映射，逐项核验旧U/count与新增合法候选嵌套。

19次建树约20分钟，来自exp210单源约65秒与已测闭包/压缩成本的估算。
此规模用于实测完整二十源容量及源族覆盖，单源原型已完成。

每进程RSS≤2,000,000,000 B、CPU/wall≤900s。
任一正确性或资源检查失败时保留已有产物并定位原因。
