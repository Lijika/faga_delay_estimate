## 假设与方案

实际 source 和 terminal 都是存在的 SRB。由 `Architecture::exists`
枚举有效坐标，得到跨度 W、H，固定初始域
`Q = 原预算盒 ∩ [-W,W] × [-H,H] × 全部Z端口`。
从 Q 内全部有限状态开始，按原 parent 递归加入全部祖先，形成 K。
输出范围 R 包含 Q 的矩形及 K 的所有坐标；K 内 parent 保持，R 内其余槽写 unknown。
该方案保留每个有效初始查询及其全部恢复读取，预期完整输出保持。

本地合成自检包含根、初始有限状态、跨出 Q 的必要祖先、
R 内无需访问的有限状态和原 unknown；检查闭包、裁切边界及逐字节结果。
正式数据由独立 Python 检查 Q 全有限包含、标记集合对 parent 闭合、
全部标记状态的原距离严格下降、裁切有限域与 K 一一对应、
Q 内逐字节保持、唯一根及原盒外判定边界。

当前访问契约使用实际端点差值。整数跳格平移查询、虚拟端点或全 tie DAG
需要重新定义 Q，相关范围在 Obsidian 理论笔记中单列。

## 预注册门与比较

主目标是为后续二十个源提供容量空间。冻结两个条件估算门。

- 每源转置压缩流不超过 `(100000000 - 80784016 - 1000000) / 20`
  向下取整，即 910,799 B。
- 每源解压表不超过 `(2000000000 - 1066463232 - 64000000) / 20`
  向下取整，即 43,476,838 B；1,066,463,232 B 来自 exp205 最大 RSS，
  64 MB 为额外恢复和运行预留。

两门都依赖其他源同大小及现有实现驻留成本保持的假设。
实际二十源容量、完整程序峰值内存与代码成本在下一阶段实测。
若原型未过容量门，保留测量并选择其他存储表示。

原表与裁切表的全部 6176 条开发请求、八映射 CSV 必须逐字节相同，
完整 U/count、失败分类及每次重复结果保持。
本轮属于部署等价实验，accuracy 证据复用 exp210；新算法与新选择器另验。

每臂先做一次恢复及 200 轮查询预热，然后五对 AB/BA 交错串行运行；
每次先测一次独立恢复，再做 200 轮完整查询。
裁切流首次恢复写文件并核对完整 SHA；原流复用 exp210 的完整往返证据。
计时恢复输出使用 `-`。
查询 CSV 每次完整 SHA 须相同，解析、加载和写出在 query 区间外。
分别报告恢复 CPU 与每请求查询 CPU 的 df4 双侧 95% 配对 t 区间。
恢复 CPU 不超过 0.25 s；查询区间上界小于零时报告查询加速，
区间含零或为正时只保留相应容量结论及实际成本。
