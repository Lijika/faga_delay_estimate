# 实验16 residueMultiplier=2 与 source-short 组合

日期 2026-09-17，基线提交 ec59369（默认 `source-short 150`）。目标：验证把 residue 格点
加倍（`-residue-mult 2`，moduli 20×24、scale 120）与现有选择性端点修正组合，是否在公开集、
两个 exact 留出集与成本上稳定优于当前默认。

**结论：不提升默认（本轮 src 零改动）。** mult=2 的精度全面更好：公开 1M accuracy
93.5419 → 94.0890，逐行绝对误差 568,149 行改善、431,850 行持平、**0 行变差**（对照是
当前默认 m1-ss150）；两条 exact 留出集直接对照当前默认也从 77.466 → 79.516（32 行，
13 改善 / 19 持平 / 0 变差）与 89.221 → 90.100（65 行有效标签，15 / 50 / 0）。但它的固定
建表成本（+52s/次，表规模 4 倍）抵消了精度收益：**本地筛选代理分**（不是官方成绩）在
1M 口径为 −0.0037、10M 单次口径为 +0.0082，符号在两个口径间翻转，没有稳定更优；同时
峰值 RSS 从 418MB 升到 1,345,244 KiB，即 1,377,529,856 B = 1.378 GB / 1.283 GiB，
仍低于 2 GB 与 2 GiB 两种上限表述。保留 `-residue-mult 2` 作为可选高精度配置。

## 1. 方法与制品

本轮没有修改 src：候选完全由现有开关组合而成（`-residue-mult 2` × `-endpoint-mode
source-short -endpoint-short-distance T`）。`build/estimate-exp16` 与上一轮的
`build/estimate-exp15-default` 哈希相同（`ca728439…`），即默认行为未变；根 `./estimate`
仍 `45b592f2…`。golden 只用于评分，从未进入 estimator。

小样本筛选（前 100K 公开请求）：m1-ss150 accuracy 93.5677 / MAPE 1.6496%；
m2-ss150 accuracy 94.1155 / MAPE 1.5084% → 值得做全量扫描。

## 4. 成本与本地筛选代理分

CPU 为 `/usr/bin/time` 的 user+sys，全部来自实验16 窗口（load ≈ 3，绝对值偏高）；
原始 time 文件保留在 validation/results 与 /tmp/exp16：

| 样本 | m1-ss150（当前默认） | m2-ss150 |
|---|---:|---:|
| 1M sweep | 38.76s | 96.37s |
| 1M round1 | 40.64s | 91.91s |
| 1M round2 | 39.72s | 90.76s |
| 1M round3 | 39.95s | 94.18s |
| 1M round4 | — | 90.45s |
| **均值（本轮样本数）** | **39.77s (n=4)** | **92.73s (n=5)** |
| 实验15 安静窗口 5 次均值 | 29.77s（引用，不并入本轮） | — |
| 10M 单次 | 49.09s | 100.63s |

配对比较：round1–3 的 m1 均值 40.10s 对 m2 均值 92.28s，ΔCPU = **+52.18s**（n=3 对，
同一时间窗）；几乎全部是固定 build 成本（mult=2 build ≈ 60.6s，mult=1 ≈ 11s），与行数
无关（10M 中 9M 命中缓存）。本轮所有 time 样本的 RSS 峰值是 1,345,244 KiB，即
1,377,529,856 B = 1.378 GB / 1.283 GiB，出现在 m2-both 的 1M 运行；mult=1 为 418 MB。

**本地筛选代理分**（公式 0.8·acc + 0.15·100·(1−CPU/1800) + 0.05·100，用上面的 CPU 均值，
一致性按 1M 输出 5 次相同计；官方要求五次运行的平均 CPU，本轮未能满足安静窗口，故这些
数字只作筛选参考，**不是官方成绩**）：

| 口径（样本数 / 窗口） | m1-ss150 | m2-ss150 | Δ |
|---|---:|---:|---:|
| 1M（n=4 vs n=5，load≈3） | 94.5021 | 94.4984 | **−0.0037** |
| 10M（各 n=1，load≈3.4） | 94.4244 | 94.4326 | **+0.0082** |

精度项差 +0.4376；时间项差在 1M 口径为 −0.4413、10M 口径为 −0.4294。两个口径的符号相反，
差值都落在由 CPU 波动（±3s → ±0.03 分）决定的噪声内。

## 5. 决策

**保持默认 `source-short 150`（mult=1），不提升 mult=2。** 依据：

1. 代理分没有稳定优势。1M 均值口径为 −0.0037，配对 round1–3 口径为 +0.0028，
   10M 单次口径为 +0.0082，符号随口径变化，量级都在 CPU 波动范围内；
2. 资源代价是实质性的。本轮所有 time 样本的峰值 RSS 为 1,345,244 KiB，即
   1,377,529,856 B = 1.378 GB / 1.283 GiB，上限 2 GB = 2,000,000,000 B、
   2 GiB = 2,147,483,648 B，两种解释都通过，但余量从约 1.6 GB 降到约 0.6 GB；
   每次运行固定增加约 52s CPU；
3. 精度收益是真实的并已记录，作为可选配置保留：`-residue-mult 2` 与任意 endpoint 模式组合
   均可用，`-residue-mult 2 -endpoint-short-distance 150/200` 是精度最高的实用组合。

**1B 规模未测**，下面只给条件式关系。两次运行的 CPU 均值都低于 1800 s 时，时间分有效，
代理分差为
`Δproxy = 0.8·Δacc − 0.15·100·ΔCPU/1800 = 0.4376 − ΔCPU/120`。
系数 0.15·100/1800 等于 1/120，临界值 `ΔCPU = 52.52 s`，与脚本里
`score(acc2, cpu+critical)` 与 `score(acc1, cpu)` 相等的断言一致。本轮实测均值差
52.97 s、配对差 52.18 s，落在临界值两侧，因此代理分约为打平。当两次运行的 CPU 均值都
超过 1800 s 时 time_score 同时归零，精度项决定排名，mult=2 领先 0.4376 分。两次条件
分开成立，不能从一个推到另一个。运行有效性按规则原文是 runtime 上限一小时，与时间分的
1800 s CPU 阈值不是同一件事，本轮没有测量 1B 的 runtime 或 CPU。

## 7. 未验证边界

1. 官方 1B 规模未测，§5 的条件式关系里 CPU 均值与 runtime 都缺实测。
2. CPU 测量窗口内有其它作业，load 约 3，绝对值偏高，跨批次比较只用同一窗口的配对数据。
3. 只扫描了 32/64/100/150/200 五个阈值，未测 mult=2 与 bias、PDB floor 的组合。
4. §8 说明 S 从 60 到 120 在本架构是精确的整数重标度，所以本轮精度变化来自更细的残差类
   （10×12 → 20×24）。哪些残差类贡献了多少，本轮没有拆分。未测 mult=3，其表为
   316,538,880 × 9 = 2,848,849,920 B = 2.849 GB / 2.653 GiB，超过 2 GB 上限。
5. 留出集为 32 行加 67 行，后者只有 65 个正标签。当前证据支持"这些样本上无变差"，不足以
   支持跨分布泛化。

## 8. 格点倍率与斜率整数精度（本架构核对）

`buildPotentials` 计算 `slope = selfLoop × (S / |v|)`，其中 `S = lcm(mx, my)`，
`mx = max|dx| × mult`、`my = max|dy| × mult`。本架构的 Net 位移只有
`|dx| ∈ {1,2,4,10}`、`|dy| ∈ {1,2,4,12}`（160 条 Net、16 种位移），于是

| mult | mx × my | S | S/\|dx\| | S/\|dy\| |
|---:|---|---|---|---|
| 1 | 10 × 12 | 60 | 60, 30, 15, 6 | 60, 30, 15, 5 |
| 2 | 20 × 24 | 120 | 120, 60, 30, 12 | 120, 60, 30, 10 |

两者都是整数，且 mult=2 的每个商恰为 mult=1 的 2 倍（对上述 span 集合成立，因为
`60/|v|` 全部整除）。实测斜率也正好翻倍：m1 `a=750, b=635/−625`，m2
`a=1500, b=1270/−1250`。因此在本架构上倍率不引入新的斜率取整误差，倍率改变的是残差
类数（10×12 → 20×24）与表的整数标度。该整除性质只对当前 span 集合成立，不能外推到
其它架构。
