# 实验839 共享表示与RSS的系统判断

2026-10-29，依据exp836至839的原始结果重审共享方式。
正式exp825仍为完整1B CPU160.776248秒、同次分层exact抽样
Acc98.881628718%。当前目标为约100秒且Acc严格大于99.1%并留余量。

## Altitude

RSS余量值得使用。它给运行表示更多选择，但精度来自恢复出的值，
速度来自完整执行路径。exp836固定普通残差，精确名义背景使开发
Acc提高0.476821pp，说明背景信息有足够价值。下一表示需要说明
如何保留这部分信息，以及启动展开后能删去哪些必经工作。

本轮出现了一个具体的容量误判风险。旧表示在每个A下可选256个
全局B，四向码本10.17MB；条件表示在每个A下可选16个局部残量，
展开表144.70MB。单方向的组合数量分别为524288和32768。
新表示每组可以定制形状，同时可选变化数量减少16倍。更大的数组
并没有建立函数族包含关系，表达能力要用完整曲面及最终评分检查。

CPU方面，exp839测得1.23GB和表带来1.182189秒启动增量；历史
100M总增量2.574856秒。启动摊销有实际作用，查询布局也有尚未
解释的成本。后续RSS方案应同时给出静态编码、展开值、初始化工作、
每请求地址依赖和数据工作集，再用完整100M决定联合收益。

## Tactical

exp837发现的14.08%构造主码差异已经通过exp838统一。同一8251条
开发请求，Acc差由−0.018980pp变为−0.047535pp。条件身份修复通过，
当前配置的质量门继续失败。该结果排除了用这项来源差异充分解释
失败的判断，固定16码配置结束扩大。

两轮构造L1分别改善32.32%与31.20%，开发L1却分别恶化4.88%与3.90%。
exp838开发L1比exp837更低，最终Acc也更低。后续诊断要分别处理
构造支持与最终评分，沿用当前整数路径和同一真实残差，保留受影响
距离组。条件码的纯CPU交换价值保持未测，不能从质量失败推导速度。

## Depth

完整角色覆盖容易遮住条件模型的数据稀疏。每个方向有
59904×120=7,188,480个已知架构曲面，当前构造119,808个，
只占1/60。exp838的2048组中位数为53条，173组少于16条。
把参数按组拆开后，这批数据所支撑的局部自由度发生了变化。
训练内大幅改善只说明当前数据上的拟合能力，稀疏的单独因果贡献
仍未得到验证。

固定架构的名义场可以作为交付前结构资产进行完整离线编码。
真实请求标签及未知分布的验证仍须隔离。这个边界在
Obsidian《认证有限场的全域码选择与验证身份》中已有推导，
exp728深化报告第8.6节也明确区分了两者。因此，下一项高价值
数据诊断是先在有界结构子域取得完整名义覆盖，再检查候选表示的
可达质量。这里使用的600秒、4GiB离线门属于本轮研究成本选择；
比赛的2GB约束适用于提交程序。

这并不预告全域训练必然成功。exp834只检验了原全局双码表示、
每对四上下文及固定轮数，exp838检验了当前条件16码和稀疏构造。
它们分别限制自己的配置。完整名义覆盖若仍不能保留所需质量，
才有更强证据降低这个共享单位的优先级；若质量恢复，则继续检验
静态压缩、展开峰值和完整CPU。新增有效候选仍按100M→1B推进。

## 证据与限制

原始证据位于validation/results/exp836至exp839，exp837/838最终
整数输出、码号和偏置独立复算通过，exp839十四次初始化复算通过。
本记录新增训练、完整程序运行与标签均为0；当前研究对象已经观察，
不声明未知请求上的新收益。官方平台、可交付的新展开表示及最终
约100秒与99.1%以上的联合目标继续待验。
