# 实验484 全端口现有源码工程优化消融

2026-10-18，在查看本实验结果前登记。测试数据统一使用实验482已独立
检查的 U-role 非重复 1M 输入，SHA-256 为
`b1b68b9474b019fdc0248732573d5ee2fa4424a7911ff2a3d292f50fc2a50664`。
输入包含全部208个合法非I源端口与288个Output目标端口，含逻辑端口；
40,000行已冻结 exact 样本也覆盖两端完整集合。本轮预热、计时和输出
核验只使用该完整1M，不使用端口子集作为测试数据。

## 假设与四臂

主假设是当前未提交源码的两项等价工程优化能降低全端口非重复请求
CPU。A以 exp353 冻结源码在 Xeon 上重编译；D只应用
`src/residue_estimator.cpp`和`src/residue_estimator.h`的诊断字段编译期
裁剪；X只应用`src/xgb_residual_base47_fast.h`的填充子树提前终止；
DX同时应用两项。现有工作区的三处改动只作为只读来源。

四臂均用远端同一版本 g++、`-std=c++17 -O2`、相同宏和静态链接参数
编译；基础源码来自`build/exp353/src/`，不写正式入口和交付指针。
复用既有的架构、预计算residue和upper-tree对象并冻结SHA；先核对A
对已发布exp353的完整输出SHA，再比较各候选的逐行等价性。X候选另
遍历冻结模型所有填充子树，检查其全部后代叶位模式一致。D与A另以
现有`tests/exp51_quadrant_probe.cpp`对同一完整1M逐行输出全部诊断
字段并核对SHA；细项等价性与正式程序输出分别验证。

发布CPU基线仍为exp323默认，exp482已在同一输入/机器上测得
113.5233秒；exp354发布版为100.9933秒。A与DX的本轮对照用于排除
重编译工具链差异，不能直接把不同编译器的时间差归因于算法。

## 指标与执行

先执行四臂各一次完整1M预热，并验证四份输出逐行契约、完整SHA、
单线程、RSS不超过2,000,000,000字节、CPU及wall均不超过3600秒。
任何输入身份、全端口覆盖、编译、模型结构、输出契约或资源失败即
停下，保留现场。三轮固定顺序为 A/D/X/DX、DX/X/D/A、
A/D/X/DX；每轮对A进行配对，记录完整程序user+sys CPU、
wall、初始化、峰值RSS、线程、输出身份和缓存统计。

CPU差采用三对样本的t95区间并加0.02秒计时分辨率余量，点估计
至少节省1.0秒/1M且95%区间上界小于0时认定实际工程收益；
只要点估计降低且区间上界小于0也保留较小收益证据。输出完全等价时
复用exp482同次输出的exact评分99.0907%，精度变化行数及配对差均为0；
任何变化需先定位再独立评分。若DX相对A达到至少1%节省且区间上界
小于0，再登记完整全端口非重复10M；100M需10M明确收益后另行登记。
此轮只改变部署计算，不引入新的标签，实验482的样本已归入开发集。

当前计划使用远端 Xeon core3 串行运行，避免其他重负载。冻结二进制
与真实输入SHA，运行记录位于`validation/results/exp484/`，私有构建
资产位于`build/exp484/`。本机开工`df -h /dev/sdd`显示可用371GiB，
远端可用50GiB；新增四份ELF与每轮输出预计低于1GiB。收尾复查
空间，只有符合项目三项清理条件的文件才逐条列名删除。

## 执行前路径修正与本机验证

冻结后、远端测量前发现运行器记录的绝对路径随机器变化，exp51探针
复制位置也需要保留`tests/../src`布局。修正见
`validation/results/exp484/runner-correction.json`，原协议和冻结文件
保持。本页输入SHA手写时少了12个字符，已按`freeze.json`完整值更正；
程序始终用冻结的完整输入身份检查。

远端同步预计算对象时SSH连接超时，估计程序尚未启动。补充
`validation/exp484_local_check.py`，对相同四臂先在本机执行模型结构、
完整1M诊断和输出检查；本机CPU只记录验证成本，Xeon配对CPU待连接
恢复后执行。新增验证采用同一全端口完整1M，不改变候选与选型条件。

远端连接恢复后，源码在`buildTables()`的`MADV_COLLAPSE`处编译失败；
远端内核为6.8，系统开发头文件缺少该定义，估计程序运行次数为0。
失败日志保存在`build-A.log`和`remote.stderr`。本机A静态ELF与发布
版完整SHA相同，四臂本机均已通过完整1M。因此后续改为把这四份
固定本机静态ELF送往同一Xeon做配对计时，四组共同保持原发布版
编译器与参数。此调整在远端性能结果出现前登记，预热、顺序、输出、
指标与扩大规则继续按原协议执行；远端编译的通过性保留为失败记录。

```sh
python3 -B validation/exp484_local_check.py
python3 -u -B validation/exp484_remote_frozen.py
```

另在查看边界输出前固定`validation/exp484_edges.py`。夹具包含全部
208个源、288个目标，同格请求、四个真实边界的最近邻请求、全部
160个同时合法的Z端口同pin零延迟，以及无效文本和网格外端点。
每份完整夹具先核对端口集合，再冻结SHA和已知零值/-1值；四个
静态ELF分别完整运行，检查端点顺序、三字段、整数、已知值及输出SHA
相同。真实边界可达性的exact标签另属独立问题，本轮检查输出等价。

## 本机正确性与机制证据

四臂静态ELF均小于100,000,000字节，A为94,087,824字节且完整SHA
与exp354发布版相同；D与DX为94,091,920字节，X为94,087,824字节。
四次完整1M的输出SHA均为
`9b0313090f82df8d148130a6bb39db63ab4acbbea9c35fcbc64ec41896ebfa5c`，
输出契约、单线程和2GB/3600秒检查通过，最大RSS1,670,004,736字节。
四次本机CPU合计593.04秒，仅作为验证成本。A、D的100万行完整诊断
字段SHA相同，分别与各自`estimate()`比较的差异数为0；模型全部
75,932个填充子树的后代叶位模式检查通过。

补充边界夹具1568行，同一完整夹具覆盖208/288端口。四臂输出相同，
其中320个零延迟、736个负值，事先固定的656个零值/-1值检查通过。
其余真实边界行只支持与冻结程序的等价结论。

本轮stderr显示全部四臂`legal_path_queries=1000000`、
`legal_path_finite=762492`，余237,508行进入residue/XGBoost路径。
`legal_path_search.cpp`与冻结版本相同，其生产排序直接读取专用表；
调用`estimateBase()`的对照代码位于本轮未开启的`EXP262_AUDIT`中。
请求占比23.7508%描述修改的可达范围，不能直接推导其CPU占比。
路径主体源码相同，逐请求完整路径轨迹未额外采集。

原始证据见`local/report.json`、`edges/report.json`、`mechanism.json`
及`baseline-source-commit.json`。精度评分按相同1M输入和完整输出SHA
复用exp482的40,000行全端口exact样本，配对变化行数为0；Xeon正式
CPU与最终扩大判定在全部三轮完成后统一分析。

## Xeon结果与判定

四次完整1M预热及十二次正式计时均通过，全部输出SHA与本机A相同，
输出契约、单线程、2GB/3600秒资源检查通过；最大RSS为
1,669,881,856字节。三轮正式CPU如下，差值为候选减同期A。

| 臂 | 三次CPU(s) | 均值(s) | 配对差(s) | 差的95%区间(s) |
| --- | --- | ---: | ---: | --- |
| A | 100.72 / 100.67 / 101.25 | 100.880000 | 0 | 基准 |
| D | 101.29 / 101.35 / 101.11 | 101.250000 | +0.370000 | [-0.755651, +1.495651] |
| X | 105.78 / 105.83 / 105.76 | 105.790000 | +4.910000 | [+4.020552, +5.799448] |
| DX | 104.36 / 104.38 / 104.36 | 104.366667 | +3.486667 | [+2.651683, +4.321651] |

X和DX在本分布上增加CPU，D的区间跨零，保留待定。相同精度下，
点估计帕累托前沿为A；计入不确定性后保留A和D，X与DX受同期A支配。
DX未达到扩大门，结束本组合向10M扩大。正式入口继续为exp354，
用户的三份源码改动保留原状。exp323默认的113.523333秒来自exp482
同输入、同机器的既有测量；本轮新改动收益以同期A为比较对象。

精度复用为99.0906975627%，95%区间[99.0701772623,99.1128958019]%，
各分组、配对差0及变化行数0见`accuracy-reuse.json`。
这是40,000行全端口开发exact抽样的结论，完整1M输出身份相同。
本轮未增加标签和评分成本；远端16次完整运行合计1,649.84 CPU秒，
本机四次完整运行合计593.04秒。stderr初始化报告约2.7至2.8秒，
该字段为程序内部计时，完整CPU已包含初始化费用。

原始16份计时、输出身份与冻结文件经`exp484_evidence_check.py`
核对通过，见`raw-evidence.json`、`timing.json`、`report.json`。
全部输出在清理前计算完整SHA。逐请求完整路径轨迹、10M/100M/1B、
官方平台及跨架构保持未验证；远端系统头文件下的源码构建失败记录保留。
本轮静态ELF的Xeon运行通过仅覆盖已测工具链产物。
