## Result

The EAT033 int16 `phase_anchor` replacement is a measured joint **negative**:
it removes the dependent `records779 -> first779 -> second779` lookup chain
and cuts complete-100M CPU `15.716725 s -> 11.617464 s` (-4.099261 s), but
loses `-9.0238797988 pp` sampled Acc (`89.8592105868%` vs `98.8830903855%`
baseline) on `1,916,928` label rows covering `59,904` pairs. Under the
unchanged preregistered gate it fails only the `98.85` accuracy floor; no 1B
run and no promotion.

The earlier EAT031 `-0.0962484369 pp` figure is unusable as a native
accuracy bound. Its Python `predictions()` mixed units: `core_q8`/`raw_q8`
are x256 scale while `old/new_nominal_q8`/`response_q8` are x8, and the
unclamped branch adds the x8 nominal delta into the x256 core, applying
1/32 of the intended change. A same-row, same-weight, same-surface
reproduction (EAT036 `first_divergence.py`, receipt
`FIRST_DIVERGENCE.json`) recovers the published `-0.0962484369` exactly,
measures an applied/intended ratio of exactly `0.03125` on all `981,955`
affected rows, and gives the corrected same-slice bound `-9.2676224338 pp`.
The native `finish596` uses the uniform x256 (intended) arm, so the real
loss of the tested anchor-at-cell-0 representation is ~9 pp, not ~0.1 pp.
Independent EAT036 audit produced no artifact; certainty is limited to the
reproduced source/unit comparison.
