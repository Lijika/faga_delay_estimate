端点分布用 Python 全量统计。公开集源端口 Z/S/A 占 67.33/17.65/15.02%，没有 I 端点，目标端口 Z/S/A 占 65.78/16.79/17.42%。新架构集源端口 Z/I/S/A 占 43.48/43.48/6.52/6.52%，目标端口 Z/I/S/A 占 35.71/35.71/14.29/14.29%。两集 manhattan 不超过 150 的比例都是 36.4%。

## 受控纯查询成本

同一 harness（`tests/exp31_phase2_query_cost.cpp`，cache 0）在两份 1M 输入上各跑 off 与 xgb 三轮，`taskset -c 3`，单进程单轮，交错进行，全部轮次保留在 `build/exp35/cost-*.json`。这 12 轮用的是合并前的 harness 二进制，该文件后来被合并版覆盖，二进制哈希未记录；源码是提交 `a121a68` 之前的 `tests/exp31_phase2_query_cost.cpp`，编译参数 `g++ -std=c++17 -O2 -Wall -Wextra -Wno-unused-parameter -I src`，轮次文件本身是证据。合并版 harness 的 sha256 是 `68c84f9c…`，命名入口和估计器选项相同，在 100,000 条公开 xgb 上复现了同一 checksum `4165372761522665447` 和同一分布。

| 输入 | 残差 | query CPU 均值 | 范围 | query wall 均值 | build CPU 均值 |

| 公开 1M | off | 17.008 s | 16.62–17.40 | 15.64 s | 26.40 s |
| 公开 1M | xgb | 18.958 s | 17.81–20.08 | 17.43 s | 26.46 s |

每轮 checksum 在模式内完全一致，off 与 xgb 不同。xgb 比 off 多约 1.95 s/1M，残差模型占查询 CPU 约 10–12%。建表约 26.4 s CPU，必须单列。查询成本约 17–19 µs/行。

CPU 比 wall 高约 8–9%。`/proc/<pid>/status` 采样 56 次全部 Threads=1，亲和性固定在核 3；同一核上一个纯自旋小程序也报出 CPU 高于 wall。这里只记录观测，不给成因结论。比赛按 CPU 计时。观测文件是 `validation/results/exp35-thread-affinity.txt`。

## callgrind 归因

callgrind 3.21.0 采样公开 1M 前 20,000 条 xgb，`--collect-atstart=no --toggle-collect=exp35_run_queries --cache-sim=yes`，输出 `build/exp35/callgrind-public-xgb.out`，40,196 bytes，Trigger 为 Program termination，`estimate` 恰好 20,000 calls。以下都是模拟指令与缓存占比，不是 CPU 占比。

`estimateEndpoint` inclusive Ir 81.37%，`estimateBase` inclusive Ir 58.57%，`applyResidual` 17.20%，`resolveOffset` 7.95%，`dedupMinEndpoints` 7.42%。inclusive 份额彼此嵌套，不能相加。`collectExits` 包含 `resolveOffset`，`estimateBase` 包含 `llround` 与内联的 architecture.h 代码，同一个函数还会按不同源文件重复归因；`stl_algo.h` 的 5.81% 就是 `dedupMinEndpoints` 内联排序部分，已经含在 7.42% 里。`estimateBase` 调用 1,259,536 次，其中根调用 20,000 次、Source 叶 110,321 次、Both 叶 1,129,215 次，平均每查询约 62 个叶。

四象限取 max 的循环里，`tableSlot` 一行 5,038,144 次加载，占全部 D1 读缺失的 61.9% 和全部 LL 读缺失的 97.3%；D1 缺失率 99.999%，LL 缺失率 95.5%。叶调用、表加载和 LL 缺失的比例支持先试四象限相邻布局这个假设，真实速度以原生前后消融为准。剪枝的收益大小本轮没有测，不下结论。

归因用的命名入口 `exp35_run_queries` 现在并入 harness，独立 probe 源码已删除；上面这份 profile 由合并前的 probe 二进制 `83a4b56f…` 产生。

## 正式 CLI 的 4M 独特饱和测量

`./estimate -in build/exp31/unique-4m.csv -out build/exp35/unique-4m-xgb.csv -residual xgb`，默认 64 MiB 缓存，`taskset -c 3`。输入 4,000,000 行、4,000,000 个不同端点对，cache_hits=0，缓存已饱和。总 CPU 109.05 s，wall 108.74 s，峰值 RSS 903,688 KiB。CLI 报告的建表 wall 25.9 s，查询 wall 74.434 s，约 18.6 µs/行。输出 4,000,000 行，From/To 与输入逐行一致，70,260 条不可达，延迟 checksum `1313354200082076152`。证据是 `validation/results/exp35-cli-4m.json`。

1B 全独特只是从这份 4M 测量做的条件线性外推，不是官方成绩。

## 布局候选与实现

`tableOffset` 原来按 `[quadrant][source][storedTarget][residue]` 存储，同一个叶的四个象限值相隔约 203 MB；改成 `[source][storedTarget][residue][quadrant]` 后四个 int32 连续 16 字节。表容量 813,957,120 bytes 不变，所有读写都经过 `tableSlot`，计算、取 max 顺序、rounding、INF 和 I 目标推导都不动，逐行输出按构造保持不变。改动只落在 `src/residue_estimator.h` 的 `tableOffset` 与注释。

候选二进制是 `build/exp35/estimate-layout`（`d636650c…`）和 `build/exp35/harness-layout`（`029b19a7…`），改动前的 `build/exp35/estimate-candidate`（`05b24d42…`）与 `build/exp35/exp31_phase2_query_cost`（合并版、布局前源码，`68c84f9c…`）保留作对照。编译参数与正式构建一致。

四象限剪枝（partial max 达到 best 就跳过剩余象限）理论上也保持输出，但需要处理 rounding 与 fallback 分支，本轮不做，收益也未测。

## 验证与前后消融

全表等价用 `tests/residue_table_equiv` 对布局源码逐 source、逐象限重建参考并比较。mult1 比较 79,134,720 项，0 不一致；mult2 比较 316,538,880 项，0 不一致。`tests/endpoint_integration` 通过 270 checks、0 failure。

逐字节一致性。公开 1M 的 off 输出与 `build/exp32/1m-off.csv` 相同，xgb 输出与 `build/exp29/estimate-full-1m.csv` 相同；3,107 独立样本的 off 输出与 `build/exp34/exp24-off-postfix.csv` 相同，xgb 输出与 `build/exp29/estimate-full-exp24.csv` 相同。harness 的数值 checksum 在布局前后也一致，公开 1M 为 off `12732869355266351452`、xgb `9655496091675031589`，新架构 1M 为 off `2982562222363282221`、xgb `11639369498928018786`。每一轮的 `residue_table_bytes` 都是 813,957,120，input hash 与上节一致。

## 决定

采用四象限相邻布局。它在两份 1M 输入上把查询 CPU 降低约 22–27%，输出逐字节不变，全表逐项等价，建表与内存不变。正式入口和交付包保持实验29，规模验收（100M、1B、五次一致性）留给主代理审查后决定。证据是 `validation/results/exp35-layout-ablation.json`、`exp35-cost-breakdown.json` 和 `exp35-cli-4m.json`。

## 未验证

布局收益只在 1M 规模、同一台机器、单核受控条件下测量，100M、1B 和赛方机器未运行。callgrind 份额是模拟指令与缓存计数。CPU 与 wall 的差异只记录，未解释。剪枝候选未实现也未测。
