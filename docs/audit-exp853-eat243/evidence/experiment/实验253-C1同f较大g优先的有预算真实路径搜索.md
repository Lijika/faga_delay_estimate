# 实验253 C1 同f较大g优先的有预算真实路径搜索

2026-10-12。exp252的raw256候选信息门通过，固定预算完成率
仍限制中长距离收益，本轮匹配比较堆排序的同f规则。

## 预注册

主假设为同f时优先较大g可以更快找到完整合法路径，提高64或256
有效取出的候选贡献。结构估计q继续使用exp251的mult2、endpoint
off、residual off，只用于排序。真实Net/Arc、终端消元、首次完成
结束和完整前驱重放保持。raw64/raw256为控制，highg64/highg256
为单项。四臂来自同一ELF，控制键(f,0,state,g)，候选键
(f,UINT32_MAX-g,state,g)，保持全部整数比较。

输入与exp252完全相同，全部12,150条正标签开发请求，171条
其余请求保持旧值，全局权重分母为12,321行。旧候选集合仍为
exp243 candidate和upper，另报告相对exp252 raw64/raw256的
独立贡献。控制臂除cpu_s外所有字段须逐行等于exp252，全部
有限winner经原始JSON独立重放，U>=exact；两组64有限时
各自256逐值保持。六条内置边界在两种排序下分别检查。

主筛选门满足任一项即可继续：

- highg256相对raw256的oracle新增至少+0.05 pp。
- highg64或highg256直接替换增量达到raw256，并且总体加权
  expanded不高于raw256的90%。

本轮全池只运行一次，wall<=1200 s、RSS<=2GB、单线程。
四臂固定逐行顺序有热数据复用，查询CPU和操作计数用于成本
诊断，性能结论另用交错完整运行验证。报告七带有限与exact行、
oracle/向下截断/直接替换增量、改善与恶化、expanded/states/
evaluations和CPU。固定开发数据用于筛选，最终在线规则冻结后
使用新请求验证。未过两项门时结束这一同f规则。

已有exp107的PDB精确搜索同f优化仅降低约0.7%扩张，其主要
成本来自严格小于答案的排序值。本轮q、预算和首次路径目标不同，
沿用真实匹配消融重新判断。证据为
`validation/results/exp107-search-audit.json`。
