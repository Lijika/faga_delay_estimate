# 实验821 当前完整曲面阶段版的100M热点复核

2026-10-29，测量前登记。exp811完整1B约160.288秒，当前目标为
未知非重复全角色1B约100秒且Acc严格大于99.1%并留余量。
exp820在l7检验构造数据，r9独立完成当前CPU画像。

## 主问题与对象

exp703画像对应旧背景与旧准备链，exp783仅比较大码本的计数变化。
当前完整曲面、直接端口解析、四阶段调度和偏置均已有变化，
需要当前程序的热点排序决定能够减少的主要工作。本轮没有算法候选，
不从旧热点比例推算当前CPU，也不宣称单次诊断的加速收益。

制品冻结为exp811/C，SHA
daf3701438679b5f6bf5b30d08b9ffaa7247357424936143b7dbec144dbddf75。
复用exp811已观察、非重复、59,904角色对覆盖的完整100M输入，
SHA为09f1ffd715b15076cbfe54707f6581db11fa516c6cb5e3f7ab873def1ed50026。
输出必须为4,013,539,201B，SHA为
1095a3ec2191c3ed0e5b2da69f5679c5b1bb2c5be32391eccb753676536abc1c。
相同输出支持复用完整CSV契约及1,916,928条exact评分，
Acc98.840391528%。本轮输入的身份与独立未知验证分别记录。

## 固定执行

r9 Xeon6226R，CPU8，同机串行。检查无其他重负载后，依次执行
一次无插桩预热、一次perf stat、一次perf record，均实际写出
100M普通CSV，保持原程序入口及数值函数。stat固定task-clock、
cycles、instructions、branches、branch-misses、LLC-load-misses；
record固定cycles:u、999Hz，只采用户态。记录完整user、sys、
wall、RSS及无插桩线程数；perf包装进程的资源单列为诊断成本。

用冻结编译和链接命令增加-g、移除-s得到调试副本。
按exp703方法逐节比较所有已分配代码及数据的类型、地址、大小、
对齐与SHA，build-id单列。只有这些节相同才用其解析原程序采样地址；
调试副本不执行完整估计、不进入交付包。
原程序、输入或输出身份失败即停止；调试节不同只停止源码归属结论，
不得把不匹配的调试副本用于地址解释。

以addr2line内联栈分别统计叶函数、包含函数、源文件与源行。
包含关系的占比有重叠；采样停顿、紧邻prefetch的指令及未解析地址
单独解释。用户态抽样不覆盖sys成本，三次计时只用于画像，不形成
配对收益区间。计数器运行比例低于90%时保留原始值并停止定量归因。

## 验证与保留

每次输出完整大小和SHA须等于已保留的exp811预热C副本，并检查
rows=100,000,000、unreachable=0、query_allocations=0。
核对完整保留副本SHA后，三份新输出逐项记录路径、身份与重建命令，
每份核对完成后删除。长期输入、原保留输出、正式ELF均保持。
当前r9有约22GiB磁盘、11GiB tmpfs，每次仅新增一份约4GB输出。
本地/dev/sdd可用266GiB。新增exact和1B均为0，正式入口保持exp811。

原始证据位于validation/results/exp821/，脚本为
validation/exp821_current_profile.py。本轮只安排完整100M，
后续候选仍按预登记联合门推进100M→1B及阶段接入。

## 实测与当前决策

三次完整100M通过，CPU分别15.576714、15.669890、15.817453秒，
输出均为冻结SHA。无插桩预热user14.055938秒、sys1.520776秒，
wall15.579710秒、RSS269,090,816B、线程数1。
调试副本所有加载节与原程序逐项相同，build-id单列。

六项计数器均运行100%。每请求893.830548条指令、561.416069周期，
LLC-load-misses为0.393084次；这些是当前程序成本画像。
15,609个用户态样本中，prepare596包含归属39.022359%，CSV解析
包含归属24.857454%，finish596包含归属12.454353%。
包含关系相互重叠，比例不相加。
叶归属中line707为13.114229%，surface779为8.860273%，
stage806为6.124672%，first707为5.855596%，
portIndex704为5.605740%，symmetric640为5.426357%。
line707对应的源行20占12.736242%，后续应检查真实数据访问和
依赖链；采样停顿的位置仍需结合指令理解。

继续核对反汇编后，1,885个样本对应0x408265的lea，紧邻前一条
0x408260目录prefetcht0。该源行占比不能解释为Line算术可删除时间。
完整反汇编片段保存在prefetch-site.disassembly.txt，
exp823据此登记保留现有四阶段、仅删除目录提示的配对消融。

全曲面查询已经替代旧D64计算，当前解析与几何准备共同占据主要
工作。因此继续采用两条具体推进线，exp822先验证同在线结构的
数据质量收益，CPU方向围绕实际首段、Line准备与解析的可删除工作
建立候选。旧画像的排序与本轮排序分别保留。

原始计数、地址、内联栈、加载节、三次输出身份及资源记录均保留。
`validation/exp820_821_evidence.py`独立复算全部地址归属、计数、
加载节记录及资源结论通过；调试ELF在r9核验，本地未再次取回。
图片或微基准未参与结论。画像运行不提供配对CPU收益。

三份输出先核对保留副本SHA，再逐项删除，释放12,040,617,603B；
路径、重建命令及保留副本见warmup/stat/record-cleanup.json。
r9收尾磁盘可用22,466,625,536B，tmpfs可用11,531,567,104B。
本地/dev/sdd收尾265GiB，未删除本地大文件。新增exact和1B为0，
正式版保持exp811。
