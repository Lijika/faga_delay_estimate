## 主假设与唯一候选

exp336同机器码采样中，SearchQueue::push占非重复U-output / 公开完整1M
约26.34% / 22.91%。基线独立函数809字节，入口保存5个寄存器。
主假设为强制内联减少调用及参数保存成本，足以超过代码尺寸与寄存器
压力的增长。exp347的rankZ内联负结果保留，当前入队候选独立验证。

候选inline只给私有`search_queue.h`的push添加
`__attribute__((always_inline))`。函数体、桶表示、完整三元组全序、
strict relax、stale、路径、cap480、weight1010、模型、Both端点、
cache0、262144行批次及16MiB文本窗口保持。使用冻结GCC13.3、
C++17、O2和通用静态构建参数。属性依据为本机
`/usr/share/info/gcc-13.info.gz`的Common Function Attributes条目，
编译检查实际语法。CPU收益属于待验证的工程假设。

改动经过LegalPathSearch唯一push调用、搜索探针、estimateText和生产CLI。
复用exp348的队列夹具及搜索与行为审计，新增依赖与接口为0。
正式入口等待完整1M验收，队列全序理论复用既有笔记。
