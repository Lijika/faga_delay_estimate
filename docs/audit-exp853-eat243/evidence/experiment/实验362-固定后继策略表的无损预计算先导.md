# 实验362 固定后继策略表的无损预计算先导

2026-10-17，在读取压缩结果前登记。exp361完整公开唯一1M的Xeon CPU
为119.35秒，其中日志初始化约16.8秒。固定策略表只依赖Port、Arc、Net、
residue参数、目标列序、后继顺序和1005/25参数，当前265,420,800字节。
本轮检验离线预计算能否以较小静态资产替代每次进程的策略枚举。

## 假设与方法

基线为exp361无插桩ELF及私有源码，正式交付保持exp354。
导出完整策略字节，并与exp361已核验的全部掩码构造保持同源。
先使用仓库现有pack_residue_zstd.cpp固定19级、单线程、checksum单帧压缩
原始字节，完整往返相同后测量压缩体积和解压CPU。

固定容量目标为压缩帧不超过5,000,000 B，给当前约94.1MB ELF保留空间。
若原布局超过此预算，再各测一次三字节平面、沿residue轴XOR差分后三字节
平面两种可逆表示。三种布局最多各一次，按可容纳并且恢复步骤最少者选择。
解压和反变换目标小于1秒，当前先记录AMD成本，Xeon决定完整性能。
所有布局须完整SHA相同，恢复原三字节存储，保持查询路径和acc。

本轮先测容量，容量满足后另登记接入。接入须沿用架构输入匹配机制，
输入或参数不同则动态构表；静态流和动态构表逐字节比较，并覆盖fallback。
实现保持通用C++及既有Zstandard库，运行时单线程、2GB、ELF小于100MB。

这项工作改善初始化固定成本，1B仍需继续减少逐请求搜索成本。
完整1M通过并取得相对exp323的CPU收益后再做10M；100M等待10M比较。
本轮没有新增exact、精度选型或100M/1B计时。
私有目录为build/exp362，证据为validation/results/exp362。
