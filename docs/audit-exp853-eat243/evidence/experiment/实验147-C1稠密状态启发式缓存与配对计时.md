# 实验147：C1 稠密状态启发式缓存与配对计时

## 目标与假设

exp146 的 test-only `unordered_map<uint64_t,int>` 在单次 query 中最多保存9,632,000项。
本轮将同一目标下的启发式缓存改为定长状态数组：

```text
state = (y * width + x) * zCount + zIndex[sp]
stamp[state] == generation  => value[state] is valid for current target
value[state] == -1          => provider returns unknown
```

假设定长索引保持逐状态语义，将缓存存储压到每状态两个32位整数，同时减少哈希查找、
节点分配与清理成本。只改 test-only provider，不改 `Router`、生产估算器、默认参数或正式包。

## 固定基线与数据

- 基线提交：`cabb296`（exp146组件探针结果）。
- 请求：复用 `validation/results/exp146-router-safe-residue.csv` 中的92行，输入SHA先校验。
- 精确对照：exp146逐行输出和开发集 `exact` 标签；plain Dijkstra仍固定检查8行。
- 正式身份：exp131静态包SHA `aed8b929957a14cd5a2ae73bf94fedfd0cfaa86732ff79a7ee08a9e7afca064c`。
- 估算状态容量：9,632,000项；定长数组目标字节数 `9,632,000 * 8 = 77,056,000 B`。

## 执行与测量

1. 编译与运行前检查 exp146 输入、样本行、标签、架构和正式二进制 SHA。
2. 输出逐行核对：plain/span/safe答案、各自扩张数和松弛数必须与 exp146 一致；safe 标签
   匹配、搜索完整、`h(target,target)=0` 自检通过。
3. span 与 safe 各执行一轮不计时预热。随后进行5个配对批次，每批完整运行92行，顺序固定为
   `span→safe, safe→span, span→safe, safe→span, span→safe`。固定单线程 CPU 3、关闭Router
   查询缓存与landmark，分别记录每批 query CPU/wall、扩张与松弛数。
4. 报告配对差 `safe-span` 的均值、样本标准差和双侧95% t区间（df=4）；同时报告与exp146
   单次 map-cache 计时的原始差异，仅作为非配对参考。
5. 报告完整进程 CPU、wall、峰值RSS、线程数、dense cache 分配字节数及缓存命中/计算计数。
   运行资源上限为单线程、RSS≤2,000,000,000 B；超限即停止。

## 判决门槛

- 任一答案、扩张数或松弛数与exp146不同：停止，检查generation切换、状态编码和unknown哨兵。
- RSS必须低于2,000,000,000 B；缓存数组字节数必须与状态数计算一致。
- 若RSS较exp146少至少128 MiB，且CPU没有明确退化（95%区间下界高于0.5秒/92行），
  则保留dense cache作为组件候选，进入更大请求集筛选。
- 若CPU区间不确定，保留结论为“内存表示更紧凑，CPU效果未定”，不做生产接入。
- 正式接入仍需独立完整1M精度与资源验收；本轮不读取golden，不声明精度收益。
