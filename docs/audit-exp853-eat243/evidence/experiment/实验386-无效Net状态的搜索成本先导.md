# 实验386 无效Net状态的搜索成本先导

2026-10-17，在新统计前登记。对应exp258建议的Dead-Net Bitmask。
exp385远端串行计时期间，本机只运行独立开发统计。
基线为exp354搜索主体，CPU正式比较基准保持exp323。

主假设是无效Net状态占用了可观的排序、入队和cap，预计算有效位图能
避免部分无后继状态。竞争解释是这些状态只集中于边界，覆盖很低；
新增位图访问可能超过省下的操作。当前只插桩观察，所有搜索行为保持。

按真实arch.resolveNet逐cell和源Z生成3个uint64位图，
实际大小按ceil(Z数/64)*cell数*8计算，当前预计1,584,000字节。
不存在cell全部置0。查询goalId对应状态即使Net无效也必须保留，
因为原搜索在resolveNet前检查到达目标。逻辑目标和I折叠沿原逻辑。

记录每次成功relax中无效且非goal的数量、无效有效出队数，以及预算
耗尽请求中至少有一次此类出队的数量。rank求值按非goal分母记录。
原expanded先增加再检查Net，统计必须保持这一顺序。
在cap480、weight1010运行U-output和U-role各512条及公开前512条，
分别复用exp384的对照字段与路径，逐项完全一致。每次实际resolveNet
的valid与位图再次核对，计数排除probe边界自检。

若两套U分布无效非goal求值占比各>=3%，或预算耗尽行中受影响份额
各>=1%，且新增表示不超过2MB，则保留过滤实现资格；否则固定方案止于统计。
该门只判断进一步实现是否值得投入。插桩CPU不作为加速成绩。
过滤将改变预算使用，未来输出和acc需新请求验收；
本轮理论仅说明保留goal后，删除无后继状态对已有成功路径的条件关系。

正式src、入口与交付保持。新增exact、评分和完整估计器CPU均为0。
