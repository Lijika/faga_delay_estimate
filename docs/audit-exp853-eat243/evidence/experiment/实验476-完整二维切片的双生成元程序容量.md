# 实验476 完整二维切片的双生成元程序容量

2026-10-18预登记，先于新切片结果。exp475等费自环归一化使完整样本
编码减少4.88%，多边cycle替换12.09%，未过固定格式扩大条件。
当前沿原二维cycle方向测试完整切片，CPU发布基准保持exp323，
正式入口保持exp354，八源工程对照保持exp468/ki。

固定前两个源ZSEA[0]、ZLE[0]，目标ZSEA[0]、ZLE[0]、ZDE[0]、
ZQW[0]；余类(0,0)、(5,6)；四种有符号方向。
每组包含该余类在[-119,119]×[-549,549]内的完整二维格点，
每切片552点，64切片，共35,328次逐值检查，零轴重复单列。
全部属于同架构名义开发数据，复用Field.certified核验每点。

主假设为一个完整切片可以由少量带支持的双生成元程序覆盖。
两种固定tie均trace并按exp454分解。同位移及同费用生成元在
本路径支持内合并。对每条路径枚举线性独立生成元对；仅有一维
生成空间时枚举单生成元；其余cycle按原次数吸收到连接词。
记录完整连接词见证及两个生成元，每个程序用精确整数行列式求值。

每个程序在全部切片点上检查可行值≥名义真值。按新覆盖点数最多、
数值程序字典序的固定规则greedy选程序；未覆盖点保存原值。
选中见证独立重放，支持端口、位移和费用均保持。
完整程序取最小与原值残余逐点恢复全部35,328点。

主指标为每切片选中程序数、残余比例、循环次数求值次数，以及实际
随机访问编码的原始/Zstd容量。计入每程序9个int16数值、全局字典、
每切片20B根索引、u32程序引用及残余点的u16键/i16值。
连接词与生成元完整见证保存于实验资产，运行时只查询名义距离值；
末段Bellman掩码、真实几何及完整估计器为后续独立成本。

条件投影按全160源×160目标×120余类×4方向除以64切片的比例缩放，
同时说明源、目标和余类代表性假设及字典共享不确定性。
投影原始模型<1.5GB、压缩模型<80MB时扩大完整余类和目标，
再形成完整1M/10M候选；否则结束当前固定数值格式扩大，保留程序
覆盖与容量证据。任何上界、支持或恢复失败立即停止。
该门仅筛选本格式成本，全源容量及真实CPU/acc仍待实际验证。

资产位于build/exp476/，原始证据位于validation/results/exp476/。
本机/dev/sdd开工373GiB可用；本轮在本机顺序运行，远端不增大文件。

## 2026-10-18续跑结果

冻结文件身份与自检保持，执行完整64切片、70,656条路径。
35,328次恢复检查通过，对应34,408个去除零轴重复后的不同位置。
每片选中公式数中位9、均值10、最大22；全局580个数值公式，
640次公式引用。167个残余值占0.472713%，使用原值保存。
所有可行公式均为认证名义距离的上界，连接见证重放、完整模型解码
及Zstd回读通过。

实际随机访问模型14,976 B，压缩4,206 B。按预登记相同比例投影，
完整160源为原始2,875,392,000 B、压缩807,552,000 B；
源、目标和余类代表性仍是假设。两项容量均未过，因此结束当前
九个int16公式加显式引用格式的扩大。共享数值公式、不同编码及
带逐点误差控制的近似表示保持独立研究资格。

分析CPU17.246264秒，峰值RSS244,473,856 B。原始结果在
validation/results/exp476/report.json，执行命令如下。

```sh
python3 validation/exp476_pair_programs.py run
```

本轮未改估计器，真实CPU、acc、全部端点与跨架构均沿用已有身份。
本轮无超过10GB的新文件，删除1份已核对SHA的恢复副本，释放14,976 B；
与exp479至exp481共同清理13份，共38,113,374 B。收尾/dev/sdd仍为
372GiB可用，完整计划与重建命令见exp481/cleanup-plan.json。exp479开始检查跨切片共享线性空间基，单独预登记容量与
逐片误差区间。
