# 实验594 紧凑树节点与直接行输出

2026-10-22，在构建与查看性能前登记。exp593六项固定消融结束，保留
D64+旧R8。基线为exp591/view，冻结模型、背景、舍入、解析与CLI。
本轮仅修改私有候选，正式源码和比赛包保持既有身份。

## 假设与候选

每个分裂当前分别读取feature与threshold，并将53项整数特征转为
float32。P将feature和INT16 threshold打包到一个32位节点，直接
比较原整数特征；叶值保留float32并按原树顺序累加。合法特征均为
精确可表示的整数，数值等价由完整1M逐字段trace核对。

输出当前使用两次string append并暂存数字。W直接在固定1MiB缓冲
中复制原请求行并格式化整数，减少重复长度检查和中间复制。
长行保留直接写出路径，flush及写入错误继续返回给既有require。

固定候选A=原view、P=紧凑树节点、W=直接行输出、PW=两者组合。
通用x86-64/SSE2、静态链接、禁fast-math与FMA融合，无新依赖。

## 验证与决策

仅在r9项目目录运行算法。先在exp501全端口唯一1M上核对P的完整
trace字段，再在exp501及exp562完整1M比较所有候选。各候选完整
输出大小与SHA须等于冻结D64输出，复用该输出的精度、契约与标签。
检查线程1、查询分配0、RSS<=2GB、CPU<=3600秒、ELF<100,000,000B。

每份输入先各完整预热1次，再按A/P/W/PW及逆序交错六轮。每轮
候选与A配对，使用Student t区间；六项比较按Bonferroni分配总
alpha0.05。两份输入的配对区间下界均>0、且各节约>=0.005秒/1M
才合格。合格者中两份输入平均CPU最低者进入10M。

10M复用exp591的完整唯一全端口输入、固定正反序六对计时及契约
检查，逐行输出保持相同。节约>=0.05秒且95%区间下界>0才推进100M。
本轮若均未过门，结束固定候选，保留原view。输入唯一与全端口
证据复用不变的exp580/exp589身份，算法、评分与核查CPU分别记录。

## 扩大100M的登记

2026-10-22，在查看100M结果前登记。10M等价收益已通过预设门槛，
每行解析、特征、树和背景随机访存仍占主要成本，启动成本在更大规模
中摊薄。100M复用exp580完整唯一全端口输入，核对冻结SHA、输入身份和
已验证的唯一性/端口覆盖证据。固定PW单次完整程序运行，包含初始化、
完整读写，目标CPU<100秒；本次不据单次计时宣称相对前版的统计显著性。
同次输出做完整契约检查，并按100M真实端口人口权重评分相同239,616条
独立exact标签，精度下界须>98.2%。评分及契约核查CPU分列。
10M约332ns/请求用于成本分析，1B目标仍需完整规模实测。
