# 实验839 展开内存的启动成本与查询成本边界

2026-10-29，查看启动测量前登记。接续用户建议，把2GB以内的运行
内存作为可用资源。exp816已经证明完整双码和表能展开到约1.50GB
RSS，并保持全部输出；其100M平均CPU增加2.574855667秒。本轮
补测其中尚未单列的启动成本，帮助选择下一种展开形式。

## 假设与范围

静态资产恢复、和表生成与目录重映射的固定成本，可能解释exp816
在100M上的部分退化。读取次数与内存容量分别核算，初始化和查询
分别测量。exp816旧停止决定保持，当前正式入口仍为exp825。

复用exp816冻结的A、C两个静态ELF。A为exp811原双码表，C为完整
精确和表。SHA和静态大小必须与原freeze逐项一致。输入只含
`From,To`表头；源码中initialize位于CSV读取之前，因此这一运行
执行资产恢复和表生成，并包含进程启动、空CSV处理及销毁成本。
两臂输出必须同为`From,To,delay\n`，rows与query_allocations均为0。
它属于初始化接口诊断，完整100M或1B运行次数为0。

## 固定测量与判断

r9 Xeon6226R、CPU8、单机串行。先预热AC，再固定AC、CA各交错三对，
保留每次user、sys、wall、RSS与线程。主指标为C减A的完整空输入
CPU配对差，报告六对均值及t区间。单次CPU≤15秒、RSS≤2GB；
加载节与算法未变，沿用exp816逐行等价及100M评分证据。

将当前启动差与历史100M总差并列。两者采集时点不同，剩余差只作
机制估计，不能命名为纯缓存或纯TLB成本，不能据此发布速度收益。
若启动增量足以覆盖历史总退化，则下一轮必须重新检查完整尺度效应；
若仍有明显剩余，下一表示须同时减少查询工作集或改变数据共享，
继续扩大同一完整和表的优先级降低。

不从本轮空输入结果推算有效1B成绩。提高Acc需要保存或计算更好的
背景信息；本轮原函数展开只检验CPU和内存的交换。新候选取得明确
联合收益后，仍及时按100M→1B验证与接入。

## 资源与证据

私有目录validation/results/exp839和build/exp839，不重建程序，
不生成标签、不修改正式入口。输入和输出均小于100B，
保留全部14次输出。实验脚本复用exp709的计时与身份工具。
本地/dev/sdd开工259GiB可用，r9磁盘约3GiB、tmpfs约14GiB可用。
启动测量的原始日志和源码检查定位一起保存。

## 实测与独立复算

14次空CSV诊断全部通过，六对正式测量的平均CPU为
A0.363361333秒、C1.545550500秒。C减A为1.182189167秒，
95%区间[1.177362529,1.187015804]秒。
峰值RSS分别269,176,832B与1,496,072,192B，全部单线程。
两臂14份输出均精确等于14字节表头，计数均为0。

历史100M总增量为2.574855667秒，当前初始化差约占45.91%。
跨时点相减得到1.392666500秒的剩余差。它支持同时审查启动和
查询路径的成本，时间采集差异使其只能作为机制估计。
本轮没有区分缓存、TLB、指令执行及预取的各自贡献。
初始化增量本身尚不足以解释历史总退化，原完整和表停止决定保持。

独立审核从14份run日志、空输入与输出重新复算线程、RSS、CPU和
配对区间，核对全部命令及历史差值，通过。原程序SHA在运行前
严格核对，空输入保留真实初始化。证据见report.json和
independent-audit.json，复算脚本为同目录audit.py。

这项诊断使RSS研究的下一步更具体。保持原函数的完整展开已经
证明可行，代价包含约1.18秒固定增量及尚需优化的查询路径。
更高保真的展开需要另定义生成值和完整容量；它可能使用不同的
共享方式，也可能替换更多公共准备工作。当前结果只限制原A+B
完整和表的布局及运行方式。

正式estimate与subm/latest/estimate-bin的SHA均保持
c4b3c845cfd91fac8865bcecf168569a020431ff11da02b937f1955c43a8a54d。
本轮完整100M、1B、exact和发布均为0。收尾本地/dev/sdd可用259GiB，
r9磁盘约2.9GiB、tmpfs约14GiB可用，删除0B。
