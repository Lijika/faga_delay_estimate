# 实验826 完整只读目录的物理大页合并

2026-10-29，测量前登记。exp824全域质量候选构造与exp825新请求
继续推进。本轮检验整张只读目录的地址转换成本，候选与精度路线
分别冻结，不把各自尚未验证的收益相加。

## Altitude与唯一候选

复读03的机器模型与运行内存边界后，检查到exp811的目录为
115,015,680B静态BSS数组，当前初始化仅恢复内容。
r9内核6.8.0-124-generic，THP策略为madvise。exp71曾在另一种
查询表上取得收益，这一历史结果用于提出假设；当前表、算法和
机器条件的收益由本轮测量决定。

唯一候选保持exp811全部资产、四阶段、批8及预取，在目录恢复后，
对数组内完整系统页执行一次MADV_COLLAPSE。采用Linux UAPI
编号25，r9旧构建头文件缺少该常量；本机UAPI与Linux man-pages
原始材料已经核对。sysconf失败或内核拒绝时继续使用相同目录。
函数不改变数组内容及虚拟地址，整次初始化CPU计入完整运行。
代码与数值求值顺序保持，候选不读取请求集合或未来请求顺序。

## 机制与完整门

复用exp823组件及exp816配对框架，使用私有对象完整输出路径。
239,616查询×4折及99,200边界先核对全部整数、double位模式与56B状态。
再用同一组件检查一次实际页合并，AnonHugePages至少100MB，
strace记录调用成功；用注入EINVAL检查相同组件结果及未合并状态。
组件仅为开发机制验证，新增完整程序测试继续采用100M与1B。

机制门通过且exp825的数据与exact任务结束后，r9 CPU8同机串行。
基线exp811和候选各预热一次，再AC/CA/AC/CA/AC/CA六对100M。
输入复用exp811已核唯一和全59,904角色覆盖的100M，
每次完整输出SHA必须保持1095a3ec2191c3ed0e5b2da69f5679c5b1bb2c5be32391eccb753676536abc1c。
复用该输出的完整CSV契约及1,916,928条exact，新增exact为0。

静态ELF严格小于100MB、线程数1、RSS≤2GB、CPU与wall≤3600秒。
预热候选超过基线1.25倍即停止；其余完成六对。
A−C平均至少0.25秒/100M，df5双侧95%系数2.570581835636314，
区间下界为正才扩大。通过后及时进行完整1B配对，实际节省至少
2.4秒才通过阶段接入，平台性能另验。内核拒绝调用时的数值正确性
与平台是否有CPU收益分别记录。失败只限制当前目录、硬件和页策略。
