# 实验475 受支持自环的等费循环归一化

2026-10-18预登记，先于新结果。完整程序CPU发布基准为exp323，
正式入口及交付仍为exp354；当前最快八源原型为exp468/ki，
exp472真实非重复1B CPU291.09秒。此次为全源容量的局部结构研究。

主假设为保留全部访问端口的连接词，能够支持把大量二维多边cycle
归一化为四向长线自环。复用exp453的八源、两种tie、每组2048条
已认证名义路径，共32,768条；这些样本全部属于开发数据。
比较exp454原分解及单项等费归一化，连接词保持。

每方向从连接词的访问端口选择最低费用自环。cycle二维位移需分别
被10和12整除，所需方向均有支持，且替换费用与原cycle完全相等；
其余cycle保留。每条路径核对原路径、原分解及新分解的端口、
二维位移与费用。受支持替换费用更低会与认证最短路前提冲突，
遇到该情况立即停止并保留反例。

主指标为多边cycle按重数的替换率、独立程序数及完整实际编码容量。
两臂均计入全局cycle字典、完整连接词、生成元引用、程序选择索引、
每请求生成元次数和偏移。使用同一固定二进制格式与已有Zstd打包器，
报告原始/压缩容量、逐源分布、CPU及峰值RSS。
样本程序容量仅支持样本结构结论，全源容量需要后续完整二维切片。

至少50%多边cycle被等费替换且完整原始编码减少时，扩大当前归一化
格式；否则保留恒等式及结果，完整切片继续比较原二维cycle方向。
任何恢复失败停止扩大。该轮尚无估计程序改动，完整1M/10M计时在
可运行候选形成后执行；全源、真实acc及官方平台均待验。

理论及前提记录在Obsidian的“受支持自环的等费循环归一化”。
证据目录为validation/results/exp475/，候选资产位于build/exp475/。
本机/dev/sdd开工373GiB可用；该轮本地小原型，远端大实验保持串行。

## 结果与判断

全部32,768条路径的原分解与新分解恢复通过，受支持更低费用反例为0。
多边cycle按重数替换率12.087650%，每组为1.643714%至31.119368%。
原/新cycle字典147/145项，独立程序22,980/21,367项。
完整原始编码1,157,558降至1,101,084 B，少4.878719%；
Zstd为348,054降至331,956 B，少4.625144%。
选择索引和次数部分374,472降至373,896 B，变化很小；
主要差额来自程序字典779,866降至724,012 B。

循环替换率未过预登记50%条件，因此停止扩大当前归一化格式。
保留等费归一化与实际小幅容量收益，后续完整二维切片以原二维cycle
方向为主。样本程序字典及随机键分布尚不能证明全源容量。
结构研究CPU合计约57秒，进程峰值RSS619,343,872 B；
两臂打包CPU0.670217/0.474026秒，恢复CPU0.004025/0.002264秒。
原始证据见validation/results/exp475/report.json；二进制编码逐项
恢复及Zstd完整SHA回读均通过。正式估计器、CPU和acc保持原身份。

远端仅做空间检查，剩余54,123,495,424 B，df显示51GiB。
本机收尾仍显示373GiB可用，本轮保留小型可重建原型资产，
删除文件0份，释放0 B。
