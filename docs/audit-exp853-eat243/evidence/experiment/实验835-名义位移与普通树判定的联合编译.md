# 实验835 名义位移与普通树判定的联合编译

1B约100秒、Acc严格大于99.1%并留余量。本轮检验公共准备的整组工作，

## 判断与假设

复读深化报告6至9章、01的操作并集和03的真实执行边界后，
检查exp825实际worker。名义位移使用首段之后的实际位移与Net偏移，
普通两树也使用实际位移；16路分派再选择各自的坐标表和端口比较。
这些有限域可以在初始化时联合编译，减少在线除余、比较和模型分派。
exp821的4.587759次branch miss/请求是全程序计数，属于研究线索；
本实验不将它全部归因于普通树，也不据此预测节省秒数。

候选C将两轴的名义商、余类、方向、距离路由及实际位移判定位写入
同一记录；端点坐标判定位和端口对判定位按route连续排列。
在线合并各项后读取原来的两张叶表，double加法次序保持。
H/V、首Net、Line、CSV、目录预取、批8及曲面取码顺序保持。
初始化完整计算和3,159,576B新增BSS数组都计入CPU及RSS。
本轮只有一种布局，通过完整测量判断其缓存与控制成本的联合效果。

## 数值与资源门

冻结exp825 worker、全部头文件、模型、架构、资产、二进制与原构建参数。
使用私有目录，生产入口保持。全部两轴有限域核对原算术与位掩码；
端口字段及新增数组范围在初始化检查。复用239,616条全角色组件、
四fold和99,200边界案例，对准备字段、全部特征、背景、raw位模式及
整数输出逐项比较。运行两份百万组件缓存并核对完整trace SHA。
每个新表都有独立的原表达式对照；数值差异即停止完整计时。

静态ELF严格小于100,000,000B，静态自包含、单线程、
RSS不超过2,000,000,000B、完整CPU及wall均不超过3600秒。
新增常驻数组不得超过4MiB；普通模型的在线预测分支由表索引替代。

## 全景复盘与失败边界

当前阶段仍为1B CPU160.776248秒、同次分层exact抽样
Acc98.881628718%。本轮保持了完整函数，将原在线计算改成共享表读取；
结果说明这个固定布局的完整成本增加。指令、访存及缓存竞争各自的
贡献尚未单独测量，表大小和分支数量均不足以推断实际速度。

本次停止范围包含36B两轴记录、全角色×16路端口掩码、六张坐标表、
动态route取掩码，以及原批8和四阶段曲面调度的组合。
联合编译的数值等价条件获得支持，其他表示与执行图仍需各自验证。
本轮结束数组布局与批次扫描。

复读报告及01、02、03解答后，后续研究继续同时回答三个问题。
新表示能保留多少高保真背景信息，查询能省去哪组必经工作，
完整静态信息与热数据需要多少资源。exp775的高保真行教师、
exp776/818的目录容量边界、exp816的精确展开成本和本轮公共准备
成本共同约束下一候选。教师精度、名义加权L1、完整CPU分别作为
对应阶段证据，完整函数的联合收益决定扩大与接入。

02的状态风险界需要限定完整预测函数族，03的等价调度只保持
冻结函数；二者都不能提供当前曲面编码的精度与CPU达标保证。
exp835保留了所有普通模型信息，但增加了完整成本；exp834保持
在线容量而判别增益不足。这两条证据分别限制执行布局与构造配置，
后续需要改变共享信息和查询工作的组合，继续保留各自否定范围。
