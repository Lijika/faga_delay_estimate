# 实验353 缓存关闭时省略请求键计算

2026-10-17，起点28f5967。基线为正式exp335/exp334，ELF SHA为
`51f0002a31230262bc993110b64d68fe0a3ace6f225d5882dff6e7fd43cadd2b`。
开工可用421,175,558,144字节，`df -h /dev/sdd`显示393GiB可用。

## 主假设与唯一候选

当前estimateText在cache0时仍计算两次pinId并组成请求键，随后lookup
立即返回false。主假设为在构造键之前检查现有cache_.empty()，可以减少
每次未知请求的共同费用。候选lazy-key只修改私有residue_estimator.cpp，
将key初始化为0，把原键计算与lookup置于`!cache_.empty()`分支内。
末尾原insert保留，容量为0时继续立即返回。

预测、校准、非法输入、统计、SearchQueue、搜索预算、模型、目标分组和
显式开启缓存的功能保持。新增接口和配置均为0。完整请求结果缓存默认
关闭，性能测量中每行独立计算。采用冻结GCC13.3、C++17、O2和通用静态构建。

已检索estimateText的main与HybridEstimator消费者，以及cache_.init、
lookup、insert和pinId的定义。容量在单次调用中保持，pinId为纯算术。
理论见Obsidian《关闭缓存时请求键求值的可省略性》，沿用原校准阶段。

help及/dev/full。新增24行夹具，由边界7行加非法目标行后重复三遍组成，
