# 实验741 当前正式核的四MiB输出缓冲

2026-10-26预登记，报告7.4的有限工程对照。基于exp733当前成本，
只比较冻结exp728的1MiB输出缓冲和4MiB缓冲。完整行复制、整数格式化、
输入融合解析、距离核、编译参数及资产保持。固定4MiB使主线程栈中
输入和输出缓冲合计5MiB；先记录实际栈上限，若不足则停止该布局。

复用exp720完整非重复100M和exp733保留的相同输出参考，
候选为纯等价改动，复用已有完整契约和1916928条100M抽样exact评分。r9单核8，
一轮AB预热、六轮AB/BA交错，同机串行、无其他研究负载。
每次验证完整输出SHA、行数、不可达数、查询分配、线程、RSS和时长。
旧输出与候选输出逐字节身份相同后，逐名删除重复CSV，记录重建命令。

采纳门为平均节省>=0.25秒/100M、配对t的95%下界>0，
所有硬约束通过；未过门停止该4MiB布局。该门只限定缓冲容量和当前I/O
组织，其他表示的I/O成本另测。通过后及时阶段接入并跑完整1B，
1B结果独立报告，不从100M外推成绩。

## 结果

14次完整非重复100M全部输出相同，六个有效配对的A/B平均CPU分别
17.815009167和17.813700000秒。节省0.001309167秒，95%区间
[-0.118224864,0.120843198]秒，未过0.25秒门。停止4MiB缓冲配置，
生产版本保持。所有执行资源检查通过，删除的相同输出共56189966938B。

收尾发现元数据误将1B的3833856标签数写入100M记录，已更正为当前
100M对应的1916928条，参考`exp728/package-check.json`的相同输出SHA。
原freeze、原report及执行驱动保留，修订见`score-scope-correction.json`。
计时、完整输出身份、零精度差及采纳结论均不受影响，没有重跑完整程序。
