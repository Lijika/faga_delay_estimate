# 实验603 固定模型容量分配与尾块推理成本

2026-10-22，构建与查看新结果前登记。基线为exp602发布的exp601/PQ，
ELF76,633,368B，SHA为
`f3d96c4b06162812778015628d1978c6753dfba03fbad7adc7ac9d886c082196`。
已验完整100M CPU27.066669秒、1B CPU276.287395秒。当前goal为
Acc严格>98.2%并留余量、未知非重复全端口1B CPU100至300秒。

## 假设与范围

exp589的两个接近95MB候选构成容量分配对照。D96保留近域rank512、
远域四方向各rank96；N768D64采用近域rank768、远域四方向rank64。
它们分别提高远域与近域的表示能力。保持全部模型资产、R8、特征、
舍入和浮点恢复顺序，移植exp601短坐标解析、center预取、批8及
固定尺寸点积，检验此前的精度收益能否在当前实现下取得联合收益。

D96的最后32项单独使用32项SSE2整数点积，每个尺度块按原顺序恢复
double；每次32/64项int8点积均不溢出int32。近域768仍按64项分块。
编译前固定rank，加载资产的维度和字节检查继续保留。通用x86-64、
SSE2、静态链接，禁fast-math及FMA融合；代码不要求新增CPU扩展。
理论见Obsidian《带32维尾块的固定INT8点积等价条件》。

可改validation/exp603_rank_cost.py，生成私有源文件和头文件。
调用方为prepare596的预取、finish596的背景查询，完整CSV、审计入口
均复用exp601。正式源码与exp602提交包保持冻结。本轮无训练。

## 数据、门槛与停止条件

全部算法测试、数值审计和计时在r9指定目录。先各用完整唯一开发1M
核对exp589的全部trace字段逐位相等，再用exp501和exp562两份已用
全端口唯一1M检查输出SHA与各自旧模型相同。每份完整请求覆盖
59,904端口对。旧输入、标签和输出身份不变时复用契约与精度证据。
同时检查单线程、核内分配0、RSS<=2GB、CPU<=3600秒、ELF<100MB。

每份输入先A/D96/N768D64预热一轮，再正逆序交错六轮；同机串行、
无离线训练重负载。精度按26源族、时间按配对轮次独立bootstrap
10000次，seed20261022603；两候选用97.5%区间控制多重比较。
主指标为0.8×配对Acc差(pp)-1000×新增每1M CPU/120，点值>=0.01、
同时区间下界>0，且Acc至少提高0.02pp、精度差区间下界>0、距离及
近轴各组下降<=0.03pp，才通过本轮门。该CPU倍乘属于成本筛选外推。
若两者通过，选两数据较低联合分最大的候选，差<=0.005取CPU较小者。

均失败时停止本配置扩大，保留准确率、成本和帕累托证据。通过时先
冻结唯一候选，再登记未参与选择的新全端口唯一1M验证，随后按
1M→10M→100M推进。1B阶段目标以完整实测为准；当前两套已用请求
仅支持开发选型，不能提供新请求或官方隐藏集结论。
