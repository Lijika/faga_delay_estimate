# 实验34 残差目标变换对照

日期 2026-09-21（Asia/Shanghai）。本轮只比较 XGBoost 训练目标，正式入口和 C++ 推理保持不变。标签来自 `validation/results/exp18b-labels.csv`，golden 未读取。

## 方法

沿用实验19A 的六个外层留出、`stable_hash("inner|key") % 5` 内层 80/20 选参、原 44 个特征、单线程 `reg:absoluteerror`、实验19A 的四项网格和训练权重。三种目标为：

| 名称 | 训练目标 | 预测反变换 |
|---|---|---|
| `add` | `exact - fast` | `fast + raw` |
| `ratio` | `(exact - fast) / fast` | `fast * (1 + raw)` |
| `log` | `log(exact / fast)` | `fast * exp(raw)` |

预测统一使用现有 round-half-up、非负截断和 `fast <= 0` 原值保留规则。实验脚本为 `validation/exp34_target_transform.py`，逐行结果为 `validation/results/exp34-target-transform.csv`，汇总为 `validation/results/exp34-target-transform.json`。

## 六折结果

表中为分带加权 accuracy，MAPE 为同一外层测试集的正 exact 行平均相对误差。

| 留出 | `add` | `ratio` | `log` |
|---|---:|---:|---:|
| endpoint hash 20% | 96.199 | 96.108 | 96.114 |
| 西侧训练、东侧测试 | 95.870 | 95.859 | 95.871 |
| 东侧训练、西侧测试 | 96.087 | 95.933 | 95.944 |
| 端口组合 hash 20% | 96.153 | 96.067 | 96.088 |
| 距离 ≤300 训练、>300 测试 | 97.288 | 97.262 | 97.272 |
| 距离 >24 训练、1至24 测试 | 78.198 | 79.065 | 79.138 |
| **六折平均** | **93.299** | **93.382** | **93.405** |

平均 MAPE 分别为 `3.28355%`、`3.23496%`、`3.22812%`。相对 `add`，`ratio` 平均增加 `0.08304` 个百分点，`log` 平均增加 `0.10518` 个百分点；`ratio` 仅 1/6 折严格提升，`log` 仅 2/6 折严格提升。三种目标所有外层折均选中 depth 4、64 trees。

## 完整训练池与独立架构一次性评估

按上节「下一步」执行：三种目标在完整训练池（10,024 条标签剔除 12 条 stress 同端口对，10,012 条，与实验19A 全量拟合一致）上重拟合，网格在池内 80/20 上选择，三种目标都选中 depth 4、64 树；随后在实验24独立架构样本 3,107 条上一次性评分（完整端点剔除规则命中 0 条，3,063 条可达 + 44 条负 exact；golden 未读）。重拟合的 `add` 模型与冻结 `exp19a-model.json` 逐行相同（sha256 `18279168…`，0 不一致），说明管线与基线同条件。

修订 2（2026-09-22）：原评分直接使用 `exp24-holdout-samples.csv` 的历史 `fast` 列，而该列是实验24 修复前版本，六条 I 目标假可达后来才修为 `-1`，所以当时报的 38/44 只是历史输入的结果。本次改用当前生产入口的 `./estimate -residual off` 在同一 3,107 条请求上的输出作为 `fast`（二进制 SHA `db2cca1e…`，输出 SHA `60464c2f…`，生产命令与输入见 JSON 的 `protocol.postfix_off`），并与已提交的 `validation/results/exp24-postfix-verify.json` 对齐：完整 From/To 逐行一致，变化行恰好是提交记录的六个端点 2091、2617、2877、2924、2946、3033，全部由有限值变为 `-1`，44 条负 exact 全部为 `-1`，3,063 条可达行不变；没有根据 exact 标签设置任何 `-1`。原始样本列保留为 `fast_pre_fix`，修复后值记为 `fast_post_fix`。

| 方法 | 等带加权 accuracy | 语料加权 accuracy | 语料加权 MAPE | 负 exact 一致 |
|---|---:|---:|---:|---:|
| off（post-fix） | 78.7974 | 93.5780 | 1.6546% | 44/44 |
| `add`（= frozen） | 81.7597 | 95.3763 | 1.1836% | 44/44 |
| `ratio` | 81.6126 | 95.3087 | 1.2023% | 44/44 |
| `log` | 81.6198 | 95.3540 | 1.1910% | 44/44 |

预声明门槛（语料加权 Δ > 0 且相对 `add` 的配对 95% CI 下界 > 0 且等带 Δ ≥ 0）：`ratio` 语料 Δ −0.0676、配对 CI 下界 −0.0032；`log` 语料 Δ −0.0222、等带 Δ −0.1399，两者均未通过。

分带（语料加权 accuracy，`ratio`/`log` 相对 `add`）：band 0 −2.010/−2.067、1-12 +1.029/+0.971、13-24 −0.227/−0.292、25-50 +0.365/+0.471、51-100 +0.055/+0.085、101-300 −0.151/−0.105、301+ −0.064/−0.014。收益集中在短中距，损失在最短带与长距，不是稳定、可解释的整体收益。

样本等权配对（相对 `add`）在 0..1 accuracy 尺度上为 `ratio` +0.00143 点、`log` +0.00160 点；换算成百分点（JSON 的 `mean_percentage_points`）是 `ratio` +0.14299 个百分点、CI [−0.00317, +0.28915]，`log` +0.16016 个百分点、CI [+0.00900, +0.31132]。之前的日志把 `mean_points` 直接写成「百分点」，差了 100 倍，此处修正。这组配对是**样本等权**（每行同权），而表中 accuracy/MAPE 是**分带语料加权**（长距带权重高），两者符号可以不同：样本等权下 `log` 略正、`ratio` 跨零，语料加权下两者都为负；该 CI 只描述当前七带样本的抽样波动，不推广到隐藏十亿请求。门槛以语料加权和等带口径为准，结论不变。

训练池、输入身份、模型 SHA256、参数、逐行预测与运行时间见 `validation/results/exp34-holdout-eval.json` 与 `exp34-holdout-predictions.csv`，三个模型为 `validation/results/exp34-model-{add,ratio,log}.json`。`--reuse-models` 现在连网格也不重训：`grid_reused=true` 时直接沿用上一版记录的 `grid_candidates`/`grid_seconds_total`/`best_candidate_train_seconds` 与参数，`final_train_seconds` 为 null；字段 `grid_seconds_total` 是四次候选训练之和（复用值约 0.25–0.26 s），`best_candidate_train_seconds` 是最优候选单次（约 0.10 s）。修订前日志里的 `selection_seconds` 实际是最优候选的单次训练时间，现已按实际含义标注。修订没有改变 3,063 条可达行的任何 accuracy/MAPE（JSON 中 `revision.metrics_unchanged_vs_previous=true`）。

离线评估的 CPU 与 wall 不成比例：本轮 `--reuse-models` 运行报告 CPU 7.58 s、wall 1.35 s，上一轮报告 CPU 约 9.64 s、wall 4.12 s，说明 Python/xgboost 的模型加载与预测使用了额外线程，本轮没有采样线程数。固定 OMP/OPENBLAS/MKL/NUMEXPR 的代码在 `validation/residual_xgb.py` 第 24 行，但 `exp34_holdout_eval.py` 先 import numpy/xgboost、后 import 该模块，因此当前执行器并没有在数值库导入前设置这些变量；这一点只作为环境说明，不为离线评估另做代码或性能优化。生产 C++ 估计器进程实测 Threads=1（`validation/results/exp35-thread-affinity.txt`），其单线程计时证据独立保留。

## 决定

实验34否决 `ratio` 与 `log` 目标变换：独立架构上两种变换相对同条件 `add` 基线均为净退化，且未通过预声明门槛。两者不导出 C++、不接入正式入口、不做公开 1M 与规模消融；实验29 继续作为正式入口。现有证据不支持目标变换方向，后续只有出现新的路径级误差证据再重新检查。
