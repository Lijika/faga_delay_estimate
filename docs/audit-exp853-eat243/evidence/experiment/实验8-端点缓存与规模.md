## 设计

复用现有 `ResidueEstimator` 对外接口与 `estimateText` 的最终答案缓存：

1. `estimate` 的纯数值逻辑提为 private `estimateBase`（same-pin 优先、exists、端点类、
   table、straight-line fallback、必过 Line、rounding 全部保留，不做 query 计数、不查 memo）。
2. `estimate` 只做现有计数与可选端点；候选 `EndpointMode Off/Source/Target/Both` 默认 Off；
   CLI `-endpoint-mode off|source|target|both`，直接写入 `residueOptions` 与
   `hybridOptions.residue`，与 `-short-exact`/`-bias-*` 可组合（short-exact 命中时走 Router，
   bias 在最终答案后叠加）。
3. 候选算法与实验6 完全相同：源端 Z/NZ 的 resolveNet 出口；I 目标用
   `resolveNetPredecessor` 直接逆 Net，Z*/logic-out 目标由 incomingArc 的源 I 反查前驱
   Z+gap+terminalArc；短候选含同 pin 0、同格 Arc、单 Net、单 Net+Arc；每段自带 Line；
   min 集空返回 -1。中间叶只调 `estimateBase`，不查 memo、不做递归修正；候选 scratch
   作为成员按真实最大出入 Arc 预留、每请求 clear。没有 9.4M 逆表，也没有新 wrapper。
4. cache 只存最终完整请求结果（键仍为 From/To 对）。
5. 复核修正：`estimate` 在 `base.unreachable` 时直接返回 -1，不再进入候选枚举（否则
   Block 空洞上的同格 Arc 会被短候选接受）；候选输出 -1 时 `stats.unreachable` 跟随最终
   答案计数；新增非同 pin、同格空洞 Arc 回归（SRB_80_0/ILE[0]→SRB_80_0/ZDE[0]，四模式均为 -1）。

`resolveNetPredecessor(x,y,netIndex)` 由 impl 提供并已提交（04083a9）：返回真实前驱
ResolvedEdge（x,y=前驱格、delay=gap、valid），完整双向审计 forward_valid=9,417,280、
reverse_valid=9,417,280、两方向 0 mismatch。本轮只读该接口，未改共享 geometry。

## 1M 端到端（cache 64MiB，冷启动含建表，单线程，计 user+sys CPU）

单次（四模式各一次）：

| 模式 | wall | user | sys | CPU | RSS | acc | exact率 | 平均相对误差 | 综合分* |
|---|---|---|---|---|---|---|---|---|---|
| off | 11.57s | 12.27s | 0.35s | 12.62s | 417,824KiB | 91.621356 | 5.113% | 2.2175% | 93.191918 |
| source | 15.92s | 16.38s | 0.34s | 16.72s | 417,860KiB | 93.240706 | 5.674% | 1.7457% | 94.453232 |
| target | 21.30s | 20.40s | 0.37s | 20.77s | 417,860KiB | 92.005955 | 5.387% | 2.1058% | 93.431680 |
| both | 54.61s | 52.13s | 0.97s | 53.10s | 417,676KiB | 93.670214 | 6.032% | 1.6241% | 94.493671 |

*综合分 = 0.80·acc + 0.15·time_score(本次 CPU) + 0.05·100；上表四个单次运行各自全部
cache miss（1M 请求互不相同，单次运行内无重复）。

两候选各 5 次（一致性实测，输出 sha256 各自五次相同）：

| 候选 | 5 次 CPU(s) | 平均 CPU | 输出 sha256 | 一致性 | time_score | 综合分 |
|---|---|---|---|---|---|---|
| source | 16.80 / 19.41 / 18.50 / 17.64 / 17.83 | 18.036 | a9271af4c26b…7064a | 5/5 相同 | 98.99800 | **94.442265** |
| both | 59.15 / 61.37 / 52.92 / 64.12 / 51.55 | 57.822 | c2238392c9ee…00a36 | 5/5 相同 | 96.78767 | **94.454321** |

选择算术（与主代理口径一致）：accuracy 差 0.42950756pp → 权重 0.8 后 0.3436 分；每多
1 CPU 秒损失 0.15/1800·100 = 1/120 分，故 Both 优于 Source 的条件是平均额外 CPU
< 96×0.42950756 ≈ 41.233s。本次实测平均额外 CPU = 57.822−18.036 = 39.786s，小于阈值，
Both 以 +0.012056 分微弱领先。注意两候选 5 次的 CPU 波动约 ±10%（后台有其他作业），
0.012 分的差距在噪声量级内；同一致性条件下 Source 是更稳的选择。

## 10M 重复公开请求（cache 64MiB，冷启动，同制品）

请求 = 公开 1M 的 From/To 重复 10 次（10,000,000 行）。等 impl 的最终 Router 回归结束
（herdr 状态 done）后才开始计时；机器仍有其他用户的 pi/herdr/codex/mineru 作业。另一个
不属于我们的 `./estimate -exact /tmp/ce2.csv` 是在先前 1M 五次批量期间观察到的，按主代理
要求保留；到 10M 计时时该作业已结束，因此不声称它在 10M 期间一直存在。本批每候选只跑
1 次，只作 timing 筛选；一致性 100 沿用 1M 五次实测，不是五次 10M 实测。

| 模式 | wall | user | sys | CPU | RSS | cache_hits | 与 1M 输出一致性 |
|---|---|---|---|---|---|---|---|
| off | 22.27s | 19.88s | 1.58s | 21.46s | 417,856KiB | 9,000,000 | 10/10 块逐字节相同 |
| source | 23.73s | 21.62s | 0.87s | 22.49s | 417,816KiB | 9,000,000 | 10/10 块逐字节相同 |
| both | 71.75s | 70.57s | 1.61s | 72.18s | 417,880KiB | 9,000,000 | 10/10 块逐字节相同 |

cache 容量 4,194,304 项（64MiB / 16B），1M distinct 全部装下且无淘汰，后 9M 全部命中
（实证 hits=9,000,000，非推算）。10M 单次 CPU 差 both−source = 49.69s，对应综合分差
0.3436 − 49.69/120 = −0.0705，即在重复请求规模下 Source 反超；这与 1M 的 +0.012 形成
方向相反的薄差，说明该决策对工作负载尺度与机器噪声敏感，需按实际评测规模在安静机器上定。

block-hash 验证：把每个模式的 10M 输出按 1,000,000 数据行切成 10 块（去表头）分别算
sha256，10 块彼此相同且等于对应 1M 输出的首块：off `f2179edcfa4e7c26…e4d4092`、
source `f3a50156d8733b57…111505de`、both `465f2b24a12e73d6…0158d458`；1M 整文件
sha256 分别为 `3044018c4eb5818a…fec762f`、`a9271af4c26bc7de…467064a`、
`c2238392c9eeaa60…bb00a36`。完整 CPU/RSS/hits/哈希见
`validation/results/endpoint-integration-10m.json`。

### 本批结论

保留 Source 与 Both 两个候选，生产默认继续 Off；不因 +0.012 采用 Both——该差值在 CPU
噪声量级内，且 10M 筛选下方向相反。是否启用候选留给后续在目标评测规模、安静机器上的实测。

### 下一阶段 100M/1G 方案（暂不跑，避免与其他 agent 重叠）

- 请求流：公开 1M From/To 重复 100/1000 次，不落 40GB 文件；用
  `(printf 'From,To\n'; for i in $(seq 1000); do tail -n +2 body.csv; done) |
  ./build/estimate-endpoints -in /dev/stdin -out /dev/null ...`，表头只喂一次。
- 输出：计时跑 `-out /dev/null`（fopen 支持），只取进程级 user+system CPU、RSS 与 stderr
  的 cache_hits；如需行值验证，另跑一次 100M 写盘（约 4GB）做块哈希与 1M 输出对比。
- 口径：同一 `build/estimate-endpoints`、cache 64MiB、冷启动含建表、单线程、串行；
  每候选先 1 次筛选，胜者再在安静窗口补 5 次一致性/平均 CPU 后算综合分。
- 前置：先与 impl/其他作业协调窗口；本批不跑重计时。

## 环境与计时口径

- 计时全部串行、单线程；进程级 `user+system` CPU 作为评分时间（wall 仅记录）。
- 本批机器存在其他活动作业（见上），CPU 波动已记录；10M 计时在 impl 回归结束后才开始。
- 端点候选的中间叶不走 memo，只有最终请求结果进 cache；上面 10M 的 9M 命中即该语义的实证。
