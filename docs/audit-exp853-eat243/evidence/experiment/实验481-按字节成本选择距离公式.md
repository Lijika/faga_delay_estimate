# 实验481 按字节成本选择距离公式

2026-10-18预登记。exp480紧凑格式每个公式8 B，首次使用一个生成元
组合另需12 B，每个独立残余点4 B。选中公式新增覆盖至少6点时，
即使完全不复用生成元字典，也比独立保存这些点至少节省4 B。
根索引保存公式和残余数量，固定每片4 B，两类共享。

固定沿用exp476的64个完整开发切片、两种tight边次序和认证真值。
两个候选分别使用原循环集及exp480补全循环集，唯一变化为greedy
仅接受新增覆盖点数大于5的公式；达到该条件的候选仍按最大覆盖数、
字典序选择。剩余点保存原始值。条件只比较当前固定编码的原始字节，
压缩率必须实际测量。

比较exp480两臂已有完整覆盖选择结果，分别单独报告循环补全、
按字节停止及必要组合的效果。全部公式保持原上界与连接见证要求，
完整原格式和紧凑格式均逐点恢复，Zstd完整回读。
固定主指标为实际紧凑压缩字节，辅指标为原始字节、公式数及残余数。
候选压缩体积减少即保留机制；条件全源原始<1.5GB且压缩<80MB时
扩大切片。投影沿用相同每片成本及压缩率假设，全源容量仍须实建。
任何恢复或上界失败停止。最终交付保持全端口、未知非重复请求范围。

```sh
python3 validation/exp481_byte_cover.py run
```

私有资产为build/exp481/，证据为validation/results/exp481/。
当前三个研究方向均保留正式exp354入口，CPU基准为exp323。

## 结果

两臂各完成70,656条路径和35,328次距离恢复，紧凑格式回读与Zstd
恢复全部通过。固定停止条件减少公式数，原值残余随之增加。

| 循环集与选择 | 公式记录 | 残余点 | 紧凑原始B | 紧凑压缩B |
| --- | ---: | ---: | ---: | ---: |
| 原循环、完整覆盖 | 640 | 167 | 6,804 | 2,989 |
| 原循环、字节停止 | 507 | 495 | 6,836 | 3,288 |
| 补全循环、完整覆盖 | 802 | 0 | 8,104 | 3,359 |
| 补全循环、字节停止 | 505 | 492 | 7,192 | 3,492 |

原循环的压缩体积增加10.003346%；补全循环的原始体积减少912 B，
压缩体积增加3.959512%。固定6点条件的局部字节收益成立，完整
组合受生成元复用、残余索引和压缩率影响。当前两个候选结束扩大。
平均公式求值次数为7.921875和7.890625，纯组件调用次数减少，
完整程序CPU保持待验。

两臂分析CPU为13.234332和45.856503秒，最高RSS265,457,664 B。
条件全源静态压缩为631,296,000和670,464,000 B；补入随机访问
前缀索引后，运行时主体为1,410,816,000和1,479,168,000 B。
索引每片8 B，全源98,304,000 B，已从保存的紧凑字节独立重建
并核对全部256个切片偏移。整个估计器的其余状态须另外计入。

目前最小静态表示为exp480基准紧凑格式，条件压缩573,888,000 B、
运行时主体1,404,672,000 B。该有限样本缩放继续依赖每片成本及
共享率假设，完整160源需要实建。结果提示跨端口的共享结构需要
进一步研究，当前逐片公式与线性基都没有满足交付体积。
