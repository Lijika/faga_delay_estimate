## 假设与方法

主假设为扩大码本增加随机LLC miss，且总CPU退化并非主要由
新增指令造成。`perf stat`仅计量硬件`cycles,instructions,LLC-load-misses`
及进程user/sys，冻结交错顺序A,C,C,A；同一r9 CPU 8串行，
完整100M非重复输入、普通tmpfs输出、单线程。输入为
`/dev/shm/eda2026-exp781-scale/u-role/requests.csv`，
SHA-256
`b26b7e7942dadcc21f58251758fd60da3d0222f8a80bcefd9d86703ddbad7bea`。
单次运行目录预留4GB以上、单次完整输出核对历史SHA，
依次保存`validation/results/exp783/{0-A,0-C,1-C,1-A}.json`；
完整输出是临时文件，核对后逐条删除，样本exact和输入长期保留。

判别标准为两次成对的LLC miss均增加至少10%，指令数增量
低于5%，且CPU增量同号；符合则优先研究保留信息但改变
热访问布局的完整替代候选。若LLC方向或CPU方向不一致，
暂停“码本超缓存”归因，转查初始化/流水/代码布局。
这是一轮成本诊断而非算法收益门，perf本身会扰动计时；
不以两对计数替代已通过的六对完整CPU或新的联合门。
如性能计数复用率不足90%或重负载干扰则停止推断。
无训练、新标签、100M生成或生产入口修改。

输出重建方式在r9的`research/exp781`下运行：
`taskset -c 8 <上述冻结ELF> -in <上述冻结输入> -out <临时输出>`。
预期A完整输出4,013,572,706B、SHA-256
`d69146449c13321f6acc1ae665e169b54be75aa41214f3783fd31a95771dbe75`；
C为4,013,573,040B、SHA-256
`0b244862fb19602f4db2d872c7a597ea0170b325f6e7db60a753d417f68403fd`。
本轮复用的是已观察开发输入，硬件计数只作机制证据；
未知1B与最终99%/100秒仍需独立实测。

## 配对结果

两对AC/CA完整执行，四次均输出1亿行且端点输出SHA与原
exp781首轮的对应A/C值逐字节相同。perf三个计数器的
`pcnt-running`均为100%，原始记录位于
`validation/results/exp783/`。两次A/C分别如下：

| 配对 | A cycles / instructions / LLC-load-misses | C cycles / instructions / LLC-load-misses |
| --- | --- | --- |
| AC | 57,396,239,006 / 88,027,027,798 / 39,961,389 | 63,688,393,340 / 87,057,867,416 / 88,767,107 |
| CA | 57,280,277,023 / 88,027,597,412 / 39,877,057 | 63,370,835,893 / 87,056,909,866 / 84,287,963 |

平均每100M多46,608,312次LLC-load-miss（+116.8%），
多6,191,356,602个cycles（+10.8%），指令数少969,923,964
（-1.1%）。两个配对均满足预登记的方向和幅度门；
原六对完整CPU仍是性能比较依据。新增miss与增加的CPU
同向且规模相符，支持“更大热工作集是主要嫌疑”的工作假设，
硬件计数本身不构成单因素因果证明。perf JSON未保存user/sys
拆分，这是本轮记录的限制，不能据此定位内核态变化。

四份临时完整输出分别为`profile-0-A.csv`、`profile-0-C.csv`、
`profile-1-C.csv`、`profile-1-A.csv`，每次核对历史大小和SHA
后逐名删除；可按上节冻结命令与输入重新生成，`/dev/shm`
收尾可用20G。下一轮优先检查码号访问偏斜及可以在不改
预测函数的条件下降低热集的布局，同时独立记录初始化成本。
