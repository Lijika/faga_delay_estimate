# 实验836 背景共享与最终目标的第一性诊断

2026-10-29，查看新结果前登记。本轮回答高保真共享与查询成本长期
未能联合达标的原因。正式入口保持exp825，完整1B CPU160.776248秒，
同次分层exact样本Acc98.881628718%。最终目标为未知非重复全角色
1B约100秒且Acc严格大于99.1%并留余量。

## 问题与可证伪判断

实际交付对象是从CSV到整数delay的完整程序。背景名义L1、表项数、
随机读取次数分别描述中间对象，其排序与最终目标的关系须验证。
本轮只复用冻结数据与模型做归因，不训练新候选，不改历史停止门。

第一项判断为当前普通请求仍受背景表示误差显著限制。固定exp822
所选B1R0开发函数，H/V逐行保持，只将ordinary背景替换为exp744
认证名义exact加首段fee；再与exp766已保存的E2残差做四格。
若固定当前残差的背景替换提升至少0.20pp且总体超过99.1%，将
高保真信息保留列为下一表示研究的首要质量问题。若只有匹配E2
通过，背景与残差适配须共同推进。两者都未过时重新审查缺失状态。
该oracle背景没有可交付成本，四格仅支持冻结开发人口的质量归因。

第二项判断为单一名义L1门不足以识别最终查询价值。对exp813/814
已有8320条方向0开发曲面，找到原百万请求中所有匹配键的请求，
用原exp809固定raw0和同一整数解码，比较exp808背景与两份既有
单次读取表示。核对完整552点代理L1、实际查询点名义误差和最终
得分。任何排序分歧只说明该开发子域的代理失配。结果同向也只
支持这两个配置，仍需完整CPU才可判断联合收益。本轮保持旧停止
决定，不因新增诊断直接重启候选。

百万请求沿exp822所选B1R0的折外开发函数，H/V全部保持。
它与正式程序共享背景表示和模型结构，折外raw与正式最终训练raw
分别记录。以下四格只改变普通请求的背景或已冻结残差。

| 普通背景 | 普通残差 | 整体开发Acc |
| --- | --- | ---: |
| 当前exp822 | 当前折外raw | 98.879722905% |
| 认证精确名义值 | 当前折外raw | 99.356543786% |
| 当前exp822 | exp766 E2 | 98.880805476% |
| 认证精确名义值 | exp766 E2 | 99.383595702% |

固定当前残差恢复背景提高0.476820881pp，主假设通过。
背景固定时改用E2提高0.001082571pp；精确背景下更换残差提高
0.027051916pp。当前主要可回收质量来自背景表示。该结果没有
给出精确名义背景的可交付容量或CPU，也没有证明任何固定码长的
最优失真。训练、样本覆盖与表示族的贡献仍需继续区分。

ordinary共979,323行，背景MAE2.881081ps，精确背景下未舍入
剩余误差MAE3.337686ps，两者相加后的MAE5.625029ps。

保持当前raw，将背景误差保留75%、50%、25%、0%，整体Acc依次为

50%诊断点的余量仅0.0331pp，而且收缩依赖oracle。
这给出当前开发集所需改变量的尺度，不能作为未知请求的算法。

## 代理门与实际查询重放

exp807的8320条方向0曲面匹配到8251条ordinary请求、8124个键。
保持exp809原raw，exp808背景的开发Acc98.985056957%，
exp813和exp814分别为98.980375970%和98.974172888%。
整曲面代理L1分别改善1.741426%和0.949426%，实际查询点按truth
加权的名义L1分别上升，最终Acc下降0.004680987pp和0.010884069pp。
这批数据给出代理目标与最终评分排序分歧的具体证据。

两配置的CPU没有测量，不能据此认定当时错过了联合正收益。
旧停止决定保持，单次读取结构、特定码量与真实联合收益分别判断。
后续质量筛选优先使用同函数最终解码；名义L1保留为机制指标。
涉及速度交换的候选，需同时计入可能接受的精度代价和完整CPU。

## 共享粒度的第二项诊断

第一阶段完成后，先写axis-protocol.md，再对同批认证曲面执行
固定exp822码本的行、列常数诊断。各常数从完整名义误差及原
权重求加权中位数，未用真实标签拟合。两臂各执行一次，互不组合。

同一8251条请求的当前Acc99.030637759%，精确背景99.509075122%。
每qx行加一个自由常数后为99.122804843%，回收参考增益19.2642%，
代理L1下降19.6934%；每qy列常数为99.107987473%，回收16.1672%，
L1下降19.1346%。两项均未过预登记的50%回收及25%L1门。
行常数范围[-39,48]，列常数[-48,96]，仅为本开发子域观测。

本结果停止固定曲面码后单独添加行偏置或列偏置的优先推进。
它没有否定重新联合选码、行列共同拟合、其他共享主体或其他数据域；
剩余损失也不能全部称为不可加性交互。共享曲面的粒度仍是设计选择，
下轮需要直接区分信息表达能力、构造覆盖与优化损失。

## CPU判断与研究顺序修正

正式exp825的完整1B为user143.228894秒、sys17.547354秒。
到100秒需减少60.776248秒，即完整成本37.8018%。
exp821的包含式采样不能提供各部分可删除时间，当前尚缺少与最新
结构对应的、保持其余依赖的因果成本分解。

exp816精确和表用1.227GB换成一次读取，100M增加2.574856秒；
exp835改用3.160MB联合准备表，100M增加1.770843秒。
两者均保持原输出，只限制对应布局与机器条件。exp826的100M收益
扩到1B后，单对user减少4.191225秒、sys增加4.496785秒，
同时存储条件变化。静态压缩、运行空间和完整CPU应分别核算，
读取次数、分支数及局部用户态收益均不足以单独排序完整成本。

此前研究在多个实验中同时固定完整曲面共享单位、名义L1筛选门和
既有准备链。这个决策缩小了可探索范围，使新增数据、中心训练和
表布局承担了较多验证工作。exp836把当前质量缺口重新定位到背景，
并排除了单轴自由偏置足以回收主要损失的具体假设。

下一轮先登记所需保留的信息和能删除的整组在线工作，再选择表示。
同预算候选先完成便宜的固定函数最终评分；速度型候选允许登记
精度代价，最终按完整CPU与Acc共同判断。表达能力的乐观诊断、
结构数据覆盖、训练所得值分别记录。已有明确收益仍及时走
100M→1B，最终99.1%门与阶段进展分开记录。
