# 实验350 固定桶边界比较

2026-10-17，起点49b65ae。正式入口及比较基线为exp335/exp334，
ELF SHA-256为
`51f0002a31230262bc993110b64d68fe0a3ace6f225d5882dff6e7fd43cadd2b`。
开工可用421,829,431,296字节，`df -h /dev/sdd`显示393GiB可用。

## 主假设与唯一候选

基线push在每次入队时读取vector起止地址、相减并右移，求得桶数量。
exp336同机器码采样中push占非重复U-output / 公开完整1M
约26.34% / 22.91%，这些比例仅用于定位热点。主假设为将固定桶数量
表达为编译期常量后，可减少上述指令及寄存器占用，改善完整程序CPU。

候选constant只修改私有`search_queue.h`，将push的
`key < buckets_.size()`改为`key < kBuckets`，并用同一私有
`static constexpr size_t kBuckets = 65536`初始化原vector。
所有桶修改点均已检索，构造后数量固定；clear只清各桶条目。
生产对象在main内直接构造，LegalPathSearch持有唯一SearchQueue，
当前生产调用链保持原对象持续使用。排序、桶内表示、大key堆、
cap480、weight1010、模型、cache0、目标分组及全部输出语义保持。
采用冻结GCC13.3、C++17、O2和通用静态构建参数，新增接口与依赖为0。

受影响路径为LegalPathSearch唯一push调用、搜索探针、estimateText
及生产CLI。队列分区和全序复用Obsidian的三级位图与非单调整数桶笔记。
构建后检查局部夹具机器码是否使用常量比较；该证据限夹具，
完整生产性能由Xeon实测判断。

## 冻结验证与计时

普通O2及ASan/UBSan复用既有队列夹具，逐次检查395400次push、
242496次pop与75次clear，覆盖负id、重复项、同id不同g、key下降、
全部层边界、大key与UINT64_MAX。随后核对12150条搜索非时间字段、
126462条路径边，复用48184条已标注请求、7行边界、6类CLI消费者、
特殊CSV、诊断、help及/dev/full检查。任一行为或身份差异即停止计时。
输出相同时复用对应标签、评分和分组误差，预期变化0行、acc配对差0。

Xeon Gold6226R核3、单线程、同机串行，全部远端命令仅在
`/home/lhj/lhjwork/eda2026`执行。先对非重复U-output开发前缀
20k和100k各预热AB一对，再按AB、BA、AB各测三对，共16次。
完整程序CPU使用user+sys，包含初始化、解析与CSV写出。
配对差采用df=2的95% t区间，两端各扩大0.02秒计入舍入；
1%为预先固定的实际幅度参照，有明确CPU收益的方法继续保留。

100k差区间上界小于0时，扩大至完整非重复U-output 1M三对AB、BA、AB，
前置两臂20k预热一次，后置候选公开完整1M两次，共10次。
100k区间跨零保留待定并停止本轮扩大；下界大于0结束固定实现扩大。
完整1M验收核对行数、端点顺序、恰好三字段、整数delay、精确EOF、
完整SHA、多次一致、单线程、RSS<=2,000,000,000字节、
每次<=3600秒和ELF<100,000,000字节。

有效阶段成绩依次来自完整非重复100M CPU<100秒、完整非重复1B
CPU 100--300秒的对应规模实测，最终请求事先未知。1M及小样本用于
筛选和交付检查。输入内唯一性与参与选型分别记录，完整请求结果缓存
保持关闭，每行独立计算。新增exact及评分成本单列。
