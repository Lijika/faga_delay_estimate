# 实验387 最大值差分紧凑行的先导

2026-10-17，在新结果前登记。exp385前两轮的44.24MB独立极差数组使CPU增加，
完整三轮仍在收尾。新主假设是把元数据与原值合并为连续10字节行，
并用领先槽到本行最大值的差收紧证书，能够减少独立数组访问并提高覆盖。
竞争解释是10字节寻址及额外减法仍比原8字节行昂贵。

本轮固定每行保存int16最大值M与四个uint16差D[q]=M-F[q]，
65535表示INF。有限差最大65534，可以逐值恢复。全INF行M=0，
四差均为65535。结构大小static_assert为10字节，无额外指针和descriptor。
原表176,947,200字节，新表221,184,000字节，常驻增加44,236,800字节。
转换瞬时仍保留旧表，预计比exp354增加221MB峰值，资源必须实测。

线性领先槽w有限且margin>=D[w]时，原最大值为L[w]+M-D[w]。
其余分支计算max有限(L[q]-D[q])+M。INF、Line、舍入、非负截断保持。
初始化逐行恢复全部88,473,600槽；现有EXP262审计逐次核对q，
六类边界与四权重通过后，在U-output/U-role及公开各512条核对
非CPU字段和完整路径，并记录原全域与新证书覆盖。

私有范围为build/exp387/src搜索头文件和cpp、实验helper与runner。
复用exp353冻结源码，正式入口与交付保持exp354，CPU基准保持exp323。
当前只做表示和覆盖先导。两套U分布覆盖各提高至少35个百分点、
常驻增加不超过50MB且初始化峰值RSS不超过2GB时，保留完整程序试验资格。
该门只判断本轮固定格式的后续投入，CPU仍须Xeon完整1M配对实测。

开发请求与exp384相同，纯等价改动复用标签，新exact及评分CPU为0。
原始证据放validation/results/exp387，阶段prepare、pilot排他创建。
