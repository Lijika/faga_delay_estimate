# 实验828 主体码条件的近轴残量形状

2026-10-29，查看新候选结果前登记。exp825完整100M继续优先，
本轮在本机完成小型机制判别，避免影响r9计时。

## 全局判断与唯一变更

exp827在原B码条件下只让514/8,320条开发键选用非零修正，
近轴L1改善2.963738%，低于8%门。这个结果提示当前三个可学习形状
对同B码内剩余差异的表达有限。主体A码保存更多完整曲面形状，
本轮检验按A条件分组能否保留更有价值的近轴差异。
该解释为待验证假设，训练量与条件数的变化一并计入结果。

保持exp822/824的A/B/c、两位选择码、零形状、三个学习形状、
四轮加权中位数更新及所有数值规则，仅将条件从256个B码换为
2,048个A码。沿用exp827方向0的119,808条构造曲面与8,320条
互斥开发键，已经观察过的数据继续标为开发机制证据。
修正自身及A加修正均须在int16范围内；所有零权重列保持零。

四方向展开A为13,565,952B，加原B共14,696,448B，较原两本
10,174,464B增加4,521,984B。每请求仍读取A、B各一次，选择码由
原32位目录的高两位给出。完整独立两位流为7,188,480B，
真实压缩、静态ELF与访问成本另验。与exp827相比，修正参数数目
增加八倍；同一目录位宽不能单独证明相同缓存成本。

## 固定机制门与停止条件

复用相同名义权重，开发近轴L1至少改善8%，全曲面至少改善2%，
远域逐点保持，逐键近轴目标不增加。核对原word低30位、选择码、
展开A及独立标量公式；32条开发键枚举全部四种修正。
空簇、零权重、并列和int16边界使用同一已验证的拟合函数。

CPU≤300秒、wall≤600秒、RSS≤2GiB，新增资产≤50MB。
通过后才扩大四方向并检查固定R0的真实最终评分；需要匹配残差时
另行登记。未过门停止这两种条件下的固定四形状表示，保留各自边界，
下一轮重新检查剩余误差的结构与查询工作量。完整程序测试继续100M→1B。

本轮新exact及完整estimate为0。证据放validation/results/exp828，
实现为validation/exp828_primary_shapes.py。本地/dev/sdd开工265GiB。
理论接续Obsidian《冻结双码条件下的近轴形状细化与目录余位》。
