# 实验199 C1 映射前驱链安全剪枝与端点提升诊断结果

2026-10-10。实验199在exp198冻结输入上验证了端点提升、Arc-only安全
剪枝和xor4去重。正式源码、`estimate`、交付包和既有统计门保持不变。

## 等价性

- 7个cycle映射及并集共49,408行输出检查通过。
- 每个映射和并集的 `prediction` 与未剪枝实验198逐行完全相同。
- 实际重放得到的U没有低于exact；没有 false finite、false unreachable
  或评分恶化。
- 并集 accuracy 仍为 `96.681109918%`，相对exp174的40源`all`预测为
  `+0.134277123 pp`；相对正式exp131同样本的组合点增益为
  `+0.217606752 pp`，只作开发样本点描述。

## 工作量

本轮程序输出的累计计数（7个映射、40棵树、6176条请求）：

| 项目 | 计数 |
| --- | ---: |
| query级端点准备 | 6,176 次（端点集合只计算一次/query） |
| 有seed的链尝试 | 907,356 |
| 完整链 | 552,801 |
| Arc-only LB拒绝 | 395,438 |
| replay resolver调用 | 1,240,829 |
| terminal resolver调用 | 128,775 |

exp198无剪枝诊断在含xor4的8映射下为4,391,817次逐hop resolver和
541,419次terminal resolver；实验199同时删除了重复xor4，因此本轮计数
不能直接作为同模式CPU差值。它证明了端点重复准备已移除，且Arc-only
剪枝在当前候选集上保持逐行结果。

## 结论

DeepSeek建议的三个低风险动作均通过固定开发集等价检查：

1. 端点集合提升到query级；
2. 使用 `seed + mapped Arc和 + terminal Arc` 的非负费用下界；
3. 删除与cycle4逐行相同的xor4。

Arc-only版本比包含Line项的乐观计数保守，首轮不把未单独证明的Line
费用加入剪枝。下一步可以在同一私有二进制上做固定带权配对CPU测量；
完成前不接入生产。距离带硬跳过、Pareto模式生产选择和新请求泛化仍未
被本轮证明。
