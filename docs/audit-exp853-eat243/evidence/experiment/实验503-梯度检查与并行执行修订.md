# 实验503 梯度检查与并行执行修订

2026-10-19，训练尚未开始，模型质量尚未查看。
原始模型、初始化、随机种子、2048步预算和全部验收门保持。

## 原始失败与诊断

原检查在r9第0组中心差分失败，解析导数0.26679655273598285，
差分0.2667625159658016，容差2e-6，训练按约定停止。
原始源码、冻结文件和完整失败日志保留在
`validation/results/exp503-gradient-failure-01/`。

独立诊断仍使用全部18组、2,396,160个唯一矩形键，覆盖208源、
288目标和59,904端口组合，每组合40值。全部组的重复索引梯度、
样本方向导数与参数梯度内积一致。原步长1e-7使17组发生ReLU折点
跨越，15组超出原容差；只缩短步长后全部组通过。
逐样本以longdouble计算损失差后，最大导数误差约4.33e-9。
全端口原始证据见
`validation/results/exp503/gradient-diagnosis/report.json`。

## 检查修订

令各检查样本的激活为a、随机方向引起的变化率为b，
取`h=min(1e-7, min(abs(a/b), b!=0)/4)`。全部a/b必须有限且
最近折点距离严格为正。逐值检查正负扰动和中心激活的符号完全一致。
对同一批次、同一随机方向重新运行全端口梯度检查。

Huber损失逐样本以longdouble计算正负差后求和，预测仍执行原float64
实现。容差继续为`2e-6*max(1,abs(解析导数),abs(差分导数))`。
这只修订数值检查，训练损失、梯度和更新公式保持原值。
全部18组修订检查通过后，才能开始训练。

## 离线并行

每台机器一次生成自己9组的只读标签矩阵，使用fork共享矩阵，每组一个
进程、BLAS1线程。组种子独立，参数与输出目录按q独立，各组仍执行
完整2048步。每个进程保存检查过的模型与资源记录，父进程收齐9组
后才写完整训练记录。检查fork前父进程只有1个线程。

r9继续等待exp500完整评价check返回0后才训练；l7在梯度检查通过并
核对同一检查记录SHA后开始。算法与模型评价继续只在r9执行。
本次修订通过检查后单独提交，原失败提交和证据保留。
