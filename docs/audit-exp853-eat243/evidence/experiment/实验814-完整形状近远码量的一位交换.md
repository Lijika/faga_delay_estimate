# 实验814 完整形状近远码量的一位交换

2026-10-29，预登记。exp813方向0近4096/远1024配置的全L1
改善1.741425658%，近轴退化5.579406924%、远轴改善10.334642041%。
本轮检验同一32位字段内的容量分配是否限制单次读取表示。
exp811继续独立执行冻结1B，本轮全部在本地历史开发集上筛选。

## Altitude

最终目标同时要求改善表示信息和查询成本。固定完整形状单次读取，
将远域的一位码号预算转给近域，近8192、远512、共同偏置10位，
共10+13+9=32位。四方向int16正文为7,913,472B，目录仍为
115,015,680B，实际静态压缩及在线成本另验。
近轴高损失、远轴已有改善支持这一次容量交换假设；总L1与各域结果
决定扩大，码本规模本身不构成最终Acc或CPU收益。

## 固定数据、训练与判据

沿exp813的方向0、26,624条构造曲面、8,320条非构造开发曲面、
qx<2的92格分域、原权重、尾锚及四轮训练；构造与开发交集为0。
固定种子20261029814。基线仍是exp808重估偏置后的A2048/B256。
复用exp813原生assign、自检和独立损失审核，只改变码量与位拆分。

1. 保持exp813机制门，总加权L1改善至少2%，近远各域退化至多0.5%。
2. 全字段回读、8,320条损失与共同偏置最优性、269条全码枚举通过。
3. 离线CPU≤900秒、wall≤600秒、地址空间≤4GiB；8线程只用于离线训练。
4. 通过才做四方向和最终评分；失败停止此8192/512配置，
   同一分域不再继续扫描码量。下一步须增加诊断信息或改变共享假设。
5. 新完整程序仍使用100M→1B，正式单线程、ELF<100MB、RSS≤2GB；
   当前机制结果仅作开发筛选，未知请求泛化与最终联合收益另验。

## Tactical与Depth

两个域在同一查询中互斥，域内编码的信息预算却共享同一32位目录。
该实验区分一次读取结构与具体近远容量配置的限制。
若近轴仍退化，继续加码的价值缺少支持，应检查共同偏置、域内
形状共享或原A+B组合结构在近轴承担的表达作用。

证据保存validation/results/exp814/。原型为
validation/exp814_region_budget.py；本地开工/dev/sdd可用266GiB。

## 结果

全加权L1从1,164,769,147,405降至1,153,710,531,638，
改善0.949425540%，低于2%门；近轴改善4.233942898%，
远轴退化2.905951298%，分组门失败。全字段恢复、8320条损失与
偏置最优性、269条全码枚举通过。离线CPU38.992927815秒、
wall12.969665776秒、RSS2,002,817,024B，满足离线资源门。

停止此8192/512配置，并按登记停止当前分域的码量扫描。
两个配置将损失在近远域间移动，单次读取函数族在这两组预算下
尚无可部署质量依据；最终Acc、全域静态容量与在线CPU均未测。
