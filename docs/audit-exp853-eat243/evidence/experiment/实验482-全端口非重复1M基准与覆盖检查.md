# 实验482 全端口非重复1M基准与覆盖检查

2026-10-18，实施前登记。用户要求后续测试数据端口全覆盖。
主分布采用既有U-role规则，覆盖208个有出路的非I源端口与288个
Output目标。两端集合由官方JSON的Net、Arc与端口方向独立核对。
补充答复排除I端点，相关规则保存在Obsidian赛题测试集目录。

## 数据与固定方法

复用exp261经过真实图连通性核验的生成器和reach.bin。
生成完整非重复1M，proposal seed为20261018482，
shuffle seed为20261019482。沿用可达、非自查询、随机全局顺序要求。
独立检查全部行的格式、端点资格、可达性、精确去重和EOF，
保存每个源、目标端口频数；任一合法端口缺失立即停止后续运行。

均匀抽取40,000行作为exact评分请求，seed为20261020482，
抽样输入也必须覆盖208个源与288个目标，缺失时停止并重新登记抽样方法。
保存原行号，在任何新标签读取前冻结。已有标签交集单独记录。
本轮仅建立冻结发布版的全端口基准，后续模型选型需新的独立请求验证。

## 完整程序比较

CPU固定基准为exp323发布默认版，ELF位于远端
`build/exp320/narrow/estimate`。当前交付exp354使用远端
`build/exp353/estimate`。另外记录同一exp323关闭缓存的匹配配置，
将默认缓存费用和其他工程变化分别列出。

Xeon core3同机串行。每臂先用完整1M预热一次，随后三轮顺序
固定为A/B/C、C/B/A、A/B/C；A为exp323默认，B为exp323 cache0，
C为exp354。完整输出每次写文件并核对SHA，一致时复用同次评分。
计时记录完整user+sys、wall、初始化、RSS、线程数及缓存计数。
输入生成、exact标签、输出核对与评分分别计费。

预登记统计为三对CPU差的t95区间，另加0.02秒计时分辨率余量。
acc及配对差按源pin成组bootstrap，固定seed20261021482，
2,000次重采样。按源/目标类型与距离分别报告误差和变化行数。
此轮为基准校准，CPU及acc均不作为新算法的验收成绩。

## 验收与停止

完整1M、两端全覆盖、输入唯一、输出行数与顺序、恰好三字段、
整数delay、精确EOF、多次SHA保持、单线程、RSS不超过
2,000,000,000字节、每次不超过3,600秒。
任何输入覆盖或输出契约失败立即停止；记录原始失败。
正式入口与已有源码分别冻结身份，采用私有实验目录。

本地开工时`/dev/sdd`可用约372GiB。远端可用约51GiB；
本轮新输入、输出与生成中间文件预计小于1GiB。
收尾核对重复输出的完整SHA后逐项清理，记录重建命令与释放量。

## 实测结果

2026-10-18 在 `r9r4900` 的 Xeon core3 完成远端阶段。命令为：
`python3 -B validation/exp482_full_role_baseline.py remote`，本地分析命令为：
`python3 -B validation/exp482_full_role_baseline.py analyze`。

`validation/results/exp482/input.json` 记录完整1M输入恰好1,000,000行且无重复，
覆盖208个源端口和288个目标端口；`sample-freeze.json`中的40,000行exact样本
也覆盖同一端口集合。输入检查、输出契约、单线程和RSS门槛均通过。A、B、C
九次完整运行的输出SHA均为
`9b0313090f82df8d148130a6bb39db63ab4acbbea9c35fcbc64ec41896ebfa5c`，
最大RSS为1,693,908,992字节。

完整运行的平均CPU秒为A `113.5233`、B `113.5700`、C `100.9933`。B-A
配对差为 `0.0467 s`，95%区间 `[-0.2246, 0.3180]`；C-A 为
`-12.5300 s`，95%区间 `[-13.0033, -12.0567]`；C-B 为
`-12.5767 s`，95%区间 `[-13.2203, -11.9330]`。40,000行exact样本的
基准准确率为 `99.0907%`，bootstrap 95%区间为 `[99.0702, 99.1129]`，
变化行数为0。完整输出、exact标签和分析报告分别保存在
`validation/results/exp482/`及`build/exp482/`。

开工冻结时可用空间为 `398,826,827,776`字节，当前收尾检查为
`397,523,726,336`字节，期间增加占用 `1,303,101,440`字节（约1.21GiB），
没有满足大文件清理条件的对象。结论是：本轮全端口U-role基准已经冻结，
C臂的CPU收益可作为后续比较基线；本轮未改变正式入口。
