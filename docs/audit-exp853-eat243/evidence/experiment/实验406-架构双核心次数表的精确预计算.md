# 实验406 架构双核心次数表的精确预计算

2026-10-18，新结果前登记。正式exp354，CPU发布基准exp323。
主假设是exp405重复计算同一组架构双核心费用，架构全域精确预计算可以降低名义候选成本。
竞争解释是21MB表访问或初始化抵消查询收益，候选扫描本身仍占主要部分。
理论见Obsidian《架构双核心次数函数的全域精确预计算》。

固定4096组架构矩阵、象限与首末方向，NX取0至20，NY取0至60。
全部5,246,976项在读取请求前计算。有限值按cost16、x8、y8打包为uint32，
无限值用UINT32_MAX。两核心非空，最多支付78个核心Arc；
构建时验证全部H/V子矩阵非负有限、78*Mmax<65536及每项容量与计数边界。
表容量20,987,904字节，运行时生成，不扩大正式ELF。原exp401解析式为控制。

候选只替换exp405固定双核心的费用与稳定分配求值，全部桥、顺序、真实DAG、
筛选、输出和计数保持。原源码与冻结结果复用，不改正式入口。
同ELF以固定运行参数选择解析式或表，记录二进制身份。
77条开发中段全部名义结果、真实结果、稳定见证与DAG工作量逐项保持；
sanitizer前4条核对，既有exact与评分复用，不生成新标签。
新增一次只读计数运行记录实际双核心查表键数量和重复度，该运行不参加计时。

独立组件检查完整5,246,976项解包与解析式逐项相同，
全部4096分支各8×8边界次数与穷举分配比较，共262,144项。
普通与ASan/UBSan都执行全部检查。
新组件集使用固定seed202610180406，从5,246,976个键中抽1M项，
排除exp401已用的全部1M键，先冻结再测；检查内部唯一性与开发集不重合。
这些是名义组件键，完整未知请求泛化及总体acc另验。

本机AMD只作语义与资源诊断。Xeon Gold6226R核3、通用O2、单线程串行，
组件先完整读入，在同ELF中各预热1次，再交错3块，每块每个方法遍历1M不同键一次。
主性能指标为表对解析式每键CPU差，最小实际收益预定5ns/键；
三块配对t区间95%上界须小于0才判查询收益明确。
77条选择器先分别预热，再按A/B、B/A、A/B进行3个完整进程配对，
每进程同时记录初始化、选择CPU、完整CPU和峰值RSS。
报告同样的配对差区间，完整进程不预定必须更快；
按初始化差除以每请求或每候选节省给出条件摊销点，假设单列。
组件差和完整选择器差分别报告，均不算完整估计器阶段成绩。

每个运行CPU≤120秒、RSS≤2GB、单线程；sanitizer放开虚拟空间限制并核对RSS。
所有语义、稳定词或资源失败即保存证据并停止扩大。
查询收益、初始化和候选重复度共同决定继续共享min-plus表示或缩小表。
本轮完整估计器运行、总体评分、新全图exact均为0。
正式候选形成后继续用1M、10M、100M阶梯，最终acc严格大于99%。
开工/dev/sdd可用385G，收尾记录清理清单。
