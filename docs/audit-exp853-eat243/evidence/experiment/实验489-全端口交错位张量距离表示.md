# 实验489 全端口交错位张量距离表示

2026-10-18，查看候选结果前登记。exp486端口双投影与exp488三组min-plus
因子的固定配置均未达到质量门。本轮假设为对应lane位和几何位的交错顺序
能保留更多端口耦合，使小TT核心在完整端口域同时满足质量和容量要求。
资料见`doc/全端口距离表示-交错位张量列车资料-20261018.md`，
独立推导保存在Obsidian《端口与几何交错的张量链及双表查询》。

## 固定数据与候选

复用exp483认证字段及exp487的`context0.i32`，方向(+,+)、余类(0,0)，
全部208合法非I源、288 Output目标及552几何点，共33,067,008值。
已查看的认证域作为开发域，新exact标签0。正式入口保持exp354，
exp323继续作为后续完整估计程序CPU基准。

端口重新编号为源26族×8 lane、目标36族×8 lane。Z的20族顺序沿用
`roles()`；源逻辑族为A/S各Q0、Q1、Y，目标逻辑族为A/S各0至5、D、M。
逻辑A至H字母映射lane0至7。保存原名称、ID和新坐标并检查完整双射。

```text
sf=a0+2*a1; tf=b0+2*b1+4*b2+12*b3
sl=s0+2*s1+4*s2; tl=t0+2*t1+4*t2; pk=sk+2*tk
i=x0+2*x1+4*x2; j=y0+2*y1; g=46*i+j
A=[a1,p0,x0,b0,a0,p1,x1,b1 | y0,p2,b2,x2,b3,y1]
B=[a1,p2,x1,b1,a0,p1,x0,b0 | y0,p0,b3,x2,b2,y1]
shape=[13,4,2,2,2,4,2,2,2,4,3,3,3,23]
```

两排序各独立训练rank上限32/48，顺序固定A32、A48、B32、B48。
全部端口和全部几何参与每次训练及测试。第8轴后切为6656×4968，
保存全域双射证据，禁止更换排序或按测试结果选择迭代轮。

## 拟合和解码

拟合`Z=(D-trend)/(128+125*i+125*j)`，`trend=125*i+127*j`。
float64从左到右TT-SVD，调用安装版SciPy的经济型`gesdd`直接SVD。
每步保留`min(cap,rows,cols)`列，以U每列最大绝对值坐标为正固定符号。
记录全部奇异值、实际rank、弃去平方范数及逐步CPU/RSS。
Context7连接失败，接口依据本机安装版帮助及官方文档核对。

保存float64核心作表示参照。每个核心独立选择2次幂尺度，按半值远离零
舍入成int16，存int32指数，完整核对范围、非有限值和保存回读。
零核心指数固定0。启动时在float64中按模式次序展开左右两个半链，
第8轴切口得到的两表一次转换成float32。原核心和float32表分别保存。

对每个请求按行优先混合基计算左右键；按rank顺序以float64累加两行
元素乘积，逐次乘法与加法分开。恢复整数分母和趋势，半值远离零取整，
截断到非负；同端口零位移显式输出0。完整评价直接使用这一求和顺序，
最终整数SHA与实际解码路径一致。

每臂分别完整评价浮点核心、量化核心的float64表、最终float32表。
从exp485冻结的rank128空间基资产提取同context参照，完整评价。
记录总体、近轴/内部、每源/目标、类型、族和lane分组，逐端口对保存
误差极值、变化数、评分和绝对误差总量。保存每阶段完整整数输出和SHA，
量化及表转换的变化数单列。端口对误差区间只作当前有限域证据。

量化核心回读后重新展开，逐位核对保存的float32表，再全域回读解码，
核对整数输出、SHA与误差区间。每个端口对另做一个独立标量查询，
共59,904次/臂。准备时和后续核验均覆盖全部端口，禁止缩窄端口集合。

## 资源、扩大与停止

四臂合计训练CPU上限6000秒，每次SVD后检查；离线峰值RSS先固定
1,500,000,000字节，超限保留已完成证据并停止当前协议。标签数组和
LAPACK工作区均计入RSS。资源调整须另行登记，保持完整端口域。
BLAS固定8线程，四臂串行。本机CPU只记录离线成本。

每context核心标量上限r32/48为31,194/66,410，全480 context的int16
主体为29,946,240/63,753,600字节。每臂按实际序列化文件×480计算
含头保守静态量，指数、rank、模式、映射全部计入；Zstd另记录。
全480 context查询表主体为714,178,560/1,071,267,840字节。
这些数值属于固定布局的数组容量，其余context精度与程序总RSS另验。

任一臂完整全域评分总体≥99.97%、近轴≥99.9%、含头条件静态≤80MB、
全context查询表≤1.5GB，并通过全部身份、保存解码和资源检查，才登记
完整八context验证。质量门对本开发域作确定性判断，统计区间留给未参与
选型的真实请求验证。四臂均未过则结束本固定排序/rank配置扩大。
末端谱与各阶段误差用于判断表示容量、量化或索引问题，原判定保留。

通过八context和全部余类编译后，先按完整未知非重复全端口1M测试
真实acc和完整程序CPU，再按1M、10M、100M阶梯验证。所有启动展开、
解析与输出均计入完整程序CPU。真实acc>99%、100M<100秒、
1B的100–300秒、官方平台和跨架构表现继续作为活动目标。
