# 实验274 查询局部格点标签

2026-10-16。基线为exp273私有完整程序，提交18e91e6。当前完整
独特U-output 1M两次CPU为324.02与323.22秒，阶段目标为100秒。

## 预注册

主假设是把distance和parent按查询首次触及的格点连续存储，可以
减少随机标签访问与逐状态清理成本。两表继续使用32位元素；每格
仍保存全部Z端口。cellBase保存格点到局部块的映射，查询开头只
清除上次触达格点的映射，新格点的distance块连续填充kInf。
局部向量按需增长并复用容量，支持原query接口中的任意cap。

堆和parent继续保存原全局id，保留原tuple全序、strict relax、q、
1024有效展开预算及动态父链。finish的环检测上限改用result.states，
它与原touched状态数相同。rank准备只保存局部偏移，向量扩容后
重新按偏移访问。实现涉及init、query清理、prepareRank、relax、
stale判断及finish；公共调用方、模型、CSV和架构加载保持。
独立推导保存在vault的`查询局部格点标签的状态等价`。

修改范围为私有legal_path_search.h/.cpp及实验runner。先复用
35,702条开发请求的逐次q、搜索字段、完整path及七组CLI，再核对
Arc费用变体。追加128条请求在cap=-1/0/1/17/1024/4096下的
配对搜索及路径检查，穿插非法格点与同端点早退；审计版检查局部
偏移映射并记录扩容。任一语义差异即停止候选。

冻结源码、编译参数、ELF、模型、输入及runner身份，保留通用
编译参数。正式src、./estimate和subm保持现状。已有开发请求
与exact标签用于纯等价检查，本轮保持模型、特征及阈值。

远程r9r4900先进入~/lhjwork/eda2026，在core3单线程串行运行。
两套原序独特20k各臂预热一次，正式顺序AB、BA、AB。主指标为
完整程序user+sys，配对差用df2的95% t区间；两分布均点省至少
1%且差值区间上界小于0，支持明确工程收益并进入完整1M。点省
且区间跨零保留待定，明确变慢时停止组合。阶段指标只记录进度。

明确加速后追加两次候选完整U-output 1M，与exp273已核验SHA
比较；跨批CPU只描述规模结果。AMD/WSL2另用同ELF与同20k协议。
repeated 1M沿用1,000个独特请求，预热一次、AB/BA/AB，记录
cache miss和hit。全部运行核对原序、行数、三字段、整数delay、
精确EOF、完整SHA、单线程、RSS≤2,000,000,000字节及3600秒限制。

本地开工df可用419GiB，远程可用193GiB。证据位于
validation/results/exp274，构建位于build/exp274。跨FPGA架构、
官方平台及完整100M和独特1B性能留待各自验证。

## repeated与验收脚本修复

repeated 1M含1,000个独特请求。三对平均CPU从3.490降至3.427秒，
点省1.81%，配对差95%区间为[-0.115,-0.012]秒。time的user和sys
各保留0.01秒，双臂CPU差的舍入误差界为0.02秒。按这个界扩大区间
后上界跨零，因此repeated结论为输出与资源通过、观察到小幅节省；
它的收益确定性弱于独特20k。八次输出SHA均为
`4517d95d2c3a31591de0121ee5db4a124078ce2e847f7bfcc18f9468aa13b07a`，
最大RSS为1,764,032,512字节。两臂诊断各有1,000次cache miss和
999,000次cache hit。证据见repeated.json和raw-repeated/。

首次追加验收在冻结辅助脚本身份查找处抛出StopIteration，发生在计时
之前。freeze.json记录了准备机器上的绝对路径，验收脚本原先按相对
路径精确查找。本轮只修正exp274_acceptance.py的路径定位，继续检查
完整字节数与SHA，原freeze、主runner和候选ELF保持。回归测试覆盖
full和repeated两个入口，并验证SHA变化会被拒绝；本地和远程均通过。
原失败脚本、traceback和修复前后测试日志保存在acceptance-path-failure/。
