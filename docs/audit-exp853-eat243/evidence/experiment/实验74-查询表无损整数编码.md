# 实验74：查询表无损整数编码

日期2026-09-26。开工 `/dev/sdd` 可用490G。

## 预注册

- 基线exp71动态bin SHA `47a7ef40b9f4260e54ea4f646ae9bf3e33536bc770d1e570468203b98f7a94a0`，当前根入口同SHA；模型仍exp63。相同1M unique输入SHA `2cf587f1b27ccc5699040e64ea3efc6eb68c100cfd72a36cad383383a018d7bd`，输出SHA `c17380dddfeba86addf764bad79a887eb25bab8544d4f64f69d8cb3097fe7e19`。
- 先对当前成品完整1M `perf record` 确认主要热点；实验71已测大页仅降低部分dTLB成本，本轮检查查询表整数编码能否降低所读数据规模。
- 假设有限表值均为 `gcd(scale, slopeA[0..3], slopeB[0..3])` 的倍数。先在Obsidian记录基于种子、势、转移和终点公式的整数闭包推导，再用现有friend读取器对mult1/mult2的所有表项检查公因子、有限范围、INF和编码/解码差异。理论与实际数据都满足才允许私有编码原型。
- 预定表示为有限表值除以公因子后的int16，保留-32768为INF；有限商必须位于[-32767,32767]。必须逐项完全还原，禁止近似、裁剪或改变取整。无法表示时保留原表行为。
- 先测结构与内存成本，再固定具体实现。当前mult2原表813,957,120字节；新增一份int16查询镜像约406,978,560字节，两份总计约1.22GB。是否保留宽表或转换存储，需结合现有写表/探针消费者及2GB预算决定。
- 只改存储表示；数值、模型和输出保持。原型需完整1M输出SHA/逐行契约、探针和资源检查通过，再预热后3对交错CPU。CPU差95%上界<0且综合点收益≥0.01才正式接入；最终包验收仍为3轮1M。每distinct查表成本按K外推，平台1B/隐藏集尚未验证。

## 原型验收与判定

私有候选 `build/exp74/estimate-packed` 使用 `-packed-table` 运行。3,107 条 holdout 与冻结 exp63 输出逐字节一致，SHA 为 `d9ff0c3ef22a08957b7d3b7c1ad211262bf0d541d9e00ebeafd039eada954808`。

完整 1M 使用输入 `build/exp57/timing-1m-unique.csv`（SHA `2cf587f1b27ccc5699040e64ea3efc6eb68c100cfd72a36cad383383a018d7bd`），三轮输出契约、行序、端点、字段、整数 delay、EOF、线程数和资源门槛均通过，输出 SHA 均为 `c17380dddfeba86addf764bad79a887eb25bab8544d4f64f69d8cb3097fe7e19`。候选最大 RSS `1,265,344,512 B`，仍低于 2,000,000,000 B。

与 exp71 基线进行 3 对交错运行，CPU 差（候选−基线）为 `+3.00/+4.46/+3.11 s`，均值 `+3.523333 s`，95% 区间 `[+1.503631,+5.543036] s`。综合收益点估计 `-0.029361`，保守下界 `-0.046192`，未达到预注册门槛。原因是每次查询增加 int16 解码和乘法，节省的表带宽不足以抵消算术成本；候选不接入正式路径，正式版本继续 exp71。

原始计时证据：`validation/results/exp74-timing-1m-unique.json`。候选源码保留在提交 `06b62d6`，可在该提交运行 `sh scripts/build.sh` 后用 `./estimate -packed-table` 重建；正式源码由后续提交 `8128c23` 恢复。失败候选保留用于回溯，1B 与隐藏集未测。
