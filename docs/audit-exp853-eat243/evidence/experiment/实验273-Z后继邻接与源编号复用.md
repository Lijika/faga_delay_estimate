# 实验273 Z后继邻接与源编号复用

2026-10-15。基线为exp270私有完整程序，ELF身份从其freeze.json读取。
exp272采样中relax占约46%至47%，后继循环及端口查找仍在线执行。
第一阶段独特1M目标为100秒，当前基线两次为370.26与366.50秒。

## 预注册

主假设是按架构一次构建有序Z后继邻接，可减少每次展开的端口分类
和两次编号查找。init按原Arc顺序保存`{sourceIndex,delay}`，
保留重复Arc。LegalPathSearch与ResidueEstimator均按端口编号递增
排列全部Z端口，rank源的前缀编号与搜索Z编号相同。

relax直接接收Z编号，原坐标由同格准备状态确定；目标相等判断使用
原goalId。Z种子及非Z种子继续在原调用位置更新，非Z源的直接Arc
检查、非Z目标的terminal检查及finish保持原实现。
同一输入应保留全部strict relax、q、tuple键、有效出队、parent、
路径与最终整数输出。独立推导见vault笔记
`Z后继邻接的顺序保持与源编号直用`。

修改范围为私有`legal_path_search.h/.cpp`及实验脚本。调用方为
ResidueEstimator的init/query及既有search-check；公共接口、模型、
CSV、架构加载和正式入口保持。新增内存只来自静态Z邻接。
源编号前缀在审计构建逐端口断言，每次relax仍与原id及q比较。
复用35,702条开发请求、109,505,958次q与路径检查、七组CLI，
另用已有Arc费用变体前128条开发请求检查q、搜索字段和完整路径。
任一语义差异即停止候选。

远程r9r4900工作目录内core3同机串行，两种原序20k各臂一轮预热，
正式顺序AB、BA、AB。主指标为完整程序user+sys，配对差使用df2的
95% t区间。两分布均点省至少1%且区间上界小于0，支持明确工程
收益并进入完整1M。点省且区间跨零保留待定，明确变慢时停止组合。
所有运行核对输出SHA、原序、三字段、整数、EOF、单线程、
RSS不超过2,000,000,000字节、CPU及wall不超过3600秒。

远程明确加速后，追加两次候选完整1M并与exp270已核验SHA比较，
检验规模、资源及多次一致；跨批CPU仅描述，不计算配对区间。
AMD/WSL2使用同ELF、同20k和同协议，跨机器结论分别报告。
本轮沿用exact标签，纯等价实现不参与模型或阈值选型。
100秒阶段指标继续标记进度，已证明的CPU收益继续保留。

源码在`build/exp273/`，证据在`validation/results/exp273/`。
冻结编译命令、源码、补丁、输入、模型对象及ELF身份。本地开工
`df -h /dev/sdd`可用419GiB，本轮沿用已有输入。

`315ec21349def0a9a3e808ca66b331f987617d41d919a67c7de412958717d06d`。

11,904字节，实际分配容量与峰值RSS以测量为准。

35,702条开发请求的109,505,958次q、搜索字段及完整路径保持，
七组CLI输出相同；原Arc费用变体的七条边界和128条开发请求的
逐次q、搜索字段及路径也相同。现有审计构建逐Z检查源编号前缀，
逐relax检查原id，逐次q比较原estimateBase。

静态ELF和原序20k，按一轮预热、AB/BA/AB运行。

## repeated检查

20k结果读取前另存`repeated-protocol.md`，随后使用原repeated 1M，
共1,000个独特请求。远程一轮预热、AB/BA/AB三对，平均CPU
3.640至3.497秒，配对差-0.143秒，95%区间[-0.181,-0.105]秒，
节省3.94%。八次均输出1M行并通过完整契约，SHA同为
`4517d95d2c3a31591de0121ee5db4a124078ce2e847f7bfcc18f9468aa13b07a`。
最大RSS为1,764,028,416字节，两臂诊断均为1,000次cache miss、
999,000次cache hit。证据见`repeated.json`。

通过，完整SHA同为
`86dca80df1fa1ce5ccf78aca15e3e96177238a8362040aa22392213f41a5612c`，
