# 实验754 核心lane拓扑与整数端点势审计

2026-10-27预登记。前轮exp751/752排除了固定族均值表和有限采样
INT8左系数更新，exp753完成14次100M后联合门失败。本轮继续为
路线B寻找更有效的名义背景表示，先核查报告第3章的lane归约前提。
这项结构检查只决定是否具有无损归约资格，完整部署收益另验。

读取exp728冻结的五个架构JSON，只将名字完整匹配I/Z族加[0..7]
的端口定义为lane核心。family保留I/Z及完整族名，其他逻辑端口
作为边界单列。边轨道键包含Arc/Net、起止family、相对lane、
dx/dy和其他语义字段；Arc费用取原整数delay，名义Net费用为0。
每个轨道必须恰有八个成员且源lane完整，端口Direction须保持。

在拓扑全部通过时，逐轨道计算整数R(e)=8w(e)-sum(orbit weights)，
以BFS检查H(v)-H(u)=R(e)。保留完整整数势、冲突数量和首条闭合
约束见证。独立从原边与完整轨道权重重算见证，各步首尾相接且
闭合R和非零即足以证伪本端点势表示。合成检查覆盖可行势、
单边扰动导致冲突，以及缺失轨道成员。

若有拓扑或势冲突，停止把该核心当作无损八倍归约；按原始边定位
失败范围。相对lane的近似主项、完整lane剩余和有证明的支配边删除
仍需分别验证。若全部通过，再核验真实Net位置映射、Line费用和
逻辑端点消元后才构造压缩背景。两种结果均保持完整端口身份，
本轮不改变生产入口和模型。

全部计算在r9的research/exp745，CPU30秒、wall60秒、RSS1GB，
新exact标签和完整estimate运行均为0。冻结JSON身份须与exp750
登记的exp728架构相同。原始证据保存在validation/results/exp754。
本地开始约273GiB，r9开始约24.35GB可用。理论笔记为
《核心lane边轨道与端点势的整数一致性条件》。

## 结果

核心320端口、40族、2912边组成364个完整八成员轨道，拓扑条件通过。
整数势传播后2563条边与赋值冲突，六步约束见证的缩放闭合和为56，
即原单位7ps。见证全部来自Arc，按原JSON重新取出每步的八个轨道
费用后复算一致。它是带正负号的约束游走，不能当作有向可行路径。
这种轨道均值加端点势的无损表示停止；相对lane统计主项和完整lane
剩余继续具有研究资格。真实Net位置映射与逻辑端点消元未验。

首次合成自检只有一条独立环，单边扰动在轨道去均值后仍相容，
负控制的预期不成立。失败运行未进入真实图审计，原代码、冻结记录和
stderr保存在`validation/results/exp754-self-check-failure/`。
增加第三类边形成独立闭合约束后，正负控制和缺边检查均通过。

主审计CPU0.286083秒、wall0.286442秒、RSS23,633,920B。
`validation/exp754_audit.py`独立读取原始Arc复算48个费用并核查闭合和。
完整estimate、100M、1B与新exact均为0次，生产版保持exp728。
