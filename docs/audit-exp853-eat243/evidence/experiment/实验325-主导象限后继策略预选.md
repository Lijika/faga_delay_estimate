# 实验325 主导象限后继策略预选

## 条件预注册

2026-10-16。基线为exp323正式静态ELF，复用exp320/narrow，
SHA为14b6fea221e7158c6acab1a51768a9e83ba7e570f5744e6416490cd1ffae1b1a。
主目标为减少独特请求的搜索工作，100M小于100秒、1B为100至300秒
继续作为阶段指标。开工本机/dev/sdd可用398GiB，远端可用183GiB。

主假设是四角主导条件成立的格点上，多数有用后继可以由冻结名义
排序表的前三个分支覆盖。初始化按目标列、residue、真实Net落地
端口和象限计算前三个Arc位置，以三个5bit位置存入uint16。
评分键固定为1000*rankScale*arcDelay+1010*slot。舍入和权重
仍由原搜索执行，这个预选键用于候选生成。真实坐标、完整端口、
Net、Arc、前驱和路径重放全部保持。

固定三个单项候选policy1、policy2、policy3，分别选前三个中的
前1、2、3个。只在已有rankCell.margin>=rankSpan_、窄表有效、
落地端口已建索引且预选至少有一个有限分支时生效；其他格点仍
枚举完整后继。保留原邻接顺序。预算固定480，权重1010，Both
端点回退、模型、upper tree、bias及CSV契约保持。

预选表根据加载架构生成；度数超过31的落地端口使用完整枚举。
当前架构预计新增176,947,200B，实测初始化和峰值RSS。所有算法
候选采用通用O2静态构建。正式源码和交付入口保持exp323。

本轮先用exp257的12,150条正标签开发请求审计四臂搜索与所有有限
路径，baseline逐字段重现既有light01-480记录。检查预选打包的
独立排序对照，普通与ASan/UBSan均执行。路径费用用原JSON的
独立解释器逐边检查，重放失败时先修复原型。

联合开发数据固定为U-output 9,472条、U-role 14,080条和exp258
12,320条，沿用已查看的exact、分层人口权重与stratum。先独立
路径审计，再在空闲Xeon核3串行执行现有完整进程测量。每分布
四臂预热一次，计时顺序固定ABCD/DCBA/ABCD，三对配对差用
t区间并计入0.02s计时舍入；精度沿用10,000次分层配对bootstrap，
seed固定20261016325。新增exact标签为0，评分和估计CPU分列。

主指标是各分布的总体acc、配对精度差、变化行数、分带和端口对
误差、完整CPU、初始化、展开、relax、q求值、成功率与RSS。
新预选表初始化计入完整CPU；小样本若由初始化主导，保留查询
工作量和两规模诊断资格。总体acc严格大于99且无明确区间支配的
候选保留；最低实际CPU收益固定0.5%只用于效应描述。区间跨零
保留待定，本机AMD性能不用于淘汰。精度通过后优先对U-output
完整成本较低的臂验证新请求；初始化主导时先做固定100k诊断。

停止条件为固定三臂审计及联合开发比较完成；精度未过的固定臂
停止扩大并保存证据，合格臂继续新请求和完整1M。后续新候选另行
冻结。新请求、完整1M、100M、1B、跨架构和比赛平台本轮待验。
理论见Obsidian的`主导象限后继预选的路径合法性与近似边界.md`。
