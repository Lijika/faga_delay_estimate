# 实验70：查询诊断计算性能画像

日期2026-09-26。开工 `/dev/sdd` 可用490G。

## 预注册

- 基线exp66动态版 `build/exp66/estimate-unordered`，SHA `6686f424e4f923df3b6991da6e648553aad5d98a2c4cd46564e44cb2faf16d89`，当前根入口同SHA；源码提交 `175449a` 的队列优化已接入。模型保持exp63。正式包bin SHA `1f68d9248f5fab50494bcb0cf6d0f53ae15945b1fb4429b75cdf78b80cecf1c8`。
- 冻结1M unique `build/exp57/timing-1m-unique.csv`，输入SHA `2cf587f1b27ccc5699040e64ea3efc6eb68c100cfd72a36cad383383a018d7bd`，完整输出SHA `c17380dddfeba86addf764bad79a887eb25bab8544d4f64f69d8cb3097fe7e19`。
- 先运行一次 `perf record -g -e cpu-clock:u`，对无子调用累加的热点和汇编采样定位；随后按ROI选择单变量优化。实验66在优化前记录 `quadrantDiagnostics` 为30.41%，候选理由需由当前成品画像再次核实。
- 可接受方向优先复用同一数值函数，使编译器删除生产调用不读取的诊断字段；必须保留探针的完整诊断输出。诊断与生产数值共用实现、INF/rounding/Line/端点语义保持，属于当前不变量。
- 候选先检查零值、不可达、边界端点、完整1M输出SHA与契约；若涉及诊断编译，检查现有探针能链接且结果与冻结probe一致。正确性通过后预热、同机串行3对交错CPU。通过门槛为CPU差95%上界<0，精度等价综合收益点估计≥0.01。资源要求单线程、RSS≤2,000,000,000 B、每轮≤3,600秒。
- 公开1M只用于性能和输出契约，模型保持。每distinct请求的成本优化按K外推，hidden/1B需平台结果；不得把1M差乘1000直接当1B收益。

## 结果

完整画像103,213样本、丢样0，输出SHA与冻结值一致。无子调用累计份额为 `quadrantDiagnostics` 39.25%、`runResidueDijkstra` 15.58%、`fillTargets` 15.14%、`RadixFrontier::top` 10.94%、`applyResidual` 5.64%。`perf annotate` 中诊断函数89.17%的样本在表读取后的依赖store附近，采样位置包含执行延迟，不能据此认定store本身耗费全部时间。

一次 `perf stat` 为106,538,496,511 cycles、144,744,853,008 instructions、IPC 1.36、509,163,143 cache misses、290,505,930 dTLB loads及73,682,479 dTLB misses（25.36%）。这支持内存/地址转换延迟是需调查的瓶颈，计数为整进程口径。I/O及锁未出现在主要用户态热点；程序仍为单线程。输入和输出SHA均核实。

| 候选 | 依据与成本范围 | 风险/工作量 | 顺序 |
| --- | --- | --- | --- |
| 生产叶调用内联共享诊断函数 | 39.25%函数占比中有不被读取的诊断计算，收益只是其中一部分 | GCC flatten属性一处，保留同一数值实现 | 本轮测量 |
| 表使用透明大页 | 高dTLB miss；主机策略为madvise | 要测页实际合并和平台支持，需处理分配对齐 | 后续单变量候选 |
| 表值缩放/压缩 | 813,957,120字节查询表 | 需证明量化无损、取值范围和INF契约 | 待独立分析 |

本轮唯一代码变量为 `estimateBase()` 添加GCC `flatten` 属性，编译器可内联 `quadrantDiagnostics` 并删除未读字段。改变代码生成，不更改候选枚举或数值公式。渐近成本仍是每叶4个表值及O(1)算术，模型和输入输出成本保持。

候选动态bin SHA `aab20f571999765c6b1baa0be6d3407527c18f99e166c6b3f0a6690a9bdcc6b3`。私有 `quadrant_probe` 的99条回归和14条边界/无效端点输出与旧exp51探针逐字节相同，生产值/诊断值差异0。两个dump SHA分别为 `510c772ca8be122f37b59858c5d2d974687aae33a87a9e5cecac1e3751aefe5a` 和 `c05e34981a4431ebfc43b6a4e99e2a57ff1e3395fc3ae50928bc541913a20724`。

`build/venv-ml/bin/python validation/exp70_timing.py` 在相同1M输入预热后交错3对，候选减基线CPU差为 `+0.23/-0.47/-0.59 s`，均值 `-0.276667 s`，95%区间 `[-1.376815,+0.823482] s`。点综合收益+0.002306、保守下界-0.006862，未通过门槛。8次完整输出/资源契约全部通过，原始证据 `validation/results/exp70-timing-1m-unique.json`。

本轮结论为性能收益未确定且点收益不足。正式源码移除该属性，候选保留在 `validation/exp70_flatten.patch` 和私有bin中；可对exp66源码执行 `git apply --unidiff-zero validation/exp70_flatten.patch` 后用既有g++构建命令复现。该零上下文格式避免保存patch的空白上下文被 `git diff --check` 识别为空白错误，应用预检通过。这个结果与热点受内存延迟影响的假设相容，不单独证明其成因。正式包和根二进制继续为exp66。

收尾 `/dev/sdd` 可用490G，本轮未删除文件，释放量0；1M输出及画像保留。下一步独立测量透明大页是否实际合并及降低dTLB miss。
