# 实验355 exp323对照补充协议

2026-10-17，候选100M仍在执行时，用户指定CPU基准固定为exp323，
并允许探索阶段acc下降，最终版本要求acc严格大于99%。本补充在查看
100M完整计时结果前固定，原候选运行和预登记保持。

同一Xeon核3、同一完整非重复U-output 100M、同一run_scale计时器和
真实文件输出，在候选运行及检查全部结束后执行exp323。先以相同20k
预热一次，再完整100M一次。exp323采用原发布默认cache64，候选采用
默认cache0；输入唯一保证两者结果命中数均为0。消除全miss探测成本
作为工程收益的一部分。原exp323 ELF SHA为
`14b6fea221e7158c6acab1a51768a9e83ba7e570f5744e6416490cd1ffae1b1a`。

分别记录user+sys、wall、RSS、线程、全量合同与输出SHA，并比较100M
逐字节输出。CPU差使用候选减exp323，节省比例使用1-候选/exp323。
本次顺序固定候选、exp323，每臂一次，结果仅给点差，时序漂移和重复性
未量化。单次CPU增加时先调查环境与成本，正式收益结论需要足够配对证据。

21600秒诊断上限、3600秒资源判定、2GB及单线程要求沿用原协议。完整
100M缺少全量exact，公开1M acc与该分布CPU分别记录。候选输出保持时
复用公开99.0106972142%，其他算法探索按各自输出重新评分。

原启动SSH在20秒处超时，远端进程继续运行；核对进程及输入检查后保持原次。
输入检查CPU95.443434秒单列，完整父文件SHA及前缀关系通过。
