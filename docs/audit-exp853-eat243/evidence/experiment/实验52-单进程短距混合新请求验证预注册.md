## 主指标与门槛

报告 baseline、完整 `xgb-base`、混合三者的逐带 accuracy、MAPE、可达性和配对差。主比较为
混合−`B_perf`，按原始七带请求份额加权；配对 bootstrap 10,000 次，seed 20260925，带内重采样，
保留 negative exact，band 0 全量时不重采。要求 accuracy 差的95%下界大于0，等带 accuracy 不下降，
false reachable 和 reachable false unreachable 不增加，negative exact 无 false reachable。

若主精度门槛通过，候选再按实验47固定协议在同一新请求上做一次 `1M unique` CPU screen，比较
baseline、同源码 xgb 和 hybrid，预注册预算沿用实验47的联合约束：新切片精度点估计对应的
`Δ综合分 >= 0.01`，95% 下界为正，并满足单线程、RSS≤2GB、wall≤3600s。screen 通过后才补做
100M repeated/mixed；只有全部资源和输出契约通过才进入五次1B验收。

精度或等价门槛任一失败，保留完整新请求标签和原始输出，正式入口继续 `B_perf`，不跑100M/1B。

## 2026-09-25 采纳预算复核

复核发现 `exp52-stage-timing1b.json` 经实验47的 `budget_summary()` 生成时沿用了实验46精度
常数，原点估计预算3.066211 s、区间预算3.397547 s来自旧切片。实验52的1M screen已正确
使用本轮精度，五对1B的实际时间、资源、输出及差值区间保留有效。

用本轮accuracy增益0.038360753 pp、95%下界0.029886082 pp重算，点估计CPU差预算为
`120*(0.8*0.038360753-0.01)=2.482632 s`，区间上界须小于
`96*0.029886082=2.869064 s`。现有CPU均值差为-6.424 s，上界为6.546672 s，条件综合收益
点估计+0.084222、保守联合下界-0.030647，候选不采纳的结论保持。

可按下列只读计算复核；原JSON保留，修正记录位于
`validation/results/exp52-adoption-budget-audit.json`，其中记录三个来源文件哈希。

```python
import json
a = json.load(open("validation/results/exp52-fresh-validation.json"))["gates"]
t = json.load(open("validation/results/exp52-stage-timing1b.json"))["paired"]
point = a["corpus_weighted_gain_points"]
low = a["paired_ci95_points"][0]
print(120 * (0.8 * point - 0.01), 96 * low)
print(0.8 * point - t["mean_seconds"] / 120,
      0.8 * low - t["ci95_seconds"][1] / 120)
```
