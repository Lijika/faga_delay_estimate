# 实验108 P4 真实端点跳格信号预注册

2026-09-27。本预注册先于无标签探针实现及结果。基线为 exp92 正式包 SHA-256 `607b52e80cb6dad8905e4c46ff3ed45fa7670730b165e3ca995e34c97c837c63`，47 维模型 SHA-256 `92a3c09217e7881fc07704159f4ba7d123f233bcb21dab5f78a2a8fc61c015cc`。架构五文件身份沿用 `validation/results/exp106-freeze.json`。研究代码留在实验分支及私有构建目录，不改正式入口。

## 假设与固定信号

真实 Block 跳格使源端首个 Net 或目标端末个 Net 的位移超过名义 Net 位移；47 维含端口名义位移和端点位置，但没有 `resolveNet` 算出的真实位移与 Block 费用。若源端是 Z 口，正长度路径的首个 Net 固定；若目标端是 I 口，末个 Net 固定。排除同 pin 零路径。候选四个特征固定为源/目标 Net 的额外轴向位移与 Block 费用；费用等于该跳的总 delay 减实际位移跨越的 Line delay。仅在对应端口类型且解析有效时取值，其他行置0。此前实验12曾将首末 Net 的 Block 费用直接加到近似值，效果为负；本轮只检验其作为 XGBoost 条件特征的价值。

## 无标签预检

数据为实验106冻结的 affine unique `[42M,44M)` 共2M行，SHA-256 `e4f7d186975dadf461ca06dd852052b60ced140b3a3156bf61309875af2283d9`。两个连续1M分别计数。C++ 探针仅用 `Architecture::parsePin`、`resolveNet`、`resolveNetPredecessor`、`lineDelayCrossing`；目标前驱通过正向 resolver 回放核对坐标与费用，抽样见证逐条记录。已有47维的名义 Net 位移和端点位置只能给出跳格可能性，本预检测量实际发生率；不声称这些特征在统计上完全独立。

每个1M中，源端或目标端任一真实跳格的并集须至少350行，且每类非零费用/位移与 resolver 语义一致。微秒级成本门槛为同进程解析基线与计算信号的三对交错运行中，平均增量CPU不超过2us/行；报告点估计、配对t区间、进程RSS和完整输入SHA。任一窗口覆盖不足、回放失败或成本超限即停止，不读取新标签，也不训练。覆盖与CPU只是必要条件，不作为精度收益证明。

## 通过预检后的训练及验证

若预检通过，仅训练一个固定的51维 `reg:absoluteerror` 模型：exp92的47维加上述4维，沿用46,505行已核验 exact 训练池、七带权重、128树、depth8、eta0.1、gamma1、seed20260919及其余exp92参数。开发窗口只用已有 exp93 `[38M,40M)` 和 exp105 `[40M,42M)` 标签，各自分带加权评估，对照冻结exp92；没有参数扫描。进入独立窗口要求合并精度增益至少+0.03pp，两个开发窗口点增益同号为正，分带配对 bootstrap 95%下界为正，两类可达性误判不增加。否则停止。

通过开发筛选后冻结模型、特征源码、阈值和SHA，再生成独立 affine unique `[44M,46M)` 七带样本的 exact 标签。独立主门槛是点增益至少+0.03pp、分带配对 bootstrap 95%下界正、两类可达性误判不增加；成组变体按族重采样。仅达到主门槛后测三对交错单核1M unique CPU，综合点收益至少+0.01且保守95%下界正，随后才做完整1M输出契约与资源验收及不可变打包。本轮不跑1B；同架构泛化不外推到其他架构。

原始证据放 `validation/results/exp108-*`，候选私有产物放 `build/exp108/`。每阶段记录命令、输入、源码、探针二进制、模型SHA和停止原因，并提交Git。golden只用于最终评分。预检失败时将结论限定为这四个真实端点跳格特征。

## 预检与开发结果

两个独立的1M无标签窗口分别有 7,076/7,096 行触发真实端点跳格，源端 3,880/3,906 行，目标端 3,211/3,205 行。resolver 语义、目标前驱正向回放均通过。三对交错的增量CPU为 48.70 ns/行，配对t的95%区间 `[45.49,51.92] ns/行`，通过覆盖与成本门槛。原始计时和见证行为 `validation/results/exp108-signal-raw.csv`、`exp108-witnesses.csv`，摘要为 `exp108-signal-screen.json`。探针二进制 SHA-256 `b78646a9679d8fbc1ae885d47b042df3397e3b4b8f4c1b2bcb6c2f7e05a485de`。

训练池46,505行中296行有非零新增特征；exp93/105开发窗口分别为37/36行。47维重训对照逐字节复现exp92模型SHA。固定51维模型 SHA-256 `aa8a65dd8e72bb2e8b36894bb5a0ee6fb414ac7701de76195271dcbbe2fd7cb2`；开发精度相对exp92为 `-0.024625/-0.033275 pp`，两个窗口合并分带配对 bootstrap 95%区间 `[-0.048753,-0.008901] pp`。两类可达性误判均为0。开发门槛失败，停止该模型，不生成 `[44M,46M)` 标签，也不接入正式入口。覆盖表明信号可在线取得；结果只否决本轮固定四特征、固定容量模型。

训练命令 `build/venv-ml/bin/python validation/exp108_path_model.py`，完整模型、输入及预测身份见 `validation/results/exp108-development.json`，逐行预测见 `exp108-development-predictions.csv`。该阶段未读取golden或独立标签。

同一探针与冻结2M输入另用 `/usr/bin/time -v -o validation/results/exp108-signal-rss.txt build/exp108/path_signal doc/eda比赛文件/arch build/exp106/fresh-2m.csv /dev/null` 补测，峰值RSS为47,056 KiB；该数仅对应探针，正式推理未接入。RSS原始证据 SHA-256 `d887edfe013dd8d0e6671e41f0e222f3c59bb129cddc2b993d93b8114bba4024`。本批开工与收尾时 `/dev/sdd` 可用空间分别为477G与475G；未删除文件，清理释放量0。单项开工空间未另行记录。
