# 实验494 全端口查询切口的直接矩阵分解

2026-10-19，查看新分解结果前登记。exp491及exp493完整端口TT的主要
误差已经出现在浮点表示阶段。本轮用直接矩阵SVD区分查询切口的rank限制
与链内其他截断带来的误差，固定查询键及输入变换，作为表示方法诊断。

## 假设与完整数据

复用208源、288目标、四方向、两认证余类及552几何，共264,536,064值。
使用exp491固定混合基双射，矩阵完整形状为13,312×19,872。
trend臂拟合exp491原始张量，residue臂拟合exp493的(D-H)/DENOM张量。
全部数据属于开发集，新增exact标签0。直接SVD分别保留rank512/1024，
同rank配对exp491/493的最终双表输出及浮点表。

对任一固定切口rank为r的TT，其矩阵秩至多r。直接SVD的尾部能量给出
归一化Frobenius误差下界，额外TT约束可能增加误差。tanh评分使用
原始整数距离，另作完整评价，谱尾部与tanh评分分别报告。
理论前提和推导见Obsidian《查询切口的矩阵秩与链内额外截断》。

## 实现与成本

复用已验证的数据双射、decoder、评分及分组流程。两臂直接调用安装版
SciPy float64经济型gesdd，记录当前签名与帮助、全部奇异值及能量。
保留前1024个左奇异向量，按固定列块重新计算投影右因子，逐块核对
全部264,536,064值的实际平方残差与谱尾部。两侧保留子空间的正交误差
须<=1e-10，相对能量差须<=1e-9，保存回读与完整SHA须相同。

先安排l7claude完成trend臂原型，16核机器使用8个BLAS线程，
输入约2.12GB，完整经济型SVD的工作内存单列记录。该原型验证完整
端口域的分解、资源与表示质量。成功完成分解且峰值RSS<=64GB、
wall<=3600秒后安排residue臂；该门限制本轮离线计算成本。
算法评价、模型评价及计时均安排r9r4900串行，其他主机只做离线分解、
输入重建与模型序列化。正式单线程资源限制另行验收。

## 评价、配对与停止

每臂的两个rank均固定不调参。先保存float64投影表，再分别对左右表
使用单个二进制尺度的int16舍入，最后展开float32查询表。
完整解码float、quantized、tables及最终verify，覆盖全部端口与全部值；
每阶段每端口对每context另做一个独立标量查询，共479,232次。
同端口空路径保持0，residue臂恢复H及非负残差。

主机制指标为直接分解与同rank TT浮点表的完整归一化平方误差比，
比值>=2视为链内截断存在明确改进空间；这是本轮机制门。
主质量指标仍为总体>=99.97%、近轴>=99.9%，最小实际配对收益
0.01个百分点。按26源族成组bootstrap，seed20261019494、2000次，
报告95%区间、源/目标/类型/族/lane/context分组及变化、改善、恶化数。
固定两rank和两臂按上述成本门执行，最终结果全部保留。

直接双表int16在A8的主体为33,980,416/67,960,832字节。
A480条件主体为258,408,448/516,816,896字节，超过80MB静态筛选门。
本轮产物用于判断可保留的表示精度与后续压缩空间；正式实现需另有
容量、真实acc及完整程序CPU证据。查询表、商图、初始化及其他资产
分别计量，固定正式入口exp354、CPU基准exp323、精度参照exp258。

## 完整核验与容量

16个完整阶段合计解码4,232,577,024值，每阶段评分257,647,104值，
共7,667,712次独立标量查询；residue另有3,833,856次独立H公式检查。
最终tables/verify的完整输出与配对统计SHA相同。独立checker分别在r9
重新计算全部264,536,064值的连续误差，并与谱尾及原训练记录一致。
两个checker均exit0、stderr空，CPU88.955123/94.254496秒，
wall54.902084/58.462633秒。

A8量化NPZ为33,981,178/67,961,594字节。A480直接int16因子主体
为258,408,448/516,816,896字节，元数据另计，足以判定静态门未过。
trend查询双表主体为516,816,896/1,033,633,792字节；
residue加完整商图后为976,879,616/1,493,696,512字节。
这些条件尺寸与正式完整程序2GB峰值验收分别成立。

最终紧凑证据277文件取回本地，逐成员完整SHA一致，见`evidence-import.json`。
真实acc、其余472个context、正式CPU、全端口100M/1B及平台表现继续待验。
正式入口exp354及三项生产源码保持开工身份。
