# 实验842 固定双码本的共享残量价值与容量诊断

2026-10-29，观察候选结果前登记。正式入口保持exp825，目标仍为未知非重复全角色1B约100秒，Acc严格大于99.1%并留余量。现有ELF为90,509,336B，额外预算至98至99MB约7.49至8.49MB；运行RSS严格不超过2,000,000,000B。

## 问题与假设

exp840完整名义场在128个主码组提供449,350条曲面。exp841的条件16码舍弃了原B256的选择自由度。保留原A2048/B256、逐键C与32位目录，仅用共享修正增加信息，可以隔离表示变化与运行查询成本。

本轮从冻结的exp824方向0原目录与exp840的全部所选曲面出发。计算原预测减精确名义值的残量，固定原码号及偏置。对每格点按exp777的非负名义权重计算加权残量均值，再按`floor(x+0.5)`取整数；权重总量为零时修正置零。比较两个固定选项。

- A按原2048主码、曲面位置共享一张修正表，保留原两次码本访问；进一步可以离线并入A而不增加在线访问。
- AB按实际共现`(A,B)`、位置共享修正，保留原码本；一个额外在线地址读取得到该修正。它是有条件的容量上界诊断，不将全AB和表自动视为可部署方案。

残量均值精确最小化加权平方误差，未对加权绝对误差或最终Acc作最优承诺。训练只使用已认证的公开架构名义值，原百万历史真实标签只用于评分。

## 冻结评价及停止

先核对原输入、曲面和码本身份。仍使用exp840已选的方向0 ordinary历史14,731行，在相同真实残差、强制首段、cycle及整数解码下比较current、A、AB与exact。对完整449,350条曲面计算名义加权L1，另以当前真实评分计算Acc与分组差，按26个source_family同exp840固定seed重采样9,999次。

质量门要求候选相对current提高至少0.20pp、回收至少40% exact参考增益，同时95%成组下界大于0，near_axis、distance、direction、fold的任一非空组下降不低于0.05pp。容量门要求用原zstd编码测方向0。当前仅选128/2048主码，A容量按所选非零码的压缩字节乘16再乘4估算；AB容量按所选实际码对的压缩字节乘四方向实际共现总数与所选码对数的比例估算，两个估计再加索引、复原器和对齐预留256KiB，并与现有ELF相加，要求落在98至99MB以内。所选组与完整方向可能有不同熵，这些估计只作筛选，正式接入前必须实测四方向ELF、RSS、CPU。A与AB分开判定，质量和容量同时通过才进入全域验证；否则固定加权均值、保持码号和偏置的表示停止。

先量化exp824实际共现的工作集。现场已核对四方向为417,978、443,537、436,286、426,008种，全部int16和表需1,903,085,136B，结合原工作集不能直接使用完整融合表。方向0所选449,350键含17,927个实际码对，中位每对9键，2,447对只有1键。全域可压缩大小不可由所选组线性外推为已测。

不调用完整估计程序，不生成新exact标签；主域其他方向、静态制品、完整CPU仍未测。质量门通过时才实测容量、单线程RSS与新100M，符合联合收益则立即完成完整1B并接入。当前实验只访问exp842私有目录及既有冻结资产。

## 核验与资源

输出加权零权、偏置、残量、两臂整数修正和原current逐行等价检查。独立复算A与AB的分组加权矩、样本输出与分组评分；原曲面身份沿exp840冻结记录。离线CPU与wall各不超过900秒，研究峰值RSS不超过4GiB，运行产物位于r9私有目录。开工本地`/dev/sdd`剩余259GiB，r9根盘剩余2.4GiB，tmpfs剩余14GiB。

A方案的名义L1上升2.46798%，在开发评分上也退化。AB方案下降22.9923%，回收exact参考Acc收益22.8865%，达到的0.112762pp仍低于预登记0.20pp门。AB相对current同时95%源族区间为[0.083596,0.148434]pp，提供正向机制证据。四个距离分组分别提高1.22497、0.22748、0.06459、0.04192pp，两个近轴分组分别提高0.04498和0.22961pp。**原端点方向2的8行**下降2.67643pp，影响全组平均约−0.00145pp；剩余14,723行方向0提高0.11428pp。这个稀疏方向组违反预登记分组门，须与方向0曲面选择分开解读。

A所选128个完整修正曲面压缩正文16,871B，四方向与全A码保守投影ELF91,855,320B。它低于静态硬上限，质量门未过，且未用到98至99MB利用目标。AB的17,927个完整修正曲面压缩正文2,630,028B，按四方向1,723,809实际共现数保守投影ELF352,056,052B，远超严格100MB上限。方向0所选组中位每AB码对9个名义键，约13.65%的码对只出现一次。该投影含四方向映射表和256KiB复原预留，仍只具筛选效力；四方向的压缩熵和收益尚未实测。

启动修正前发生两次无结果的启动失败。首次缺少本地脚本依赖，第二次r9的Python版本不支持`hashlib.file_digest`；冻结22项资产成功后，AST加权函数遗漏`DIM=552`导致累计前停止，`startup-amendment.json`记录冻结脚本与修正后脚本身份。最终原型CPU38.610785秒、wall39.600987秒、研究RSS1,100,222,464B。独立审核两轮通过，覆盖全部744,123,600个当前、A及AB加权重建整数，逐码组抽查加权矩、预测整数、原端点方向与fold分组和源族重采样。最终审核CPU9.996274秒、RSS787,017,728B。

两方案均未同时通过质量与容量门，依冻结规则停止该表示的四方向建模、新100M、1B和正式接入。AB的正收益限定在方向0所选组历史开发请求；全域、官方未知、查询CPU及匹配残差仍未验证。全码对完整表的额外1,903,085,136B，加上基准RSS已超2GB预算；仅扩大RSS不能解决这个方案的静态信息和随机访存成本。后续共享修正需让每个静态字节覆盖更多实际码对，避免为每个码对配置完整552点曲面，并先检查最终评分与在线读取成本。本轮固定均值方案的失败仅限相应表示，压缩码本、按高收益区域共享或重新训练残差均未验证。
