# 实验289 二次幂步长状态编号

## 预注册

2026-10-16，基线为 exp281 combined，ELF SHA 为
`dd8d0d8f901d5051f04010d8a3644acb87157a06e6cab625586cffabf35d1d34`。
本轮只在私有源码替换状态编号与解码，搜索预算保持 1024，
模型、q、图、邻接原序、队列比较、strict relax 和终止规则保持。
search768、no-tree、tree-mode0、endpoint-both 和 search2048 的历史候选继续保留。

主假设为二次幂步长可以减少全局 id 解码成本，同时保持物理状态展开、
父链与逐行输出。正式入口、用户构建脚本和交付包保持现有身份。
影响范围为 `legal_path_search.h` 的私有编码状态与局部映射、
`legal_path_search.cpp` 的初始化、`rankCell.idBase`、`id` 和 `decode`，
以及本轮夹具和 runner。所有外部消费者继续接收相同 Result、路径与 delay。

对 N 个 Z 端口取 S 为不小于 N 的最小二次幂，仅在最大合法 id
`(66000-1)*S+N-1 <= INT_MAX` 时使用 `cell*S+z` 和 shift/mask。
容量条件不满足时继续使用 `cell*N+z`；局部标签始终每格 N 槽紧密分配。
推导、前提和保序证明见 Obsidian
`agent-theory/二次幂步长状态编号的全序等价.md`。

## 检查与测量

独立 C++ 夹具直接使用注入生产私有头文件的同一片段，
检查 N=1、非二次幂、官方 N=160 全域往返与严格保序，
并检查 N=16385、24000、32537 的容量分支。队列混合 push/pop、
重复 tuple、非单调 key、65535/65536、大 key 和 clear 与 dense 编号及标准库参考比较。
分别运行 O2 与 ASan/UBSan。任一语义差异时保存证据，停止扩大测量。

复用 exp281 已核验的开发 12150、U-output 9472、U-role 14080 条请求，
逐行核对除 cpu_s 外的全部搜索字段与完整路径 SHA。
caps 768 组、weights 80 组、Arc 变体 128 条、连续查询、局部标签扩容、
same-pin、零延迟、不可达、无效坐标与 boundary/bias0/off/source CLI 同步检查。
精度标签与评分可按冻结输入、标签、权重和完整输出 SHA 复用。

远端 Xeon `r9r4900` 在 `/home/lhj/lhjwork/eda2026` 内串行运行，
绑定 core 3，完整进程 user+sys 含初始化和 I/O。本机 AMD 负责构建与语义检查，
计时只作参考。开发联合测量固定 U-output、U-role、exp258 三个 exact 样本，
各预热 AB 一次，再 AB/BA/AB 三对，A 为 baseline，B 为 stride。
同一次计时输出用于 acc、CPU、完整 SHA 和输出契约检查。

CPU 报告三对差值均值和 df2 Student-t 95% 区间，两端各加 0.02 s
表示 time 舍入。最小实际收益预设 0.5%，仅记录效应。
候选按总体 acc 严格 >99% 与同分布 CPU–acc 前沿保留；
相同输出时配对精度差、分组差与变化行数均为零。
至少一个 Xeon 样本差区间下端 <=0 时继续完整 1M，
三个样本均明确变慢时记录当前固定实现的负证据。

完整阶段使用既有 20k U-output 前缀各臂预热，
独特 U-output 1M 固定 AB/BA 两对，CPU 使用 df1 区间并加舍入。
stride 公开 golden 完整 1M 连续两次，同次输出用于评分；
baseline 评分按同 ELF 与完整输出身份复用，公开 CPU 仅作跨批描述。
repeated 1M 预热 AB 后运行 AB/BA/AB 三对，另用两个诊断进程记录
cache hit/miss 和初始化，诊断成本单列。

每次完整估计核对端点原序、恰好三字段、整数 delay、精确 EOF、完整 SHA、
重复运行一致、单线程、RSS <=2,000,000,000 B、CPU/wall <=3600 s。
独特 1M 全量 exact 缺失单列。阶段指标保持 1M <100 s、
100M <100 s、1B 100-300 s；本轮 100M/1B、跨架构和官方隐藏集待验。
通用静态构建沿用原参数，代码等价性确认后可与 search768 单独组合验证。

## 结果

候选 ELF SHA 为
`3a75afba64329434ef2c538101b04b5f23e6f45765be9f00d3dba7aaddb7d6f2`，
大小 94,083,728 B，基线 ELF、模型与搜索预算保持。
O2 与 ASan/UBSan 夹具各核验 12,936,000 个状态编码、回解、
局部标签地址及严格保序；每次运行合计核对 110,877 次混合队列 pop。
N=160 使用 stride=256、shift=8，N=24000/32537 触发原稠密路径。

搜索检查涵盖 36,678 条请求和 360,978 条路径记录；
输出除查询计时字段外全部逐行一致，路径完整 SHA 一致。
覆盖开发 12,150、U-output 9,472、U-role 14,080、
caps 768、weights 80、Arc 变体 128 条。局部标签扩容、
连续查询和边界 CLI 均通过。候选与 exp281 完整输出 SHA 保持，
因此三套样本的 acc 分别按同输入、标签与输出身份复用为
99.325323%、99.375113%、99.302253%；
逐组精度差、变化/改善/恶化行数均为 0，旧分组误差见
`sample-report.json` 引用的原始报告。

Xeon core 3 上三套 exact 样本各预热两臂，再 AB/BA/AB 三对。
