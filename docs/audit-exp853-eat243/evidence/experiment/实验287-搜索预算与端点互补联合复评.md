# 实验287：搜索预算与端点互补联合复评

## 预注册

2026-10-16，工程基线为 exp281，基线提交 `c7d856c`。
exp283 的 search512 是对照。固定两个新候选 search768 和
search512-both；前者把真实路径搜索上限从1024降为768，后者在
exp283 search512 同构副本上，把端点枚举设为历史 endpoint-both。
两项改动均在当前私有源码编译，不改变搜索 q、路径重放、真实图、
模型及最终 bias；对照运行同一套完整程序。

主假设为中间预算能使 exp255 上的 acc 从 search512 的
98.994106% 严格超过99%，同时减少 CPU；另一条假设为 both 端点
提高短预算下的 acc。两者在同一输入上可能相互作用，故不能相加
历史收益点值。单项 search512、endpoint-both 原始证据继续保留。
候选四套总体 acc 均须严格超过99%，且按同分布 CPU–acc 前沿保留；
区间不能区分的方案待定。最低实际 CPU 节省预设为0.5%，仅描述效应。

先固定七行边界、U-output 9,472、U-role 14,080、exp255 12,320
及 exp258 12,320 条旧开发样本与原标签、行序和权重。四臂先正序
预热，再正序/逆序/正序三轮。Xeon core 3 同机串行完整进程
user+sys；每次估计输出既作 CPU 计时输出又作 acc 输入。
配对 CPU 取三对 Student-t 95%区间，两端各扩0.02s；
分层配对 bootstrap 10,000次、seed=20261016283。逐分布报告
总体和分组误差、配对差与变化/改善/恶化行数、CPU和acc区间。
区间未做多重比较校正，三对计时不保证正态性。

候选的私有源码限 `main.cpp` 和 `residue_estimator.cpp`。
所有运行校验端点原序、恰好三字段、整数 delay、精确 EOF、完整 SHA、
多次一致、单线程、RSS≤2,000,000,000B、wall/CPU≤3600s；
边界与 exp281 完整 SHA 相同。历史 baseline/search512 的样本 SHA
匹配 exp283。ELF<100,000,000 B，保持通用静态参数及原架构对象。

输入、源码、ELF、runner、旧结果和协议冻结。输出若与预期身份
冲突，停止该运行并保留失败记录。新预测组合经过旧样本筛选后，
冻结候选并在未参与选择的新请求上生成经核验的 exact 标签；
完整独特 U-output 1M 验证在下一阶段单独冻结。重复请求与独特
请求不混用，AMD时间仅参考。CPU目标仍是独特1M<100s、
100M<100s、1B 100–300s；计时效果不随行数线性外推。
正式入口、用户改动和交付包保持。本轮不做全量1B。

开工 `df -h /dev/sdd` 可用约411 GiB，收尾检查空间和清理清单。
预计新输出均低于10GB；不清理未经三条件逐一核验的文件。

## 结果

Xeon Gold 6226R、core 3 上完成七行边界和四套开发样本共 68 次估计进程。
CPU 与 acc 均来自同一次完整程序输出；输出契约、端点顺序、整数 delay、精确
EOF、完整 SHA、多次一致、单线程和 RSS 约束均通过。`validation/results/exp287/report.json`
的 `all_passed` 为 true，最大 RSS 为 1,697,841,152 B，新增 exact 成本为 0。

分组误差以原始报告为准。

当前批次的点前沿为：U-output 保留四臂；U-role 保留 baseline、
search512、search768；exp255 保留 baseline、search768、search512-both；
exp258 保留四臂。search512 在 exp255 的总体 acc 为 98.994106%，按新规则
不通过该分布的 acc 门。exp282 的历史通过候选、exp286 的 tree/endpoint
候选及其原始区间继续保留，未因本轮四臂筛选删除；跨实验批次的计时不直接
混入本轮点前沿。

本轮仍只使用已查看开发样本。search768 改变输出，不能复用旧 acc 结论；
下一步冻结排除历史训练和选型 pin 的新请求，先生成 exact 标签，再用同一次
完整估计运行联合记录 CPU、acc、输出 SHA 和资源。新请求通过后再做完整独特
1M 验收，正式入口和交付包暂不更新。AMD 本机计时仅作参考，第一阶段独特
1M `<100 s` 仍未达到。
