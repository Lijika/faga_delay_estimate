# 实验173 真实上界等价查询成本

2026-10-10，分支`research/exp173-upper-clamp-query-cost`，起点`ae40770`。
正式exp131保持，开工`/dev/sdd`可用453G。

## 假设与固定候选

固定exp172的40源截断输出。控制为原始逐树扫描sourceArc及固定P重放；
单项routing将可达源树/最小Arc按源端口离线列出，组合pruned进一步以当前best
替代固定P阈值，并在“全部名义费用+已经观察到的非负Gap费用”≥best时提前结束。
parent恢复函数、源树顺序与终端分解复用；候选新增逻辑只影响计算量。
名义费用/Gap均非负，理论入口`真实上界重放的非负费用提前终止.md`。

数据为6176开发请求，exp172逐行输出作为等价证据。timed kernel只接收端点与P，
expected只用于输出断言。先全量审计3版本，再各预热2轮；CPU3单线程串行，
10组顺序交错reference-routing-pruned/pruned-routing-reference，
每版本每距离带50遍。不缓存请求或终端；pin解析与CSV读写在计时外。
同一requests在循环中重复，只作组件成本，工作集、真实unique冷缓存另验。

40独立压缩流一次完整恢复，全部298945600 B与raw逐字节比较，
单独记录含文件读取/分配的恢复CPU及源表初始化CPU。

## 门与停止条件

主候选为组合pruned，输出全部等于exp172，worsened仍为0。
weighted CPU按每带样本均值×exp138语料带权外推1M distinct。
组件扩大门为pruned-reference的配对t95区间上界<0、点省≥10%；
10对的区间用df9常数2.262157162798205。routing作为单项归因。
另列条件综合收益`0.8×0.08542289430631102−(weightedQuery+restore+seed)/120`，
accuracy与CPU联合保守下界只描述开发分布和K=1M假设，
正式联合门与独立新请求另验。

整进程timeout300s、RSS≤2GB、单线程。失败现场保留；
组件门失败停止该固定组合扩大，已有精度行为和其他CPU优化继续。
无正式静态ELF、生产缓存或完整1M声明。
