# 实验304 轻度加权LTO完整1M等价验证

## 预注册

2026-10-16。exp302已冻结w1.01/512的通用O3+LTO实现并通过模型、
路径和完整开发输出等价检查。本轮须由其100k结果保留完整验证资格
后执行，固定同一ELF，不改变编译参数、源码、算法或输入顺序。
主假设为完整1M输出保持，CPU减少。exp299的102.36 s与公开
acc99.028029%作为历史进度，同批性能基线直接使用原w1.01/512。

Xeon core3同机串行，两臂20k预热，独特1M按AB/BA两对，
候选公开1M两次，repeated预热后AB/BA/AB三对，共16次。
完整user+sys包含初始化和I/O，unique用df1、repeated用df2的
Student-t 95%配对区间，两端加0.02 s舍入。0.5%只记效应，
区间跨零保留待定；两次独特1M都<100 s才记录第一阶段达到。

所有运行输出必须逐字节等于exp299同分布的w1.01/512输出，
同时检查行数、端点顺序、三字段、整数delay、精确EOF、完整SHA、
多次一致、单线程、RSS<=2GB与CPU/wall<=3600 s。复用相同
公开输出的golden评分和原新请求精度，配对精度差与变化行均为0。
源码逐文件相同且完整repeated输出一致时，复用原1,000 miss/
999,000 hit诊断身份；独特输入原1,000,000 distinct证据保持。

新增exact和评分成本为0，估计成本单列。任一输出差异先保存证据
并停止等价判断。仅通用编译选项，AMD计时只作参考；原LTO与
packed等历史候选分开保留。独特1M全量exact、100M/1B、跨架构、
平台与隐藏集另验。开工磁盘约407GiB，收尾复查。

## 完整结果

16次完整运行的契约、SHA、多次一致、单线程和资源检查通过，
三类完整1M输出与exp299保持。公开acc复用99.0280294290%，
配对精度差0 pp、变化行0。候选独特1M为102.83/102.94 s，
均值102.885 s；同期基线102.18/102.68 s，均值102.43 s。
候选减基线的配对差为0.65/0.26 s，95%区间含舍入为
[-2.042710,2.952710] s，保留待定。第一阶段尚未达到，最快
已验收的独特输入记录继续为exp299的102.36 s。

公开1M两次118.13/118.68 s。repeated均值3.03 s对3.286667 s，
节省7.809331%，差区间[-0.291009,-0.222324] s。该收益只对应
repeated分布；20k/100k、独特1M和repeated分别保留证据。
相同源码与完整输出支持复用1,000 miss/999,000 hit记录。

估计总CPU682.20 s，新增评分、exact和cache诊断成本均为0。
最大RSS1,694,433,280 B，最大wall118.70 s。原始结果见
`validation/results/exp304/timing.json`和`report.json`。独特
全量exact、100M/1B、跨架构和官方平台仍待验证。收尾磁盘
405GiB，删除0项、释放0 B。
