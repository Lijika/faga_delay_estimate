# 实验276 查询内格点排序准备缓存

2026-10-16。CPU基线为exp275私有候选，提交aec1e2f，独特U-output 1M
平均232.92秒。精度基准为exp258。正式src、./estimate、subm和已有用户
改动保持现状。本轮范围为私有搜索头文件、cpp与实验脚本。

## 预注册

主假设是同一查询再次准备同一格点时，复用已计算的坐标差、余数、Line、
四角线性项、leader、margin、表行指针与编号基数能减少CPU。固定使用
按格点索引的RankCell缓存，由既有cellBase是否为负标记本查询有效性。
每查询继续清理上次触达映射，首次触达保持原标签初始化和排序计算，
后续准备复制缓存值。查询内目标和表保持固定，跨查询重新计算。

私有改动只涉及RankCell存放与prepareRank。q、完整(key,id,g)队列、
strict relax、stale、有效cap、parent及路径重放保持。构建保留通用O2，
两台CPU使用同一ELF。固定这一缓存表示，本轮不调容量或布局。新增全格
缓存按`Architecture::kCellCount`分配，实际内存随完整程序测量。

在查看结果前冻结源码、ELF、编译命令、模型、架构、输入与协议。审计版
对每次复用重新计算并逐字段核对缓存，统计prepare与复用次数；生产版
省去重算和计数。复用35,702条搜索及109,505,958次q、完整路径、七组CLI、
128条Arc费用变体、768组cap和80组weight检查。全部通过后复用12,320条
exact开发样本与原分层权重，要求总体和七组acc差为0、变化行数为0。

性能采用两种原序独特20k，单线程core3、同机串行、避开其他重负载。
每臂预热一次，正式AB/BA/AB三对，主指标为user+sys，候选减基线使用
df2的95% t区间。两分布点省至少1%且区间上界小于0时，扩大到完整1M。
点省但区间跨零保留待定，明确变慢时停止扩大该候选；阶段目标只记进度。

两机分别报告，并保留计时舍入误差界。远程限定r9r4900的~/lhjwork/eda2026。
明确加速后候选运行完整独特U-output 1M两次，SHA与exp275比较。另跑公开
golden 1M，与exp258部署输出逐行配对；总体和七组acc差为0、变化行数为0。
repeated 1M沿用1000个独特请求，预热后AB/BA/AB，记录cache命中。

全部输入保持原序。输出核对行数、端点、三字段、整数delay、精确EOF、完整
SHA及重复一致。单线程、RSS不超过2,000,000,000字节、单次不超过3600秒。
算法语义出现差异时停止性能试验，保留失败证据。CPU未改善时保留原候选。

理论依据写入vault的查询内格点排序准备的缓存等价笔记。实验结果仅代表
已测请求和CPU；其他FPGA架构、官方隐藏平台、完整独特100M/1B另验。
开工本地可用417GiB，远程193GiB。保留冻结产物和按名引用的输入，清理
逐项核对副本身份、可重建性和引用关系。
