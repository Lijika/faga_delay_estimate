# 实验332 有界目标端口分组

## 预注册

2026-10-17。正式基线exp323，研究基线采用exp331同ELF关闭结果缓存。
主假设为64Ki行批次按目标端口分组可改善目标主序排序表的访问局部性，
省下的查询成本覆盖额外解析、缓冲、分组和原序写回。每条请求实际执行
完整预测，完整请求结果缓存保持关闭。开工/dev/sdd约399GiB可用。

三臂固定为原程序baseline、原序批次fifo和目标分组grouped。后两臂
使用同一批次实现，仅执行顺序不同。固定最多65,536条、4MiB原文，
超过字节上限的单行清空批次后单独执行。输入端点原文与输出顺序保持。
只在私有源码更改main请求循环，搜索、模型、架构解析与费用保持。
其他CLI配置保持原序；生产源码和交付包保持。

受影响消费者为CSV的头部/空行/非法行处理、输入行原文保存、首条
不可达诊断和写出失败路径。分组key由原Architecture解析目标获得，
非法目标进入单独分组，计算仍调用原answer。原序批次承担同样的目标
解析和缓冲费用，用于识别分组本身的影响。

理论依赖见Obsidian的“有界目标分组与请求换序等价”，逐请求清空堆、
重建局部标签及端点数组是前提。测试覆盖稳定排列、逆排列、连续批次、
容量边界、超长单行、CRLF、空白、非法输入和缺尾换行。ASan/UBSan
检查批次容器。按请求身份核对已有145,800搜索记录中480臂的全部字段
和路径；比较分组次序下的结果。标签身份保持时复用原评分。

## 固定测量与扩大条件

两候选先在四组已标记开发样本共48,184行、7行边界及特殊CSV上比较
完整输出SHA。搜索路径检查和局部自检通过后，在Xeon核3依次执行
20k、100k原始非重复输入。每个规模先预热三臂一次，再做三个交错块，
顺序baseline/fifo/grouped、grouped/fifo/baseline、baseline/fifo/grouped。
每次均为完整程序，真实文件读写，总计24次性能运行。

主指标为100k完整CPU的grouped减baseline配对差，同时报告grouped减fifo
和fifo减baseline，t区间df=2另计0.02秒舍入。预定1%作为实际效应描述，
有效CPU收益仍保留。100k上grouped差区间上界小于0时扩大至完整1M；
区间跨零时保留待定，并允许完整1M解决规模不确定性；区间下界大于0
时结束固定实现扩大并记录负结果。20k与100k分别报告，禁止把差异
全部解释为CPU缓存，硬件计数器另验。

完整1M阶段三臂一次20k预热，unique三块按相同顺序执行，grouped公开
1M两次。输出与exp331参考完整SHA相同后复用评分。每次检查完整行数、
端点原序、3字段、整数delay、EOF、SHA、单线程、RSS≤2,000,000,000字节、
CPU与wall各≤3600秒，任一失败保存证据并停止。新增exact与评分预算0。
完整unique缺少全量exact，已查看输入属于开发集，隐藏集和跨架构另验。

有效阶段成绩来自非重复100M及1B完整算法实测；本轮1M承担筛选与交付
检查。正式接入和打包另按项目现行流程进行。候选使用通用O2静态构建，
避免加入机器专用指令和依赖。资源与输出可复用性由最终ELF身份判断。
