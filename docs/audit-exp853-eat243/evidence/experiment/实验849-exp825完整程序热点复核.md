# 实验849 exp825完整程序热点复核

2026-10-29，分析当前正式版前冻结。exp825在非重复U-role
1B CPU160.776248秒、同次分层样本Acc98.881628718%；
目标约100秒、Acc严格超过99.1%。exp821的热点画像属于
exp811，exp825替换了完整曲面和目录。本轮只复测当前身份，
不把旧版本采样比例用作当前因果成本。

固定exp825的静态ELF SHA `c4b3c845cfd91fac8865bcecf168569a020431ff11da02b937f1955c43a8a54d`，
以及已通过全部唯一性、59,904角色对和契约检查的非重复100M
输入。只进行一次当前ELF的完整程序perf record（cycles:u,
999Hz,CPU8），报告CPU(user+sys)、wall和线程/RSS；
输出必须有4013554735B，SHA
`730a9fcbb9153e0423f64a88e7823230068454e7272f708e2fec4b90c87af73b`。
精度复用相同输入与正式输出的既有1,916,928条exact，
本轮不重算标签。perf成本只作画像，不作为加速证据。

用原冻结编译参数增加调试符号、去掉strip，逐节检查原ELF
全部已加载代码和数据与调试副本完全一致后才能关联地址；
不等价则只保留地址和计数，不做源码归属。分开统计用户态
叶函数、包含函数、源行和未知地址，含关系不得相加；
system CPU另列。寻找能跨CSV解析、几何准备、名义访存
共享状态或直接删除的工作，先定义行为等价候选及费用，
完整100M明确收益后立即扩大1B和接入。

本轮保留perf及小型证据，4GB输出在tmpfs确认完整SHA后
逐名删除，输入和正式版不动。根盘空间约2.4GB、
tmpfs余14GB，CPU诊断≤90秒、wall≤180秒；峰值运行
RSS≤2GB。开工本地`/dev/sdd`剩余259GiB，收尾复查。

## 结果

R9的冻结100M输入和exp825静态ELF均按原SHA核对。一次`perf record`
完整程序CPU15.933929秒（user14.254227、sys1.679702），
wall15.950315秒、RSS270,188,544B、线程1；100M输出
4,013,554,735B、SHA与正式版相同，复用同次1,916,928条exact的
Acc98.883090386%。调试副本全部加载代码和数据节与正式版一致。
用户态15,715个采样已完成符号归属；本轮不产生速度改进。

包含函数采样中`prepare596`为38.8164%、CSV解析为26.1534%、
`finish596`为13.204%。叶函数中`line707`为13.4267%、
`surface779`为9.5005%、`pin723<'\012'>`为7.6869%、
`pin723<','>`为6.1279%、`first707`为5.5170%。
包含归属存在重叠，采样不能直接换算可删除CPU。`line707`对应
`exp707_prepare_metadata.h:20`，exp821曾将相邻热点定位为
目录预取停顿；本轮仍需按反汇编核对，不把它计为可直接删除的
Line算术。用户态采样不包含sys CPU。

首次续跑前的相对路径错误和第二次恢复时证据写入冲突均保留在
R9私有`exp849-startup-failure-*`目录。第三次只运行一次完整
`perf`；写入`record-cleanup.json`后，输出已核验并删除，但重复
写入的`write()`拒绝覆盖，随后修复报告脚本并复用已有采样恢复
符号化，没有为修复脚本重跑估计程序。远端辅助脚本的
`validation/exp703_current_profile.py`指向
`../../exp821/validation/exp703_current_profile.py`。
`freeze.json`记录的是测量时脚本身份；当前脚本只修正结果恢复。
原始`profile.data`、节身份、完整输出证据、采样与恢复记录已取回
`validation/results/exp849/`。独立读取报告核对了15,715个样本、
全部源文件采样计数、perf文件SHA、输出与既有100M的完整SHA、
调试节等价及删除证据；叶函数列表仅保留前60名，少6个样本。

## 架构判断

当前非重复U-role 1B实测CPU160.776248秒、抽样Acc98.881628718%。
用户进一步核实榜单头部是有效的真实1B成绩，且领先队伍没有使用
请求对缓存；所给截图包括Acc99.04%至99.37%与CPU约74至90秒的
成绩。这使约100秒/99.1%以上的联合目标和榜单差距成为研究架构
需要处理的事实。历史Q&A的打榜复制说明保留原文，不能用它推定
用户此次核实的成绩依赖缓存。R9与官方CPU型号及分布的精确一致性
仍待平台测量。

exp836仅替换普通请求的背景为认证精确值，固定旧残差时开发Acc
由98.879723%提高至99.356544%；可回收的0.476821pp中，
近轴贡献0.347536pp。它证明当前缺口有信息来源，尚未提供可编码
且足够快的表示。exp847排除固定两系数秩二AB修正，exp848排除
固定粗状态常数输出校正；它们没有排除路径机制条件、完整请求
评分定向编码或新的数据表示。

下一轮改变研究对象为完整CSV到整数预测的在线计算链，优先考虑
同一份端点/有向路径状态在解析、首段、背景与残差间共享，并让
新的高价值信息替换整组当前必经工作。质量先以认证名义场、
同一最终整数评分及按真实角色对加权的独立请求检验；CPU同时
量化初始化、地址依赖、可删除准备工作与sys成本。针对近轴等
已证实的质量集中域，先测乐观信息上界和编码成本，再筛条件
快速路径。避免继续只调相邻码本、单项预取或原秩二系数。
保留exp825作为固定对照；新的完整候选取得明确联合收益后，
立即进行非重复100M、1B实测和符合规则的正式接入。

本地`/dev/sdd`收尾仍有259GiB可用，释放0B；远端核验后删除了
本轮约4.014GB的输出，失败目录和perf证据保留。
