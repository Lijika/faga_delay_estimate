## 1. 目标与方法

1. 用只读 From,To 的诊断工具统计公开 100 万请求的距离带、端点类别、Block/Line/边界命中，
   抽样 exact Router 得到**真实误差**（不用 golden 做决策）。
2. 按调研文档的建议逐项做最小可复核尝试：短距 exact、Block/Line/边界几何、整数权 fallback
   （radix）、周期图/有限 residue、CRP/MLD、CCH、ALT/TNR/Hub Labeling、PDB、residual ML。
3. 每个候选在 100K（必要时 1M）公开语料上做消融，记录 accuracy/MAPE/P50/P95/P99/max、
   高估/低估、CPU、RSS、输出哈希；不达标者明确"不采用"。

工具（本轮新增，均不进入默认估计路径）：

### 6.2 周期图 / 有限 residue（`plan_probe --periodic`）

> 范围修订。此探针调用全图 Router，且部分目标坐标超过打印的内部切片范围。下方 13 组历史数值只能描述这些采样请求，周期图的有界误差与误差成因仍需各自的证据。

无 Block 内部切片（x∈[16,75], y∈[150,199]），固定 lane，13 组同残差类位移：

```
max_slack=5.0ps（相对 slack 0.00–0.23%）
```

- **结论**：在无 Block 的周期内部，residue 下界几乎**紧**（≤5ps）；语料级的 ~50ps slack 来自
  Block/边界/端点几何，而不是周期结构本身。支持"内部用 residue、局部用 exact/overlay"的路线。

### 6.4 CCH（`plan_probe --cch --width W --height H`）

> 正确性证据修订。旧 `ZGraph::terminalCost` 把当前位置 Z 当作其 Net 的 I 落点结束，省略了真实 Net 位移与费用；本节两条查询路径共用该函数，因此 8/8 一致无法验证指定 Z 目标的距离。旧计数保留作历史。标准 CCH 的独立局部原型与正确性证据见实验20B、20C。

Z 状态窗口图（每 cell 160 状态），按度数升序全收缩，短边取自 in→v→out 组合：

| 窗口 | 节点 | 原始边 | shortcut | fill-in | 收缩时间 | 验证 |
|---|---:|---:|---:|---:|---:|---|
| 2×2 | 640 | 2,048 | 238 | 0.12× | 0.01s | 8/8 一致 |
| 3×3 | 1,440 | 7,776 | 150,289 | 19.33× | 0.05s | 8/8 一致 |
| 4×4 | 2,560 | 16,640 | 938,920 | 56.43× | 0.83s | 8/8 一致 |

- fill-in 随窗口 **0.12× → 19.3× → 56.4×**；`--width 2/3` 在 1.2s 内完成，
  4×4 的验证部分因 O(n·|E|) 扫描耗时 100s（已按要求不再重跑）。
- **该数字只描述当前原型**：消元顺序是初始出度排序，没有 nested dissection、没有独立
  customization、没有标准层次查询，shortcut 计数还包含已有边降权次数，因此**不能外推为
  "标准 CCH 全图不可行"**；标准 CCH（nested dissection + customization + 层次查询 + 更大区域）
  仍未验证。本原型的结论仅是：在这种简化消元下，窗口放大时 shortcut 增长很快。

### 6.8 Block / Line / 边界几何修正

- 现有证据：分层统计里 Block 相关分组误差显著（水平可穿越两侧 proxyAcc 71.06、垂直不可穿越 75.42），
  但**占比小**（合计 2.1% 行，综合分上限 ~0.47）；`--periodic` 显示无 Block 内部 slack ≤5ps，
  说明这些分组正是几何效应所在。
- 本轮做的尝试是**分组拟合 + 上界分析**（proxyAcc × 占比），未实现独立的 Block 绕行下界修正：
  要保证下界语义需要"绕行额外位移"的可证明估计，属于下一轮工作。

## 6.10 分层偏差诊断（实验3：bias-band 是否只是距离混合偏差）

问题：§5 的分带常数校正是否只是"距离混合"造成的伪结构？在空间、端点类别、几何维度上是否
还有可泛化的残差？只有通过事前的 accuracy screen 才允许提出生产改动，本轮默认路径保持不变。

### 方法（含本轮修正）

- `tests/query_profile.cpp --dump-tags <csv>`：把 `--samples-per-tag` 的 exact 样本按与 `--dump`
  相同 schema 单独导出（已提交 829d253，本轮未改）。
- `validation/stratified_bias.py`：合并 band/tag 两个 dump（按六元组去重），
  - **权重**：band 样本用逆采样率 `w_i = N_band / n_band`（N_band = 完整 1M request 的该带行数，
    n_band = band dump 去重后该带样本数，tag 样本不参与 n_band），并在每个被评估子集内归一化，
    目标是对应测试子域的近似条件均值（带的占比取该子集样本）。
    采样说明：`selectSamples` 是从固定起点等间隔取第 k 个匹配，**不是随机抽样**，
    因此这是依赖"带内有代表性"假设的探索性加权诊断，不是设计无偏估计。
    合并 band+tag 的表只作 **pooled_descriptive**（无加权指标，标签组被人为富集）；band-only
    另给 **band_only_weighted**（分层 + 总体，w=N/n）。
  - **标签一致性**：主路径对每个样本比对 C++ recorded tags 与 Python `Model.tags`，不一致直接
    报错（不允许混用两种定义去生成权重）。
  - **缓存身份**：缓存键 = request 内容 SHA-256 + 精确 limit 值（0=全量）+ 架构 5 个 JSON 的
    SHA-256 + `tag_logic` 版本号；任一变化即失效重建，避免把别的文件/别的标签语义的计数拿来用。
  - **screen 更名**：原 `gate` → `accuracy_screen`（0.3 是事前实用筛选门槛，**不做显著性检验**）；
    通过只能记为 `needs-production-evaluation`，本轮**未评估生产就绪性**，默认不变。
  - 分层维度：distance band、source/target port class、geometry 标签、x1 四分位、位移象限。
  - 校正对比：M0 不校正、M2 分带上中位、M5=band×geometry、M6=band×class_pair
    （M5/M6 带 `min_samples=12` 阈值，稀疏桶回退到 M2）。

### 标签定义差异的实证排查（本轮）

假设：`ReferenceArchitecture.move` 不检查 origin 是否属于有效 SRB，而 C++
`Architecture::resolveNet` 会检查；当某个 Net 的名义前驱落在 Block 空洞时，Python 会接受该着陆。

实测（`recorded` 来自 C++ dump，`python` 来自 `Model.tags`）：

```
/tmp/eda1/profile1m_band.csv: rows=742 mismatches=6   (全部为 target_land_block)
/tmp/eda3/band.csv:           rows=382 mismatches=2   (同上)
/tmp/eda3/tags.csv:           rows=143 mismatches=10  (同上)
```

18/18 个不一致样本的名义前驱都落在 Block 空洞（`origin_in_tiles=False`），且 Python `move`
仍然返回有效落点，例如：

| 请求 | 名义前驱 | C++ recorded | Python(修复前) |
|---|---|---|---|
| `SRB_93_444/S_DQ0 → SRB_90_445/ZLE[1]` | (80,445) delta=(10,0) | target_land_block=1 | 0 |
| `SRB_70_314/S_DQ1 → SRB_66_316/ZLW[1]` | (76,316) delta=(-10,0) | 1 | 0 |
| `SRB_9_152/ZSNB[3] → SRB_77_355/ZLN[4]` | (77,343) delta=(0,12) | 1 | 0 |

修改共享根因：`validation/verify.py` 的 `move()` 增加起点存在性检查（先 `rg` 全部调用点：
`verify.py` 的 audit 路径、`residual_ml.Model.hop/landing_blocked`），与 C++ 语义一致。
修复后 **1872 行（4 个 dump）0 不一致**；`python3 validation/verify.py audit` 仍通过
（8/8 路径、几何检查、5800 空洞核验）。

`target_land_block` 的语义说明：它只检查目标名义位移对应的**特定前驱**是否能着陆，
在存在 Block 跳过、以及 Z*/I* 端点的情形下只是几何代理，不能当作精确的"不可达"或
"所有着陆都被阻塞"。
