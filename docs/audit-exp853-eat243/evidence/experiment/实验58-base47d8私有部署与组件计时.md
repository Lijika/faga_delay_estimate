# 实验58 P1：base-d8 私有部署与逐行契约

日期：2026-09-26。固定基线为实验29 `./estimate`，SHA-256
`db2cca1eb976df543b2b7281326402fd77fc7b58bf1492d530535903df88ba35`；正式入口、正式
二进制、交付包、`RESULTS.md`、`DESIGN.md` 本轮均未改动。本轮只做实验58冻结候选

## 假设与候选

假设：实验58 的 `base-d8`（47 维 = 生产 44 特征 + `base`、`base-fast`、
`base/max(fast,1)`，64 棵树、depth 8、seed `20260919`）可以在生产残差路径上以
**不调用 `lowerBound()`、不构造商图上下界表** 的方式部署，逐行输出与 Python
参考列完全一致，且新增 CPU 明显低于 `96 × 0.120597 = 11.5773 s/1M unique`
的预算。

实现边界（顶层决策已固定，未改变）：复用已有 `xgbFeatures` 与 `base.value`，
追加三列并使用生成的静态树头；不修改正式 `-residual xgb` 路径的语义。

## 逐行契约（冻结 P1 样本）

输入为冻结 merged 请求的尾部 6178 行（`build/exp58/fresh-6178-requests.csv`，
SHA `deffaf1fd01eb75f68f811730c2595e16ddbe89b4c1715a47691713b2c4d2f43`），
参考列为 `validation/results/exp58-base-depth-predictions.csv`（SHA
`967e56bb6b7d21c85e874aeeb85f2f319497081412b8a6f3315110f7985ad8d6`）的 `base-d8`。
命令：

```sh
build/exp58/estimate-base47d8 -arch doc/eda比赛文件/arch -residue-mult 2 \
  -endpoint-mode source-short -endpoint-short-distance 150 -residual xgb-base47-d8 -quiet \
  -in build/exp58/fresh-6178-requests.csv -out build/exp58/fresh-6178-base47d8.csv
```

结果（`validation/results/exp58-base47d8-private-contract.json`）：6178 行，
`From/To` 顺序不一致 0 行，`delay` 与 Python `base-d8` 列不一致 **0 行**，
99 行 negative-exact 全部为 `-1`，文件以换行结尾且无多余内容。边界契约：
12 行 same-pin 全部为 `0`，3 行非法 pin 全部为 `-1`，空输入输出只有表头，
边界夹具与基线 `./estimate -residual xgb` 逐字节一致（
`build/exp58/contract-fixture-{baseline,base47d8}.csv`）。
对照：实验41 `xgb-base`（50 特征，`build/exp41/estimate-base`）与实验47
`xgb-base24`（`build/exp47/estimate-hybrid24`）在同 6178 行上端点顺序和
negative 契约同样通过，数值分别有 5769/5748 行与本候选不同（不同模型，预期）。

## 组件 CPU：同进程探针

`tests/exp58_base47_probe.cpp` 在 CPU 3 上用冻结 fresh 行的真实特征
（`fast` 取 `-residual off` 输出、`base` 取实验41 私有基线输出）交错 5 轮，
共 4942400 行，逐行走两条与生产完全相同的路径：

| 路径 | 秒 | µs/行 |
|---|---:|---:|
| 生产残差（19A，1838 节点） | 6.526712 | 1.320555 |
| base-d8 残差（14662 节点） | 16.509799 | 3.340442 |
| **差值** | **9.983087** | **+2.019887** |

即新增 **+2.02 s / 1M unique**，预算是 `96 × 0.120597 = 11.5773 s`，探针判定
`within_budget=true`（`build/exp58/probe-base47d8.json`）。这是纯残差替换的边际
成本，不含建表、端点枚举、缓存与 I/O；探针 RSS 100204 KiB。

## 端到端 1M unique 计时：未完成（环境阻塞）

批次 b1（`validation/results/exp58-base47d8-private-timing-b1.json`，与
`exp58-base47d8-private-timing-contaminated.json` 同内容）用冻结
`build/exp57/timing-1m-unique.csv`（SHA `2cf587f1…`）、`taskset -c 3`、每侧一次
预热、交错 10 对：基线与候选各 10 次运行，输出行数 1000000、端点顺序 0 不一致、
negative 集合完全一致（各 17585 行），基线输出 SHA 复现实验57 冻结值
`30565755…`，候选输出 10 轮完全一致；峰值 RSS 903.5–904.0 MiB（< 2 GB），
线程数恒为 1。但该批 **顺序未平衡**（基线总是先跑）且主机争用严重
（wall/cpu 最高 2.0，基线 CPU 在 43.9–58.7 s 间漂移），配对均值 `-2.337 s`、
CI `[-4.374, -0.300] s` 不能作为可信点估计；其绝对量级（数秒）与探针的
+2.02 s 同阶，都远低于 11.5773 s 预算。

后续三次带 checkpoint 的 clean 批次（顺序平衡 + 1 Hz 检测"存在其它
estimator 即拒绝该轮"）都在记录到 0–2 对时被外部 SIGTERM（工具调用 rc=143），
包括 `setsid` 分离进程、改名到 `/tmp` 的二进制副本，以及最终用
`systemd-run --user --scope`/transient unit `eda-exp58-timing-b3` 启动的进程；
对照组（CPU 100% 空转 150 s、`sleep`）正常存活。同时刻另一执行会话在运行
`validation/exp58_base47d8_formal.py`（对 `build/exp58/estimate-base47d8-opt`
的五次 1B 正式验收），其守卫把任何外来 `estimate` 进程和本次的 transient unit
视为 competing load 并拒绝/中止该轮（`validation/results/exp58-1b-formal/formal.log`，
round01 baseline 在 04:03:19 被其自身守卫中止）。为避免继续污染正式验收，
本 agent 已停掉 `eda-exp58-timing-b3` 并停止一切 estimator 运行。完整时间线与
resume 命令见 `validation/results/exp58-base47d8-timing-environment.json`。

**待补的唯一证据**：干净的 10 对顺序平衡端到端 1M unique 计时（
`python3 validation/exp58_base47d8_private.py --stage timing-clean`，逐对
checkpoint 到 `validation/results/exp58-base47d8-timing-b3.json`），必须在
1B 正式验收结束后的静机窗口执行。

## 预算判定

- 精度：`base-d8` 增益 `+0.120597 pp`，95% CI `[+0.070505, +0.170398]`（实验58
  冻结证据，本轮未重算）。
- 预算：`96 × 0.120597 = 11.5773 s/1M unique`。
- 组件边际成本（探针）：`+2.02 s/1M unique` → 通过，余量约 5.7 倍。
- 端到端配对：待静机窗口确认；b1 的两侧绝对量级与探针一致，未发现超出预算的
  迹象。
- 资源：单线程（线程数恒为 1），峰值 RSS 904.0 MiB ≪ 2 GB；未做五次 1B 验收。

## 复现与停止条件

- 契约：`python3 validation/exp58_base47d8_private.py --stage contract`（写
  `exp58-base47d8-private-contract.json`）。
- 组件：`taskset -c 3 build/exp58/exp58_base47_probe --arch doc/eda比赛文件/arch
  --requests build/exp58/fresh-6178-requests.csv --fast build/exp58/fresh-6178-off.csv
  --base build/exp58/fresh-6178-base.csv --repeats 160 --rounds 5
  --json build/exp58/probe-base47d8.json`。
- 计时：静机时 `python3 validation/exp58_base47d8_private.py --stage timing-clean`
  （`--max-pairs` 可分块续跑）。
- 证据 SHA：契约 `5df9cae2…`、b1 计时 `76e969ce…`、环境记录 `635f5a18…`、
  探针 `0a1e7d10…`、导出 `73098fe5…`，均在 `validation/results/` 与 `build/exp58/`。
- 若端到端 CI 上界超过 `11.5773 s`，或任何一轮逐行输出与 Python 参考列不一致，
  关闭该私有部署候选；`base-d6` 保留为成本对照。优化方向（更小的静态布局、只算
  被读特征）由并行会话在 `build/exp58/estimate-base47d8-opt*` 上继续，本轮的
  `xgb-base47-d8` 作为其 pre 基线（同一二进制 SHA）。

## 局限

- 组件探针只覆盖残差替换的边际成本，不含建表/端点枚举的相互作用；端到端数字
  仍待静机测量。
- 全部证据只在单一架构 `doc/eda比赛文件/arch` 与 `[16M,18M)` 冻结窗口上成立。
- 环境下存在并行执行会话与 1B 正式验收，本轮的端到端批次受其阻塞；b1 批次
  顺序未平衡，只作量级参考。
- 未修改正式实现、交付包与正式二进制；本轮改动均为新增模式（默认关闭）。
