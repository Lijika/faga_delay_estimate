## 预注册

2026-10-16，exp291 完整结果已提交 `6c75f8d`。本轮保留 exp287
search512-both 的冻结源码和 ELF，在 `build/exp292/fixed/` 创建私有修复版。
影响范围为私有 `main.cpp`、实验 runner 和证据；正式入口、源码、构建脚本、
交付包和用户改动保持。

已运行的 32 行复现中，显式 `-endpoint-mode off` 相对同预算 search512
参考改变 9 行。单行反例为 `SRB_68_396/ZQE[6]` 到 `SRB_37_355/A_F5`，
参考为 1459，冻结 Both 注入版为 1615，日志仍显示 off。两者 main 源码
仅在初始化前强制赋值 Both 处不同，residue 实现相同。原始证据见
`validation/results/exp292/repro.json`。

主假设为修复后默认预测与 exp291 完全一致，显式端点模式恢复到同预算
search512 语义。修复记录端点参数是否显式给出，仅在既有 productionCore、
uniformMinus3、base47-d8 和 legal-path 构建条件成立时注入默认 Both，
同时保留显式模式；诊断使用实际传入 estimator 的模式。帮助文本说明
默认优化模式与诊断配置。模型、bias、搜索预算及启用条件保持。

CLI 回归覆盖默认、显式五种模式、双横线别名、重复参数最后值、均匀 -3 bias、
显式 base47-d8、关闭模型、旧模型、零 bias、非默认阈值、bounds、hybrid、
exact 与七行边界。默认配置与冻结 Both 比较，其余配置与同预算 search512
比较。复现样本与边界输入用于回归，全部结果保留。仅 main 的参数配置和
诊断变化，搜索源码与资产逐文件一致时复用已有路径核验。

CLI 通过后在 Xeon core 3 串行执行默认路径。两臂先跑 20k 预热，再对
exp291 的 12,314 行旧样本各跑一次并复用相同输出的评分；该样本作为回归集。
完整独特 1M 按原版/修复版、修复版/原版两对测量，修复版公开 1M 跑两次，
repeated 1M 跑两次验证一致性。CPU 包含初始化和 I/O；同次输出同时承担
精度、行序、字段、整数、精确 EOF、完整 SHA 与资源验证。

所有默认输出必须与对应 exp291 冻结输出逐字节一致；相同输入、标签、权重
和输出身份下复用原评分，新增 exact 和评分成本为零。两对 CPU 差使用 df1
Student-t 95% 区间并加两端 0.02 s 舍入，仅描述部署性能差；该修复没有预期
算法收益。单线程、RSS <=2,000,000,000 B、CPU/wall <=3600 s、ELF <100 MB。
出现输出差异或契约失败时保留证据并停止扩大。AMD 时间只用于成本参考。

总体 acc >99% 和逐分布 CPU-acc 前沿规则保持；精度下降与分组误差沿用
exp291 的原始记录。100M/1B、独特 1M 全量 exact、跨架构与官方平台待验。
开工磁盘约 410 GiB 可用，收尾复查；本轮保留原始证据。
