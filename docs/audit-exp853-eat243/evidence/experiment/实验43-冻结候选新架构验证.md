## 样本与七距离带

复用 `scripts/make_scale_requests.py --mode unique --rows 6000000`，保留仿射序号 `[4,000,000,6,000,000)` 的 2M 行；既有实验24 用 `[0,2M)`、实验31 用 `[2M,4M)`。置换是 `j=(A·k+B) mod N`，行 k 只随 k 与 N 变化，因此新切片与已记录区间按序号不相交；生成后仍要抽行核对前 4M 与已记录的 `build/exp31/unique-4m.csv` 一致，并把核对结果写入证据。

七距离带按冻结探针的定义，扫描和抽样前已写明：`0`、`1-12`、`13-24`、`25-50`、`51-100`、`101-300`、`301+`。

## 预测与评分

两侧都用冻结 CLI 直接在 kept 的 From/To 上输出，Python 只读输出评分，不另造模型推理。评分复用 `validation/exp31_phase2_eval.py` 的 `evaluate_rows` 与完整 From/To 对齐：精确行数、唯一完整六元键、子集/乱序不变，缺行/重复/错键即失败；负 exact 独立统计，`fast<=0` 原值保留。主 accuracy 按 `exact>=0` 归一，MAPE 只统计正 exact。报告语料权重（`N_band / kept 行数`，负样本计入）与等带、每带、短距/边界/Block 诊断。已通过的 Python/C++ 一致性（10,024+99+3,107 行逐行相同）保留为特征侧证据，不在新集重复造推理。

## 区间与门槛

主比较是唯一预声明假设：candidate 减 baseline。区间用七带分层配对 bootstrap：带内重采完整记录，保留负样本，每次重算可达分母，band 0 若全数抽样则不重采；10000 次，固定 seed 20260923。方法在结果里写明；实验40 的加权 sandwich 区间只作历史参考，不能写成新样本的区间。

预声明门槛，四条全过才算通过：

1. 新集语料加权 accuracy 增益 > 0，且分层配对 95% 下界 > 0；
2. 等带 accuracy 增益 >= 0；
3. 可达性（生产 unreachable 比例）不比实验29 恶化；
4. negative exact 的输出仍然准确。

失败则候选保持 off，新集本轮不转训练集重试。精度通过也不等于接入：还需实验42 五次输出契约全部通过，并把 CPU 配对区间与公共集预算 `96 × 0.068026 = 6.530496 s/1B` 一起报告，才进入接入讨论。

## 证据边界与文献

新样本只代表架构生成器给出的请求分布，官方隐藏集、全独特 1B、赛方机器和 SOTA 仍未验证。实验24/31 的样本在实验28/32/34/40/41 反复用于选型，所以实验41 的“盲测”只能指相对训练端点独立，不代表选择独立。

局部文献 `EDA2026-FPGA布线延迟估算两轮调研汇总.md` 的 WP532 “ML-Based Delay Estimator” 支持架构最短路径标签、静态 C++ 与特征成本这条路线；该文对 Versal 器件给出的 <=5% 覆盖率数字是对另一器件口径的观察，不能当作本题 accuracy 证据。

## 实现修正（2026-09-23，协议不变）

审查后对驱动 `validation/exp43_fresh_validation.py` 做了三处修正，冻结协议本身不改：

1. `stratified_paired_bootstrap` 每个重采样的统计量改成**跨带合并**的语料加权配对分子除以合并可达分母，与 `evaluate_modes` 的语料加权 accuracy 口径一致，不再是逐带比值相加；负 exact 仍留在重采样里、每次重算可达分母，带 0 全数抽样不重采。新增夹具：带 0 一行、带 1-12 三行时合并比值是 25%，逐带相加会报 50%，自检要求两者可区分。
2. negative exact 门槛收紧为候选 `false_reachable == 0`（原为“不比基线差”），其余预声明可达性检查保留：`reachable_false_unreachable` 不劣于基线、`unreachable_agreement` 不低于基线。
3. kept 样本强制唯一完整六元端点键；用 `exp31_phase2_eval.align_predictions` 增加对齐控制自检，重复 kept 键、缺行、重复行、乱序预测都会被拒绝。

自检 16 项全过（无估计器运行）；抽样阶段输出保持原样，未重跑标签生成。等带门槛读的是等带**加权** accuracy（`weighted_accuracy_percent`），不是 `evaluate_rows` 的原始逐行 `accuracy_percent`；新增两个判别夹具（加权与原始方向相反时门槛必须跟随加权字段）。
