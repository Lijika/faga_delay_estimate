# 实验1：建立可信基线（第一阶段）

日期：2026-09-17
基线提交：`a5fb8df`（本轮提交见文末）

## 1. 本轮目标

1. 给 exact Router 补一个**不依赖实现自身**的 reference（显式物化图 plain Dijkstra），覆盖
   terminal predecessor、heuristic on/off、同 pin、同 SRB、logic/logic、logic/Z、Z/logic、Z/Z。
2. 给默认引擎 ResidueEstimator 增加最小可复现的独立验证入口：构表成功、输出非负、确定性、
   零距离、公开八条路径 fast/exact 对比与误差摘要；估计器不得接触 golden。
3. 复测公开百万行，确认提交路径输出与基线一致，记录 accuracy/MAPE/P99/CPU/RSS/哈希。
4. 只做第一阶段，不实现 CCH/HL/ML/XGBoost。

## 4. 内部一致性结果

### 4.1 `--quick`（通过，0 失败）

- 架构计数：ports=496（Z=160、I=160、logic=176）、arcs=8192、nets=160、srb=60200、blocks=7、lines=19（5 h / 14 v）。
- 八条公开检查路径逐边核验：`973/843/786/997/929/562/692/661` 全部等于 golden Min Delay。

### 4.2 `--resolver`（本轮修正的断言，通过，0.67s）

- Gap resolver 与独立参考模型在 **10,560,000** 组 (cell, net) 上比较：mismatch=0，
  有效边 9,417,280，含 Line Gap 收费 1,934,080，越界拒绝 175,360，落点命中 Block 拒绝 39,360。
- Block 专项：可穿越跨越 240 次；非可穿越 walk 480 次全部落在 Block 内而失效
  （`blocked-landings=480`），`nominal-offset-kept=0`、`offset-extended=0`、**`offset-shortened=0`**。
- 基线遗留问题：在 `a5fb8df` 上跑全量 `verify_internal` 会报 1 条 FAIL
  （"crossing a non-crossable Block never shortens the fixed offset"）。原因是断言写成
  "所有非可穿越 walk 都必须落在 nominal offset"，而该架构中水平 span≤10 < Block 宽 16、
  垂直 span≤12 < Block 高 50，永远到不了 nominal offset，必然落进 Block 而失效。
  实现本身与独立参考模型 0 mismatch，属于**陈旧断言**，本轮改为正确不变量（不得缩短）。

### 4.3 `--oracle`（新增独立 reference，通过，55.9s）

显式物化 (cell, port) 图上的 plain Dijkstra（无模板、无启发式、无 landmark），与实现三配置
（plain Dijkstra / span A* / span+ALT）对照：

```
terminal predecessors checked=3 identity-mismatches=0 router-mismatches=0
oracle queries=16 expansions=27310758 router cases=21 unreachable=5 mismatches=0
plain_expanded=9519969 span_expanded=66920635
```

覆盖：同 pin（含无出边端口，两引擎都短路为 0）、同 SRB（含 I* 端点）、
Z/Z、Z/logic、logic/Z、logic/logic、Z/I*、logic/I*、方向不可达、heuristic on/off。
terminal predecessor 用结构恒等式验证：`d(src→logic) == min_over_33_arcs(d(src→I*)+arc.delay)`，
组合值对 oracle、router 对组合值均一致。

## 7. 结论

1. **提交路径冻结可信**：输出 SHA 与 accuracy 与基线逐字节/逐位一致，五次运行一致，
   CPU/RSS 在噪声范围内；本轮所有改动都是测试/日志侧。
2. **exact Router 不再以自身为唯一 oracle**：现在有显式物化图 plain Dijkstra 参考，
   终点矩阵、terminal predecessor 恒等式、heuristic on/off 全部对照通过。
3. **ResidueEstimator 有独立可复现验证入口**（`build/verify_estimator`）：构表、非负、
   跨两次独立建表的确定性、缓存一致性、零距离、八条公开路径 fast/exact、误差摘要。
4. **基线遗留的 1 条全量 FAIL 定性为陈旧断言**并已修正（实现与独立参考 0 mismatch）。
5. **确认下界偏置**：1M 样本高估 0、低估 948,869；八条长路径全部低估；
   短距离/Block 交互误差最大（短距离 spot max −49.8%）。

## 8. 未解决问题与下一轮优先级

1. P0：residue 表未建模 Block skip/cross（292 ps）与不可穿越 veto、也未显式建模
   terminal 端点状态 → 短距离与 Block 两侧误差（本轮量化：八条路径 MAPE 4.59% /
   max 10.14%；短距离 spot MAPE 12.24% / max 49.80%）。
2. P0：精确路由仍无法做 fallback：span A* 在长距离约 0.17 s/query（1K 样本 172 s），
   ALT 8 landmark 建表 38 s。需要整数权 radix-Dijkstra + 短距离/Block 交互的**有界 exact 回退**，
   并给出 `L<=exact<=U` 证书覆盖率。
3. P1：单次 CPU 的 92% 是 residue 建表（10.7 s / 11.6 s）。若要冲 time score，
   先优化建表（或缩小 301.9 MB 表），收益比查询侧更大。
4. P1：几何/边界误差分解仍未按"路径级"归因（现有 Block 标签只描述端点几何）。
5. 未验证：十亿行官方运行（无官方机器），本地百万行分数不能替代官方成绩。
