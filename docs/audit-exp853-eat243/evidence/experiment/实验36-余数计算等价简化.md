# 实验36 余数计算等价简化

日期 2026-09-22。起点提交 `4b9a9fd`（实验35布局）。本轮只改 `ResidueEstimator::residueOf` 的取余写法，不碰 cutoff、模型和 rounding，也不加生产 flag。正式 `./estimate` 与 `build/submission/estimate` 保持实验29（`db2cca1e…`）。

## 改动

旧写法每轴两次取余，`rx = ((dx % mx_) + mx_) % mx_`，`ry` 同理。`mx_`、`my_` 由 init 保证为正，C++ 的截断取余给出 `r` 落在 `(-m, m)`，所以负数时加一次 `m` 就回到 `[0, m)`。新写法是

```cpp
int rx = dx % mx_; if (rx < 0) rx += mx_;
int ry = dy % my_; if (ry < 0) ry += my_;
return rx + mx_ * ry;
```

每个叶调用从 4 条 `idiv` 降到 2 条。`objdump -d --demangle` 显示 `estimateBase` 的 `idiv` 总数从 6 降到 4，其中位于 `12a34/12a41/12a4c/12a58` 的四条正是 `residueOf` 的两轴两次取余，另外两条属于 fallback 的步数除法，保留不动。

## 等价自检

`tests/exp36_residue_of_check.cpp` 用已有的 `ResidueTableAccess` 友元设置真实模数并调用真正的私有 `residueOf`，不初始化估计器、不建表。枚举 mult1 到 mult4，模数分别是 10×12、20×24、30×36、40×48，位移范围 x 取 ±183、y 取 ±613，覆盖正常查询范围 ±119/±549 并留了余量。共比较 1,801,236 项，0 不一致，负值、0 和整除边界都包含在内。架构最大净位移确认为 10 和 12，mult2 与 harness 报告的 20×24 一致。

## 逐字节与数值一致性

新 CLI `build/exp36/estimate-mod`（`b9dda9ea…`）在公开 1M 的 off 与 xgb 输出分别与 `build/exp32/1m-off.csv` 和 `build/exp29/estimate-full-1m.csv` 逐字节相同；3,107 独立样本的 off 与 xgb 分别与 `build/exp34/exp24-off-postfix.csv` 和 `build/exp29/estimate-full-exp24.csv` 逐字节相同。

新 harness `build/exp36/harness-mod`（`ff2b2a94…`）的数值 checksum 与实验35 布局版一致。公开 1M 为 off `12732869355266351452`、xgb `9655496091675031589`，新架构 1M 为 off `2982562222363282221`、xgb `11639369498928018786`。表容量仍是 813,957,120 bytes。

## 决定

保留这次取余简化。收益小但方向稳定，等价性有全范围自检和逐字节证据支撑。它是实验35 布局之后的第二个等价加速，正式入口仍是实验29，规模验收留给主代理。证据是 `validation/results/exp36-modulo-ablation.json`。

## 未验证

只在 1M 规模、同一台机器、单核受控条件下测量，100M、1B 和赛方机器未运行。`residueShift` 里的取余没有改。cutoff 候选未实现也未测。
