# 实验99：depth10末层删除与depth8直接对照

日期：2026-09-27。开工 `/dev/sdd` 可用约479G。

## 冻结协议

实验98等价工程优化通过，三对1M unique CPU平均减少1.31秒。当前假设为该优化足以让实验93 depth10相对实验92 depth8有实际综合收益。本轮直接配对，不合并两轮CPU均值。depth10模型、输出和精度区间复用实验93，accuracy增益 `+0.040127154 pp`，95%区间 `[+0.000556993,+0.080474344] pp`；完整输出等价证据见实验98。

基线固定为 `subm/versions/exp92-gamma1-384b9bf-dirty/bin-estimate`，SHA-256 `607b52e80cb6dad8905e4c46ff3ed45fa7670730b165e3ca995e34c97c837c63`。候选为 `build/exp98/estimate-trim`，SHA-256 `64d5e9dc05ae0a3db8aa52be4dd97ada7df24b05c5f7da343819577d3b782b91`。精度报告 SHA-256 `0baa25fbf5fd95f37a99650c1b53c65eca30a4b5d58a192831634740f3149a7d`。输出SHA分别固定为实验93记录的 `4cb01b787e9d72f48827d8d37aca656a67e5a83b0784943030466092fdf87d8b` 和 `d7b5f9ac590c97004404ee7827fa8161f287d19172566f0f1cf2d8979fe105fa`。

复用 `exp78_timing` 的进程树线程采样、完整1M契约和计时流程。输入、核3、双方预热一次、3对交错与实验98相同，禁止同期重负载。主指标 `ΔS=0.8Δaccuracy-ΔCPU/120`，通过条件为点收益至少 `+0.01` 且联合95%保守下界大于0；CPU配对用3对t区间，精度用实验93的七带bootstrap区间。可达性位置、完整SHA、多次一致、单线程、RSS<=2GB、wall<=3600秒单独检查。

```sh
build/venv-ml/bin/python validation/exp99_trim_vs_depth8.py
```

原始报告 `validation/results/exp99-trim-vs-depth8.json`，私有计时文件在 `build/exp99/`。通过后按打包规则接入；失败保留实验98的工程收益，整体候选继续受本次收益证据约束。1M unique仅支持已测分布，平台1B与隐藏集收益未验证。

## 结果

| 配对 | depth8 CPU/s | 优化depth10 CPU/s | 差值/s |

| 1 | 26.45 | 29.73 | +3.28 |
| 2 | 27.20 | 31.75 | +4.55 |
| 3 | 27.13 | 30.93 | +3.80 |

CPU差均值 `+3.876667 s`，三对t区间95%为 `[+2.290640,+5.462694] s`。复用实验93精度点增益 `+0.040127 pp` 后，综合分点差 `-0.000204`，联合95%保守下界 `-0.045077`；预设门槛未通过。depth10末层删除减少了成本，但当前优化模型相对depth8仍无可确认的综合收益，保持私有候选。

双方预热和六次正式运行分别重现冻结的完整1M输出SHA；端点原文、行数、3字段、整数delay、精确EOF和17,585个负值位置检查通过。最大RSS 571,150,336字节、最大wall 31.79秒，进程树采样单线程通过。脚本使用与实验93一致的depth8二进制，命令均取生产默认参数；输出SHA核对了参数效果。收尾 `/dev/sdd` 可用约479G，释放量0，无需清理大文件。
