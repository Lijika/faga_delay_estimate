# 实验78：128 树候选独立复核预注册

日期：2026-09-26。exp77 已冻结的 128 树模型不作任何修改，性能比较若触发仍固定为 3 对交错运行。

- 候选模型：`build/exp77/model-128.json`，SHA `28445cb3bcd08dfc6838984f2e5a1a4491656919208215ffbabfa655757e3774`。
- 控制输出：实验63/exp71 正式包，模型和 `-3 ps` 语义固定。
- 新窗口固定为 affine unique `[30M,32M)`，七带各至多 1024 条 exact；排除训练池、所有历史窗口和 exp76/77 样本，命中即停止且不补样。
- 主指标仍是按距离带份额加权 pooled accuracy，配对 bootstrap 10,000 次、seed `20260925`。候选通过需点增益至少 `+0.03 pp`、95% CI 下界大于0、false finite 和 reachable false unreachable 不增加。
- 只有该精度门槛通过，才进入同一 1M unique 输入上的 3 对 CPU 交错比较；精度失败则不测性能、不改正式入口。

本轮用于验证已冻结模型的跨新窗口泛化，不根据结果重新选择模型；隐藏分布和平台 1B 结果未验证。

## 精度与初始成本结果

新窗口2,000,000请求，exact样本6,174行，七带完整，完整端点排除命中0。64树控制输出与实验63静态包逐行相同。候选accuracy为96.358077%，控制96.326452%，差+0.031625 pp，bootstrap 95% CI [+0.011613,+0.051856] pp；MAPE 0.936620%→0.927866%，两类可达性误判均为0。

模型SHA与exp77相同；padded导出512向量位级遍历自检通过。动态候选 `build/exp78/estimate-128` SHA `c7be9724565b8ee4df01daffa03cd45e286385d5373bd992a5244e5b7632e2d5`，6,174行C++输出与Python候选逐行相同（完整SHA `feb2787753fbde873ab8894fd8344b47d6e4082710987d06ef1470db8e61c38c`）。

与exp71静态包预热后3对交错，CPU差为+1.91/+1.54/+2.34秒，均值+1.93秒，95% CI [+0.935414,+2.924586]秒。综合点收益+0.009217，精度下界和CPU上界组成的保守下界-0.015081，接入门槛失败。每轮1M完整SHA稳定（candidate `a25c7c7c3483c5d8dcc20716de2e2294e693246256bec0a9162550fd539d33cc`），端点、行数、整数delay、EOF、单线程、RSS及wall通过，峰值RSS≤926,068,736 B。个别记录CPU大于wall，原始数据保留，主指标按预注册CPU计算；三对样本的区间限制如实保留。

第一份临时计时脚本把基线SHA应用到候选，预热后断言失败，未产生有效配对记录。修复后的 `validation/exp78_timing.py` 分别检查两侧SHA并采样实际进程树，完整3对证据在 `validation/results/exp78-timing-1m-unique.json`。

exp78复用exp77配置时曾把阶段JSON写入exp77文件名，后已修复配置按实验编号写入，exp77记录恢复已提交原文，exp78原始阶段记录保存在 `validation/results/exp78-stage-requests.json` 和 `exp78-stage-sample.json`。exp78的32M全量文件仍沿用私有名称 `unique-30m.csv`，其元数据和实际行数为32M，ordinal切片为[30M,32M)。

初始候选保留到exp79做数值等价工程优化，精度证据复用，正式入口保持exp71；exp77较早窗口+0.026485 pp的结果同时保留，本轮通过不改变该窗口未过点门槛的事实。
