# 实验843 保留双码的B条件融合修正与留出组验收

2026-10-29，新实验结果前登记。正式入口exp825与完整1B的CPU160.776248秒、抽样Acc98.881628718%保持。最终目标仍为未知非重复全合法角色1B约100秒及Acc严格高于99.1%。

## 假设与对照

exp842的AB组均值有方向0正收益，但为17,927个已选组的实际码对逐一保存完整曲面，四方向静态投影352MB。exp827已检验固定B256与2bit近轴三条修正，在稀疏构造样本上未过机制门。这里保持原A2048/B256和每键C，增加每B最多八条完整552点修正形状，并用32bit目录原bit21及高两位组成三位修正码。零码严格复现原B，运行时将B和修正恢复成融合B表，保留原有两次码本读取及地址依赖层数。

对每个B组用完整认证曲面的原名义L1权重，冻结B码与每键C，按残量逐次选当前加权损失最大的曲面初始化其他七码；随后执行四轮按列加权中位数中心更新与严格改进选码。必须裁剪修正，使原B+修正保持int16范围。新表示的码0为零，逐键训练内名义L1应非增。只在训练集构造形状，不用真实标签训练。

## 数据、质量门和停止

复用exp840已经冻结的方向0完整449,350条曲面和原始身份。128个已选主码按顺序，每四组取第`seed=20261029843`的`seed%4`槽作为留出组，其他96组用于B条件形状训练；留出组约占1/4，用完整名义场重新选码，检验跨A的表示迁移。历史百万开发请求按训练组与留出组分别评分，使用exp840冻结同次的原current、exact真实整数与最终残差函数。额外比较全部128组，避免只看留出小样本。名义损失及真实评分分开记录。

容量先测方向0融合B表的zstd编码字节与留出目录3bit码的频率。全域映射不能直接从所选组的熵推定，只给出最坏10,782,720B的独立3bit流上界和四方向B融合表原始9,043,968B；完整四方向目录压缩及ELF在质量门通过后再实测。恢复后的形状需要4×256×8×552×2B运行容量，在线使用原A和融合B表；是否快仍需完整程序实测。

质量门预先设为留出组相对current至少+0.06pp、全部128组至少+0.06pp，留出组至少回收对应exact参考的12%，并要求两个差的26源族9999次bootstrap双比较同时95%下界都为正。只对留出组内样本量至少100的near_axis、distance、direction、fold分组要求相对current不低于−0.05pp；样本量不足100的组单列其贡献和方向，不用小组均值决定大规模实验。要求所选组额外曲面zstd正文折算四方向加目录和256KiB预留仍小于99MB；压缩投影仅作筛选。质量门失败就停止本固定B8完整形状配置，不继续全域构造。通过时按协议全四方向无标签构造、确定ELF与RSS，随即跑新100M；联合收益明确后完整1B并接入阶段版。

首个门只做有界原型。完整所有角色、四方向、静态ELF、100M、1B和官方未知请求均尚未验证。独立审核应检查每键码0可重建原值、偏置不变、非增、合法int16、冻结集合身份、留出分组不相交以及评分从原始整数独立计算。离线CPU与wall≤900秒、研究RSS≤4GiB；比赛CPU单线程、RSS≤2GB、ELF严格小于100MB仍分别核验。
