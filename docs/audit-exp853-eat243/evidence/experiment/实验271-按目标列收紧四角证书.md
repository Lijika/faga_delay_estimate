# 实验271 按目标列收紧四角证书

2026-10-15。exp270在远程core3的两分布20k分别省2.37%和
2.42%；AMD第二机区间跨零、点估计变慢。先用局部原型衡量
目标列专属的有限行极差是否值得继续实现，正式入口保持原状。

## 预注册

以冻结的exp270候选ELF和同源码为基线。对每个已存目标列`c`
扫描它的全部余数、Z端口连续四槽行，计算
`D_c=max_row(max_{finite} F-min_{finite} F)`；现有全域极差为
`D=max_c D_c`。查询已固定`rankColumn=c`，若线性最大值与
第二名差`G>=D_c`，且领先槽有限，则原四角最大值保持。
列由加载架构生成，只有通过原int16值域检查的窄表可用。
无窄表及其他回退分支维持原计算。证明与边界见vault笔记
`目标列局部极差的单槽证书`。

仅在本地私有`build/exp271/pilot/`编译instrumented
search-check；不改预测计算。用exp269固定的U-output、
U-role原序各512条，记录原`D`与新`D_c`的逐次q覆盖、
额外扫描CPU、搜索字段和完整路径一致性。
先冻结exp270源码/ELF、协议、编译命令、脚本、两个输入身份。
若两分布覆盖各提高至少5个百分点且扫描新增CPU均低于1秒，
再单独实现、审计和远程配对；否则停在原型。
完整1M及跨架构性能需要独立核验，不由覆盖率推断。

本地`/dev/sdd`开工可用419GiB；远程exp270完整1M
运行期间不在远程执行其他负载。所有文件保留在
`validation/results/exp271/`与`build/exp271/`。

## 原型结果

两组样本均使用冻结的exp269前512条输入。U-output的
1,718,388次窄表求值中，原证书命中777,754次，
逐列证书命中790,135次，覆盖率增加0.72个百分点；
U-role的1,473,806次中，命中642,436至648,161次，
覆盖率增加0.39个百分点。额外逐列扫描CPU分别约111和
109毫秒。原全域`D=5,256`，两组原命中计数与exp269
逐项相同；512条搜索字段及路径前缀均与exp270一致。

两分布均未达到固定的5个百分点覆盖增益门槛，停止该项
在线实现与远程计时。证书的数学有效性不受性能结果影响；
原始数据见`validation/results/exp271/freeze.json`及
`pilot.json`。本地`/dev/sdd`收尾可用419GiB，
释放量按`df -h`的整数精度为0GiB，本轮未删除文件。

补充离线核验`prefix-check.json`确认两组恰好512条搜索记录，
以及所有`index<512`路径边的完整相等。原型只记录新增扫描
CPU，完整进程CPU、峰值RSS及线程未单独采样。
