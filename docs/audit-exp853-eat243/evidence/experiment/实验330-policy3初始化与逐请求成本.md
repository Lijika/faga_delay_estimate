# 实验330 policy3初始化与逐请求成本

## 条件预注册

2026-10-17。正式基线保持exp323，候选复用exp325冻结policy3 ELF。
算法、模型、预算、策略表和构建参数保持。主假设是policy3的初始化
增加掩盖了每次请求的计算节省；本轮检查固定工作集内的重复重新计算。
本机/dev/sdd开工可用399GiB，远端工作目录可用174GiB。

两组已查看开发样本为U-role的14,080行和exp258的12,320行。两臂
均使用已有参数`-cache-mb 0`，保留其他生产默认参数。先各运行原样本
一次，要求输出完整SHA与exp325保持。随后按原行序完整复制8次与32次，
分别形成112,640/450,560行及98,560/394,240行。真实CSV读写保持。

每个分布先在两个规模分别AB预热，随后三个block按AB、BA、AB顺序，
每个block先8倍、后32倍。Xeon核3串行，避开其他重负载。每次检查
行数、端点、3字段、整数delay、EOF、换行、完整SHA、单线程、2GB与
3600秒限制。任一输出与原结果逐次重复不符时停止，保存异常。

主指标为两个规模的完整CPU配对差、每请求差和初始化差。复用Obsidian
笔记《完整程序CPU差的初始化与逐请求分解》的条件模型，以同block的
两规模配对差求斜率和截距。配对t采用df=2；完整CPU差另加0.02秒
舍入幅度，斜率加0.04除以两规模行数差，截距按线性系数传播。
0.5%作为实际效应描述，候选资格沿用当前分布内前沿规则。

逐请求差区间小于0时保留该工作集上的计算收益，后续新请求和真实
独特负载另验；区间跨0保持待定；大于0时结束固定候选在该工作集
上的扩大。完整CPU、初始化和斜率分别报告，固定次数结束后停止。
成本模型的线性前提和三对计时的统计假设单列。

两臂原样本与重复输出逐行保持后，精度沿用exp325同一基础样本、
标签和权重，各复制行权重按复制次数均分。重复行维持原有效样本量
及原bootstrap区间，新增exact与评分预算为0。U-role与exp258的
policy3开发acc分别为99.004369%和99.004302%，原区间跨99%。
本轮CPU对应分层样本的实际行序，人口加权精度单列，人口CPU仍待测。

缓存关闭后hits为0，miss数按合法解析请求数从CLI与源码推定，记录
为推定值。CPU缓存与内存工作集仍会复用，本轮证据支持重复重新计算
的成本诊断。全新请求、完整独特1M、完整算法100M/1B、跨架构和
比赛平台继续待验。生产源码与交付入口保持，实验只新增私有数据和记录。
