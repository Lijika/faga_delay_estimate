# 实验609 共享通用启动状态的安全指令分派

2026-10-22，构建与查看新结果前登记。exp608完整1M/10M发现共同
代码组织收益，F最快且完整100M已通过等价。静态检查发现AVX2单元
全局Architecture的初始化在main检测前执行vpxor/vmovdqa。因此
exp608是不可发布原型，其100M仅保留数值和单机成本证据，停止1B。

本轮修复该具体可达触发路径。三个worker仅extern引用同一arch，
arch唯一实例与malloc包装计数放在generic入口单元。扩展worker
对象文件不得含.init_array或全局动态初始化函数；共享析构与入口
按x86-64编译。全部源与链接资产复用exp608冻结值，仅改变状态归属。

A仍为exp601/PQ；F/S/D分别整路径SSE2/SSE4.1/AVX2。重复完整全端口
1M逐位trace和两套唯一1M的预热、六轮正逆计时，使用exp608相同门
和98.333333%区间；F可作为独立候选。合格扩展路径构建自动分派。
新二进制须重新验证，exp608的计时不作为当前版通过证据。

之后比较A、F和AUTO的完整10M，固定输出SHA及完整契约检查与exp608
相同，F/AUTO节省>=0.01秒、两候选97.5%区间下界>0；平均差<0.01秒
优先F。实际选择以这一步为准。选定者进入完整100M，确认无退化
后完整1B。若扩展指令无额外收益则交付通用路径，分派代码保留研究
身份；容量、资源、单线程与CLI门均保持。其他CPU的性能仍待平台实测。

可改validation/exp609_safe_dispatch.py、验证记录和本日志。复用
exp608/607量测工具。扩展路径在弱CPU上不会启动的结论必须以对象
构造检查和通用入口分支检查支持；可用时补CPU功能掩码的仿真验证。
官方测试仅在r9，且全部算法输入全端口、无重复。编译/静态检查
和完整程序CPU分开记录；源码候选与正式exp602包继续分别管理。

## 已通过的核验与中间结果

F/S/D及自动路径完整1M全部trace字段逐位保持，两套1M共98次输出
SHA相同。对象检查显示所有worker均无.init_array和_GLOBAL__sub_I，
只导出各自worker，架构对象唯一实例及析构在generic入口编译。
远端qemu-x86_64不可用，旧CPU功能屏蔽仿真保持未验。

完整10M预热及六对计时通过，F节省0.240692秒，97.5%区间
[0.222871,0.255977]。AUTO节省0.222439秒，区间
[0.213444,0.232584]，AUTO比F多0.018253秒，选择F。
完整100M CPU24.728427秒，原exp601为27.066669秒，此为历史单次
规模对照；同机配对收益依据上述10M。100M契约及完整SHA相同。
空环境、仅放单ELF的清洁目录完整全端口唯一1M输出相同，单线程、
查询分配0及资源通过。完整1B结果见后文。

首次10M复用工具时保留了旧实验协议路径，在启动算法前失败；
指定本实验PLAN后重新运行完成，失败记录见protocol-path-failure.json。

远端历史传输tar包与本地既有包完整SHA相同，模型和展开文件保持。
