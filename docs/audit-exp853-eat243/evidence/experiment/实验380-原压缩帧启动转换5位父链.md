# 实验380 原压缩帧启动转换5位父链

2026-10-17，在实现和新测量前登记。exp379已确认静态5位blob使ELF超100MB。
本轮固定保留exp354原25,534,675字节压缩帧与元数据，
仅在UpperTree初始化时逐树解压到临时8位数组，再转换为exp379同一连续5位表示。
字典复用exp379的升序值集合，另生成40,960字节反查码表；
根254、缺失255、原顺序与每树尾部零guard保持。

主假设是常驻容量下降改善随机父链访问，同时原压缩帧维持可交付尺寸。
竞争解释为在线位提取、字典依赖和启动编码增加CPU。
在线父表为548,262,860字节，加40,960字节反查码表；
临时8位缓冲逐树释放，完整RSS与初始化成本分别测量。
旧采样UpperTree在U-output占4.10%，预期完整程序收益受该占比限制。

正式源码、入口与交付包保持exp354。私有改动限定build/exp380/src中的
upper_tree.h和生成字典header。Tree::restore是init及逐槽检查共用的
私有恢复方法；evaluate、映射、路径恢复、搜索、模型、校准和I/O保持。
调用者只有UpperTree::init及审计probe；selector probe复用exp379。
通用-O2静态构建，静态ELF必须小于100,000,000字节。

先检查真实恢复方法的全部877,212,320槽、40个根、255、尾部与25,600个边界，
普通与ASan/UBSan各一遍。保留逐树编码CPU以解释初始化成本。
再核对12,150条旧开发请求的UpperTree全部结果字段、浮点位型、特征、
路径摘要与操作计数；复用exp353四个exact开发分布48,184条及边界、异常输入，
完整输出SHA必须与exp354相同。旧数据均作为开发集，等价修改复用标签，
新增exact成本为0。

通过后本机20k输出契约与资源参考，Xeon完整非重复公开1M另登记为exp381。
exp381固定三臂exp323发布版、exp354、启动5位候选，各20k预热后按
baseline/control/candidate、candidate/control/baseline、
control/baseline/candidate运行三轮。核3、单线程、重负载串行。
完整输出相同才复用公开acc99.01069721418632%，变化0行、分组误差保持；
精度余量仍小，本轮保持该事实。

完整1M主指标为配对CPU差及df=2的95%t区间，包含time舍入范围。
进入本轮10M要求对exp354节省至少0.2秒，且对exp354及exp323的
CPU差区间上界都小于0。区间跨零保留待定，明确变慢结束本轮固定表示放大。
初始化时间另列，按启动与逐请求分解解释差异；AMD计时只作参考。
单线程、RSS<=2,000,000,000字节、每次<=3600秒以及完整输出契约均须通过。

原始证据放validation/results/exp380；脚本阶段为prepare、build、audit。
依赖、协议副本、源码、二进制和输入均冻结，既有阶段排他创建。
开工/dev/sdd可用约387GiB，本轮先保留exp379生成物用于审计，删除量为0。

## 结果与证据

启动转换、等价和资源检查通过，完整1M计时见exp381。原协议副本保存在
`validation/results/exp380/protocol-original.md`，正式实现继续采用exp354。

- 通用静态ELF为94,132,880字节，SHA-256为
  `5605f030449a2e29b3edafb998e30e2801bda31033563d72fd81a1471cb0a8b7`。
  保留原压缩帧后满足100MB尺寸要求。
- 连续父码流含尾部guard为548,257,740字节，字典5,120字节，
  反查码表40,960字节。相对原877,212,320字节父表，常驻表示少328,908,500字节。
- 普通与ASan/UBSan各逐槽核对877,212,320个父值，覆盖40个根、
  288,664,470个缺失值和25,600个边界位置，全部通过。
- 12,150条开发请求的UpperTree字段、浮点位型、特征、路径摘要与计数保持；
  四个exact开发分布共48,184条、7条边界、20k及特殊输入的输出保持。
  复用原exact标签，新增标签和评分CPU均为0。
- 本机完整20k资源运行CPU为7.72秒，峰值RSS为1,356,943,360字节，
  观测单线程，输出契约通过。本机时间仅作参考。

复现入口为`python3 validation/exp380_parent_startup.py prepare|build|audit`。
原build阶段的父链probe两次因缺少声明宏编译失败，失败日志保留；
`validation/exp380_build_recovery_residue.py`补齐
`DELAY_ESTIMATE_PRECOMPUTED_RESIDUE`后完成probe，生产源码和冻结候选保持。
恢复顺序与具体命令以`build.json`的correction记录及`audit.json`为准，阶段排他创建。
独立检查`validation/exp380_evidence_check.py`已通过，
结果见`validation/results/exp380/evidence-check.json`，沿用通过的证据。
本轮完成无损性与尺寸验证；在线解码的CPU代价由exp381配对结果判断。
原始输出保留，清理删除量为0。
