# 实验228 C1 上界间隙32上调独立请求验证

2026-10-12。正式入口 exp131、交付包和私有完整程序 exp220/exp227
保持不变。本轮验证一个未参与新请求选型的固定规则：

```text
C = min(selector_prediction, legal_C4800_upper)
if C > 0 and upper - C >= 32:
    candidate = min(C + 8, upper)
else:
    candidate = C
```

exp225 只登记并筛选了间隙阈值 `1/4/16/64`，没有查看 `32`。在
exp214 开发窗口和 exp215 已查看窗口的描述性补算中，`(8,32)` 分别取得
`+0.039855 pp` 和 `+0.056189 pp`，本轮冻结该规则后不再根据新标签调整
步长、阈值或距离门。

## 预注册

复制 exp226 的同架构新请求流程，窗口固定为 `[58M,60M)`。先生成完整
2,000,000 行请求，再排除 exp174/exp203 已查看端点和基础模型训练请求，
每个距离带固定抽取 1,024 行；随后才读取 exact 标签。候选生成器沿用
exp213 的二十棵 C4800 树、八种 cycle 映射、真实重放和合法上界证书，
baseline 为 exp220 等价的 selector + C4800 向下截断。

每行检查端点、exact、权重、`upper >= exact`、整数输出及 `candidate <= upper`。
零值、不可达和上界缺失行保持 baseline。按七带总体权重计算 accuracy，
使用配对七带 bootstrap 10,000 次，seed `2026101206`。通过门为点增益至少
`+0.03 pp` 且 95% 区间下界大于 0；该门只证明固定规则在新请求上的精度，
不承担完整程序 CPU 或正式版本接入结论。
