## 预注册

基线为 exp220 的完整 UpperTree 模块，候选只给中间重放 resolveNet
增加一次查询内的 512 槽直接映射缓存。完整键包含有效坐标与精确位移
类别，碰撞时重算并替换；保存 x/y/delay/valid 全部字段，终端准备、
parent 读取、Arc 费用、候选顺序和两级预算剪枝保持原样。
缓存每次 evaluate 清空，类别在 init 根据已加载架构的 Net 位移生成。

只比较 reference/candidate 两臂。计数版每次命中再次调用原 resolver
核对四字段，同时记录实际调用及命中数；计时版移除计数和复核。
先本地检查 exp216 的固定 12,352 条完整 audit，所有旧候选、旧合法数、
26 维 float32、gain、新 U 和最终整数必须一致。parent 次数逐行保持，
实际 resolver 次数逐行不增加，缓存命中加剩余调用等于原调用次数。
计数版及计时版输出都与既有 audit 对齐。任何差异即停止。

本地通过后，等待 exp232 完整计时和 exp234 标签工作结束，再在
`r9r4900:/home/lhj/lhjwork/eda2026`、Herdr `w1:p2`、core3 串行执行。
AB 预热后五对 BA/AB/BA/AB/BA，每进程初始化一次、核对一轮，再计时
10 轮 12,352 条请求。记录初始化、查询、总 CPU、RSS、线程及完整输出。
通用 C++17/O2 静态编译，单线程、RSS<=2 GB、CPU/wall<=900 s。

主工程门为查询 CPU 节省至少 5%，五对差值的 t(df=4) 95% 区间上界
小于零。通过后再与冻结精度候选做完整 1M；未过则停止这个固定 512 槽
构造，本轮不搜索缓存大小或换 hash。全部精度证据复用原标签，生产入口

## 结果

本地完整 audit 与远程五对计时均通过。12,352 条请求的原候选、合法计数、
26 维 float32、gain、两级 U 和最终整数保持一致。每行 parent 次数保持，
缓存命中与剩余 resolver 调用之和等于基线调用数。

| 工作量 | reference | candidate |
| --- | ---: | ---: |
| parent 读取 | 19,666,809 | 19,666,809 |
| 实际 resolver 调用 | 11,197,358 | 3,969,295 |
| 缓存命中 | 0 | 7,228,063 |
| 恢复阶段停止 | 319,162 | 319,162 |
| 重放阶段停止 | 12,859 | 12,859 |

五对查询 CPU 均值差为 -0.774168 s，95% t 区间为
[-0.789125,-0.759211] s；reference 的十轮查询均值为 8.661766 s，
节省 8.937760%，通过预注册 5% 门。两臂初始化均值分别为
0.796828/0.797054 s，整进程 CPU 均值分别为 10.486/9.638 s。
最大 RSS 为 911,237,120 B，12 次运行全部单线程，退出码和资源检查通过。

报告见 `validation/results/exp235-report.json`、`exp235-evidence-check.json`。
固定 512 槽方案继续与精度候选做完整 1M 组合验证。组件七带抽样结果
仅支持当前探针的成本结论，总体输入和比赛平台成本继续待验。
