# 实验420 两源直接距离原型完整非重复1M

2026-10-18预登记。exp419首尾真实事件加精确名义中段在固定开发子集
acc 99.051530%，553行改变全部改善，尚低于99.1%的余量目标。
本轮验证这个计算范式在新请求上的精度及完整1M程序成本。

范围固定为ZSEA[0]、ZLE[0]两个源端口到全部160个Z目标。
输入在这两个端口具有有效首Net的真实源pin与全部真实目标Z pin的
笛卡尔积上均匀不放回采样1,000,000条，seed20261018420。
20,000条评分样本在该1M中均匀不放回选取，seed20261018421，
按相同源pin成组bootstrap 2,000次。此分布与全端口主分布分别报告。

原型以exp415后缀DAG代替exp419原始距离场，保留首尾接合、
正长度环、同pin、无效首Net及单Net路径。采用现有CSV读写和真实resolver。
先逐项复核15,477条开发输出等于exp419，再运行新1M。
目标为完整程序CPU至少快于exp323五倍，采样acc严格大于99%，
同时报告95%区间及99.1%余量目标。达标仍需解决全源容量后才扩大主分布。

Xeon core3、O2通用构建、单线程，预热各20k，然后完整1M按AB/BA执行。
A为冻结exp323发布二进制及默认算法配置，B为两源原型。
每次运行含架构加载、DAG映射、全部CSV解析与输出。
同机串行，峰值RSS≤2,000,000,000 B，每次≤3600 s。
输出行数、顺序、恰好三字段、整数delay、精确EOF及SHA完整检查；
两次同臂输出须逐字节相等。输入全请求键去重，原型无请求答案缓存。

exact复用已审计的`build/exp203/exact_labels`及`build/exp155/orbit.i16`，
20k标签单独计时，8条按距离分层用span-only参考求解器复核。
评分直接使用同次完整1M计时输出的20k行，不为评分重跑原型。
不可达样本单独报告，正延迟按官方tanh公式评分；总体分数的特殊值处理
明确记录。若采样精度未过或全源资产仍不满足容量，不进入10M。

原型外置架构和21,839,958 B的两源DAG，仅是研究入口，尚未形成
100MB自包含交付。完整1M结果仅支持此两源分布，不能代表官方全端口1M、
100M或1B成绩。生产入口保持exp354，研究比较基准固定exp323。

## 完整1M结果

源空间114,350个有效源pin，目标空间9,632,000个真实Z pin，
请求对空间1,101,419,200,000。均匀不放回抽取1M，与exp417开发集
请求对重合数为0。固定两源覆盖限制继续保留。

| 指标 | exp323 | exp420两源原型 |
| --- | ---: | ---: |
| 完整1M CPU，第1轮 | 102.03 s | 2.22 s |
| 完整1M CPU，第2轮 | 102.27 s | 2.20 s |
| CPU均值 | 102.15 s | 2.21 s |
| 峰值RSS，较大值 | 1,693,384,704 B | 65,703,936 B |
| 20k exact抽样acc | 99.138113% | 99.079815% |
| acc 95%区间 | [99.102418,99.171127]% | [99.023608,99.139522]% |

同输入平均速度比46.2217。两对计时差仅支持当前机器、构建和输入，
仍需其他工作集与平台证据。精度配对差为-0.058298个百分点，
95%区间[-0.108889,-0.005182]。两个方法在这份分布上互不支配。
原型的SEA子组99.005299%、LE子组99.161532%，SEA精度余量仍小。
20k样本均为正延迟，没有零值或不可达参考值。exact标签成本75.44 s，
其中8条用span-only参考求解器核对；评分CPU约2.19 s。

完整1M有579,875行预测变化，149,029行增加、430,846行减少；
带标签的20k样本有11,615行变化。两次同臂输出逐字节相同，
输出契约、单线程及资源检查全部通过。候选输出SHA为
`99c20961d82da71df39ef88bd7bc3688705ff1047dfbeebf237416d2a68bd32b`。
计时输出的原始全量CSV保留在远端`build/exp420/{a1,a2,b1,b2}.csv`。

原型与exp419开发输出15,477行逐项一致，固定源码的ASan/UBSan同样通过。
共享测试main只增加显式return 0，修订身份见shared-probe-revision。
第一次远端启动因默认Python缺少NumPy在解包与计时前停止；将NumPy导入
移到本地生成和评分阶段后成功，算法、输入、AB/BA顺序与门槛保持。

本轮通过两源原型的速度与总体采样acc门，尚未达到99.1%余量目标。
全源静态表示、其他端口接入及全端口精度仍待验证，按原协议未扩大10M。
下一步围绕目标端重复选择及内部Block误差展开；前者的充分条件已写入
vault的`目标Net事件一致时的Bellman免枚举证书`，覆盖率与CPU尚待测。
原始证据与完整复现参数见`validation/results/exp420/`，
正式生产入口继续保留exp354。
