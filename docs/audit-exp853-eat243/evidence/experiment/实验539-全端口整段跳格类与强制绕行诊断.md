# 实验539 全端口整段跳格类与强制绕行诊断

2026-10-20，在查看本轮新结果前登记。正式入口exp354、CPU基准exp323。
本轮检验全路径事件松弛解释内部几何误差的能力，为后续事件接口设计提供
证据。复用历史整段跳格推导，新增全部logic角色和完整端口资格；
历史选择性端口的输入与成绩保持原范围，全部测试使用208×288数据。

## 固定对象与方法

沿用exp536完整非重复1M、exact、全部208份exp499认证场、160个正cycle、
真实首Net落点a、费用w、名义首段v及Line(a,t)。logic源取a=s、v=w=0。
令c=a-v、d=t-c。两臂仅使用同宽14、同费292ps的水平跳格。

第一臂为完整整数净跳格类松弛
`L0=w+Line(a,t)+min_k[Dplus(d-14*k*ex)+292*abs(k)]`。
第二臂保留三个路径类，零跳格使用`max(Dplus(d),H)`，
非空净零使用`Dplus(d)+584`，其余k沿用第一臂。
H为必须离开相同行带时的上下绕行势下界。所有目标保留端口身份。

四个势斜率固定为共同尺度120下的
`(1500,1270),(1500,-1250),(-1500,1270),(-1500,-1250)`。
从完整Net+Arc宏图重新构造势，逐条检查全部8,192宏边的不等式。
势包含全部源及目标logic状态，中间消元只对160个Z状态取min。
全部可跨Block宽、费和方向由当前架构核对。有限认证域外查询使用
全局可行势与0的max；Z同端口零位移使用正cycle。
每行整数k在下一个292*abs(k)已达当前最小值时停止。

复用exp535输入核验与exp536名义读取。第一臂、第二臂、exp536 oracle、
exp354和`max(exp354,L1)`在同一完整1M上分别评分。
两臂必须逐行不超过可达exact，修正exp354后的绝对误差逐行保持或减少。
这两个条件任意失败即保留失败证据，停止质量结论与生产原型。

## 固定指标与停止

主假设为净跳格类加必经绕行足以描述主要剩余几何误差。
机制门同时要求第二臂真实acc≥99.1%、相对exp536几何平方和
减少≥25%、源pin配对acc收益的95%下界>0。
另记录第二臂相对第一臂的增益以识别H的贡献。

与生产组合的继续门为相对exp354的acc收益≥0.02pp且95%下界>0，
它只说明精确字段诊断值得后续研究。静态容量和CPU仍需新的实现证据。
三项配对比较共同使用2000次完整源pinbootstrap，seed20261020539。
报告端口族、四种角色、方向、近轴、边界、Block两侧及行带分组。
保存全部k查询次数、域外势使用次数、胜出类别和完整整数预测SHA。
零路径和无效源在该1M中的实际数量单列；专项边界输入另验。

若机制门失败，则结束这个固定事件松弛，利用误差与胜出类判断
是否应保留有序事件或最后接口位置。完整名义字段的压缩成本保持独立，
当前精确场诊断的精度不能充当可交付模型的精度。
