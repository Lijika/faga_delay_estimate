# 实验770 端口名单字读取与完整100M

2026-10-27预登记。exp769的远域双侧INT16展开在完整100M增加
0.527082秒，固定布局停止。exp733公共解析与准备回放为10.684370秒，
因此速度侧同时检查所有请求都会经过的端口解析成本。

## 假设与范围

冻结exp728全部模型、几何和批8流程。规范端口解析已有可读8字节
检查，当前分别逐字节寻找第4至7位置的分隔符、再读取首尾4字节
生成完整端口键。本轮从该处一次memcpy读取uint64，使用高32位
的零字节检测定位最早分隔符，原短名称键由同一寄存器移位恢复。
直接端口目录、长度与完整键校验以及慢路径保持。

零字节掩码的高位可能受低字节借位影响；最早命中仍对应最早零字节。
只有掩码非零才调用ctz。通用x86-64小端构建，读取范围仍由原guard
保证，4至7字节名称和逗号/换行两种分隔符均检查。该变化旨在减少
重复载入、名称长度循环及其依赖，实际收益由完整CPU判断。

改动只在私有exp723_fused_parse.h，worker保持原文。复用exp723的
1,775,888个全496端口组合、单字节变体、随机输入和溢出案例，
以及45,003行包含CRLF、空白、跨缓冲、超长行及末行的reader夹具。
guard page覆盖每个截断位置，快路径接受的字段与旧解析相同。
新增接口与模型为0，完整estimate只运行100M和通过后的1B。

## 完整规模协议

复用exp720/733全有效角色、唯一100M及完整输出SHA；此为等价优化，
同输出复用完整契约与1,916,928条exact评分。候选与基线每次输出
SHA须相同，各预热一次后AB/BA六对，r9 core8串行。完整CPU包含
初始化、读取、求值和输出，保存user/sys、wall、RSS和线程。
计时期间停止其他远端重负载。

平均节省至少0.25秒/100M且95%配对t区间下界为正才继续；
14次单线程、RSS<=2GB、CPU<100秒、wall<=3600秒、零查询分配及
静态ELF<100MB均需通过。成功后立即清洁目录100M、阶段接入、
同函数完整1B；实际1B成绩与历史exp728参考分别记录。
失败限定本次单字读取布局，不继续扫描位技巧或名称特例。

沿用exp769/761的计时、完整SHA核对、逐项重复输出清理和独立复算。
私有目录research/exp770，新增资产预算200MB，源码与协议先冻结。
本地开工/dev/sdd约270GiB。最终未知非重复1B CPU约100秒、Acc>99%
且留余量的目标持续有效，本轮精度保持当前函数。

候选增加0.305292167秒，95%区间[0.241541205,0.369043129]秒。

停止扩大；具体指令依赖及分支代价尚未分解，其他解析形式另验。
