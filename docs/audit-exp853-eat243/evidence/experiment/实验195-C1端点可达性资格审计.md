# 实验195 C1 端点可达性资格审计

2026-10-10。承接 exp194 的失败诊断：有限 `h_safe` 不能证明请求可达。当前只审计
`Architecture` 的必要端点条件，不运行 exact Router，不修改正式算法、交付包或既有统计门。

## 固定候选

对请求 `q=(s,t)` 定义：

```text
E_s = valid(resolveNet(s, net(sp)))                         if sp is Z*
      any valid(resolveNet(s, net(a.to)))                  otherwise
      over outgoing Arc a from sp whose destination is Z*

E_t = valid(resolveNetPredecessor(t, net(tp)))             if tp is I*
      any valid(resolveNetPredecessor(t, net(a.to)))       otherwise
      over incoming Arc a to tp whose source a.to is I*
```

同针脚和同单元直接 Arc 路径单独保留为 `local_direct`。最终必要过滤器为
`local_direct || (E_s && E_t)`。它是不可达过滤器，不是完整可达性证明。

输入是 exp174 同序的 `From,To` 请求文件；exact 只在 Python 结果核对阶段使用，C++ guard
不读取标签。输出记录两侧尝试次数、有效性和最终 guard。

## 门

- 可达行不被过滤：`exact>=0 && !guard` 必须为零。
- 不可达行全部被过滤：作为当前样本的覆盖观察，不写成全域定理。
- 端点条件通过但 exact 不可达的行逐条保留，作为中间 port-state 可达性反例搜索入口。
- 只有第一项是安全必要条件门；第二项通过也不授权生产接入。
