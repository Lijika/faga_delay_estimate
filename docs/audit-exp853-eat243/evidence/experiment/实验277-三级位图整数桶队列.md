# 实验277 三级位图整数桶队列

2026-10-16。CPU基线为exp275，精度基准为exp258。exp276缓存准备通过
等价检查，性能待定，继续采用exp275。exp275独特U-output 1M平均232.92秒，
完整输出与acc已通过。当前提交d5d2538，正式入口和交付包保持现状。

## 预注册

主假设是扩大整数桶覆盖可减少大key四叉堆的排序。exp275固定128条诊断
请求及边界自检中，大key入队178,728次，占全部391,137次的45.69%。
该比例用于提出候选。本轮固定16位桶地址，key小于65,536采用三级位图
定位最小非空桶；更大key保留原完整(key,id,g)四叉堆。每桶仍按(id,g)
延迟建堆，保持非单调插入、重复项和原全序。

固定65,536个桶、1,024个底层64位字、16个中层字与一个顶层字。
桶元数据放在vector中，查询clear只遍历非空位图。本轮仅修改私有
search_queue.h，搜索算法、q、cap、strict relax、stale、parent和重放保持。
使用通用O2编译，两台CPU使用同一冻结ELF。容量和表示在查看结果前固定。

先用标准完整三元组优先队列逐次核对push/pop/clear，覆盖key下降、
63/64、4095/4096、65535/65536、UINT64_MAX、有符号id和连续查询。
运行ASan/UBSan，再检查35,702条搜索、109,505,958次q与完整路径、
七组CLI、128条Arc费用变体、768组cap及80组weight。语义差异停止计时。
纯等价方案复用既有exact标签和开发请求；原exp258分层加权acc及七组误差
要求相同，变化行数为0。

性能采用两套原序独特20k。每臂预热一次，正式AB/BA/AB三对，core3、
单线程、同机串行并避开其他重负载。主指标为user+sys，候选减基线使用
df2的95% t区间，另报告0.02秒舍入界。两分布点省至少1%且区间上界小于0
时扩大到完整1M。点省但区间跨零保留待定，明确变慢时停止扩大该候选。
阶段指标只记录进度。

远程限定r9r4900的~/lhjwork/eda2026。两机分别报告同一ELF结果。通过扩大
条件后，候选运行完整独特U-output 1M两次，与exp275已验SHA比较。公开
golden 1M单次候选与exp258部署输出逐行配对，acc及七组误差保持，变化行数
为0。repeated 1M含1000个独特请求，预热后AB/BA/AB并核对cache命中。

每次运行检查输出行数、端点原序、三字段、整数delay、精确EOF和完整SHA。
资源要求单线程、峰值RSS不超过2,000,000,000字节、每次不超过3600秒。
更多桶的初始化与内存成本计入完整程序；工作量插桩另建诊断副本。

理论依据为vault的三级位图整数桶的最小项保持笔记，复用已有全序证明。
其他FPGA架构、官方隐藏平台、完整独特100M/1B另验。开工本地416GiB，
远程193GiB。保留复现输入与冻结产物；清理遵守逐文件三条件。
