# 实验229 C1 固定上调32私有集成与整程序 CPU

2026-10-12。正式入口 exp131 和交付包不变，私有完整程序以 exp220
为对照。exp228 在未参与本轮规则选型的同架构新请求上验证了固定
`(8,32)` 规则，增益达到独立精度门。本轮只验证该规则的等价部署、完整
1M 输出契约和整程序资源。

## 预注册

复制 exp220 的源码、对象、静态编译命令和完整输入，仅在
`UpperTree::evaluate` 最终预测生成后加入一条规则：

```text
if prediction > 0 and expandedUpper - prediction >= 32:
    prediction = min(prediction + 8, expandedUpper)
```

合法上界来自固定的二十源 C4800 查询，模型、特征、Line 剪枝、缓存和编译
参数全部保持不变。候选源码、对象、ELF 和计时证据保存在 `build/exp229/`，
正式入口、`build/submission/` 与 `subm/` 不修改。

先对 exp220 的 6177 条 exp226 请求和 exp121 的 14 条边界请求执行逐行检查，
确认候选输出满足端点顺序、整数 delay、三字段、精确 EOF、零值和不可达值
语义；`-bias-ps 0` 两臂逐字节一致；候选为静态 ELF。任一检查失败即停止
整程序计时。

本地检查通过后，远程在 `r9r4900:/home/lhj/lhjwork/eda2026` 的 Herdr
`w1:p2`、core3 上单线程串行运行 public、unique、repeated 三种完整 1M
输入。每种输入先做 AB 预热，再做 BA/AB/BA 三对交错计时；记录 CPU、wall、
峰值 RSS、线程数、输出行数、端点顺序、字段格式、精确 EOF、完整 SHA 和
cache miss。两臂各次同分布输出 SHA 保持一致，对照 SHA 与 exp220 冻结记录
一致。

精度采用 exp228 独立请求的增益和七带配对 95% 区间，综合分使用：

```text
Δ综合分 = 0.8 × Δaccuracy - ΔCPU / 120
```

unique 和 public 的综合分点值至少 `+0.01` 且保守下界大于 0，repeated 的
CPU 区间下界不高于 0 时通过本轮 CPU 筛选。资源门为单线程、峰值 RSS 不超过
`2,000,000,000 B`、每次运行 CPU/wall 不超过 `3600 s`。本轮结论限定为
exp220 相对比较和完整 1M 输入；平台 1B、跨架构和正式接入仍需独立验收。

```bash
PYTHONDONTWRITEBYTECODE=1 python3 validation/exp229_integrated_step32.py freeze
PYTHONDONTWRITEBYTECODE=1 python3 validation/exp229_integrated_step32.py check
PYTHONDONTWRITEBYTECODE=1 python3 validation/exp229_integrated_step32.py remote
PYTHONDONTWRITEBYTECODE=1 python3 validation/exp229_integrated_step32.py report
```

## 限制

本轮不修改正式入口与交付包，不证明平台 1B、跨架构表现或 exp220 相对正式
版本的整体综合收益。

## 实测结果

固定 `(8,32)` 的私有集成通过完整 1M 输出与资源检查，以及预注册的条件
CPU 筛选。候选 ELF 为 `93,768,336 B`，SHA-256 为
`09bf5991d01f07a69caedba022d57287925a91816ebc6366b1cd8c1a0e5d5e5d`。

预注册正文的“6177 条 exp226”存在笔误。冻结脚本、输入身份和实际检查均
使用 exp228 的 6179 条请求，两臂分别与该轮离线预测逐字节一致。14 条边界
请求、零值和不可达语义、`-bias-ps 0` 一致性及静态 ELF 检查全部通过。

远程为 Xeon Gold 6226R、core3，每组 AB 预热后按 BA/AB/BA 串行计时。
24 次运行全部保持单线程，最大 RSS 为 `1,658,122,240 B`，最长 CPU 为
`82.29 s`。public/unique 各有 1,000,000 次 cache miss，repeated 为 1,000 次。
取回的六份输出又按原请求独立检查行数、端点顺序、三字段、整数 delay、
精确 EOF 和完整 SHA，与各次远程记录一致。

| 完整输入 | 对照 CPU 均值 | 候选 CPU 均值 | 配对 CPU 差及 95% 区间 | 条件综合点值 | 保守下界 |
| --- | ---: | ---: | --- | ---: | ---: |
| public 1M | 76.4300 s | 76.1333 s | -0.2967 [-0.6275, +0.0341] s | +0.028161 | +0.003705 |
| unique 1M | 82.2400 s | 82.0933 s | -0.1467 [-0.2471, -0.0463] s | +0.026911 | +0.004375 |
| repeated 1M | 2.1200 s | 2.1233 s | +0.0033 [-0.0346, +0.0413] s | +0.025661 | +0.003646 |

综合分析使用 exp228 的独立精度增益 `+0.032111 pp`，95% 区间为
`[+0.004987,+0.060598] pp`。该计算假定目标 1B 完整运行的新增查询工作量
约为本轮 1M miss，缓存命中路径的增量可忽略，时间分仍为正。
精度下端点和 CPU 上端点各使用 2.5% 的单侧失覆盖预算；在边际区间有效的
前提下，Bonferroni 合成下界控制总计 5% 的失覆盖概率。bootstrap 和仅三对
计时的 t 区间仍有近似误差，本轮 CPU 证据只支持该同机比较。

公开 golden 全量 accuracy 从 `97.3811371988%` 提升到 `97.4203000111%`，
增益 `+0.0391628122 pp`。对照评分复用 `exp227-baseline-score.json`，其
输出 SHA 与本轮 public 对照一致。完整报告为
`validation/results/exp229-report.json`，输出复核为
`validation/results/exp229-evidence-check.json`；原始输出、计时、stderr 和
score 保留在 `build/exp229/`。

收尾 `/dev/sdd` 可用 `463,778,152,448 B`，冻结时为 `464,100,831,232 B`，
净减少 `322,678,784 B`。本轮删除 0 B，新增文件均保留用于复现。
正式 exp131、交付包与 exp220 对照保持原样；平台 1B、跨架构和相对正式
版本的整套收益继续待验。
