# 实验393 长线间四跳短连接核的容量与真实重放

2026-10-17，在读取新统计前登记。接续exp391、392，检查共享局部短连接
能否支持参数化长线段。正式入口为exp354，CPU固定基准为exp323。
本轮只有私有资源原型，影响tests/exp393_short_bridge.cpp、
validation/exp393_short_bridge.py、本日志及Obsidian理论笔记。

主假设是完整lane的有限短连接可以由架构生成并共享，但显式收缩边的出度
可能成为新的瓶颈。对象从一次L Net落点的I端口开始，经0至4个非L Net，
以Arc接入下一个L源Z。L按官方JSON的水平10、垂直12定义，共32个端口。
保留起始L、目标L、名义位移、最小Arc费用及完整短连接见证。
名义核的Gap为零；它只用于容量、共享和候选见证检查。
真实Block/Line通过原Architecture::resolveNet逐步重放。

动态规划状态为短Net数、当前Net的I、累计名义位移，逐层精确取最小Arc费。
核在每个起始L、目标L、名义位移上保存一条最便宜见证，等费按短Net数、
端口顺序固定选择。这里只证明名义有限路径族的最小值。
实际几何会改变有效性、落点和Gap费用，名义最小见证须逐条实测。

数据分成两个固定用途。官方五个JSON用于完整名义核容量。
exp207同SHA的256条定向开发exact路径用于提取相邻L之间不超过4跳的短连接，
包含0跳接续；重复的L自接续和非空短连接分别报告。
重放原连接应保持实际端点和费用，再比较相同名义键的最小见证。
逐条记录无效、实际终点变化、费用相同或增加；同端点且费用更低需要检查
exact路径证据。此样本属于已查看开发数据，比例不作为总体acc。

预先固定主指标为核条目总数、每个起始L的平均及最大出度、16字节记录容量、
按60,200个真实格点展开的显式容量、各层DP工作量和见证重放结果。
16字节是紧凑数组的预算模型，实际编译布局另报。
显式收缩图只有在平均出度不超过128且16字节记录全域展开不超过
1,200,000,000字节时保留扩大资格；失败只结束该显式格式。
共享核、分解求值、按目标检索继续独立研究。

固定资源为单次原型CPU不超过120秒、地址空间不超过2,000,000,000字节。
普通及ASan/UBSan的合成小图将DP与枚举全部短词比较。
独立Python检查全部见证的Arc、位移和费用，并对固定起始L序号
0、8、16、24复算完整DP费用，包括缺失键；修改费用的负对照应失败。
真实重放检查全部已提取短连接。新exact、总体评分和估计程序CPU均为0。
这些检查通过后才讨论具体未知请求的程序选择，尚不进入昂贵完整1M。

命令为`python3 validation/exp393_short_bridge.py prepare|run|check`。
证据放validation/results/exp393，私有产物放build/exp393。
开工本机/dev/sdd约386GiB可用，收尾记录释放量。

## 结果与下一步

普通及ASan/UBSan小图逐词枚举通过。全部124,640条见证的Arc、位移、
费用及费用修改负对照通过。独立Python对4个起始L复算15,580个有限键，
完整费用及缺失键均保持，各层状态计数也相同。
名义核构建CPU为0.246919秒、进程峰值RSS为48,160,768字节；
完整名义进程CPU为0.361361秒，编译和检查成本另列于原始记录。

32个起始L的出度均为3,895。按16字节记录，共享核为1,994,240字节，
按60,200个真实格点展开则为120,053,248,000字节。
两项显式格式条件均未通过，`retain_explicit_graph=false`，
结束该显式收缩图扩大；共享核继续保留。

真实重放5,815个子连接保持原路径端点和费用，其中5,325个为0跳接续，
490个为非空短连接。名义最小见证在全部连接上仍保持端点和exact子路径费用；
490个非空连接中481个与原词相同，9个换成另一条等费词。
所选原短连接均没有名义与实际位移差，跨Block跳格的短桥覆盖仍待另验。
这些结果支持共享部件的局部语义，尚无未知请求选择器或总体精度证据。

下一步检查长线骨干的距离表。任意L-only路径的名义位移均为
`(10u,12v)`，可以把同端口重复段及多次L换向统一为一个受限距离查询。
先测有限名义域的容量、路径元数据、真实子路径重放与免逐跳求值的资格，
再研究短连接的目标导向组合。该方法的新增信息是任意L换向的整体费用，
不同于exp392只合并同一Z重复段。

原始记录为`validation/results/exp393/`，核CSV保存在`build/exp393/kernel.csv`。
复现依次运行prepare、run、check，正式入口保持exp354。
本机收尾约386GiB可用，删除0字节。新增exact、评分、估计程序CPU均为0。
