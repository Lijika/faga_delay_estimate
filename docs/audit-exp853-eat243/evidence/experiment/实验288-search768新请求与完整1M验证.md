# 实验288 search768 新请求与完整 1M 验证

## 预注册

2026-10-16，exp287 已提交 `64ecaca`。本轮固定 search768，基线采用 exp281
combined。两份 ELF、源码、模型、真实图、q 和最终 bias 保持 exp287 的冻结身份，
新编译成本为零。影响范围为新实验 runner、私有数据和实验记录；生产入口、
构建脚本、交付包及其他用户改动保持。

主假设为 search768 在同架构新请求上保持总体 acc 严格大于 99%，并在完整独特
1M 中减少 CPU。CPU 最小实际收益固定为 0.5%，仅描述效应；候选按同分布
CPU–acc Pareto 前沿及不确定性保留。旧 no-tree、tree-mode0、端点模式和
search2048 等候选继续保留原始证据及适用范围。阶段目标仍为独特 1M <100 s、
100M <100 s、1B 100–300 s，样本收益和 1M 收益分别报告。

## 新请求及 exact

固定 affine unique 窗口 [74,000,000,76,000,000)，沿用现有生成器的私有副本。
排除集合复用 exp284 冻结的历史开发和训练文件，加入 exp284 新样本、公开完整
1M、既有独特完整 1M 和 repeated 输入中的完整 pin。逐文件核对身份，
按排除后人口计算七个距离带权重，报告排除人数与保留比例。

固定 seed=20261016288，各非零距离带 reservoir 抽取至多 2048 条，零距离全部
保留，按原序输出。样本与排除集合的完整 pin 交集须为零，抽样不读取预测或新标签。
协议、候选、样本及其身份提交后，才生成 exact 标签。

标签使用已核验的 `build/exp203/exact_labels` 与冻结 `orbit.i16`。1–12、
13–24、25–50、51–100 四带各选前两条额外用 plain Router 对照，共八条。
exact CPU、RSS 和 wall 单列；零延迟与不可达逐行核对。准入以总体加权 acc
严格 >99% 为条件，配对下降、区间和各组误差完整保留；若该条件未过，记录结果
并结束此固定候选的本轮扩大验证。

## 联合测量

远端 `r9r4900` 的 Xeon core 3 同机串行，AMD 本机承担构建、自检和评分，
本机 CPU 只作参考。新样本两臂各预热一次，再按 AB/BA/AB 三对测量，
A 为 baseline，B 为 search768。完整进程 user+sys 含初始化与 I/O；
acc 使用同一次计时进程的输出，相同输入、标签和输出 SHA 时复用评分。
总体 acc 按排除后人口加权，分层样本 CPU 为实际样本行序的未加权完整进程时间。

固定 10,000 次七带配对 bootstrap、NumPy Generator、seed=20261016288，
CPU 使用三对差的 df2 Student-t 95% 区间，两端加 0.02 s 舍入。报告七带
accuracy、平均相对误差、变化/改善/恶化行数及 CPU–acc 点前沿。区间逐项解释，
不作多重性保证，三对计时不足以检验差值正态性，pin 相关性也限制请求级重采样解释。

## 完整 1M

新请求精度条件通过后，在 `build/exp262/output-1m.csv` 上用既有 20k 前缀
各臂预热一次，再 AB/BA 两对完整独特 1M。使用完整输出契约、SHA 与同臂一致性，
配对 CPU 取 df1 t 区间并加舍入。完整独特 1M 没有全量 exact，精度结论范围
为新样本及公开 golden，不把两者分数直接赋给该 1M 输入。

search768 在公开完整 1M 上连续运行两次，同次输出作公开 golden 配对评分。
baseline 复用同一 ELF 在 exp281 的已核验公开输出，CPU 比较按跨批描述。
repeated 1M 使用既有 1000 个独特请求，先各预热一次，再 AB/BA/AB 三对；
另运行两次短诊断记录 cache hit/miss 和初始化，诊断成本与主性能结果分列。

每次估计检查端点原序、恰好三字段、整数 delay、精确 EOF、完整 SHA、
多次运行一致、单线程、RSS <=2,000,000,000 B、CPU/wall <=3600 s。
零、不可达及无效文本边界复用 exp287 相同 ELF 的七行原始证据。
出现身份或输出契约冲突时保留现场并停止该阶段。正式接入与打包另行按
完整 1M 和不可变版本规则核验，本轮不执行完整 1B。

## 复用及成本

新 runner 复用 exp284 的抽样、exact 调用、计时、逐行契约和基础核对工具，
每个正式输出由 adapter 标明实验 288 及 runner 身份；临时 fresh 进度结构
沿用模板，最终 `fresh.json` 是本轮完整记录。新逻辑带 assert 自检。
原始证据写入 `validation/results/exp288/`，生成输入与私有产物写入 `build/exp288/`。
独占创建冻结与正式结果，重复执行已完成阶段会退出，保留原始文件。

开工 `df -h /dev/sdd` 可用约 411 GiB。预计所有新增文件均小于 10 GB，
收尾再记空间与清理量；删除前逐条核对同族副本、可重建性和按名引用。
