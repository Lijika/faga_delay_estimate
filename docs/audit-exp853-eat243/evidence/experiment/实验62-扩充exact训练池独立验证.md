# 实验62：扩充 exact 训练池

日期：2026-09-26。开工时 `/dev/sdd` 可用 493G。

## 预注册

- 基线是实验61静态包 `subm/versions/exp61-base47-d8-walk-aa33480/bin-estimate`（SHA-256 `f87675a4b99d8ba39f5f5634c21ec252c5235e67ed95f14ff6f96592a43d07f9`）。
- 单项候选只扩充训练池：实验18B的 10,024 条，加实验56、57、58、61各自的 exact 样本。47维特征、六个屏蔽槽、`reg:absoluteerror`、depth 8、64树、seed `20260919`、单线程、训练权重和 `-3 ps` 都沿用实验58/61。每个完整端点只入池一次；遇到冲突标签即停止。
- 使用 affine unique 生成器的 `[20M,22M)`，七带各至多1024个 exact 标签。样本与公开1M、训练池及历史独立窗口的完整端点隔离；排除命中即停止且不补样。公开 golden 不参与训练或选型。
- 主指标为按新窗口原始带份额加权的 accuracy 差。七带配对 bootstrap 10,000 次，seed `20260925`；点增益至少 `+0.03 pp`、95%下界大于0、可达性误判不增加才进入私有部署测量。最小综合点收益 `+0.01`，精度下界和CPU上界构成的保守综合下界须大于0。
- 通过精度门槛后，在同一冻结 1M unique 输入上做预热及3对交错 CPU/RSS 测量，核对完整输出、单线程、2GB和3600秒门槛；随后按打包规则验证公开1M与holdout。失败候选保留原始记录，正式入口继续使用实验61。

## 结果

`build/venv-ml/bin/python validation/exp62_more_labels.py --stage requests|sample|score`。
原始证据：`validation/results/exp62-stage-requests.json`、`exp62-stage-sample.json`、`exp62-score.json`；候选模型在 `build/exp62/model-base-d8-more-labels.json`（SHA-256 `451a1c728881f0d80defb351ed7e3a637c643cda3a2dea35080ea2167061ae9f`）。

- 新窗口2,000,000行，6,180条exact；七带完整，历史端点排除命中0，距离和带划分检查通过。旧模型的Python预测与正式包6,180行逐行一致。
- 扩池训练34,731行。记录的 `fast` 与冻结 off 入口有74处不同，训练前按端点顺序重新计算并更新。候选加权 accuracy `94.197746`，基线 `95.651818`，差 `-1.454071 pp`，配对95%区间 `[-1.604702,-1.307209] pp`；MAPE `1.493013%` 对 `1.112522%`。两侧可达性误判均为0。
- 独立权重核查发现原训练池10,024行没有负exact，新增四批共379条负exact；旧 `train_weights()` 的 `1/max(exact,1)` 给负行约96.9%的总权重。新模型初值 `0.050525`，总节点1,224；原模型初值 `26.083807`，总节点14,662。这解释了模型容量收缩和大幅退化，是候选训练输入与权重不匹配的直接证据。
- 精度门槛失败，本候选停止；不做1M性能测试，也不更新正式入口。针对负exact权重另立候选，并使用未参与本轮判决的新窗口。
