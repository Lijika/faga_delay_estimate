# 实验508 全端口逐行尾参数的模差分编码

2026-10-19，在查看exp507覆盖核验结果及本轮压缩结果前登记。
exp507完整row臂已离线生成208份源资产，当前XZ合计187,193,864B，
超过80MB组件门。固定主假设为沿行轴及余数轴消除参数间重复后，
可以降低静态字节数，同时完整保持每个常数和阈值。
本轮与exp507核验并行开展离线编码，覆盖门仍以r9的exp507完整结果为准。

## 数据与固定候选

输入为exp507完整row臂，208源、288目标、四方向、120余类、12行，
共345,047,040条int16常数加uint8阈值记录。使用同一端口映射，
逐源校验原始/压缩SHA、头、长度与端口ID。全部记录都参与编码和核验。

固定两个布局。`row_delta`沿行i做模差分；`row_ry_delta`先沿行i，
再沿ry做模差分。int16常数按uint16位模式处理，阈值按uint8处理，
每轴第0项保持，后续项保存与前项的差。完整逆变换分别沿相反轴顺序
做独立逐项前缀恢复，恢复后检查原始数组及exp507完整源文件SHA。
理论复用Obsidian《距离场端口重排与模差分的无损性》，两轴是同一
可逆变换的组合。该恒等式对固定整数位模式成立，压缩收益另行实测。

顺序沿用exp507的目标、方向、rx、ry、行；编码后拆常数低/高字节面，
再写阈值。每源XZ preset6，头保留完整exp507头及新增布局标识。
端口映射计入静态容量。运行时恢复主体仍为1,035,141,120B。
基线为未差分的exp507 row臂；不增加量化、几何预测或阈值选择。

## 调度与验收

l7使用8个进程离线编码。r9在exp507完整核验退出0之后，串行核验
两臂全部345,047,040条记录，检查XZ精确结尾、头、端口ID、SHA、
常数/阈值逐项相等、重新序列化的exp507原始SHA。任一项失败保留现场。
覆盖计数复用同身份exp507报告，算法测试与质量评价只在r9进行。

主指标为完整静态字节数。固定机制门为相比原row资产至少减少10%，
容量门为含mapping不超过80,000,000B；主体不超过1,100,000,000B。
组件继续门同时要求exp507 row臂覆盖至少50%、相对exp504增加至少10pp。
通过者按较小静态资产选择；两臂均未过组件门时结束本固定布局。
容量与覆盖为完整枚举结果，不附抽样置信区间。

这次编码保持已有名义组件的行为。真实图acc、未覆盖位置的完整表示、
生产初始化/单线程RSS、完整程序CPU及100M/1B目标继续分别验收。
本轮无新增exact标签，exp506真实开发标签不参与本轮布局选择。
离线CPU、wall、最大单进程RSS分别记录。

脚本为`validation/exp508_tail_codec.py`，证据在`validation/results/exp508`，
私有资产在`build/exp508`。开工本机约362GiB可用；r9资产传输前约1.7GiB，
本轮继续按实际空间检查安排传输。旧原件及按名引用文件保持。
