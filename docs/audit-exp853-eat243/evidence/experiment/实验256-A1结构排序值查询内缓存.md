# 实验256 A1 结构排序值查询内缓存

2026-10-12。exp254的512预算达到开发accuracy目标，本轮保持
每个查询的全部排序值，仅减少同状态再次relax时的重复求值。

## 预注册

q由真实状态与固定目标决定。首次distance从无穷变有限时计算
q并写入稠密数组，随后更小g读取该q。下一query重置全部touched
distance；当前query首次有限时覆盖q。理论见Obsidian
`固定目标结构排序值的查询内缓存.md`。增加每状态一个int，
同ELF的raw/memo均分配数组，原排序、512预算和完整前驱重放保持。
六类内置边界在两臂分别检查。

输入为exp254完整12,150条正标签开发请求。原raw512除cpu_s外
全部字段须保持；memo除arm、cpu_s、evaluations外全部字段及
完整路径须保持。memo的evaluations须等于states，原臂须不少于
states。以旧完整JSON路径证据验证相同证书，准确率和逐行输出
严格保持。任何语义差异结束这一实现。

远程core3串行执行，exp255结束后传输并启动。一对预热，
五对计时顺序raw-memo/memo-raw/raw-memo/memo-raw/raw-memo，
每次独立运行完整开发池，计时含初始化和证书输出。采用配对df4
t95=2.7764451051977987。主工程门为重复求值减少至少5%、
总CPU点节省至少3%、配对CPU差95%上界<0。wall/CPU每次
<=1200 s、峰值RSS<=2GB、单线程。全局加权查询CPU另列成本诊断。

当前输入用于组件工程筛选；完整程序、1M和跨硬件继续各自验证。
未过工程门结束此固定缓存实现，保留输出等价证据。开工
`/dev/sdd`可用428GiB，关闭时记录空间和清理量。
