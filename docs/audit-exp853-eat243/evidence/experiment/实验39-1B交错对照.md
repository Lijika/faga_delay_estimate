# 实验39 1B 交错对照

日期 2026-09-22。实验38 的历史对照被机器状态混淆，本轮用最小驱动让正式 `./estimate` 与 `build/exp36/estimate-mod` 在同一段机器状态下交错跑 repeated 1B，各三轮。正式入口和交付包不改，现有实验38 的大型输出不覆盖。

## 驱动

新增 `scripts/run_1b_interleaved.py`，只做编排，测量与校验全部复用现有工具。`scripts/run_scale.py` 负责一轮计时、线程采样和 3600 秒硬超时，`scripts/verify_scale_output.py` 负责单次流式核对 1000 个 1M 块、精确 EOF 和完整 SHA。驱动自己不做任何计时或解析。

默认序列是 baseline、candidate、baseline、candidate、baseline、candidate，严格交错，漂移由交替顺序平摊；`--sequence` 可以换成其它预声明顺序。每轮在 `validation/results/exp39-1b-interleaved/` 留下 `roundNN-<side>.json`、`.time.txt`、`.stderr.txt`、`.run.log` 和 `roundNN-<side>-verify.json`，跑完汇总到同目录的 `summary.json`。任一轮不满足退出码 0、测量有效、1000/1000 块、线程不超过 1、RSS 低于 2 GB、完整 SHA 时，驱动停止后续轮次并保留已有证据。`--resume` 跳过已经通过且文件齐全的轮次，`--dry-run` 只打印命令。

启动前驱动检查身份，基线二进制以 `db2cca1e` 开头，候选以 `b9dda9ea` 开头，1B 输入的 meta SHA 以 `8174755d` 开头，参考 1M 存在，磁盘空间高于输出估计加 1 GB。候选轮显式带 `-residue-mult 2 -endpoint-mode source-short -endpoint-short-distance 150 -residual xgb`，基线轮不带任何额外参数，走默认训练配置。

## 结论

输出契约全部通过，候选的时间没有收益，在这组交错测量里反而慢 1.265%。候选的布局与余数简化只作用在数值路径，而 repeated 1B 里 999,000,000 次查询走缓存；先前把差额归到每行 `applyBounds` 钩子的解释与 `src/residue_estimator.cpp::estimateText` 的调用链不符：缓存命中在进入 `estimate` 前直接返回，`applyBounds` 只在 cache miss 后执行。差额来源待定位，本轮只保留 +1.265% 的描述统计，不推断具体原因。正式 `./estimate` 与 `build/submission/estimate` 保持实验29，源码和默认入口不改。全独特 1B、赛方机器和官方分数仍未验证。证据是 `validation/results/exp39-1b-interleaved/summary.json` 与同目录的六轮记录。
