# 实验206 C1 中长距离候选覆盖淘汰诊断

2026-10-11，承接exp203已验证选择器与exp205静态部署。
本轮只作机制诊断，数据来自已查看的exp174开发6176行；新标签和总体收益另验。
私有目录`build/exp206`，开工`/dev/sdd`可用445 GiB。

## 预注册

主假设为C1200名义树的有限区域限制了101–300及301+的候选覆盖。
逐项固定统计源匹配、终端候选、盒外、盒内unknown、链断裂、32跳、
映射费用>1200、真实Net无效、实际终点偏离与终端无效。
每个有source seed的tree×endpoint按最先失败原因归入唯一类别；
剩余类别为合法路径，各类数量之和必须等于尝试数。cycle0单列，
cycle1–7合并结果须与exp202完整U7及valid_count逐行相同，cycle0须复现all。

40棵已认证原树、cycle0–7、32跳和1200映射费用保持。
另检验已有理论的推论，原树C1200、最小Arc48且cycle保持Net位移时，
parent恢复长度至多25，因而32跳限制在该候选族内应为零淘汰。
若该预测失败，保留原始记录并检查映射与树证书后再扩大实验。

分七带报告每阶段计数、各阶段仍有候选的请求数及代表总体权重。
以盒外加unknown占全部中长距离尝试的80%以上作为继续较大预算局部原型的
机制门；若主要损失来自真实重放或endpoint偏移，则优先研究实际几何路径。
诊断比例描述当前开发请求与固定候选族。

预先选择256条供下一轮exact路径导出的请求。每个长距离带取64对，
按目标y五区、source class与target class分组，高损失行与同组低损失行配对。
损失采用正式P的已知单行评分损失；组内按损失排序，每组最多取一半行，
按组剩余容量轮流取高低端，固定行号打破tie。所有请求、标签和配对身份
先写入冻结清单。该批样本用于解释机理。

远程r9r4900在exp205计时结束后串行运行，全部命令位于约定工作目录，
core3、timeout600 s、单线程、RSS≤2,000,000,000 B。计时仅为诊断成本。
验收为逐行U/计数一致、分类守恒、合法U≥exact以及样本配对规则通过。
达到资源限制时停止扩大并保留结果。

```bash
PYTHONDONTWRITEBYTECODE=1 build/venv-ml/bin/python validation/exp206_coverage_funnel.py freeze
# 冻结并提交后，经herdr运行probe，再取回原始结果
PYTHONDONTWRITEBYTECODE=1 build/venv-ml/bin/python validation/exp206_coverage_funnel.py report
```

101-300与301+合计尝试278,891次，其中盒外或初始unknown为278,882次，
占`0.9999677293`，超过预注册的0.8机制门。两带尝试阶段代表总体权重
分别为51.892349%和26.554796%。101-300仅有3条请求留下合法候选，
301+没有留下候选；中长距离缺口由初始空间覆盖主导。

恢复链最大长度为14，`hop_cap`淘汰为0。原树C1200、最小Arc 48和当前
位移保持映射给出的25步上界在本轮逐行结果中得到支持，32跳上限没有
成为淘汰原因。51-100带仍有7,838次名义预算淘汰，表明较大预算原型
需要同时保留容量和真实费用检查。

远程r9r4900、core3、单线程运行通过。exp206 CPU/wall为`1.23/1.23 s`，
RSS为`319,422,464 B`；输出`build/exp206/funnel.csv`大小3,828,661 B，
SHA-256为`3d8246eb1b1299fd55b919d5a36568eb481ff94bfe66a807860898a7961f6d4e`。
冻结清单为`validation/results/exp206-frozen.json`，漏斗证据为
`validation/results/exp206-coverage.json`。本轮仅说明固定开发集和候选族
的覆盖机制，没有产生新标签、总体accuracy或生产CPU结论。

## 结论与限制

盒外和初始unknown已经超过继续较大预算局部原型的机制门，下一轮可冻结
单源`ZSEA[0]`、预算2400的容量和查询原型。原型需要报告完整压缩大小、
6176条请求的新增候选覆盖、候选质量和查询CPU/RSS。若新增覆盖只表现为
盒外或unknown而没有可接受的候选质量或容量，应停止扩大。

本轮结束时`/dev/sdd`可用空间约`444 GiB`，开工记录为`445 GiB`，
释放量为0。没有删除实验输入、输出或其他大文件。
