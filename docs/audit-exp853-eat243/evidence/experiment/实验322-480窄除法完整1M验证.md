# 实验322 480窄除法完整1M验证

## 条件预注册

2026-10-16。exp320的480窄除法已通过等价审计，CPU尚未测量；
exp319的480完整公开精度仍待核验。只有exp319公开acc严格>99，
且exp320按冻结短规模协议保留完整测量资格，才准备本轮。
候选为exp320原ELF，规则、预算和通用O2构建保持。

exp321事前成本依据给出约-2.018604s/1M的条件估计，来自原
窄除法完整收益与480保留工作量。现有480两次独特100.05/
100.33s用于进度参考。工作量迁移与编译布局假设可能影响估计，
主结论以本轮同机配对完整程序为准。

复用exp308的完整16次协议，Xeon core3串行，20k两臂预热，
独特1M AB/BA两对，候选公开1M两次，repeated预热与
AB/BA/AB三对。unique用df1、repeated用df2 Student-t 95%
配对区间，加0.02s舍入；区间跨零保留待定，0.5%仅作效应。
公开acc>99且两次独特CPU<100s时记录stage1_accepted。

每次检查完整SHA、行数、端点原序、三字段、整数delay、精确EOF、
多次一致、单线程、RSS<=2GB及CPU/wall<=3600s。输出必须与
exp319同分布原480保持，复用同输入同标签同输出的精度证据，
相对480变化0行；相对exp258的下降与分组风险保留。
acc与CPU取同次完整运行输出，评分与exact新增成本为0。

远端计时期间暂停同步和编译；AMD仅记录执行成本。独特1M
全量exact、100M/1B、跨架构和平台表现继续待验。
开工磁盘401GiB，收尾复查；其他历史候选资格保持。

baseline为100.37/100.23s，narrow为98.25/97.93s，均值
100.30/98.09s。配对差为-2.21s，95%区间含舍入为
[-3.373558,-1.046442]s，节省2.203390%。两次候选均低于
100s，公开acc严格大于99，`stage1_accepted=true`。
exp321事前条件预测为-2.018604s；实际方向和量级支持该预测，
精确的工作量归因仍受编译布局与请求分布影响。

两次公开CPU为114.16/114.53s，输出与原480完全相同，复用

56,281改善、299,659恶化、1,018评分持平。七距离带acc为
99.411432/97.468738/99.072150/99.184633/99.106654/
99.071036/98.835436%，唯一零标签保持。新请求12,312条的

0.010697pp，隐藏集风险继续单列。
