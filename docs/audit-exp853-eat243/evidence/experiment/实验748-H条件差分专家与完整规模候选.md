# 实验748 H条件差分专家与完整规模候选

2026-10-27预登记。exp744的生产差分在H组贡献总体0.050131548pp，
exp747的全phase族均值短点积未通过质量门。本轮直接检验可部署的
H替换专家，沿用exp728完整普通路径及V8，只在原event679判为H时
使用一个共享8棵depth6模型。

## 固定学生与开发门

两臂C8/P8采用exp744的共同89列/生产差分93列；沿用相同loss、权重、
学习率0.1、source-pin三折及其余固定参数。仅H行参加训练，源族和
完整pair身份保持。每臂3个折外模型；通过开发门后再拟合一个全开发
H模型。全部非H预测逐字节保持冻结T2D6/V8。

相对冻结整体Acc提高至少0.02pp，三个折各自正收益，源族9999次
重采样的同时95%下界为正，距离、方向和近轴组下降至多0.03pp，
才构建完整候选。P8相对C8的整体增益须至少0.01pp才承担差分查询；
C8单独通过时直接保留C8。两臂同时满足条件则共同进入100M。
固定seed20261027748，两个基线比较采用Bonferroni区间。
叶编号、JSON原序求和、最终整数与CatBoost原生逐行一致。

本轮复用已验证的历史真实请求、完整truth和生产响应。全部计算在r9，
离线CPU300秒、wall300秒、RSS8GB，私有build/exp748。H判定可由任意
未知请求的端点与首Net得到；完整程序继续覆盖既有source/target角色域。
角色域外端点的官方规则仍是exp740开放项。

## 完整规模计划

开发门通过后立即编译静态自包含候选并检查实际ELF小于100MB，再使用
新生成的全端口非重复100M请求。源pin及请求与训练记录隔离，随机打乱
后每个pair取前4条，共239616条完整exact标签，抽样精度明确标范围。
标签成本单列，完整输出取样来自同一次计时运行。

两臂计时采用一次预热及三轮AB/BA；三个臂采用一次预热及全部六种排列。
基线为冻结exp728，同机串行，计时前完成全部离线重负载。
完整输出契约、SHA、至少五次一致、单线程、RSS≤2GB和每次≤3600秒
均通过；精度差至少0.02pp、分组下降至多0.03pp，综合收益95%下界
大于0且点估计至少0.005分时接入阶段版，并立即完成非重复全端口1B。
100M的1B时间换算仅用于筛选，最终报告完整1B实测CPU、同次精度和资源。
最终交付总体Acc严格大于99%及其他赛题硬约束继续有效。

### 启动资源修订

首次以4GB地址空间上限启动时，CatBoost在线程创建处抛出
`pthread_create has failed: Resource temporarily unavailable`。保留失败
脚本与日志，恢复到exp744已完成相同8线程训练的8GB离线地址空间预算，
同时关闭core生成。候选、输入、参数和收益门保持，重启前未读取新评分。

## 实测结果

两臂完成三折共六个模型，JSON/native叶与整数输出通过，非H逐行相同。

0.100480369和0.099954311pp，同时源族区间全为负。H组各下降
5.562465068和5.533343147pp，训练H精度也只有88.18%至88.31%。
P8相对C8仅增加0.000526058pp。两臂均未过开发门，完整程序运行0次。

成功重跑CPU7.532123396秒、wall4.863977365秒、RSS2,423,799,808B，
属于离线成本。远端结束可用35,442,806,784B，本地仍约273GiB，
没有符合清理条件的大文件，释放量0B。原始结果位于
validation/results/exp748/report.json，启动失败另存
validation/results/exp748-thread-startup-failure。
