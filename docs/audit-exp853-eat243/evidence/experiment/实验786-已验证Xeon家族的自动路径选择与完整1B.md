# 实验786 已验证Xeon家族的自动路径选择与完整1B

2026-10-28预登记，读取exp785六轮100M结果后冻结。
正式版仍为exp780，SHA-256为
`41329c3812f12f017cbb29c7426a0713b124927625b82babc1226fd72e7f4146`。
exp785的P在r9单路Xeon Gold 6226R/22MiB L3稳定节省
0.6880558s/100M，区间[0.5376024,0.8385092]；
普通AVX2的区间跨零。P输出与正式版完整SHA一致。
目标6242R为同family6/model85、单路约35.75MiB，
但微架构同族及容量更大都不构成性能保证。

## 唯一修改与预期

仅将目标机P分支的CPUID单路L3阈值从32MiB改为20MiB，
使已经实测的6226R运行自动分派时选择P；
6242R仍满足相同ISA、family/model和容量检查。
其他CPU仍根据AVX2能力进入普通A，否则为SSE2标量F；
它们的速度证据按各自平台独立描述，不把r9秒数迁移。
所有分派在程序启动时执行一次，只有一个工作线程，
不固定或亲和任何官方CPU核心；测试端的taskset只用于
控制计时。exp785的A在r9未达到有效收益，本轮有助于
区分已测Xeon与未测通用CPU的收益边界。

高杠杆研究仍是背景信息与随机工作集的联合压缩，
本轮是已具信息的exp780函数上的等价执行增益。
没有新训练、代码本或模型，若最终输出SHA相同，可按
同一输入身份复用exact评分；资源、完整程序CPU仍分别计。

## 门与停止

独立构建auto静态ELF<100000000B，检测结果在r9为
family6/model85/AVX2/23068672B。模拟无AVX2、AMD
及35.75MiB Intel选择无越级ISA；无L3信息时不启用P。
完整1M验收、首轮exp785四路径等价和静态安全检查。
再复用exp781现成非重复100M、同一输出SHA，auto对F
至少节省0.25秒/100M，CPU点估计不高于exp785强制P
六轮均值加0.15秒；单次自动路径等价变更凭exp785的
六对P区间作统计支撑，记录新的运行点估计和全部资源。
不满足则停止该自动阈值，不进入完整1B。

通过100M后，同机同CPU8配对F/auto完整非重复1B，
复用原exp780已核验输入（35197849579B，SHA-256
`3e01ed8f591ca1c06e3e4c36e66853437b784efbff22d1cc9880d4baf1adc474`）。
两臂逐次核对输入SHA，输出使用memfd普通文件、每臂
完整SHA；要求输出逐字节与exp780一致、
单线程、RSS≤2000000000B、CPU/wall≤3600秒。
要求候选CPU节省>0及折算综合分≥0.02，
单对1B仅报观测值，不能冒充时间置信区间。
若SHA等于保留归档的exp780结果，重用其3833856
条exact和完整契约；不另行产生数十GB重复副本。
未知新1B和6242R实机仍需最终官方确认。

通过1B后清洁空环境完整100M再验、独立复算、
按`subm/versions/README.md`的不可变版本顺序打包；
原有版本及正式根入口在门槛未过前保持不变。
原始证据放`validation/results/exp786/`。

## 2026-10-28 实测与停止

只在私有候选把family6/model85的L3阈值改为20MiB，
复制exp785冻结worker和原头文件并核对SHA。
新ELF为84,938,776B，SHA-256
`aa6f6737a8d499baca042a13237e81edbaf4eb85cf9f5185aa33130c1038a315`。
r9原生CPUID读到22MiB和AVX2；模拟19MiB、22MiB、35.75MiB、
AMD及不同model的分派断言通过，8000例与标量结果一致。
完整1M的端点、行数、整数、精确EOF和完整输出SHA通过。

复用已观察100M输入，auto的完整CPU为15.481602s，
较exp785同机六次F均值16.046173s节省0.564571s；
比强制P均值15.358118s慢0.123485s，达到预登记门。
完整100M输出4,013,572,706B，SHA与正式版相同，
单线程、RSS264,716,288B，exact身份复用。
这一次auto计时与历史均值比较，统计依据仍是exp785的
六对F/P结果，不能把它写成新配对区间。

同机CPU8、磁盘1B输入和memfd输出的单对F/auto完整运行中，
正式F的user/sys/total为141.863316/15.694605/157.557921s；
auto为139.199278/19.253082/158.452360s。两个输出均为
40,135,610,837B，SHA-256都等于exp780的
`c34adca505a48a2f2eb39e14c09049ea1da0fca772a73b84bf11af23baa7f0ce`；
两臂输入各自前后完成SHA核验，单线程，峰值RSS分别为
264,720,384/264,716,288B。沿同输出身份复用exp780的
3,833,856条exact，样本Acc98.824550329%，差0。
本对auto多用0.894439s，折算综合分-0.007454，
未达到节省>0及增益≥0.02的1B门。
`validation/exp786_audit.py`由逐臂回执独立复算通过。

100M使用tmpfs输入输出，1B使用磁盘输入与40GB memfd输出；
auto在1B的user少2.664038s，sys多3.558477s。
一次配对不能分离I/O、调度、页缓存和硬件路径的因果贡献，
也不能给出性能置信区间。这次失败限定当前自动阈值、
这组1B输入和运行条件，不证明预取在6242R或所有机器无益。
按预登记停止本候选的清洁目录验收与正式发布，
`./estimate`及历史不可变包均保持exp780；
其他CPU和6242R实机加速仍未验证。

开工前本地`df -h /dev/sdd`可用266G，收尾同为266G，
本地释放0B。100M完整输出已按`100m-auto-cleanup.json`
验证SHA并删除；两臂1B输出在各自完整SHA与旧版合同身份匹配
后关闭memfd，没有生成磁盘副本。保留现成100M和1B输入、
exact标签、原始回执及远端独立候选构建物。
