## 假设

- **H1 规模可行**：正式入口（实验29 冻结二进制）在 10M 全独特请求上单线程完成，且
  `build + 10 × (wall_10M − build) ≤ 3600 s`，即 100M 全独特可在一轮 3600 s 上限内跑完。
- **H2 缓存对照**：全独特输入上 cache=64 的命中数为 0（distinct key 远超 3,145,728 插入上限），
  只多付探测开销，CPU 与 cache=0 的差应在本机波动量级内；exp49 的 2M unique 已给出同方向证据。
- **H3 外推边界**：若 100M 一轮完成，则按同一每行成本外推的 1B 全独特（约 2 万秒）远超 3600 s，
  赛题规模下"全独特 1B 不可行"这一结论在本轮获得直接可审计证据，而不是纯外推。

本轮只做可行性判别与边界记录，不产生候选、不改默认容量、不做正式综合分验收。

## 输入生成规则

```sh
python3 scripts/make_scale_requests.py --arch doc/eda比赛文件/arch \
    --mode unique --rows 10000000 --block-rows 1000000 \
    --out build/exp50/unique-10m.csv --json build/exp50/unique-10m.json --check-rows 100000
```

生成器规则固定（`unique`：行 k 取 j=(a·k+b) mod space 的混合基数分解），不引入随机种子。
生成后必须核对：

1. 行数 10,000,000、block 1,000,000 对齐、meta JSON 记录完整 SHA 与字节数；
2. 前缀逐字节一致：`[0,4M)` == `unique-4m.csv`、`[0,6M)` == `unique-6m.csv`、
   `[0,8M)` == `unique-8m.csv`（不重叠与身份依据来自实验31/43/46 记录）。

100M 输入（仅当 10M 满足继续条件才生成）：

```sh
python3 scripts/make_scale_requests.py --arch doc/eda比赛文件/arch \
    --mode unique --rows 100000000 --block-rows 1000000 \
    --out build/exp50/unique-100m.csv --json build/exp50/unique-100m.json --check-rows 100000
```

同样核对 `[0,10M)` 前缀与 10M 文件逐字节一致。

## 计时协议

- 正式入口参数：`-residue-mult 2 -endpoint-mode source-short -endpoint-short-distance 150
  -residual xgb`，附加 `-cache-mb 0` 或 `-cache-mb 64`；不传 `-quiet`（需要 stderr 的
  `build=…s`、`cache_hits=…` 汇总行）。
- `taskset -c 3`、串行、`scripts/run_scale.py`（含 3600 s 硬超时）、同一工作目录、无预热。
- 10M：cache=0 与 cache=64 各 **至少 2 轮**，顺序 `0,64,64,0`（交错抵消机器漂移）。
- 每轮结束后立即用 `scripts/verify_scale_output.py --mode unique --input build/exp50/unique-10m.csv
  --expect-rows 10000000 --output <out> --json <verify.json>` 核对输出契约（行数、From/To 原文与
  顺序、整数 delay、精确 EOF）。
- 每轮保留 `run_scale.py` 的 JSON、stderr、time 日志、verify JSON；输出 CSV 记录 SHA 后删除
  （可重建，重建命令写入证据 JSON 与本日志）。
- 100M：继续条件满足后，cache=0 与 cache=64 各至少 1 轮；同样逐轮验证。

## 门槛与停止条件

硬门槛（任一违反即停止该规模，保留负结果）：

1. 退出码 0；2. 观测线程数 == 1；3. 峰值 RSS × 1024 ≤ 2,000,000,000 B；
4. wall ≤ 3600 s；5. verify 通过（行数、端点原文、整数 delay、精确 EOF）；
6. 同一 cache 设置的多次运行输出 SHA 一致。

继续/停止规则（预先固定）：

- 10M 完成后计算 `est_100M_wall = build_10M + 10 × (wall_10M − build_10M)`，取 10M 各轮的
  最大 wall；`est_100M_wall ≤ 3600 s` 才生成并运行 100M，否则**记录停止证据、不启动 100M**。
- 100M 完成后按 `est_1B_wall = build_100M + 10 × (wall_100M − build_100M)` 报 1B 外推值，
  并注明这是 100M 单点线性外推；**本轮不跑 1B**。
- 若 10M 各轮 wall 相对差 > 25%（机器状态不稳），先记录并重跑一轮，仍不稳则以最大值判停。

## 预注册分析

按规模与 cache 设置报告：CPU（user/sys）、wall、峰值 RSS、线程、`cache_hits`、建表秒数、
每行边际成本 `(wall − build)/rows`、输出 SHA 与 verify 结论；比较 cache=0/64 在同一规模上的
差；给出 100M 实测（若执行）与 1B 外推；空间开工/收尾读数。

## 边界与不做的事

- 全独特输入不是赛题公开分布（公开 1M 扩到 1B 时 distinct key 仅 1M），本轮结论只描述
  "全独特"这一上界负载，不外推到隐藏集成绩。
- 不读 golden、不改生产、不删已有文件；清理只针对本轮可重建输出，逐条记录 SHA 与重建命令。

100M 实测 2183.4 s，比预注册外推 2318.8 s 快 5.8%；两轮输出 SHA 相同（`befd804c…`，
100,000,000 行，4,065,567,578 B）。每行边际成本 10M 20.4–23.0 µs、100M 21.55–21.56 µs，
与实验35 的 20.7 µs/行一致；缓存设置对全独特负载无影响（命中 0）。

### 1B unique 外推与停止结论

`est_1B = 28.9 + 10 × (2183.44 − 28.9) = 21,574.3 s ≈ 5.99 h`，为 3600 s 上限的 **5.99 倍**；
按预注册规则本轮**不启动 1B**（`exp50-report.json` 的 `one_b_extrapolation.within_budget=false`）。
由于 10M→100M 的每行成本几乎不变（21.55 µs），该外推有两点直接支撑：全独特负载每行成本与规模
无关，且 100M 单轮已是 3600 s 上限的 60.6%。结论：**全独特 1B 在本机与赛题时限下不可行**；
赛题公开分布（1M distinct key 扩到 1B）不受此限制。
