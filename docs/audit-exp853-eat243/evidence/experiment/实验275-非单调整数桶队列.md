# 实验275 非单调整数桶队列

2026-10-16。CPU基线为exp274私有候选，提交105af18。其独特
U-output 1M两次平均275.75秒。精度基准为exp258，公开1M acc
99.27638014510366%，复用exact开发样本99.30225286909072%。

## 预注册

主假设是延迟建立桶内堆，能节省最终未出队条目的排序工作。固定
4096个桶，每桶对应一个key，64个64位字和一个64位摘要定位最小
非空桶。桶首次出队时按(id,g)建立最小堆，后续插入维护该堆。
空桶复用时恢复未建堆状态。查询清理只遍历仍非空的桶。

key>=4096沿用完整(key,id,g)四叉堆。4096由两级64位位图确定，
本轮固定这一表示，不做边界选型。小桶始终先于大key堆出队，
每次重新查询位图，支持key下降。重复三元组保留。q、strict relax、
有效展开cap、stale和动态parent重放保持。CPU收益另待实测。

范围为私有legal_path_search.h/.cpp、新队列头文件、独立夹具和
实验runner。修改init、query清理、push/pop及empty检查，公共query
签名、调用方、架构加载、模型、输出格式保持。正式src、./estimate、
subm及既有用户改动保持。独立推导存于vault的
`非单调整数桶与延迟建堆的全序等价`，与相关笔记双向链接。

先验证标准完整三元组优先队列与候选逐次出队相同。固定覆盖重复
key、相同id不同g、非单调插入、63/64和4095/4096边界、UINT64_MAX、
有符号id、建堆后插入、提前clear及连续查询，并运行ASan/UBSan。
再复用35,702条搜索、逐次q、完整路径、七组CLI、Arc费用变体和
768组cap检查。追加8条请求在cap=17/1024、weight=-1/0/10/17/INT_MAX
下配对，保留query接口的整数计算语义。任一语义差异停止性能试验。

冻结基线和候选源码、编译参数、ELF、架构、模型对象、输入和runner。
使用通用编译参数。纯等价候选复用既有开发请求和exact标签。先做
两套原序独特20k完整程序筛选；各臂预热一次，AB/BA/AB三对，core3、
单线程、同机串行并检查其他负载。主指标user+sys，配对差使用df2的
95% t区间。两分布均点省至少1%且差区间上界小于0时扩大到完整1M。
点省且区间跨零保留待定；明确变慢时结束该固定候选。阶段指标只记进度。

远程限定r9r4900的~/lhjwork/eda2026，AMD/WSL2使用同一冻结ELF和
相同20k协议。明确加速后运行候选两次完整独特U-output 1M，核对
exp274已验SHA。公开1M单次候选运行与exp258部署输出逐行配对，
复用exact样本同样配对，要求总体和七组acc差均为0、变化行数为0。
repeated 1M沿用1000个独特请求，预热一次后AB/BA/AB，记录cache命中。

全部运行核对行数、端点顺序、三字段、整数delay、精确EOF及完整SHA，
资源要求单线程、RSS不超过2,000,000,000字节、单次不超过3600秒。
20k筛选明确变慢时停止后续1M，保留开发精度结果及未验证范围。

开工本地df可用418GiB，远程193GiB。本轮输出预计远小于10GB，保留
复现输入和冻结基线。跨FPGA架构、官方平台和完整独特100M/1B另验。

## 工作量解释与检查修复

在查看计数前保存work-diagnostic-protocol.json。诊断副本使用固定128条
请求及六条边界自检，实际有212,409次小key入队、178,728次大key入队。
小桶中15,717条参加首次建堆，6,568条参加后续push_heap，190,124条在
clear或析构时仍未建堆，占全部入队条目的48.61%。小key出队21,913次，
大key出队14,025次。候选和基线128行字段及完整路径保持，计数满足守恒。
这支持延迟排序减少工作的解释；该开发小样本的比例另有适用范围。

诊断报告首次误要求两个queue_work记录。探针未定义
DELAY_ESTIMATE_LEGAL_PATH，只含显式Search对象的一份队列，实际记录数为1。
随后提取汇总函数时曾出现header局部变量的NameError，已改用root下的明确路径。
两个问题都发生在报告检查阶段，复用已完成且相同的输出重新检查通过。
失败记录和修复说明保存在work-diagnostic-failure，计时候选保持原SHA。

validation/exp275_evidence_check.py逐项核对43份原始time、资源字段和空stderr，

补充检查节省比例、各组与总门槛结论，以及exact和公开结果与冻结候选的关联。

实验日志追加结果，预注册字节继续保存在protocol-original.md。
candidate.patch保留三个单空格上下文行，Git把它们提示为空白尾随；

## 结论与空间

保留exp275作为后续CPU优化候选，已测acc保持exp258。Xeon明确加速，
AMD性能待定。正式src、./estimate与subm继续保持现状。正式入口仍为
exp131静态身份，平台交付镜像仍为用户现有exp250身份；本轮采用私有构建。

可用206,423,334,912字节。本轮保留冻结产物、复现输入及证据，删除文件数为0，
