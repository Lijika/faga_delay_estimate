# 实验805 完整曲面的批内目录读取与有序输出

2026-10-29，预登记，候选尚未构建和计时。最终目标保持未知非重复全角色
1B完整CPU约100秒，Acc严格大于99.1%并留余量。

## Altitude

报告03的工程价值在于分开请求内依赖和请求间独立性。exp800把同步目录
读取提前至每条prepare中，100M增加6.63秒；exp804的前五组已观察到
64B压缩行解码增加CPU，最终六组仍按原协议完成。两项事实共同要求检验
完整计算链。单看正文容量无法确定运行速度。

本轮冻结exp781的原int16码本和全部预测函数。它较exp780的已验100M
精度提高0.074890107pp；改善其执行成本可以恢复阶段价值。
exp714曾在旧D64+小曲线核上测试批内stage，节省0.120838秒，
低于当时0.5秒门。当前背景是115MB目录与37.31MB完整曲面码本，
原背景点积已删除；本轮明确改变了那项实验的成本前提。

## 唯一候选与影响范围

保持稳定行视图和批8，把原prepare→逐条finish+write改成
prepare整批→读取整批目录word→finish整批并保存answer→按序write。
新增word存入Prepared596，预计原padding可容纳；实际sizeof组件验证。
模型、舍入、cycle、fee、mandatory、解析与写出格式全部保持。
stage只处理ready状态。逐请求predict和组件eval也在finish前调用stage，
所有调用者共同遵守写入先于读取。无新增预取、窗口参数或训练。

只修改私有worker和surface头的输入接口，原静态资产继续复用。
目录地址在prepare后完整已知；一个请求读取的word仅用于它自身的码本地址。
不同请求的预测只读架构、模型和表，因此可以先全部算完，再按输入顺序写出。
所有view在本批结束前保持有效。该等价理由只保证输出；真实CPU另测。

## 检查与停止门

1. 复用exp714组件的239616条见证×四折、99200个坐标及端口边界，
   比较完整整数字段和double位模式，状态保持56B；原文件以哈希冻结。
2. 生产静态ELF<100000000B，原资产身份一致；完整测试直接100M。
3. 主比较A=exp780，C=exp805，各预热一次，然后六对
   AC、CA、AC、CA、AC、CA，r9绑CPU8串行。每次核验完整输出SHA、
   单线程、RSS≤2GB、完整CPU与wall≤3600秒。exp804同机B只作最近
   历史参照，不把不同轮的B/C差写成新配对区间。
4. 输入及A/C预期输出沿exp804协议。C必须逐字节等于exp781的100M输出；
   相同完整身份复用CSV合同及1916928条exact。
5. 与exp804相同的精度差、97.5%保守区间及df5 CPU系数
   3.163381449748624。1B线性成本诊断综合分点估计≥0.02且联合95%
   保守下界>0才进入完整1B；这项诊断不称为1B成绩。

通过即完整1B、清洁验收及阶段接入。失败只停止当前批8四阶段布局；
最终99.1%与100秒继续单列。既有请求已观察，部署等价复用评分，
未知分布与官方平台表现仍需后续独立验证。

## Tactical、Depth与资源

首要检查各调用者是否取得本行word，包含提前返回与末尾不足8条的批次。
答案先存栈数组，writer仍按序执行；没有延长view至下一次refill。
报告03的有限tick证明没有映射到本机周期，本轮全部收益由完整程序决定。
exp804六组结束后才在r9编译与测试，避免污染计时。
