# 实验101：depth10四树交错遍历

日期：2026-09-27。开工 `/dev/sdd` 可用约479G。

## 冻结协议

实验99中，删除末层后的depth10相对depth8仍增加 `3.876667 s/1M unique`，综合点收益 `-0.000204`。实验93 profiling中 `applyResidual` 占用户态采样22.29%；树内索引读取串行依赖，树间路径独立。复用实验79四树交错补丁，只改变遍历调度，保持模型、每树10次比较、叶值与树号升序float累加。历史depth8四树交错平均节省0.70秒，但区间跨零；depth10热点占比更大，值得单独检验。

control为实验98删末层静态二进制 SHA `64d5e9dc05ae0a3db8aa52be4dd97ada7df24b05c5f7da343819577d3b782b91`。候选复制实验98私有源码并应用 `validation/exp79_interleave.patch`，使用相同C++17/O2/静态参数。先运行实验79的float位模式测试，覆盖随机、NaN/Inf、split等值边界，再核对实验93独立样本和完整1M输出SHA。

性能输入仍为冻结的1M unique，核3、双方预热、3对交错、单线程。每轮检查端点原文、行数、3字段、整数delay、精确EOF、SHA、RSS<=2GB、wall<=3600秒。工程门槛固定为CPU差95%上界<0，点综合收益至少`+0.01`，即平均省时至少1.2秒；通过后再与depth8直接配对并合并实验93精度区间。失败关闭该遍历候选，不修改正式源码或交付包。

```sh
build/venv-ml/bin/python validation/exp101_interleave_depth10.py --stage build
build/venv-ml/bin/python validation/exp101_interleave_depth10.py --stage timing
```

原始报告在 `validation/results/exp101-*.json`，私有产物在 `build/exp101/`。平台1B及隐藏集未验证。

## 结果

树遍历位模式检查通过135,044个向量，独立窗口6,178行逐行输出一致。control与候选的完整1M输出SHA同为 `d7b5f9ac590c97004404ee7827fa8161f287d19172566f0f1cf2d8979fe105fa`；每轮的端点、字段、整数、EOF及17,585个负值位置均通过。

三对候选减control的CPU差为 `-0.99/-1.32/-1.31 s`，均值 `-1.206667 s`，95% t区间 `[-1.672953,-0.740380] s`。等精度综合收益点值 `+0.010056`，95%下界 `+0.006170`；预设工程门槛通过。最大RSS `571,187,200 B`，最大wall `30.55 s`，全部单线程。接下来直接与depth8配对核对整体综合收益；当前结果只证明depth10自身的等价加速。

收尾 `/dev/sdd` 可用约479G，释放量0。本轮没有需要清理的大文件；计时输出可由上述命令重建。
