# 实验217 C1 双预算分阶段安全剪枝

2026-10-12。exp216静态集成本地保持全部旧统计与冻结截断输出，
ELF为93,768,336B、已测峰值RSS约1.659GB。
其远程完整1M正在串行运行。本轮先准备独立局部原型，
远程计算安排在exp216全部结束后，避免计时重叠。
私有目录为`build/exp217`，开工`/dev/sdd`可用约437GiB。

## 预注册

主假设是旧预算资格一旦排除，可以使用当前新增最小合法U减少恢复与重放。
理论见Obsidian `双预算查询保留旧计数的分阶段剪枝.md`。
固定exp216全部树、旧模型、阈值和查询枚举顺序。

四臂为reference、recovery、replay、combined。
recovery在部分原Arc或映射Arc和超过树预算时停止；
或在已排除旧资格后，sourceArc+部分映射Arc+terminalArc达到有效新增U时停止。
replay在已排除旧资格后，以全部已知Arc和加已重放Net费用为下界提前停止。
主候选预先固定为combined，两个单项用于解释成本来源。
所有臂保留旧U/count、完整新U、26维特征、gain、旧S和最终整数。

数据复用exp216的12352条query/audit，包括exp174与exp203两个窗口。
逐行核对全部数值与float32 bits，完整新U也与exp216相同。
独立计数构建记录parent读取、resolver调用与两类剪枝次数；
计时构建关闭计数，避免计数更新混入CPU效果。
先在本地每臂运行一次完整数值与工作量检查，失败即停止扩大。

组件计时包含全部12352条请求，保持原行序。
每进程恢复一次数据，分别报告恢复CPU、查询CPU和总进程资源。
每臂一次预热，再5个四臂循环轮换块，每进程查询10轮。
远程r9r4900、工作目录内、core3同机串行；各进程单线程、
RSS不超过2,000,000,000B、CPU和wall均不超过900s。
查询时间使用进程CPU钟；所有轮次核对完整结果摘要及CSV身份。

主门为combined查询CPU节省至少5%，5对差值的df4配对95%区间上界小于0。
单项使用Bonferroni调整后的97.5%配对区间，仅作消融解释。
恢复与查询分别列出，组件收益达到主门后再设计静态生产完整1M验证。
新标签、模型或阈值选择、跨架构精度与平台1B均不属于本组件实验。
