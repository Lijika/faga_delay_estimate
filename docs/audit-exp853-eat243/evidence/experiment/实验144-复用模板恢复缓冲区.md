# 实验144 复用模板恢复缓冲区

2026-10-10，Asia/Shanghai。分支 `research/exp144-reuse-template-scratch`，基线为exp143结果提交。只在私有C4候选构建中调整模板恢复临时缓冲区的生命周期；正式源码、`./estimate`、exp131包及发布指针保持不变。

## 假设与冻结身份

exp142的插桩将候选恢复成本中约 `0.251543 s` 归到分配阶段，其中同时包含一次 `values.resize` 和12次临时平面缓冲区分配/清零。当前源码在每个字段循环中构造 `std::vector<unsigned char> planes(kFieldBytes)`；成功的 `ZSTD_decompress` 必须返回完整 `kFieldBytes` 后，后续才读取缓冲区。假设将这一缓冲区移到循环外并跨12个字段复用，可减少重复分配与零初始化成本，且保持所有输出值不变。

本轮只移动临时平面缓冲区的构造语句，不改 `values.resize`、Zstandard帧校验、平面合成、dy前缀循环、C4选择规则或模型。若收益门未通过，停止该缓冲区复用方案；不因此关闭路线图中未明确排除的其他方向。

## 测量协议

先核验6,176行固定样本的完整输出SHA。public输入由baseline和候选各运行一次完整1M输出契约；unique、repeated分别预热一次，再按CPU 0串行进行10对AB/BA交错计时。使用现有 `validation/exp139_timing.py` 的逐轮执行和输出校验逻辑，按df=9、双侧95%配对t区间计算主指标（candidate−baseline CPU）。

unique和repeated均要求CPU差均值 `<= -0.05 s/1M` 且95%区间上界 `<0`，才判定缓冲区复用有可确认收益。每次运行还检查二进制SHA、完整1M行数、端点行序、恰好3字段、整数delay、精确EOF、完整输出SHA、单线程、峰值内存 `<=2,000,000,000 B` 和wall `<=3,600 s`。任何身份、输出、资源或确定性检查失败即停止。

本轮通过只证明该本机负载上的工程成本收益，不代表与exp131正式基线的综合分验收。正式接入仍需单独与exp131比较并通过完整1M门槛；不要求本地1B测试。

复现命令：

python3 validation/exp144_reuse_template_scratch.py --stage self-check

python3 validation/exp144_reuse_template_scratch.py --stage measure
