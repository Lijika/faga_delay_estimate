# 实验68：固定容量叶子权重约束

日期2026-09-26。开工 `/dev/sdd` 可用490G。

## 预注册

- 基线exp66静态包SHA `1f68d9248f5fab50494bcb0cf6d0f53ae15945b1fb4429b75cdf78b80cecf1c8`，exp63模型SHA `79e705e78d3680e9528f479dd2b6722ef6dc06ba0272c0ff0e8823385a256fe0`。按安装XGBoost 3.4.1的参数说明，`min_child_weight` 限制子节点累计样本权重（Hessian），当前默认1。
- 开发诊断发现9,646个叶子中3,177个cover<4、5,298个cover<16，中位数11.01；训练accuracy 96.937624、MAPE 0.780753%。假设限制低权重叶子可改善泛化。cover为加权量，不等于样本数。
- 单变量矩阵为 `min_child_weight` 1（control）、4、16；其余采用exp63的34,352条可达训练标签、47维和6个屏蔽槽、64树depth8、eta0.1、加权L1、256分箱、seed20260919、单线程和-3输出。control必须完整复现exp63模型SHA。
- 复用实验67已验证的开发窗口exp62与exp64、fast/base特征和包预测。先核对源文件身份、完整端点、样本数以及Python control与已验包输出逐行相同，证据不变时复用通过结果。
- 两窗口带份额加权accuracy都至少提高+0.03 pp、两类可达性误判均不增加才入选。多候选通过时最大化较小窗口收益，同分取更少节点。报告训练误差、分带误差、节点和叶子数，区分减少过拟合与增加偏差。
- 选中模型冻结SHA后，使用未查看的 `[26M,28M)` 新请求七带各最多1024条exact；排除公开1M、训练和全部历史窗口的完整端点，命中停止。配对bootstrap 10,000次/seed20260925；新窗口增益≥+0.03 pp、95%下界>0、可达性误判不增加，才进行私有C++部署。
- 私有输出逐行等于Python后，预热加3对交错1M CPU；综合点收益≥0.01且保守下界>0，再完整1M契约和资源验收。筛选失败停止本轮，保留正式exp66和新窗口。公开golden不参与选择。

## 结果

命令 `build/venv-ml/bin/python validation/exp68_child_weight.py`；证据 `validation/results/exp68-screen.json`。control完整复现冻结模型SHA，两个开发窗口与已验收包的参考输出逐行相同，完整端点隔离和源文件身份通过。

两候选两类可达性误判均为0。约束提高后低cover叶子按预期消失，训练误差和两个开发窗口误差都增加；本实验支持这两个配置增加了拟合偏差，未支持靠增加叶子权重约束改善当前泛化。两个候选均未过+0.03 pp门槛，停止此轮，不获取新exact、不进入部署。候选SHA与完整分带指标见JSON。本结果为开发筛选，独立窗口 `[26M,28M)` 仍未使用。

收尾 `/dev/sdd` 可用490G，本轮未删除文件，释放量0；模型和预测保留以复现，正式版本仍为exp66。
