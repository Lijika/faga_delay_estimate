# 实验799 exp780当前完整程序热点与工作集复核

2026-10-28，执行前冻结。正式阶段版exp780在非重复全角色1B
为165.039292s、抽样Acc98.824550329%，离约100s及Acc>99%
均有差距。exp798只在历史百万开发集的近轴普通支持域看到

## 主假设与决策

优先确认当前端到端时间落在哪条必经执行链，而后评估能同时
保留背景信息、减少随机访存或解析开销的替代结构。固定六类
互斥诊断方向：CSV解析/端点、准备及端口解析、曲面目录/书页、
修正、输出、初始化/系统调用。`perf`采样是相关性诊断，
内联包含关系和缓存未命中不能累加当作CPU时间；只有完整程序
同输入配对才能确认后续改造的速度收益。

## 固定输入、制品与测量

- r9 Xeon Gold 6226R，单线程绑CPU8，仅为控制测量；6242R及
  主流CPU速度仍需实机验证。
- 原ELF为`../exp779/build/exp779/C`，SHA
  `41329c3812f12f017cbb29c7426a0713b124927625b82babc1226fd72e7f4146`。
- 现成非重复100M输入为
  `/dev/shm/eda2026-exp781-scale/u-role/requests.csv`，SHA
  `b26b7e7942dadcc21f58251758fd60da3d0222f8a80bcefd9d86703ddbad7bea`；
  59,904个角色对，输入唯一性继承已冻结证据。
- 两次完整输出必须为4,013,572,706B，SHA
  `d69146449c13321f6acc1ae665e169b54be75aa41214f3783fd31a95771dbe75`。
  通过同输入、同输出身份复用已有exact与契约评分。
- 从exp779冻结的编译/链接命令重建带调试符号副本，
  核对所有加载节与原ELF的大小、地址、对齐和内容SHA
  （build-id可不同）；初始运行以原ELF执行`perf stat`
  `cycles,instructions,LLC-load-misses`，第二次以等价副本
  `perf record -e cycles:u -F 999`。保存原始回执与源码定位。
- 两次均核对完整输出后按名删除tmpfs输出；各次输出
  约4GB，启动时检查剩余空间>6GB，根盘不保存CSV。
  两次估计程序CPU各不超过3600s、RSS≤2GB、线程数为1。

此次只有画像，不选性能候选、不生成新请求或exact，也不改
生产代码。若二进制加载节不等价、计数不支持或输出SHA不符，
停止画像并留存失败证据；不能据失败样本作热点归因。
