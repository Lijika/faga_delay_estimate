# 实验391 同几何端口转移的精确压缩容量

2026-10-17，在读取新矩阵统计前登记。正式入口和交付保持exp354，
性能比较基准保持exp323发布版。本轮响应用户对算法范式的要求，先检查
能否在保持真实路径费用时，将每格160个Z状态压缩到较少的运动因子。
数据仅使用冻结的五个架构JSON及源码，属于架构开发分析。

主假设是相同Net位移的I端口，其到下一Z及终端Output的Arc费用矩阵存在
较低的精确min-plus因子数。竞争假设是lane特有的可达集合或费用差异
要求保留多数状态。16个几何组各自计算，另外分别使用Z列和全部Output列，
避免将终端约束误当成中间状态约束。并行Arc取最小费用，缺边记正无穷。

首先按有限mask与归一化行值检查“只差常数”的行，得到精确构造上界。
然后寻找两两不相容的有限矩阵项作为因子数下界。两个有限项
(i,j)、(k,l)若满足M[i,j]+M[k,l] < M[i,l]+M[k,j]，同一min-plus因子
无法同时取等。任一交叉项无穷也使有限因子无法同时取等。
保留完整见证，由独立checker直接复算所有不等式。
数学前提及路径接入边界另记Obsidian《同几何端口转移的精确因子下界》。

每组完整见证搜索最多50,000个递归结点，另有固定贪心下界；
未找到满秩见证时报告下界及构造上界，保持未知区间。
普通自检先包含rank1常数、常数差行、对角有限/交叉无穷与有限交叉严格不等式，
并注入错误见证确认checker能拒绝。总过程单线程，进程CPU预算120秒、
wall180秒、地址空间2GB，原始矩阵和见证存于validation/results/exp391。

主指标为按几何组求和的下界、构造上界及精确等价行数。
若Z列构造状态数<=80且全部Output列<=96，保留完整局部图原型资格。
若Z列下界>128，结束本轮“同几何精确单步因子”压缩扩大。
其余区间保留待定。这些门只筛选当前表示，有损压缩、多步摘要和门户方法
继续按独立假设研究。本轮不生成全域索引、exact标签或估计程序输出，
没有新CPU阶段成绩与精度成绩。

影响范围为validation/exp391_port_factor.py、独立checker及本实验记录；
生产代码与既有消费者保持。开工本机可用386GiB，本轮无大文件，
收尾记录空间与删除量。复现步骤先prepare，再run，最后check。

## 结果

32个矩阵的真实Arc逐项复算通过。16个几何组的Z列与全部Output列，
每组归一化行数、因子下界和行数均相等，合计均为160。
独立checker核对1632对不相容不等式，合成错误见证拒绝检查通过。
固定精确单步因子表示无法减少当前160状态，结束该表示的局部图扩大。

probe CPU0.991565秒，峰值RSS25,051,136 B，矩阵证据1,132,382 B。
没有新exact、评分或估计程序CPU。多步摘要与有损表示继续保留研究资格。
复现命令为`python3 validation/exp391_port_factor.py prepare|run`及
`python3 validation/exp391_evidence_check.py`，原始见证与矩阵见
`validation/results/exp391/{matrices,report,evidence-check}.json`。
本机收尾仍386GiB，删除0字节，正式入口保持exp354。
