# 实验696 双64因子的无损差分与启动恢复

2026-10-25，在新编码结果前登记。exp695质量门通过而直接压缩容量
投影100,520,405B未过。主干保持64/64距离条件背景及匹配残量曲线，
本轮使用exp646现成模256差分，单独改变存储编码。

## 固定假设与对象

冻结exp695方向0的12,569,664B原因子，完整SHA为
78390198e52099c39c70fec3feedf8cabbf36b24cca7941301ab06820e280538。
数组顺序为中程left/right/ls/rs、长程left/right/ls/rs，rank均64，
左右行数分别为59904/13920、59904/51120。仅对四个INT8因子逐行
同列做uint8模256差分，尺度保持全部原字节。沿用Zstd-9单线程与
checksum，不搜索级别、转置、行置换或训练参数。

Z臂复用exp695已有压缩资产。D臂使用exp646.delta编码；C++恢复
复用exp646原型，将旧完整几何header解析替换为已审核的新数组边界。
每臂独立generic x86-64/SSE2静态ELF，启动解码至64B对齐BSS，
D在原缓冲区逐行累加。恢复完整SHA必须等于原因子，查询数值因
完整字节恢复而保持，在线工作集和完整CPU继续独立验证。

## 验证与继续门

固定顺序Z、D，各一次预热和三次启动资源测量。计量恢复CPU、写出、
完整进程CPU/wall/RSS与线程数；完整SHA计算费用另列。核对Zstd帧、
原数组边界、尺度字节、模256回绕和完整恢复。读取已安装CLI帮助、
静态库和头文件，依赖身份与生成源码一并记录。

D的方向0压缩量代入exp695相同容量式，即旧近域压缩量、四份新因子、
四份exp694曲线、旧非资产ELF字节和1,000,000B预留，须严格<100MB。
每次恢复RSS<=512MB、单线程、wall<=60秒，D恢复CPU中位数<=0.5秒。
本轮离线CPU<=300秒、wall<=300秒、RSS<=1GB、新文件<=100MB。
全部通过后登记64/64匹配曲线；失败只界定本编码、布局和容量配置。
实际其他方向、完整ELF容量及100M/1B保持待验。

没有新exact、完整估计程序运行或新的质量选择。exp695的质量结论
与exp696编码成本分别保留。仅新增实验驱动、私有build和证据，
正式版exp688、历史输出和原资产保持。

本地/dev/sdd开工294GiB，远端3.08GB可用。结束记录新增与释放量。

95,097,313B，仍含1MB预留，容量门通过。Z/D恢复CPU中位数分别

独立审计从压缩流以uint64列前缀和重建，全部因子与尺度原字节通过。

离线CPU2.020942秒、wall1.886542秒，新增65,338,623B，资源门通过。
