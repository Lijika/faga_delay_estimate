# 实验200 C1 映射前驱链剪枝固定样本CPU诊断结果

2026-10-10。实验200完成10对配对进程。control是实验198的8映射未剪枝
程序，candidate是实验199的7个cycle映射、query级端点和Arc-only剪枝
程序；两者均使用同一6176行输入，输出写入`/dev/null`。

## 原始汇总更正

独立复核发现，原计时脚本构造`by_pair`时没有按`row["pair"]`筛选，
将最后一对的`-0.71 s`差值重复使用十次。原20个运行记录和计时文件未修改。
根据每个冻结计时文件逐对重算，candidate-control为
`[-0.25,+0.08,-1.38,-0.89,-1.03,-0.59,-0.56,-0.64,-0.87,-0.71] s`，
均值`-0.684 s`，普通双侧95%配对t区间
`[-0.974094,-0.393906] s`。修正只改变汇总统计，不改变本轮三项改动同时
生效、不能作单项归因的限制。

## 结果

- 20个计时进程均为单线程，RSS约`321.6 MB`，资源约束通过。
- 更正后candidate-control均值`-0.684 s`，df=9的普通95% t区间
  `[-0.974094,-0.393906] s`。
- fixed-input点结果显示candidate更快；本轮没有完整1M或平台1B结论。
- 计时使用两位小数的`/usr/bin/time`输出，统计精度受计时量化影响。

## 解释

本轮是必要组合比较，速度收益同时来自：

1. 删除与cycle4逐行相同的xor4；
2. query级端点提升；
3. Arc-only安全下界剪枝。

因此`-0.684 s`不能单独归因于某一项。实验199已证明三项组合逐行等价；
若要给单项CPU归因，需在相同7模式集合下再做control/单项/组合消融。
