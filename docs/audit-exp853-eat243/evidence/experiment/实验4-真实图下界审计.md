# 实验4 真实图下界审计

日期 2026-09-17，基线提交 f36a3c3。本轮只做诊断审计，生产算法与 estimate 保持原样，
百万行评分未重跑。审计工具 tests/bound_audit.cpp 独立于 plan_probe，唯一的生产侧改动是
src/residue_estimator.h 新增只读访问器 potential(quadrant)，用于读取现有线性势函数。

## 研究问题

当前名义位移 residue 的逐边 reduced cost 条件在真实 Block 图上是否成立，以及当前 residue
输出是否存在具体合法路径上的高估。没有反例不等于全局证明，本轮只报告可重放证据。
理论依据见 doc/paper/10-Goldberg-Harrelson-AStar-SODA2005.md 第 2 节的 reduced cost
可行性定义与路径望远镜求和，DESIGN.md 8.1 到 8.3 说明现有证明只覆盖无限无 Gap 平移图。

## 方法与命令

工具只读 Architecture 与当前 ResidueEstimator(cacheBytes=0)，一次构建。

```sh
g++ -std=c++17 -O2 -Wall -Wextra -Wno-unused-parameter -o build/bound_audit \
    tests/bound_audit.cpp src/architecture.cpp src/router.cpp src/residue_estimator.cpp
timeout 60s stdbuf -oL ./build/bound_audit --arch doc/eda比赛文件/arch --self-check
timeout 180s /usr/bin/time -f "RSS=%MKiB user=%U sys=%S wall=%e" ./build/bound_audit \
    --arch doc/eda比赛文件/arch \
    --json validation/results/real-bound-audit.json \
    --witness-csv validation/results/real-bound-witnesses.csv
```

步骤与数据结构如下。

1. 遍历所有存在 SRB 的全部 160 条 Net，用 resolveNet 取真实落点，统计有效、无效与 skip，
   并把等价 hop 按 netIndex、实际位移、gapDelay 与 lineDelay 归并到 std::map，记录首个合法
   源坐标与 multiplicity。lineDelay 由实际端点两轴 prefix 求和，blockDelay 等于 gapDelay 减去
   lineDelay。
2. 每个 hop 类型与落点每条 I 到 Z Arc，在四个象限检查真实 potential reduced cost，
   即 S 乘 arcDelay 加 blockDelay，再减 a 乘实际位移、b 乘实际位移，加源 Z 的 h 减目标 Z 的 h
   是否非负，同时检查名义 reduced cost。数值全部 int64，Line 费用单独处理以防双计。
3. 用 estimator.estimate 与 witness 上界比较。每个 hop 的 Z 到 I 上界是 gapDelay，落点每条
   出弧的上界是 gapDelay 加 arcDelay，另在一个有效 SRB 遍历全部 Arc 检查同格源到目标的
   estimate 不超过 arcDelay。代表 witness 用 Router 的 plain Dijkstra
   (useSpanHeuristic=false, landmarkCount=0, cache=0) 取 exact 复核。
4. CSV 每行 10 列，geometry 与 path 内部用分号与竖线，不含逗号。L 只取已证明的必过 Line
   费用。certified 仅表示 witness 重放成功且 exact 落在 L 与 U 之间，value 不在该证书范围内，
   因此 value 大于 exact 的行仍可以是 certified，见下文 12 行实例。JSON 分开记录
   potential_feasible、residue_admissibility 与输出语义问题，并写入 certificate 字段说明该语义。
5. 退出码约定，审计发现 residue 高估或合法路径上出现负值返回 1，工具或不变式失败返回 2。

self-check 用同一个 replay 函数验证，正确 hop 与 hop 加 Arc 被接受，错误落点与错误费用被拒绝，
有界范围内的归并 multiplicity 总和等于该范围真实有效 hop 数。

residue_admissibility 判定为 disproved，证据是具体合法路径上的高估，不是势函数负值。

势函数本身在真实位移与 Block 费用下仍满足非负 reduced cost，因此
potential_feasible 与 residue_admissibility 是两条独立结论。

可重放反例由主代理用未改动根目录 ./estimate 独立核验，输入经 /dev/stdin 传入两条 pin，
默认 cache=0 与 exact 模式 -exact -no-heuristic -landmarks 0 均 exit 0，具体数值如下。

| 请求 | witness gap | U | value | exact |
|---|---|---|---|---|
| SRB_75_0/ZSEA[0] 到 SRB_90_0/ISEA[0] | 292 | 292 | 327 | 292 |

两条都是单次 Net hop，名义 span 为 1，实际位移为 15，跨过一条水平可穿越 Block。
CSV 中这 12 条 value 大于 U 的行就是 value 大于 exact 的同一组，都带完整 from 与 to pin、
witness 路径与每步费用，可直接重放。这 12 行的 certified 为 true，与 certificate 语义一致，
因为它只覆盖 witness 重放与 L 到 U 的夹逼，不覆盖 value。

说明，早期一次运行在本工具内把 hop witness 的 U 默认成 0，产生 649 条假反例，
该次输出作废；修正 U 为 gapDelay 并重测后得到上表。最后一轮只删除了多余的
(void)blockDelay 语句并加入 certificate 说明，审计数字与上一轮一致。

## 原因

根因是 residue 的状态转移仍使用 nominal displacement。它假设每个 hop 的位移恒等于 Net 的
发布 span，真实图上可穿越 Block 会跳格，实际位移变成 span 加 Block 宽度，同时只额外支付一次
Block 穿越费用。这类跳格边上的附加值可能超过该合法一跳的成本，于是出现 value 大于 U 的具体
路径。势函数的非负性只说明该线性下界在真实边上仍可行，不能阻止查询公式本身高估。
四舍五入不是本轮已证明的根因。

## 限制

1. reduced cost 检查不含 Line 费用；Line 费用非负且另行处理，因此该检查偏保守。
2. witness 行都是单跳或同格 Arc，exact 复核只覆盖局部路径，未做全图逐对 exact。
3. 未发现反例不等于全局证明；本轮只给出 96 条高估与 12 条 value 大于 exact 的实测。
4. residue_admissibility=disproved 只针对当前函数与当前表；更换公式或表后需重新审计。
5. 只审计线性势函数与当前表读取，未审计缓存路径、多线程与官方十亿行规模。
6. 生产执行逻辑与默认参数未改，但注释同步后 estimate 经 scripts/build.sh 重新编译过，
   旧二进制哈希未记录，因此本轮不主张制品字节一致；百万行本轮未复测。
