# 技术债、隐式假设与未决自由度

本章只列能从源码、历史记录或真实数据追溯的项目问题。固定架构的专门化本身符合赛题，是否构成技术债取决于它是否使当前要求难以验证、复现或改进。

## 1. 当前方案为了预算做出的交换

| 工程选择 | 已取得结果 | 付出的代价/受限范围 |
| --- | --- | --- |
| A2048/B256、552格完整曲面加逐键偏置 | 当前六数组162,755,584 B，5资产79,398,908 B，可嵌入86,937,624 B ELF | 曲面近似有误差；CURRENT117开发1M exact-nominal干预可增加0.5125855510522541 pp，部署成本未证实 |
| ordinary raw=0 | EAT117同轮1B减少14.300811333 s，综合增加0.0949728435282 | Acc下降0.03025073031283 pp，ordinary域的精度恢复留给曲面或新的条件修正 |
| 仅33,280个direct键 | EAT176同轮减少1.378465833 s，Acc增加0.000526221367541 pp | 键空间覆盖0.115740740741%；请求命中份额不能由此推导；事件/cycle仍需旧word |

首Net费用、Line prefix、同点语义、不可达返回及非空cycle覆盖有真实图语义，需与上表中的拟合/表示选择分别理解。把所有条件分支统称为“启发式补丁”会使外部审查失去区分正确性约束与精度策略的依据。

## 2. 有证据支持的技术债

**正式构建入口分离。** 根`estimate`与EAT243包一致，根源码和普通`sh scripts/build.sh`未选择该33文件快照。直接按仓库开头的构建说明生成程序，无法据此继承EAT243的成绩。精确来源和构建参数已经在不可变包中保存，外部复现应使用包内`REPRODUCE.md`。

**文档累积的“当前”声明相互跨期。** `RESULTS.md`与`DESIGN.md`开头为EAT243，后面仍保留旧日期的“当前版本”。外部读者必须绑定日期、版本标签与SHA。EAT097实验日志的一处SHA实际对应发布记录而非ELF；本包按正式版本和RESULTS区分这两类身份，详见证据覆盖章。

**源码历史编号继续充当模块名。** 当前实现含`579`、`640`、`679`、`707`、`779`、`806`、`212`等标识。这能追溯历史实验，但模块名不足以判断当前生效路径。ordinary rawzero后，文件仍可能保留历史模型/诊断接口；是否进入最终ELF须看编译宏与链接结果，不能按头文件文本大小直接计运行成本。

**精度验证集已长期暴露。** 当前重复使用1B请求和3,833,856 exact位置。它支持配对回归与同输入等价检查，新算法在这些样本上被选择后，其成绩属于开发证据。现有报告已经标明此状态，但独立未知请求验收仍缺失。

**代价画像没有随正式版本完全更新。** exp849记录exp825的prepare约38.8164%、CSV约26.1534%、finish约13.204%；调用树区间存在重叠，不能直接相加，也不能把这些占比乘EAT243的125.208939 s当当前耗时。EAT243已经改变ordinary路径、批大小和资产恢复，仍需同身份profile才能给热点秒数。

**运行环境的速度影响未被充分分解。** EAT no-trace同身份两次1B CPU为128.627797/148.440587 s，相差19.812790 s。EAT243使用3个平衡区组缩小本轮不确定性，但其统计结论仍条件于当前主机状态。1M/100M外推102.474529091 s相对实测125.208939 s低估22.185425111%，说明固定初始化加线性请求模型存在尺度偏差。

**发布工程门与官方验收仍分离。** EAT243实际ELF完整1M契约、空环境和清洁cwd已通过，文件系统namespace未隔离；官方连续五次标记为false。这里存在明确的未完成验收项，不能把本地14次一致输出写成官方证书。

## 3. 隐式假设及反证条件

| 默认前提 | 当前支持证据 | 尚缺什么/如何证伪 |
| --- | --- | --- |
| 当前架构身份固定，源码中的宽高/端口映射可专门化 | QA固定架构；初始化检查portCount、映射和ranges | 若正式数据架构身份变化，则原模型与索引证据失效；需新资产和全域检查 |
| 隐藏请求的人口结构接近开发分布 | 当前1B完整覆盖59,904角色对；按人口权重评分 | 角色覆盖不保证坐标/距离分布一致；历史exp580平台与本地相差−0.173741289 pp |
| 名义目标的压缩误差改善能传递到真实Acc | exp780、811、825分别有正精度增量 | exp577给出代理L1改善而Acc下降的反例；每次改变表示都需同输出链真实评分 |
| 当前残差能继续补偿新名义表示 | 原名义值和残差共同达到当前成绩 | EAT162两项oracle存在0.040274435858 pp非加性；替换表示后残差可能需要重新训练 |
| 同码共享足以表示绝大多数曲面差异 | A/B压缩满足当前部署预算 | 没有固定表示类的完整条件标签统计；不能声称容量充分或接近理论上限 |
| 压缩目录仍能为新增信息保留相近压缩率 | 现有directory比1.891334，direct比15.948958 | exp379位打包反而令压缩正文增加14,333,249 B；新数据必须测完整流 |
| 较少随机读取就能加速 | direct局部展开同轮减少1.378465833 s | exp816完整和表六对全部变慢；减少读取次数与增加工作集的净效应需要测量 |
| 64批和大页提示在目标机有同样收益 | 当前r9配对通过 | 官方CPU/内核/THP状态未知；数值等价与速度复现分别验证 |
| 同一输出SHA足以复用评分 | 固定输入、标签、评分器与完整输出身份一致 | SHA只能绑定字节，不能证明标签exact正确或新分布泛化；标签来源须继续绑定 |
| 当前3区组t界具有登记的覆盖解释 | 固定ABBA/BAAB/ABBA、df=2、统计公式明确 | 区组独立性与机器状态只在本轮条件下使用；不能外推无限未来运行 |
| 1M/100M仿射外推可用于准入 | 有同ELF同机完整测量、初始化项分离 | 当前1B已有22.1854%偏差；用于筛选，达标声明须完整1B |
| x8/x256、整数趋势与float修正尺度一致 | 当前原生路径与输出身份已验 | EAT031曾出现1/32缩放错误；新导出必须检查单位、舍入、溢出与最终整数 |

这些假设的状态不同。固定架构与整数范围已有局部或全域检查；隐藏分布、条件误差迁移和跨机器速度主要仍靠经验。表中每项均给出可观察的失效条件，避免把默认前提当数学定理。

## 4. 仍有自由度的方向与其历史状态

| 自由度 | 已有依据 | 当前准确状态 |
| --- | --- | --- |
| 选择性精确距离场与合法路径上界 | exp115的20场容量投影92,552,458 B；exp150终端精确消元；exp175完整组合成本已测 | 部分组件可行，任意源覆盖、净CPU和全角色精度尚未解决；不能写成“仅因时间未做”的已成熟方案 |
| 静态格式与运行表示分离 | exp380启动转5位解决ELF；EAT243保留原预测并减少5,910,528 B ELF | 通用工程自由度已验证；每个具体运行布局仍受解码和访存成本限制 |
| 选择性direct/局部展开 | EAT176已部署33,280曲线；exp816反对全部共现对展开 | 小覆盖已可部署；覆盖增长的压缩率、命中权重与缓存代价未取得全域模型 |

| 混合8/16位高秩表示 | exp579日志明确记录先完成完整程序、该设想尚未实施 | 有明确“暂置”记录；没有现成容量、精度和CPU证明 |
| PySR符号模型与路径特征 | 工作区已建立离线特征、搜索、C++导出流程 | 工具链与任务存在；未找到足以证明其替代EAT243并同时通过最终目标的正式包 |
| 分离真实路径信息与名义损失 | EAT552/162 oracle分解提供额外信息价值 | oracle需教师/真实路径，在线可获取性与预算未成立 |
| 更改信息/动作选择器 | EAT162仅排除固定direction×forced非负0至15ps类；EAT286记录新信息设计缺少冻结arm、fold/menu来源等 | 尚未形成可启动的完整预登记方案；不等同于已证明可行 |

其中“确有技术基础，但因实现优先级暂置”的明确实例是exp579的混合位宽高秩设想。其余很多方向被搁置的原因已经包含质量、容量或CPU失败，应保留这些量化阻断，不能全部改写为“来不及实现”。

## 5. 外部诊断应优先核对的具体问题

1. **信息缺口在哪个可观察状态上。** 对当前ordinary误差，使用同一个冻结完整1M、最终整数评分和真实端点语义，区分名义表示误差、首Net/Line分解以及残差补偿。当前oracle增益不能直接分配给某一新模型。
2. **新增静态字节换回多少实际评分。** 对候选给出`压缩正文+索引+恢复器+对齐`与运行数组，并报告全域压缩结果。当前可增加ELF的严格整数上限为13,062,375 B。
3. **每请求最多增加多少CPU。** 例如期望+0.15 pp对应零综合收益CPU边界14.4 s/1B；当前还需减少25.208939 s才能达到100 s，综合得分改善与最终速度目标应同时报告。
4. **同样信息是否可用更小工作集表达。** exp816的1,226,728,368 B和表已明确变慢；任何重试需解释索引、热数据量或初始化怎样改变，并给完整程序测量。
5. **新输入何时保持未暴露。** 模型、动作集合和阈值冻结后，先固定输入/标签/统计协议再看结果。全角色覆盖、无重复和未参与选择是三个独立条件。

外部专家可从上述问题提出候选；本次审计没有为任何新方向生成算法实验、标签或性能成绩。
