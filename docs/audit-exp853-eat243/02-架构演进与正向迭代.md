# 架构演进与正向迭代

历史起点为 Git 提交 `a5fb8dfd1a04b84a5d0e9da44ec0dc52c390a563`，日期 2026-09-17。当前工作仓 HEAD 为 `a692e161d01beff64d5b8e1b19b41b3a74ae46c7`。主线包含 1,662 个提交，全部可见 refs 合计 1,673 个去重提交。逐提交时间和主题见 [Git 历史](index/git-history-all.tsv)，逐篇日志见 [实验索引](index/experiments.csv)。

本章对改变预测骨架、数据域、正式部署路径或主要资源成本的迭代逐项复盘。精度差统一用 pp。表中“历史单次”表示同分布不同批次的点值比较；“同轮配对”才支持对应轮次的差值解释。当前目标为全角色非重复 1B、Acc>99%、CPU 约 100 s；历史日志中的 98%、99.1%、300 s 和重复缓存目标保留在各自日期。

## 1. 2026-09-17 至 09-24，可信求解器、residue 近似与缓存

最早的问题是建立可核对的标签和预测基线。独立显式图 Dijkstra 用于检查生产 exact 路径，在线估算则利用 residue 表、几何特征和残差。随后工作同时沿精度模型与 CSV/缓存成本推进。
