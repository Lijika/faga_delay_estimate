## 二、赛题背景和完整约束

### 2.1 求解对象

官方提供固定的五份 JSON，描述 120×550 的 SRB 阵列、全部端口、内部 Arc、外部 Net 和特殊几何。实际存在 60,200 个 SRB；每个位置使用 496 个完整端口定义，模板中有 8,192 条有向 Arc 和 160 条 Net。图状态可以写成 `(x,y,port)`，完整端口名和 lane 会改变连接。

Arc 在同一 SRB 内连接端口并产生延时。Net 连接不同 SRB，其真实落点、有效性和费用由几何规则决定。Block 可以禁止某方向穿越，或改变真实落点并收取费用；Line 在跨越对应坐标边界时增加延时。当前 JSON 包含七个 Block 和十九条 Line。中央特殊区域横跨 x=76…89，按 y 带分布；左下角还存在缺失单元区。

请求给出两个完整 pin，例如 `SRB_20_100/IDE[0]`。目标是完整真实有向图上的最小路径费用，单位 ps。任何使用无障碍、无限周期、忽略端口或忽略回绕的近似，都需要说明与真实图的关系。

`D0` 表示在相同真实可行图上把 Line 费用置零后得到的最短距离。首段费用和必过 Line 可以从几何求出，但 `D0 + mandatory_Line` 一般只能提供相应条件下的下界。完整路径上实际跨过的全部 Line 才能计入合法路径上界。我们希望你尤其核查支持条件、最终落点、完整端口和重复跨线的处理。

### 2.3 输入域仍有一个实质开放问题

当前生成器和生产模型使用 208×288 角色端口域，共 59,904 个 pair。源角色为 160 个 Z 端口与 48 个 LOGIC 端口，目标角色为 160 个 Z 端口与 128 个 LOGIC 端口。公开 golden 全部落在此域，已测 1B 覆盖全部角色 pair。

官方文本尚未明确把所有合法请求限定为该域。存在域外可达例子 `SRB_20_100/IDE[0] -> SRB_20_100/A_A3`，已由 exact 复算。当前生产入口会先检查角色，再进入 `prepare596`，域外请求可能得到默认的 -1。`prepare596` 内部的同 pin 分支也受外层角色检查影响。

请同时讨论已测角色域的优化，以及完整合法域的正确性。需要赛事方澄清的内容可以单列。扩展域支持时，请给出有界计算方案、容量和查询成本，并核对同 pin 空路径、有效位置与不可达输出的语义。

### 2.4 指标应如何计算

对 `g_i>0`，当前评分代码使用官方形式

```text
point_i = 100 × [1 - tanh(4 × |p_i - g_i| / g_i)]
Acc = population-weighted mean(point_i)
score = 0.8 × Acc + 0.15 × time_score + 0.05 × consistency_score
```

项目在 `g_i=0` 时约定 `p_i=0` 得 100，其余得 0；官方对零值处理仍需明确。当前 1B 扩大 exact 样本中没有零真值。MAE、完全命中率和 Acc 分别报告。对相同一致性且时间分尚未归零的候选，项目使用

```text
Δ综合分 = 0.8 × ΔAcc - ΔCPU / 120
新增 CPU 预算 = 96 × ΔAcc
```

`ΔAcc` 的单位是百分点，`ΔCPU` 为一次完整 1B CPU 秒数。例如 +0.05 个百分点仅容许约 4.8 秒新增 CPU，才能在该公式下抵消时间损失。总体评分之外，本轮还有 Acc >99%、CPU 约 100 秒的双目标，请给出 CPU 与 Acc 的取舍。

## 三、exp728 当前架构和真实差距

### 3.1 在线流程

当前结构可以记为 `D64-curves-T2D6-V8-compiled-M-fused-csv-coordinate-masks-SSE2`。

1. 启动时恢复压缩几何资产，加载嵌入架构，编译首 Net、Line、Block 和端口准备元数据。查询阶段没有动态内存分配。
2. 融合 CSV 行扫描与端点解析，使用 688 槽端口直接目录，按八条请求组成一批，保持原行序。
3. `prepare596` 取得真实首落点、首段费用、必过 Line、完整端口 pair、方向、余类、距离格和事件类型；预取后续几何数据。
4. 普通路径使用 16 个 route 的 T2D6，每次选择一个 route，执行两棵 depth6 对称树。当前把 155 个一元坐标判定编译为 76,526 B 表，其余条件保留直接计算。
5. V 事件采用独立 V8 专家。H 事件在生产中沿普通模型处理。V64 原模型只部署前八棵。
6. 几何背景在近域 `qx+qy<=3` 使用 N512，在远域使用四方向 D64；远域加完整 pair、方向和余类索引的字节距离曲线修正。
7. 按冻结顺序进行背景反归一化、舍入、cycle 覆盖、首段与曲线修正、残差合成、非负截断、再次整数化和 Line 加回。
8. 保留输入原行，追加整数预测，输出完整 CSV。

`EXP640_TREES=8` 是继承的编译宏，当前普通路径实际由 `symmetric640.h` 和 `reference727.h` 实现 T2D6。请按生产宏和调用路径判断执行内容。源文件保留了历史审计分支，编译器也会删除无 trace 时未使用的特征表达式。

当前实现细节见 `source/src/worker.cpp`、`exp707_prepare_metadata.h`、`exp723_fused_parse.h`、`exp608_geometry.h`、`exp652_distance_curve_lookup.h`、`symmetric640.h`、`replacement679.h`。等价优化需保留尺度转 double 的时点、两次乘法、累加顺序与整数化顺序；改变这些顺序的方案按算法候选重新比较。

### 3.2 训练与表示

名义场保存无障碍周期结构的信息，按完整角色端口对、方向、余类和距离格建立矩阵。近域 N512、远域四方向 D64 都来自名义场拟合和量化。距离曲线继续拟合 D64 的名义误差。

当前普通 T2D6 已匹配 `base_curve` 训练，目标为 `d0-base_curve`，权重为 `1000/max(d0+mandatory,128)`。16 个 route 分别训练；普通模型训练包含本 route 的全部事件，线上 V 行由专家替换。V8 也使用曲线背景。旧 exp688 的 S8 曾匹配 Q4 背景，该历史问题已发生变化。

T2D6 使用 MAE、两棵 depth6 对称树、学习率 0.7599、Exact leaf estimation、No bootstrap、固定 seed。原始 53 特征及 16-route 分法保持，三个 outer-fold 按完整 source pin 隔离。训练线程属于离线资源。参数、标签和导出见 `training/`。

曲线 codebook 的构建来源有留出源端口；每个端口的 code assignment 仍使用自身训练距离格。请分别讨论 codebook、目录分配、残差模型的数据暴露。反复研究的百万缓存和既有 1B 均属开发证据。
