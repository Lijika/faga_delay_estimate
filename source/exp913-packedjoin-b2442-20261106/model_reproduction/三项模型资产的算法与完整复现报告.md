# FPGA 延迟估算：`frames.bin`、`books.f32`、`arch.bin` 的算法原理与可复现生成报告

> 审计对象：`FPGA-estimate-self-contained-source.zip` 中 `model/` 的三个字节级冻结资产。  
> 报告依据：原生查询 C++、`knots/fit.py`、`knots/encode_rates.py`、`knots/native/build.py`、`knots/native/arch.py`、历史架构求解器及真实二进制内容。  
> 验证状态：**冻结中间量→三个二进制文件，全部逐字节复现；从原始架构重新训练全部量化码本并重算所有源的端到端训练，已有脚本与求解器自检，但本轮未执行完成。** 这两个结论必须严格区分。

## 0. 最重要的结论

三份文件不是三个独立的机器学习模型：

1. **`arch.bin`**：五份固定赛题架构 JSON 的**无损压缩**，不需要训练。其内容决定端口、Arc/Net、设备存在性和几何障碍。原始 JSON 字节不同会改变压缩结果和图。
2. **`books.f32`**：四个方向 × 三类近场变化强度 × 十级的 **16 维残差加法量化（residual/additive vector quantization）质心**，每级有 256 个质心，float32 存储。需要在离线真实名义距离场上训练；部署端只做查表。
3. **`frames.bin`**：208 个源角色 × 四个方向的 **832 个独立 Zstd 帧**。每帧保存 288 个目标角色 × 120 个余相位的可变长度量化**层数和码字索引**。Zstd 对已量化码流的压缩是无损的，**从图距离到量化码流本身是有损建模**；绝不可称 `frames.bin` 无损保存了所有 exact 延时。

本次可重复验证：

|---|---:|---|---|

| `books.f32` | 1,966,080 | `7906e3e5b49d70cf796dec18acbc4c2e9fa319f4c96f90f3627a6e6afba9bb1f` | 从历史冻结 `books.npz` 精确按 d→c→n 叠放、转换 little-endian float32，**完全一致** |

## 2. 架构、角色与一条训练样本究竟是什么

固定图来自五个 JSON：`SRB_Port`、`SRB_Arc`、`SRB_Net`、`SRB_Inst`、`SRB_Gap`。核心统计表按：

- 源角色 `s∈[0,207]`，共 208；目标角色 `t∈[0,287]`，共 288。
- 方向 `d∈{0,1,2,3}`，控制 x、y 轴正负号。
- 余相位 `rx∈[0,9]`、`ry∈[0,11]`，`r=12·rx+ry∈[0,119]`。
- 查询格点 `qx∈[0,11]`、`qy∈[0,45]`，`j=46·qx+qy∈[0,551]`。
- `context=120·d+r`；`key=(208/288 编号中的 s·288+t)·480+context`。
- 普通位移 `dx=sgn_x(d)(10 qx+rx)`，`dy=sgn_y(d)(12 qy+ry)`；需要和 `export.cpp` 的方向定义完全一致。

真实名义距离 `D(s,t,dx,dy)` 由合法 Arc、Net 以及边界认证的有向最短路求解器产生。为了让宏观格点只拟合局部变化，训练文件保存

\[
R(s,t,d,r,j)=D(s,t,dx,dy)-125q_x-(d\bmod 2=1?125:127)q_y.
\]

只要改变数值常量、符号或源/目标角色排序，训练出来的表就不再适配原推理实现。

名义整源 `field` 文件：8 B ASCII `EX499D01`，接着 6 个小端 int32（源 port ID、288、4、120、12、46），再写 288 个目标 port ID 的小端 int32。固定头为 `8+24+288×4=1,184 B`。数据是按 `(d,r,t,j)` 排列的 int16，大小 `4×120×288×552×2=152,616,960 B`，整个源文件 **152,618,144 B**。`knots/fit.py` 的 memmap 正是从 offset 1184 读取 `(4,34560,552)`。四份训练源文件共需 **610,472,576 B** 磁盘。

**目标次序不能直接沿用旧 solver 的枚举顺序。** 历史 `sourceids` 是按当前 `kSourceIndex` 映射到原架构端口的列表；`targets.oldidx` 将当前 `kTargetIndex` 转换到求解器旧目标顺序。复现辅助代码在 `sources/repro/inputs/`，应严格按其索引，不可重新排序。

## 3. 第一步：从真实图拟合 40 近点 + 16 远点的观测与插值

源码：`sources/knots/fit.py`。固定随机数种子 `np.random.default_rng(960041)`。使用四份代表性 source 的完整名义场，每方向每份**无放回抽取 12,000 个** `(target,residue)` 曲面样本，总 48,000 个 552 维样本。

### 3.1 观测点选择

- 近点候选固定为 `qx=0..4, qy=0..7` 的 **5×8 = 40** 点；它们由 `near40` 图求解器在启动时精确生成。
- 可变远点候选从 `X={0,1,2,3,4,6,8,11}` 与 `Y={0,1,2,3,5,8,12,19,30,45}` 的积集中取。
- 基准观测 `j0=2×46+3=95`，在样本矩阵内逐样本减去 `R[j0]`，再减训练均值 `μ`；计算经验协方差 `C=XᵀX/N`。
- `--force-near` 强制先包含 40 个近点；其余通过条件协方差贪心选取，使加权的未解释协方差尽量下降。令 `K` 是已选集合、`C_cond` 是条件协方差，则选近似最大化

\[
\operatorname{gain}(a)=\frac{\sum_j w_j\,[C_{\rm cond}(j,a)]^2}{\max(C_{\rm cond}(a,a),10^{-8})},
\quad
w_j=\frac{(120-10q_x-4)(550-12q_y-5)}{120+125q_x+126q_y}.
\]

### 3.2 从观测点线性恢复某个格点

对每个方向和每个 `j∈[0,551]`，回归选择最多八个观测点；保存 9 个索引与 9 个系数+1 个截距：

\[
\widehat{R}_j=b_{j,9}+\sum_{i=0}^{8}b_{j,i}Z_{I_{j,i}}.
\]

权重使用 `C[U,U]+0.025I` 的岭回归求解。索引 0 通常为基准项、其余是按残差协方差贪心挑选的八个项。观测点自身使用恒等映射。输出存为每方向两套：`d{d}-k40-n8.npz` 与 `d{d}-k56-n8.npz`。前者用于用近点预测 16 个远点，后者用于完整 552 格预测。

从冻结 8 个 NPZ 生成的六份推理常量表，本轮**逐文本字节比对全部通过**：`nearOrder.inc`、`nearIdx.inc`、`nearWeights.inc`、`outputIdx.inc`、`outputWeights.inc`、`aqScale.inc`。这证明当前发布模型使用的插值系数与本包保留的历史中间量完全对应，**不证明重做 fit 得到同样浮点**。

## 4. 第二步：残差缩放与分级矢量量化，得到 `books.f32`

源码：`sources/knots/encode_rates.py`。方向 `d` 上使用上述 56 个观测点，其中前 40 个是近点 `u∈ℝ^40`，其余是远点 `v∈ℝ^16`。由 40 点模型得到远点初值

\[
\widehat v_i=\sum_{h=0}^{8}P_{i,h}u_{I_{i,h}}+a_i.
\]

按不同远点对最终输出的影响计算固定 `scale[d,i]`：对应 `knots/native/build.py` 的 `aqScale` 公式，它从 552 格回归权重的加权平方贡献归一化求根。定义创新残差

\[
e_0=S_d\odot(v-\widehat v),\quad S_d=\operatorname{diag}(\mathrm{scale}_{d,0..15}).
\]

40 个近点的幅度范围 `h=max(u)-min(u)` 划为 **三档**，必须采用严格边界：`h≤32` 为 0，`32<h≤80` 为 1，`h>80` 为 2。与 C++ `int(h>32)+int(h>80)` 完全一致；把 32 或 80 放进更高档曾在历史实验中造成可测精度损失。

使用四份整源场，每方向每份再无放回抽取 **30,000** 行（固定 RNG 种子 `842769`），每方向约 120,000 个观测用于训练。每个 `(d,class)` 独立训练 10 级残差码本，每级 256 个 16 维 float32 质心。第 `n` 级的具体生成代码为：

```python
km = MiniBatchKMeans(n_clusters=256, batch_size=2048,
                     n_init=1, max_iter=55, random_state=849+n)
km.fit(current_residual)
centers = km.cluster_centers_.copy()
idx = cKDTree(centers).query(current_residual)[1]
current_residual -= centers[idx]
```

**注意**原代码并非训练一个共享的十级码本；它是 `4 directions × 3 classes × 10 stages` 组中心，各自 256×16。也不是在推理阶段调用 sklearn：全部中心离线训练，推理端只按字节索引取浮点中心。

压成二进制时的精确堆叠顺序：`d=0..3 → class=0..2 → stage=0..9 → centroid_id=0..255 → component=0..15`；每项 little-endian IEEE754 float32。因此：

`4×3×10×256×16×4 = 1,966,080 B`。

恢复 16 个远点时，对每个 i、所有实际启用层求创新之和，再反缩放：

\[
\widetilde v_i=\widehat v_i +\frac{\sum_{n=0}^{\ell-1}B_{d,c,n,id_n,i}}{S_{d,i}}.
\]

数值舍入应遵守原 C++ 逐项 float32 求和顺序；改变为 FMA 或重排求和可能造成半整数输出差异。

## 5. 第三步：按每个键的实际收益分配码长，生成 `frames.bin`

### 5.1 码长决策：不是所有键统一用四层

为所有 208 个源、288 个目标、4 个方向和 120 个余相位，生成 56 个真实锚点的名义值。共 **28,753,920 个编码键**、`28,753,920×56=1,610,219,520` 个名义观测整数。`knots/export.cpp` 每次只输出一个源的 `(4,120,56,288)` int16 临时文件，即 **15,482,880 B/源**，计算完成立刻删除；208 源的累计写入量为 **3,220,439,040 B**，不需要同时常驻。

各键可用码长层数集合为

\[
\mathcal L=\{0,1,2,3,4,5,6,8,10\}.
\]

将当前残差经过 `l` 级减去最近质心，得到 16 维余量 `e_l`。脚本实际使用的 `risk_l` 是 `mean(abs(e_l) * scale)`；**注意** `e_0` 已经由 `scale` 放大过，风险计算又乘一次 `scale`，这是冻结实现的实际代理误差，不应自行改成 `mean(abs(e_l)/scale)`。

公开百万训练源先根据 `CRC32(From) mod 10 < 7` 做训练角色频率统计：

\[
f_{s,t}=\frac{\#\{\text{训练请求命中}(s,t)\}}{\operatorname{mean}_{s,t}\#\{\text{训练命中}\}}.
\]

然后逐键选择：

\[
\ell^*=\arg\min_{\ell\in\mathcal L}
\left[(1+2.0 f_{s,t})^{0.70}\,\operatorname{risk}_{\ell}
+0.5683326721191406\,\ell\right].
\]

代码用 `numpy.argmin`，发生严格相等时选择列表中最前面的（较短）级数。**输入公开集仅用于估计角色对频率，不应从隐藏标签中调参。** 公共源序列顺序、`kSourceIndex` 对应以及 `pub.raw` 必须相互对齐，否则最终码率分配不是同一个模型。

### 5.2 帧内部位级格式

每个源 `s` 与方向 `d` 有一个 `.zst` 文件 `c{s}-{d}.zst`；每帧固定处理 `288×120=34,560` 个键，索引 `i=t×120+r`。`levels` 的九个选择**不是直接写层数**，而是写 0..8 的索引，每个仅 4 bit：

```
首部 = 17,280 bytes
  byte i = level_index[2*i] | (level_index[2*i+1] << 4)
  共 34,560 个 4-bit 索引，无跨帧目录

负载 = stage-major bytes
  stage k = 0..9:
    顺序扫描 i = 0..34,559
    对 level_value[i] > k 的键写出 1 byte 的质心 id[k]
```

无边界标记也能解码，因为首部层数已告诉每级有多少个有效键。对某一帧：

\[
L_{raw}=17,280+\sum_{i=0}^{34559}\ell_i.
\]

`ZstdCompressor(level=8)` 无帧 checksum，对每个原始码流独立压缩为一帧；按 `s=0..207, d=0..3` 连续拼接 832 个压缩帧成 `frames.bin`。**长度表 `frameBytes[832]` 不在 `frames.bin` 里**，而是在 C++ 的 `frameBytes.inc`。独立训练后必须同时更新该表！

## 7. 立即可跑：使用冻结中间产物精确重组三资产

本复现包无需 GitHub、不依赖已发布 `estimate` ELF，可从原始 JSON + 冻结 `books.npz` + 已编码的 832 个帧重组。

需要 Python3、NumPy、系统 `zstd` 命令和 `libzstd.so.1`。先准备上次的自包含构建包（里面有 `model/frames.bin`），以下令 `$KIT` 为它解压后的根目录，`$HERE` 为本复现包根目录：

```bash
# 1. 从冻结压缩帧恢复独立 .zst，检查每个解码层数并重新执行 Zstd-8 字节回归
python3 "$HERE/tools/split_frames.py" \
  --frames "$KIT/model/frames.bin" \
  --lengths "$HERE/frozen/frameBytes.inc" \
  --out "$HERE/work/wire" --reencode

# 2. 用上述 832 个帧、冻结训练中心与原始官方 JSON 重新拼出三份资产
python3 "$HERE/tools/pack_assets.py" \
  --wire-dir "$HERE/work/wire" \
  --books "$HERE/frozen/books.npz" \
  --arch "$HERE/raw_arch" \
  --out "$HERE/work/model" --compare-frozen

# 3. 验证发布的六张查表/回归常量，也都是从 8 个冻结观测 NPZ 导出的
python3 "$HERE/tools/check_frozen_tables.py"
```

预期第二步显示：三份 SHA 均与第 0 节相同，`historical_exact:true`。这条操作**不进行模型训练**，是“从完整冻结中间结果重组发布模型”的字节级回归，是排查传输损坏和验证编码器的正确工具。

要独立生成**新的** 832 个帧，可把第 8 节得到的 `wire/c{s}-{d}.zst` 直接作为 `pack_assets.py --wire-dir` 的输入，完全不需要旧 ELF 或旧 `frames.bin`。

## 8. 从原始赛题图重新训练：可执行完整链

本包提供 `tools/full_train.sh`，只是将原研究包的可追溯训练脚本组合起来，**整链尚未在本轮跑完，不能声称训练 SHA 已复现**。训练依赖 `numpy/pandas/scipy/scikit-learn/zstandard`，C++17、g++、Zstd 命令。预留多 GB 磁盘、足够内存和较长离线 CPU；部署单线程限制不应错误施加到离线训练的多个进程。

脚本内依次执行（每一步失败即停止）：

- 校验五个原始架构 JSON 与本包字节相同；先构建匹配 EAT 版本，供 `trace.py` 记录查询对应的角色 key。

- 用 `fit.py --force-near` 拟合 40/56 观测点和插值矩阵。
- 用 `export.cpp` 编译离线远点计算器；由冻结 EAT 源内置模型探针生成 `pub.raw`，其输入公开请求顺序必须和 `gold.csv` 一致。
- 用 `encode_rates.py --count 208 --maxrate 10 --adaptive-price 0.5683326721191406 --adaptive-lambda 2.0 --save adaptive` 完整生成所有 832 帧和 `books.npz`。
- 用 `pack_assets.py` 拼出三资产，并独立调用 `split_frames.py` 检验帧结构；记录新的 SHA、六张推理参数表、码长直方图、名义误差与真实 Acc。

### 8.1 本轮真实执行到哪里

在本机已经从报告内独立恢复五个原始架构 JSON，编译上述名义求解器并运行自检成功。随后尝试生成一份完整 152,618,144 B 的整源场，**120 秒计算窗口结束时文件生成约 95 MiB，作业未完成**；留下的部分文件不能用于训练。因而本报告**没有**“重新训练并验证全部 832 帧生成了原 SHA”的证据。建议在有足够 CPU 和时间的服务器上运行整个 `full_train.sh`，逐阶段保存收据。

### 8.2 如何判断是否重新训练成功

首先检查 `frames` 数量 832、语法无错、`books` 维数、`arch` 解压与尺寸，再检查每一步源身份和代码表。然后对新构建的估计器完整评测 6 组；不能仅凭 `books.f32` 差不多/码率均值接近就认为复现。建议记录：

- 五份 JSON 和 4 个整源场 SHA；8 个观测 NPZ SHA；`books.npz` 每个数组 SHA；`pub.raw` 的键分布 SHA；832 个 `.zst` 的 frame length 序列和聚合 SHA。
- Python、NumPy、SciPy、scikit-learn、Zstd、BLAS 环境，随机种子，线程数，`OPENBLAS_NUM_THREADS`；还要固定求解器代码 SHA、源/目标顺序。
- 如果 `frames.bin` 不同，定位是 **量化中心不同**、**训练源不同**、**公开请求角色频率不同**、**逐键码长不同**、**单个码字不同**还是单纯 Zstd 编码差异。
- 如修改训练观测，除三份文件，还需要重新导出六个 `*.inc` 和 `frameBytes.inc`；如果修改五个 JSON，还需要同步 `shared/arch.cpp` 的 raw/wire 常量，重新验证 near40 的生成依赖。

## 9. 从二进制本身可验证、不可验证的事情

**可以验证**：Zstd 帧内容、拼接顺序、压缩设置以及全部 832 帧是否存在；逐键码长索引 0..8 的合法性；每级码字数与所有帧总字节；码本维数、IEEE754 排列；五个 JSON 原始 SHA；全部六张插值参数表与冻结 NPZ 一致。

**不能仅凭冻结模型验证**：最初从哪几个训练源采样、scikit-learn 具体安装版本、每一个 MiniBatchKMeans 的完整训练轨迹、所有原始图 shortest path 是否曾在相同代码/版本下重新生成。不能把已有 `books.npz` 的导出称为从零训练，也不能把提取 `.zst` 称为从图重新求得编码编号。这是本次审计明确留下的证据缺口。

## 10. 容易出现的失败和修复

| 症状 | 根因及检查 |
|---|---|
| `frames.bin` 的 SHA 不同，但所有码字相同 | 检查每帧是否单独压缩、Zstd `--no-check`，是否以文件输入保存 content size；Zstd 版本是否变了 |
| `books.f32` 仅少数浮点不同 | 检查 `d,c,n,k,i` 展开顺序、小端 `f4`、KMeans 版本、种子、近邻平局和 BLAS |
| `arch.bin` 多出 20 B | 很可能错误地对 5 个 JSON 启用/关闭 checksum（五帧各 4 B 差）；确认 `-19 --check` |
| Zstd 解码合法但估算错得很明显 | frame key 的 `(s,d,t,r)` 和 EAT `kSourceIndex` / `kTargetIndex` 是否一致；`frameBytes.inc` 是否同步 |
| 部分整数输出在 32/80 附近不同 | 近场分档必须 `h>32`、`h>80`；边界相等时不能升级 |
| 训练了新观测点却仍复用旧 `*.inc` | 观测点索引及线性恢复不再匹配，必须重新导出六张 C++ 表 |
| 新架构 JSON 压缩成功但查询错误 | 原始 JSON 已变、`shared/arch.cpp` 的长度没更新，或原本图支撑/near40 与新图不匹配 |
| 原名义求解器无法完成 | 全源/全曲面计算量远超通常 1M 样本，需在资源更充裕的离线主机上运行，并按源/步骤断点保存 |
